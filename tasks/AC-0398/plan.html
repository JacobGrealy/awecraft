AC-0398 — plan: interpolated modern vertex lighting

Goal

Replace the per-face shading constant FSH and the 4-level AO_MULT corner steps in gdext/src/mesh.cpp with a continuous per-vertex geometric light field (height-field sky openness + per-vertex normal-derived face shade), behind a persisted switch (modern_light, env AWECRAFT_MODERN) that short-circuits BEFORE any shading is emitted so the arm can assert byte-identity with it off.

Files to touch

  • gdext/src/mesh.cpp — the whole mechanism:
    • Ctx.modern (parse default false = pre-feature when the key is absent);
    • once-per-build 18×18 column-top grid (topmost-solid scan of the snap box, row-wise, computed only when modern && !coarse);
    • s_modern_corner(fi, wx, by, wz, …): sl = clampf(1 - 0.4·occl, MIN_AMB, 1), occl = Σ w_d·max(0, H_d - by + 1) over the 8 neighbour columns (cardinal w 0.5, diagonal w 0.25; missing neighbour → no occlusion / own height); oshade = 0.5·FSH[fi] + 0.5·clamp(dot(N,SUN)/SUN.y, 0, 1), N = central-difference geometric normal of the column tops, SUN = normalize(0.25, 1, 0.1) (flat top stays exactly FSH; flat side → 0.4–0.525; slope vertices tilt between).
    The 3 smooth emit sites take the grid: emit_ro_merged (merged key = (s, oshade) pair when modern), emit_faces (uniform/non-uniform branches), emit_ramp (the fixed 0.9 becomes per-vertex oshade — the sloped quad stops reading as one flat shade). OFF = the pre-feature code paths, untouched.
  • godot/autoload/settings.gd — "modern_light": true in DEFAULTS, sanitize_bool clamp, apply_modern() apply step (has_method guard, _StubWorld-safe) — mirrors smooth_ramps (AC-0205).
  • godot/world/world.gd — note_modern() (ctx key + tex_refresh re-mesh; NO geom_epoch bump — colour-only, collider untouched) + boot derive + AWECRAFT_MODERN=0|1 env preload (mirrors note_ramps, world.gd:3697).
  • godot/ui/menu.gd — Options row + toggle handler (mirrors ramp_check).
  • godot/ARCHITECTURE.md — Settings row + mesh.cpp lane row + AC-0398 bullet in §4 (convention: new look-switch; the C++ key-absent default OFF vs game default ON polarity).

The switch

  • Setting modern_light, DEFAULT ON (true) — the user asked for this in their own words; the project rule (AC-0205 harvest) says default to the conservative behaviour unless the user asked for the new one. Persisted on the Options surface, clamped, env-overridable.
  • C++ parse_ctx default for the key is OFF: the arms' hand-built ctx dicts (the ramp arm's _ramp_build, meshprobe) carry no key, so they stay on the pre-feature path — the ramp arm's stored _RAMP_REF fingerprint (pre-AC-0398) therefore stays byte-green, no harness edit owed. The game always writes the key at boot, so the polarity split is an arm-side detail, documented here and in ARCHITECTURE.md.
  • Short-circuit: ctx.modern == false → the height grid is never computed and the three emitters take their existing branches verbatim (byte-identity).

Why this produces a gradient where there are steps

The bands photographed in AC-0394 come from corner values that plateau: at a step edge the starlight sum drops to 0.5/0.75 and the AO multiplier steps 1.0→0.8/0.6, so a 2-cell-wide 40–60 % dark band sits on every stair contour. Modern mode makes both terms a continuous function of the neighbour heights: the sky term eases off over ~2 cells (1.0 → 0.8 → 0.6 → 0.4 scale, deepening with cliff height), and the face-shade term tilts with the per-vertex geometric normal — so the same terrain renders as a soft ramp instead of a contour line, while fully flat, fully lit ground stays bit-identical (sl 1.0, oshade = FSH) and caves saturate to the MIN_AMB floor (AC-0159's "caves feel dark" property is preserved).
