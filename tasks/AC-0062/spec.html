AC-0062 — Save / Continue with multiple save slots

User 2026-08-21: "if the menu work we just did didn't include saving and continuing, implement that next. Make sure it supports multiple save slots." The AC-0033 menu did NOT persist worlds. This task adds real save/continue across sessions, on desktop AND web (IndexedDB via user://).

What a save captures

  • World seed (Game.world_seed) and time-of-day (Game.time_of_day).
  • World edits only (delta) — NOT the whole voxel world. Recommended: track edits in world.gd as edits := {} keyed by chunk (cx,cz) → {cell index → {block id, fluid level}}. Update it inside the existing set_block (world.gd:442) and the fluid-write path so every player-caused change is recorded. On save, serialize the edit map. Keep it bounded (only touched cells).
  • Player state: position, inv (Array of {id,n}), sel, armor (Array), hp, hunger.

Slots

  • 3 named slots (0,1,2; trivially expandable later). Mirror the autoload/settings.gd persistence pattern: one ConfigFile at user://awecraft_saves.cfg, one
    per slot, OR one JSON file per slot — your choice, but it MUST go through user:// so the web export persists to IndexedDB (settings.gd already proved this works on the browser).
  • Active slot = the one the current session is playing on (set when you New World into a slot or Continue one).

Flow / menu wiring (extend the AC-0033 menu; keep its styling/state-machine — do NOT regress D1/D2)

  • Menu gets a slot list (3 rows): each shows slot state — "Empty" or "World · · edits" (whatever fields you store). Per occupied slot: Continue (load it) and a delete/clear. The existing New World (seed + New World button) assigns/creates a slot (pick first empty, else overwrite-prompt-free overwrite of slot 0 — document the rule) — keep it working.
  • Auto-save on quit: quitting to menu (Quit to Menu / browser quit) writes the active slot. (A manual "Save" in pause-options is a nice-to-have; auto-save-on-quit is the requirement.)
  • Continue = load seed + regenerate base world deterministically (WorldGen.generate is seed-deterministic, GENHASH-gated) + re-apply the saved edit delta + restore player state/time, then go straight into the game (menu first, then auto-start, mirroring the AWECRAFT_MENU_BOOT harness path).
  • New World = fresh seed (or user-entered) into a slot, no edits, player at spawn.
