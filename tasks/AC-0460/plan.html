AC-0460 stage 2a — restore occlusion culling under the warp

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Small, bounded, and it removes the one acknowledged cost of the AC-0461 decision before the flag's default is considered. This is not the lane rewrite.

1. Goal

With the warp on, a solid slab gets an occluder again — built from its own warped mesh bounds instead of a legacy-frame constant.

2. Why this is safe now (coordinator audit, 2026-10-20)

SphereMath.face_chunk_transform has exactly ONE production caller — world.gd:15363, the chunk node's transform assignment — plus harness arms. No production code reads a face chunk's node transform back, so the warp's identity node is not consumed by anything except Godot's own parenting. That is what makes restoring the occluder, and later the default, tractable; the audit is recorded in this ticket's journal rather than left as folklore.

4. Edit shape

  • Flag off — byte-identical. Keep the existing branch exactly as it is: a 15×15×15 BoxOccluder3D at local (8, y0+8, 8), gated by full_solid and _occl_enabled().
  • Flag on — derive from the mesh. When _warp_on and the same full_solid and _occl_enabled() gates hold, take the slab's own opaque mesh AABB (s.mesh_instance.mesh.get_aabb(), which is world-space under the warp) and create the occluder from it: a BoxOccluder3D whose size is the AABB size, with the OccluderInstance3D positioned at the AABB's world centre (the node is identity under the warp, so the child's position IS the world centre — set it to aabb.get_center()).
  • Guard: if the mesh or its AABB is empty/degenerate (any size component ≤ 0.01), leave s.occluder = null rather than creating a zero-volume occluder.
  • Do not shrink by a fudge factor unless the existing flag-off path does (it does not — it uses 15 for a 16 m chunk). If a margin is needed to stop an occluder covering the camera, that is a finding for the probe to show, not a guess to bake in.

5. The probe (new tasks/AC-0460/occ_probe.gd) and the arm evidence

A pure-math probe cannot see occluders, so pair the code change with the existing arm rather than inventing a new world harness:

  • Probe (pure): for a representative face chunk's warped corner cloud (the AC-0461 construction), compute the AABB centre and size that §4 would produce, and assert the centre lies within the chunk's own corner cloud bounds and the size is within [1, 40] m on each axis. Report the values. This proves the arithmetic the code performs, not the node tree.
  • Arm evidence: re-run the existing warpcensus arm with the flag on and report, in the RESULT or the log, that slabs built warped still succeed (no SCRIPT ERROR, chunk count unchanged). Do not add a new arm; if you need an occluder count, add ONE field to warpcensus's RESULT (e.g. occluders) and its harness_data row.

7. Acceptance

Under the warp a solid slab again carries an occluder, positioned from its own world-space bounds; with the flag off nothing changes at all; and the audit that makes this safe is recorded.

8. Risks

The AABB of a full slab may be nearly chunk-sized, so the occluder is coarse — that is acceptable (the flag-off one is coarse too). Do not attempt per-face occluders.
