AC-0460 stage 3 — what does the warp cost?

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. A measurement ticket: instrument, report, change no behaviour. This is the gate in front of any decision to default the warp on.

1. Goal

A number for the warp's cost per chunk and per vertex, measured inside the warp pass, from the arm that already builds 78 warped face chunks.

2. Why not the perf arms

The boundary arm walks the HOME pair, and the warp returns early for faces < 2 — it would report 0 cost for a real cost. The existing warpcensus arm is the right vehicle: it stands at the boundary, builds face chunks deterministically, and already reports warped_chunks.

4. Edit shape

  • Add statics beside warped_chunks: warp_us (total microseconds inside the warp pass), warp_verts (vertices examined), warp_surfaces (surfaces visited). Reset them in the arm before its run starts, so the numbers belong to that run.
  • Time ONLY the warp loop with Time.get_ticks_usec() around it, summed per surface. Do not instrument inside the per-vertex body.
  • In warpcensus's RESULT add: warp_ms_total (warp_us/1000, rounded), warp_verts, warp_us_per_vert (warp_us / max(1, warp_verts), 3 dp), warp_ms_per_chunk (warp_ms_total / max(1, warped_chunks), 3 dp), and keep the existing fields unchanged.

6. Acceptance

A reproducible per-chunk and per-vertex cost for the warp, with a zero-cost control when the flag is off, and the two-run variance stated.

7. Risks

Timing a loop that allocates will include allocator noise; that is acceptable as long as it is stated. Do not optimise anything — this ticket measures.
