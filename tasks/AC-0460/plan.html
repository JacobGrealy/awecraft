3. Edit shape

3.1 The counter. In chunk.gd add static var warped_chunks: int = 0 and increment it once per build inside _warp_face_slabs, after the face-lane guard, at the point the warp actually runs. The flag-off path must not touch it, so the shipped path stays byte-identical.

3.2 The arm warpcensus. A world arm in harness.gd that:

  • boots the normal world at a small radius (reuse the compact arm's boot sequence — do not invent one);
  • places the player near the home/face boundary: flat x at about SphereMath.face_width(R)/2 - 8, z near 0, so _face_stream's edge-normal gate is satisfied and faces 4/6 stream;
  • runs a bounded, deterministic number of frames (state the number; 240 is a starting point) so face chunks build and land;
  • reports: the flag state, how many face chunks are resident in the world map, Chunk.warped_chunks, and for the first resident face chunk with a mesh: the mesh AABB centre in world space, the chunk's EXPECTED world centre from SphereMath (the chunk's canonical surface point at its middle), and the distance between them (aabb_delta_m).

Expected values. Flag OFF: warped_chunks == 0 and the mesh AABB is in the legacy local frame (delta large — that is the control). Flag ON: warped_chunks > 0, and the AABB centre must be within one chunk footprint of the expected world centre (state the tolerance: 120 m, generous because the AABB centre of an arbitrary mesh is not the chunk centre) — the point is that it is in world space at all, not centimetre-precise.

RESULT keys: ok, warp, face_chunks, warped_chunks, aabb_center, expected_center, aabb_delta_m, frames.

3.3 The pixel A/B. With the player at the boundary, take TWO renders of the same frame — one with AWECRAFT_WARP=1, one without — and compare md5. A byte-identical pair is a FAILED proof (it means the warp still is not reaching the frame); a different pair with a coherent image is the pass. Use the standing snapshot recipe (no AWECRAFT_LOGIC arm for the shot — the arm owns the frame, so use the harness's own shot hook, or drive the player pose with the existing env-gated position hooks rather than inventing one). If composing a boundary shot needs a hook that does not exist, say so and deliver the arm only — do not invent a new shot system.

5. Acceptance

The warp is provably applied to real face chunks in a live world (counter and AABB in world space), the flag-off control proves the counter cannot lie, and — if a boundary shot is composable — the pixel A/B differs. If the shot is not composable, the arm alone is the deliverable and the gap is recorded, not papered over.

6. Risks

The player-position hook may not exist for a boundary spawn; then extend the arm's own setup (it runs inside the game) rather than adding env vars. A "difference" in the render could come from anything — pair it with the counter so the pixels and the number agree.
