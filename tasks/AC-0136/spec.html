AC-0136 — texture-filtering-sharp-nearest-regression

id: AC-0136 · status: open · priority: 2 · source: user · created: 2026-08-28T09:16 · parent: —

Registry notes (verbatim, quoted):

Textures are not sharp after AC-0128: filtering looks linear/blurry instead of pixel-sharp NEAREST (used before via StandardMaterial3D.texture_filter=NEAREST). AC-0128 switched opaque/cutout/flower/fluid to unlit shaders (chunk_lit_*.gdshader) with uniform sampler2D tex (no filter hint) sampling runtime ImageTextures from ImageTexture.create_from_image (data.gd tint bake + chunk.gd lit_atlas). Runtime textures likely default to LINEAR, so shader samples blurry. Fix: set shader sampler to filter_nearest (uniform sampler2D tex : filter_nearest) and/or ensure ImageTexture filter is NEAREST at creation. Verify with close-up block: single-pixel texels stay crisp at any distance/FOV; compare with pre-0128 StandardMaterial NEAREST. Gate: close-up dirt/grass remains pixel-sharp, no bilinear blur.

Goal

GOAL — Restore pixel-sharp NEAREST filtering for block textures: after AC-0128 switched opaque/cutout/flower/fluid to the unlit chunk_lit_*.gdshader materials, the shader samplers sample the runtime lit-atlas ImageTextures with default (LINEAR) filtering ⇒ block textures render bilinearly blurry instead of pixel-sharp (user-reported 2026-08-28; sharp via StandardMaterial3D.texture_filter=NEAREST before AC-0128).
