AC-0448 — options menu: reachability + developer section

Goal

  1. Every option reachable at the user's resolution — demonstrated in a frame showing the bottom-most entry, with the scroll behaviour shown, not described.
  2. Feature-flag / internal switches move under the existing Developer tab; genuine player preferences stay on the Settings page. Placement only: every setting keeps its key, default, env override and the settings arm stays green with its row count explained.

Row census (code reading, pre-fix — confirmed by the render-run measurement)

What the panel is actually doing (the confirmed defect shape)

  • TabContainer's minimum height = tallest page minimum (the Settings page, > viewport at 1280×720 and 1920×1080). The full-rect CenterContainer then centers that oversized TabContainer, so the panel's top (tab bar) and bottom (last rows, PackButton, BackButton) sit outside the window. Nothing clips (no ScrollContainer anywhere), nothing scrolls — the off-screen rows are unclickable. The tscn comment at OptionsBox/Center/VBox already records the same disease at AC-0260 (12 px separation clipped the tab bar off the top; mitigation was only the 12→6 separation cut).
  • Measured exactly by the extended menu-shot hook (pages RESULT block: rows / content height / page rect / scroll range) in a Forward+ render at 1280,720 before the fix, and again after.

Mechanism chosen — why

  • Scroll per tab page: each of the three tab pages becomes ScrollContainer (vertical auto-scroll) → CenterContainer (expand-fill) → the existing VBox. The CenterContainer restores the AC-0257 casualty (a plain ScrollContainer broke the centering): short content stays centred exactly as today, tall content scrolls with the engine's own scrollbar — the existing Godot visual language, no new chrome, no paging state machine, no fixed-height panel magic. Gamepad/keyboard focus scroll natively.
  • The tab area is bounded: OptionsBox/Center becomes a MarginContainer (margins computed at boot + on window resize: 40 px top/bottom, sides centring a ~720 px panel) so the TabContainer can never grow past the window again — the container that was missing, added at the level where the overflow is real. Without it the centered tab bar would still clip.
  • The restructure (job 2) reduces the surface: 12 internal switches move to the Developer page (below), so the Settings page stops reading as a development tool; scrolling remains as the standing container guarantee for whatever rows future tickets add (growth without a container was the root cause — the container is the fix, the split is the polish).
