AC-0164 — thread chunk I/O off main thread

Builder report · 2026-08-31 · gates run in-session (builder tier: G0/SMOKE/chunkio/save/continue/render; boundary+perf+build = coordinator)

What shipped

Design: FileAccess-on-worker (the primary directive), NOT the sanctioned fallback. The whole column I/O now runs on the WorkerThreadPool (the same pool + singleton as threadgen — the proven AC-0082 per-tid-slot / stale-drop handoff pattern): file open/read/write, ChunkIO.encode_column (~26 ms) and ChunkIO.decode_column (~20 ms) all execute inside worker tasks. The main thread only enqueues (evict save, data-landing read) and polls (io_poll). No hang, no crash, no torn file in any gate run (torn/corrupt files would fail the blob MD5 → decode fail → fail-closed gen fallback; fails:0 in both chunkio runs), so the fallback (main-thread syscall, worker-only codec) was not needed.

  • Writes: _queue_chunk_save now captures slot + face + cx + cz + data + fl at enqueue time (the active slot can change mid-flight on continue/new-game; a write in flight goes to the CAPTURED slot's dir). _drain_save_queue (same 1–2/frame pacing) just enqueues; encode + FileAccess(WRITE) run in _io_write_worker. Per-key write dedup: a second save of a column already in flight is dropped (wdedup) — its snapshot + the JSON edits diff (re-applied on load) keep the data correct.
  • Reads: new pending-load registry (_io_read_inflight / _io_read_keys, keyed by chunk key, per-tid slots in _io_slots). Checked at every data-landing site: drain data pass (pick skip, like _tg_inflight_keys), _materialize_chunk_data (never sync-loads/gens over an in-flight read), and the recenter 5×5 burst (a successful enqueue — file exists or read already in flight — sets the had_data snapshot true so the burst worker skips the column). A column with a load in flight is therefore never re-enqueued for generation and never built early (builds are gated on 8-neighbor data). Provenance counters (chunk_origin disk/gen, disk_reads, disk_read_ms) are marked when the data LANDS in _io_read_handoff. Fail-closed: a decode failure (missing/torn file) falls back to threadgen — never a silent empty column.
  • Recenter 5×5: the ~500 ms synchronous 24-column disk load (known-limit of record) is gone — it's 24 low-priority worker reads now. The drain's 1-inflate-per-frame pacing is gone with it (decode is off-main; enqueue is ~0 ms). The (0,0) spawn column stays synchronous (spawn contract: immediate ground under the player; one column, once per boot).
  • Shutdown: _exit_tree drains in-flight read+write tasks before script unload (same bounded-wait loop as threadgen/threadmesh).

Unchanged by contract: save policy (every data column saved on evict, pure stubs skipped), SAVE_VERSION 3, AWCC v1 blob bytes (chunk_io.gd untouched — it already ran worker-safe), the chunkio arm, and the threadgen no-disk-first rule.

Deviations / known notes for the coordinator's heavy gates

  • Boundary r4 walk p95: expect it to DROP below the 73–89 band. The evict-time write cost (1–2 × ~33 ms of encode+write inside main-thread frames at every recenter, worst at the crossing-16 eviction burst) is gone — those frames now pay ~0.1 ms. A lower p95 (or at least no rise) is the expected direction; the crossing-16 burst wall may also shrink since the eviction burst no longer stalls frames.
  • Invalid Task ID engine errors at is_task_completed (recenter burst-group prune, world.gd) — pre-existing known class (present in AC-0155/AC-0152 gate logs; backtrace verified as the same site in this run's logs). 6 occurrences in chunkio run 2, all from recenter, none from the new io_poll.
  • SMOKE log contains one threadgen_handoff Nil→PackedByteArray transient — the documented AC-0137-class known noise (also present once in AC-0155's smoke.log and smoke2.log); not chased per the non-fatal list.
  • Render: the box's xvfb did not hang this time; no environmental deviation. (Infra note: /tmp is ephemeral per bash call here — the snapshot was written to an absolute /tmp path and copied into tasks/AC-0164/ within the same invocation; a relative AWECRAFT_SNAPSHOT path fails Godot's save_png.)
  • Run-to-run spread is normal: chunkio wall 34–44 s across runs (≤ 60 s gate), saved-column count 108–117 (drain timing decides how many stream-set columns hold data at evict; the gated 41-diamond checks are exact in every run).
