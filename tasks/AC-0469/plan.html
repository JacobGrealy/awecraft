Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Final step of the residency merge. Deletion only, and only of genuinely dead code — the 12 ms budget and the sync fallback remain load-bearing and must not be touched.

1. Goal

Remove the face lane's now-unused constants, branches and bookkeeping left behind by G1–G3, so the residency model exists once with no vestigial second copy.

2. What the previous three steps established

  • G1: one `resident_of(face, cx, cz)` predicate (identity proved on 28,381 comparisons).
  • G2: one `_resident_order` list and one `_resident_sweep`; pacing kept per-lane deliberately; the unification exposed a latent leak (out-of-set drain stubs never freed) which is now fixed.

  • So `_face_stream` is now a thin face-side entry: the creation pass plus the travel-gated sweep.

4. Edit shape

  • 4.1 Prove death before deleting. For each candidate, grep the whole repo for references and record the count in the deviations. A candidate with any reference outside its own definition is not dead — leave it and say so.
  • 4.2 No functional change. This stage must not alter any behaviour, any pacing, any radius or any order of operations. If removing something would change behaviour, it is not dead code — it is a design decision for a later ticket.
  • 4.3 Update the comments that described the old two-lane arrangement so a future reader is not told about code that no longer exists. ARCHITECTURE.md §6 should reflect that residency is one model with two pacing policies.
