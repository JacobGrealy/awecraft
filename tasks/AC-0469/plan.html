AC-0469 stage 0 — what does 1 m everywhere actually cost?

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Measurement ticket: add one arm, change no world behaviour. The user has set the goal — blocks stay ~1 m × 1 m × 1 m, multiple planets, fly in anywhere, the same experience across the whole planet — so the FACE grid at 6.136 m cells is the anomaly to be replaced, not the standard to copy. Before anyone regenerates the planet, this stage produces the cost table that decides the view-distance trade.

1. Goal

A measured cost table for candidate (cell size × view distance) combinations: resident chunks, resident bytes, per-chunk build time, and whether each fits a frame budget — so the 1 m decision is made on numbers.

2. The arithmetic that is already known (do not re-derive; extend it)

  • face_width(R) = πR/2 = 6,283.2 m at R = 4000. face_cell_size = face_width / CELLS_PER_FACE.
  • 1,024 cells → 6.136 m blocks → 1,048,576 columns/face. 3,000 → 2.094 m. 6,283 → 1.000 m blocks → 39,476,089 columns/face.
  • Residency is radius-based, so it does NOT scale with the total: a 4-chunk radius is 81 chunks of 16×16 = 20,736 columns whatever the grid. What scales is CHUNKS PER METRE: a 16 m cell chunk covers 16 m at 1 m cells and 98 m at 6.136 m cells, so covering the same physical distance needs 37.6× more chunks at 1 m.

4. What to measure and report

  • 4.1 Bytes per resident chunk, measured — from the actual slab payload plus the node/mesh overhead the tree really holds, not from a datasheet. State where the figure came from.
  • 4.2 Milliseconds per chunk build, measured — the face lane's own figure already exists (warpcensus: ~0.42 ms warp + the mesher; report the full build, and say which part is measured vs derived).
  • 4.3 The projection table. For each candidate cell size (1.000, 2.094, 6.136 m) × each candidate view distance (say 0.5, 1, 2, 4 km): the number of 16-cell chunks needed to cover that disc, the resident bytes, and the per-pass streaming time at the measured per-chunk cost. Give the formula in the deviations so anyone can re-derive a cell.
  • 4.4 The verdict. Which combinations fit a 60 fps frame budget (16.7 ms) with the existing 12 ms face-stream budget, and which do not. State the trade explicitly: 1 m blocks at a given view distance costs N× the chunks of 6.136 m blocks at the same distance.
