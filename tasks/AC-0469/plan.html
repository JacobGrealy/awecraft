AC-0469 stage E — face chunks generate on the worker, not on the frame

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. This is the first slice of generalising the home lane, and it targets the one thing the face lane actually lacks: asynchronous generation.

1. Goal

A face chunk's terrain is requested through the existing threaded generation path and lands via the drain, instead of being built synchronously inside _ensure_face_chunk. The synchronous path stays as the fallback that the player query uses, so nothing can fail to appear — but the common case stops paying generation on the frame.

2. Why this and not "delete the home lane"

Measured (round 48): the home pair is now the SAME grid as the chart faces (6,283 cells at 1 m), so the resolution separation is gone. What differs is machinery, and the home lane holds the good half — worker generation, IO poll, drain, band priorities, pooling. The face lane's remaining weakness is that _ensure_face_chunk calls WorldGen.generate_face synchronously; the twelve-chart lap showed crossings stay solid only because of that synchronous build, which is a hitch rather than a gap. Making the face lane async is the step that lets the two lanes eventually become one.

4. Edit shape

  • 4.1 Enqueue when it is safe, build when it is not. The prestream and the ordinary window requests should enqueue. The player's own column query (get_block_key's is_inf sentinel path) must keep building synchronously when the chunk is absent — that is what guarantees the player never stands on nothing, and removing it would reopen the AC-0145 hazard.
  • 4.2 Landing must be complete before the chunk counts as resident. A drained face chunk must go through the same landing the home lane uses (data, light seed, mesh, collision, occluder) — the AC-0460 occluder parity and the AC-0466 mesh+body checks are the proof it did not half-land.
  • 4.3 Reuse the existing queue and drain. Do not invent a second worker protocol or a second drain; if the home lane's structures cannot carry a face request without a change, make the smallest change that lets them.
  • 4.4 Keep the budget honest. The face pass still spends at most FACE_STREAM_BUDGET_MS; enqueueing must not turn a budgeted pass into an unbounded one.

6. Acceptance

Face chunks generate off-frame in the common case, the player's own query still cannot fall through, every crossing still has mesh and body, generation is bit-identical, and the latency number is reported honestly.

7. Risks

(1) An async face chunk that lands late could let a crossing see an unbuilt destination — planetwalk is the guard, and if it goes red this stage is not done. (2) Two queues racing for one chunk would double-generate; keep a single owner per key. (3) If the worker protocol turns out not to be reusable for faces without a large change, STOP and report what the obstacle is rather than building a parallel system.
