AC-0077 — chunk-stream-buildcost — plan (Run 1)

Research-only pass (no .gd edits, no git, no builds). Design source: tasks/AC-0071/AC-0071-plan.html P1.3+P1.4, per binding tasks/AC-0077/spec.html (filled 2026-08-26). All measurements below are FRESH, taken this run on the current tree (AC-0107 threadmesh + AC-0118 sliced recenter ON, headless, seed 44, pool=3/3).

1. Goal

Cut the per-chunk cost of stream-in (recenter-crossing) builds: one batched per-chunk-contained light compute per crossing instead of 9 self-computes (fed into build_mesh/build_accs via the existing eff param so workers skip their own light), staged collision-body creation (player ±1 immediate, far chunks drained as low-priority units behind a single revert flag), and per-build collision_ms + per-crossing light-compute instrumentation — targeting the AC-0034 residual forward-drain p95 (fresh baseline 5216 ms at r4).

2. Files to touch (design lives here — decisions D1–D6)

D1 — P1.3 batch light: the exact integration (spec: “Run-1 states the exact integration”)

DEVIATION (documented, spec-permitted): the spec goal text says “ONE union-box (+margin) compute per crossing”, but the spec FENCE (spec.html, Fences §3) requires the batched light to produce IDENTICAL per-chunk light values to today's per-chunk compute (torch 14 exact, no visual change). A single geometric flood over the union box is provably and empirically NOT identical to per-chunk contained floods — fresh probe (`.scratch/AC-0077/probe_light2.log`, seed 44, 3×3 cluster): union box margin-0 = 296 ms for the 48×48×80 box vs 160 ms for 9 per-chunk computes (1.85× SLOWER, same 184 320 cells), and its 16×16 slices differ from the per-chunk values in 74 of 184 320 cells (0.040%) — all union-brighter (0 chunk-brighter), max Δ6 (sky/edge light leaking across chunk borders the contained kernel forbids). Margin-2 union: 346 ms, same 74 diffs. The union-flood variant is therefore rejected on both counts; the batch keeps the “one compute pass per crossing, sliced eff, workers skip light” intent with per-chunk contained floods through the same kernel (margin 0 — the contained kernel reads nothing outside its 16×16×80 box, so no margin is possible or needed).

Files:

  • godot/world/lighting.gd — new pure-static compute_light_flat_batch(items: Array) -> Array: items = per-chunk {"data": PackedByteArray (fresh copy), "cx": int, "cz": int}; returns per-item dicts {"mn": Vector3i(cx*16, 0, cz*16), "w": 16, "d": 16, "arr": PackedByteArray(20480)} — exactly compute_light_flat_chunk's return shape (lighting.gd:231). Implementation: refactor the body of compute_light_flat_chunk (column open-scan + the two contained _flood_flat floods, :278) into a private static _chunk_light_into(data, cx, cz, h, ids, sky, blk); compute_light_flat_chunk calls it (zero behavior change — G2/G3 protect), the batch loop reuses preallocated ids/sky/blk (3×20 480 B) across items and allocates a fresh eff per item. Byte-identity is by construction: same kernel, same box, same data as today's per-chunk call. Existing compute_light_flat (:146, web-faithful cross-chunk flood used by the edit-flush bulk path) is left untouched.
  • godot/world/world.gd — crossing-batch wiring + eff cache:
    • Crossing batch trigger = the recenter WANT set (world.gd:336–353: all in-radius, unqueued, unbuilt chunks) — at r4 that is exactly the 9 new wall chunks per crossing (first load: 81). WANT phase completion records _bl_want: Dictionary (key→true).
    • The drain (_drain_build_queue, world.gd:684) computes the batch before unit picks: for want-set chunks whose data is ready (c.data non-empty — data lands via the threadgen wave after recenter) and that have no valid cached eff, call compute_light_flat_batch with up to 2 ready chunks per drain call (~36 ms worst case, inside the existing budget_us 30 ms cap — first call of the frame, then the check). When every want chunk is eff'd or gone, _bl_want clears = one batch per crossing (9 chunks ≈ 9 drain frames ≈ 150 ms at steady state).
    • Eff cache _eff_cache: Dictionary key → {"data": PackedByteArray copy, "eff": Dictionary}, cap 128 (FIFO evict; eff+data = 40 KB/entry ≈ 5 MB worst case). Dispatch (_build_unit) passes the cached eff when c.data == cached.data (20 KB byte-compare ≈ 0.1 ms, only when the key is cached), else {}; after a self-compute the eff is cached from the result (sync c.last_eff / worker res["light"]).
    • Feed to threadmesh = the existing eff param: _mesh_dispatch entry["eff"] (world.gd:598) → worker build_accs skips its own light (chunk.gd:1136–1138); the sync fallbacks (build_mesh(get_block, eff), world.gd:568/578/591) consume the same eff. No handoff contract change (fresh copies, ≤6 cap, dedup, stale-drop, spawn-sync all untouched per fence).
    • Invalidation: set_block (world.gd:1158) erases the edited chunk's own cache entry only — a contained flood reads no neighbor data, so a neighbor edit never changes this chunk's light (the 3×3 mesh rebuild then reuses valid cached effs for the 8 unedited neighbors: 8 fewer computes per edit, values identical to today's recomputes). Chunk free paths (recenter MERGE_OLD/unload, _enter_candidate ~world.gd:871) erase cache + batch + staging entries.
  • godot/world/chunk.gd — no change needed for P1.3 (build_mesh :1361 / apply_accs :1543 already consume eff); only the P1.4 hook below.

Why this is the right lever (measured): probe — worker task build_accs full (light+snap+emit) = 269 ms median; with eff supplied (mesh-only) = 252 ms; per-chunk light = 17.8 ms (6.3% of the task). Mesh stage = 3 workers / 269 ms ≈ 11.15 chunks/s and is the bottleneck (first-load perf r4: 81 chunks meshed in 8.32 s ≈ 9.7/s including startup; the drain dispatch itself is fast: 2428 units / 8.32 s ≈ 292 u/s, main-apply only 158 ms total ≈ 2.0 ms/chunk). Removing light from the worker task → 3/252 ms ≈ 11.90 chunks/s (+6.7%) — the forward wall (36 chunks at r4) drops ≈ 210 ms. The batch's main-thread cost (18 ms/chunk, sliced ≤2/drain call) fits the 30 ms drain budget with 2 build units still dispatching (units ≈ 6–8 ms) — dispatch headroom is large (292 u/s vs 11/s needed), so the slice is throughput-neutral.

D2 — P1.4 collision staging (spec: “next-slot low-priority unit … single revert flag … no duplicate bodies, no orphaned bodies”)

  • godot/world/chunk.gd — new var col_immediate := true (:17 area). Today's body creation in build_mesh (:1530–1535) and apply_accs (:1596–1601): if collision_enabled and col_dirty and col_immediate: _build_collision(), and col_dirty = false only when a body was actually built (deferred chunks keep col_dirty == true + collision_body == null). _build_collision (:1615) unchanged.
  • godot/world/world.gd — single revert flag col_stage_enabled := true (env AWECRAFT_COLSTAGE=0 → false = today's immediate-everywhere, exactly the old behavior). Build-completion hook _stage_check(c, key) called from the world side right after a sync build (_mesh_dispatch/build unit) and after threadmesh_handoff's apply (world.gd:555): if col_stage_enabled and c.collision_enabled and c.col_dirty and Chebyshev(c.cx,c.cz, player chunk last_pcx,pcz) > 1 and not the spawn chunk (cx==0 and cz==0 — always immediate; the player's ±1 covers it at spawn) → enqueue into _col_pending: Array + _col_pending_set: Dictionary (dedup); else build immediately. Player-chunk tracking reuses the existing player-chunk vars (the ones set_block/recenter already maintain).
  • Staging drain inside _drain_build_queue, after the build/data unit loop and separate from band_buckets (so queue_size and the AC-0118 gates are untouched): ≤2 entries/frame, nearest-to-player-first (re-sorted per frame; ≤81 entries), per-entry validity: chunk present + mesh_built + collision_body == null (dup guard — a body is built at most once) + collision_enabled + col_dirty + in-radius (|dx|≤render_radius, |dz|≤render_radius) — else drop (erase; this is the orphan/duplicate prevention, and recenter free paths also erase pending keys). If the player is now within ±1 the body builds immediately (spec: “re-checked if the player approaches before it runs”). At the leading edge a far chunk can be a 1-frame pass-through — AC-0071-accepted; the fence’s ±1-immediate rule holds (the player's own chunk + 8 neighbors are always immediate, spawn chunk explicit).
  • Load boundary (AC-0081 save/continue): staging state is per-World-instance → a fresh World = a fresh queue; the ±1-immediate rule applies at the continued position; the validity checks are the guarantee. Revert: AWECRAFT_COLSTAGE=0 flips every col_immediate path back to immediate (one flag, no other code changes).
  • Instrumentation (per-build collision_ms, spec requirement): perf_collision_ms / perf_collision_n / perf_collision_max_ms around every body build (immediate and staged alike — the immediate value is today's inline cost, ≈1–2 ms per probe: sync build 270 ms − worker-full 269 ms).

Identity edge (union margin) — mitigated by contained-kernel design (margin 0, byte-identical by construction); probe proves the rejected variant wrong. Physics pop — ±1-immediate rule + spawn-chunk rule; 1-frame pass-through only at the far leading edge (player never there). Load/orphan bodies — per-instance state + collision_body == null dup guard + validity drops. A/B noise — D4 method + honest-FAIL clause.
