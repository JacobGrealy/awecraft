AC-0141 — blocks and items defined in JSON, loaded by the same lookups

Coordinator contract. High-effort builder applies it with tasks/templates/implement.md. Behaviour-preserving data move: every lookup must return exactly what it returns today, and the proof is a before/after table dump, not "the game still runs".

1. Goal

The block and item tables live in godot/data/blocks.json and items.json; autoload/data.gd keeps the constants, the loaders and every lookup (block(), item(), block_drops, block_tool, the rect/tint/frames helpers, match_shapeless/match_shaped) so callers are unchanged.

2. What the tables look like (measured, so the plan is concrete)

  • autoload/data.gd is 500 lines. The item table starts at :64 (100: {"name": "Stick", "icon": Color(0.72, 0.55, 0.35), "stack": 64}) and runs to at least :110 (147: {"name": "Cooked Chicken", …, "food": 5}).
  • Entries are integer-keyed dicts whose values include Color(r,g,b) objects, nested dicts, arrays of dicts, and in the recipe tables keys that are integer item ids ({105: 3, 100: 2}).
  • Also present in the same file: mobs, recipes (~120-150), tiles, and colour constants (C_GRASS_TOP…). The ticket says blocks + items, and recipes/tiles "if clean" — so blocks and items are the required scope and the rest is optional.

3. The round-trip is the risk, and it is what the gates test

  • 3.1 Integer keys. JSON object keys are strings, so the loaded dict must convert them back to ints — or every lookup (blocks[8]) silently misses.
  • 3.2 Colours. Color(0.416, 0.667, 0.251) must round-trip exactly. Choose a representation and state it (hex "#rrggbb" loses the alpha and the float path; [r,g,b,a] floats are safer). Godot's JSON keeps doubles; the values are float32 in Color, so a decimal round-trip should be exact — prove it, do not assume it.
  • 3.3 Anything that is not JSON-shaped. If a table holds a value JSON cannot express faithfully, say so and leave that table hardcoded rather than approximating it. An approximation here changes the game's colours and drops.

5. The proof — a before/after dump, not a smoke test

Before changing anything, dump the in-memory blocks and items to a canonical string (var_to_str over the dict, sorted, or a stable JSON with sorted keys). After the change, dump again and diff. The diff must be empty. Report the dump sizes so it is clear the comparison had substance — and note that var_to_str is the right tool for this comparison precisely because it preserves Godot types (Color, ints) that a JSON dump would flatten.

7. Acceptance

Tables in JSON, lookups untouched, an empty dump diff with reported sizes, genhash 25/25, save/load clean, and ARCHITECTURE.md updated.

8. Risks

(1) Integer keys becoming strings is the classic silent failure here — it would make lookups return null everywhere, which g0 might not catch but genhash and save/load would. (2) Colour precision: if the dump diff shows float drift, revert the JSON for that table and say so rather than adjusting the game's colours to match the file. (3) Do not reformat or "tidy" the tables while moving them — a data move plus a data edit makes the diff unusable as proof.
