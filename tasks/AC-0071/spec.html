AC-0071 — Chunk streaming plan (RESEARCH ONLY — no code)

User 2026-08-21: after the first load, chunks should be streamed in/out as the player crosses chunk boundaries — a separate parallel process and/or work spread across many updates doing small amounts of loading/unloading without interrupting gameplay. This relates to AC-0034 (block-break hitches). This task produces a plan of attack for the user to review BEFORE any implementation. Do not write game code, do not run renders, do not git. Deliver a readable .html plan.

Must audit first (ground the plan in the ACTUAL current pipeline — read the code, cite line numbers)

  • world/world.gd — recenter(), the build queue (how many chunks/frame, spawn-first ordering), render radius vs sim split, light/fluid dirty flush staggering, fluid sleep.
  • world/chunk.gd — build_mesh (SurfaceTool snapshot cost), collision rebuild (1 ConcavePolygonShape3D/chunk), per-block data layout, mesh/collision rebuild triggers (col_dirty, edit flush).
  • world/generator.gd / world/genhash — WorldGen.generate cost per chunk (the ~31 ms/chunk PERF3c-1 number; verify current).
  • First-load: what happens at boot (how many chunks generated + meshed before first frame, the "pop-in" cost) and what a boundary crossing costs today (sync recenter? worst boundary-chunk build? the AC-0034 diagnostics that were noted but never implemented).

The plan must propose (with trade-offs, not a single dogma)

  • Streaming policy: target-state chunk set around the player; priority by (distance, angle toward look dir, "needed for collision") with radial + ringed load order; unload policy + hysteresis (avoid load/unload flapping at the boundary); first-load fast-path (spawn chunk + ring 1 sync so the first frame isn't empty, rest streams).
  • Execution model, explicitly comparing for THIS engine: (a) budgeted main-thread work (N ms/frame of gen and/or N chunks of mesh per frame, interleaved), (b) Godot 4 Task/worker threads for generation (data-only, thread-safe: write into chunk data arrays off-main, main-thread mesh+collision only), (c) hybrid (gen threaded main+web; mesh budgeted). Hard constraint: the Web export (wasm) is single-threaded — the design MUST degrade cleanly to budgeted-only on web (feature-detect and fall back); call out exactly what works/doesn't in the browser. Also respect: one godot process at a time is about our test harness, not in-game threads — but note mesh/physics API calls must stay on the main thread in Godot (verify against docs).
  • Collision: how collision builds fit the budget (they're the heavy part — 1 concave/chunk); staged vs delayed; the interaction with player/mob physics.
  • Lighting + fluids: how the staggered flush/sleep integrate with streaming (no double work for chunks being unloaded).
  • Save integration: AC-0062 edit-deltas + continue must stay correct while streaming (edits keyed by chunk coordinates survive load/unload; re-apply on re-center).
  • Memory: peak resident chunks at render radius 4/6/8; unload frees mesh+collision.
