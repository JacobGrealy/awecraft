AC-0411 — plan: the body-disc-centre pale wash

Goal

Establish by A/B which term in the body's daylit colour path renders the disc centre as the flat pale-cyan wash (assessment: 144,209,221 at T0.5 / r21 measured 130.7,195.7,206.5) where the baked texel is 71 per cent grass and the committed formula predicts green. Fix it, then re-measure the disc centre and the disc's overall saturation/contrast at 1600 and 2600 m across T0 ∈ {0.25, 0.5, 0.75}, before and after, with the assessment's exact recipe and instrument, so the before numbers are directly comparable. Test the coordinator's link: does ONE edit move both the disc centre and the disc's overall saturation/contrast (the "pastel, low-contrast orbital material" finding) — if yes, one job; if no, say so. The landing half (120 m, 300 m, ground) must not regress against the r21 reference frames.

Hypothesis (code-reading; the A/B decides)

The bake writes sRGB-companded bytes (grass = 55,104,34; _l2s). ImageTexture.create_from_image() uploads them with no sRGB flag → linear-format texture → the shader samples the bytes as if linear and writes them to ALBEDO → Forward+ sRGB-encodes ALBEDO at the output → double companding → pale, desaturated, low contrast — worst in the daylit high-value regime, mildest where values are dark (the rim's terminator side; dawn/dusk, where sun_l = 0 gives the 0.18 floor). This is exactly the defect class AC-0242 fixed in the other nine sRGB-domain materials with the u_srgb_pre pow(2.2) pre-decode; the body (AC-0310, later) never received it. Controls: the annulus (lod_avg.gdshader) — the only far material with a truly linear albedo — reads correctly from orbit; the wash's time dependence (T0.3 dark green vs T0.5 pale) is the same texel at a different daylit value. The shader's header comment ("sRGB values throughout") is FALSE for the real pipeline and is corrected with the fix.

Terms to bisect

The body's daylit path at 2600 m nadir (shader order): (1) the texture sample's domain, (2) the day factor u_day - u_day_gain*(1-sun_l) (= 1.0 at the T0.5 nadir), (3) haz_a (limb; ≈0 at nadir — cosv≈1), (4) haz_d (= 0: d ≈ 2740 > edge 400), (5) the u_air mix (weighted by haz ≈ 0 at the centre), (6) engine lighting (ambient+directional on the lit material — shared with the correctly-reading annulus), (7) the output sRGB encode. At the nadir terms 3–5 carry ≈0 weight, so the wash is (1)+(6)+(7). The A/B isolates:

  • B0 = current tree (re-confirm first — the assessment frames predate the last two shader-hunk commits).
  • B1 = the fix (terrain-term pre-decode). If the centre snaps to a green texel-composition match → the term is (1)+(7), the domain of the terrain sample. If only partial → continue with A/Bs on (5) and (6) before declaring the fix.
