1. Root cause — godot/scenes/main.gd:193 (dangling Callable)

menu_ui.on_quit_to_menu = Callable(self, "_quit_to_menu")   // method _quit_to_menu DOES NOT EXIST

The real handler is func quit_to_menu() at godot/scenes/main.gd:233 (no leading underscore). The "Quit to Menu" button's press handler is _on_quit_btn_pressed() in godot/ui/menu.gd:215-217:

func _on_quit_btn_pressed() -> void:
	if on_quit_to_menu.is_valid():
		on_quit_to_menu.call()

Godot 4.7.1 semantics (probed on this exact engine build, temporary probe script, deleted after):

ISVALID false
SCRIPT ERROR: Invalid call. Nonexistent function 'SceneTree(ac0081_probe.gd)::no_such_method_xyz (Callable)'.

So Callable(self, "_quit_to_menu").is_valid() == false → the guard at menu.gd:216 fails → the button is a perfect silent no-op: no save write, no world teardown, no scene change, and no script error at all (stderr stays clean — which is why it looked like "nothing happens" on both platforms). One shared codebase, one deterministic root cause, identical on web + windows/desktop.

Provenance (git log): both lines were introduced together already mismatched in commit 9727c3f (2026-08-20, AC-0048): the diff adds menu_ui.on_quit_to_menu = Callable(self, "_quit_to_menu") and, 13 lines below, func quit_to_menu() -> void:. The button has therefore never worked since the pause menu shipped; AC-0033/AC-0062 verified the pause overlay and the save API directly, never the button itself. The spec's suspect window (AC-0080 hysteresis / AC-0076 queue / AC-0062 auto-save interaction) is ruled out: the failure is 100% deterministic on the plain path (no walking, no pause/unpause cycling needed), and post-fix the full teardown of AC-0080-era chunk state passes cleanly.

3. The fix — godot/scenes/main.gd:193 (minimal, causal, shared path)
