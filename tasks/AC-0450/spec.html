Registry notes (verbatim, quoted):

1) User Story:
Nobody can currently say, from a rendered frame, how much of what the player sees is missing world. "You can see through the terrain where the chunks have not been generated" has been measured as a FILL RATE (AC-0399: the built frontier is 256 m at 180 s and ~365 m at 360 s at the 2600 m view) but never as a property of the PICTURE, so every look fix since has been accepted by eye and the same square metre of missing world has been re-photographed by the user four times. This ticket gives the project a number for "how much of this frame is not drawn", at the vantage the player actually complains about, so the coverage work that follows can be proven instead of argued.

2) Technical Details:

WHAT IT MEASURES. Per frame, at a fixed airborne vantage, the pixel fraction that is (a) background / no geometry, (b) far-tier geometry, (c) near-tier geometry, (d) satellite body. Minimum viable is (a) plus a total. Reported as RESULT fields, plus a CONTRAST-WITH-DISTANCE profile: the luminance delta between adjacent terrain features sampled at several distances from the camera. The profile is what AC-0449 needs for its own acceptance ("a near field that is clear and far that is hazy is the goal, so the measurement is a PROFILE WITH DISTANCE, not a single number"), which is why ONE run serves both tickets.

WHY THE EXISTING CENSUS DOES NOT COVER IT, and this is the reason the ticket exists. The standing set already counts far holes (`r16 ... far_holes 0/0 both bands`) and it reports zero while the user photographs a hole in the same class. That is the AC-0392/AC-0393 failure shape - a check that cannot reach the defect converting an open question into a false conclusion - and it is the second time this project has had an instrument report clean on a visible defect. The standing census measures BANDS; it does not measure the BACKGROUND BETWEEN them, and the background between them is exactly where the user is looking.

THE VANTAGE. A purpose-built camera preset at N metres above the surface looking down and outward. This is already owed: AC-0394's notes audit harness.gd and find only top / iso / iso2 / lodring / sky / eyeup / sandpad / shaft, conclude "there is NO satellite/altitude camera preset - adding one is owed", and recommend adding one permanently because this class of shot is now routine. Work at the USER'S settings: render radius 24, fog full 332 m, `u_render_edge` 400 m - both derived from one home each, `DayNight.fog_far(render_radius, fog_start_pct)` (core/daynight.gd:27-28) and `(render_radius+1)*16` (scenes/main.gd:1477-1478), never restated as constants in the arm.

THE ELIMINATION A/B, the instrument's first use. The same frame in four states - as shipped / the sky's air term off / the engine fog off / the satellite body off - using the env hooks that already exist (HARNESS.md section 2 owns the list: `AWECRAFT_SKYALT`, `AERO`, `NO_WORLD_VIS`, `AWECRAFT_SAT_MESH_STEP`). Whichever removal clears the affected region identifies its owner, and the answer is currently contested: the near-field handover (the fog-wall partition plus the body's camera-distance existence window) predicts one shape, and AC-0449's corrected reading ("not blue, I meant BLUR") predicts a completely different one. Do not pre-decide; report the four frames and the four counts.

NEGATIVE TEST, REQUIRED BEFORE THE INSTRUMENT IS TRUSTED. The counter must be able to fail: point it at a known-unbuilt column (or run the frame with the coverage pass disabled once that pass exists) and show (a) RISE. An instrument whose negative test cannot fail is the defect this ticket is chartered to prevent.

GATES. `tasks/scripts/gate_census.py` - zero SCRIPT ERROR and zero SHADER ERROR AND the process exit status checked (this project has a stochastic use-after-free that exits signal-11 after a clean log); the standing set unchanged: genhash 25/25, farab h_mismatch 0, ladder 20/20, meshprobe 1.0, halo ok, lightstate 0/0, r16 all sub-flags with far_holes 0/0 both bands, boundary r4 in band, shaderforce 12/12. Render recipe is HARNESS.md section 2 (fwdshot, Forward+ through lavapipe + Xvfb, ~5 FPS, budget 1200 s per shot, verify the PNG exists). Logs go to the repo-root `.scratch/`, never /tmp - AC-0394 lost a whole run's evidence to /tmp not persisting between commands.

DEFERRED / NOT IN SCOPE. No look change, so no player-facing switch is added: the arm must be inert during normal play (AC-0140). Nothing here touches generation, streaming order or the materials - it only observes. It does not fix the hole; it makes the hole countable, and it must be committed before either of the coverage tickets so they have an acceptance instrument rather than an eyeball.
