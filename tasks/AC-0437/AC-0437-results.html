AC-0437 — interface polish: crosshair, stat-row hierarchy, inventory dim, menu gate

Date: 2026-10-16  ·  Scope: the four whole-experience findings (AC-0384 §29), in the existing visual language — polish, not redesign. All look changes ship behind a switch defaulting ON (the AC-0435/AC-0436 re-ruling: the shipped look is the user-reported defect, so the fix ships in and OFF is the A/B); the crosshair is the ticket's stated exception — a missing feature, simply corrected, no switch. Verdict: all four findings fixed; the menu gate's root cause answered (no gate existed — the button was unconditional, and the only dev/shipped mechanism in the tree is the build stamp, which covers the version string only); light gates green; generation byte-identical.

The gating finding — why a shipped build showed “Test Range”

The gate wasn't broken — it didn't exist. scenes/menu.tscn declared RangeButton unconditionally, and the tree has zero is_debug_build() usages. The only dev/shipped mechanism anywhere on the shipping path is build_windows.sh's pre-export rewrite of build_id.gd (sed of const ID := "dev" → "<stamp> <sha>", restored via its git checkout exit trap) — and that mechanism rewrites the version string only (AC-0248). Nothing ever consulted “is this a shipped artifact” before drawing a menu entry. The assessment's menu frame is therefore dev-provenance: the [dev] tag there is AweCraft[Build.ID] rendered from a dev tree — it can never leak into a stamped build, where the same label renders the stamp. The fix reuses the project's single source of truth for “shipped artifact”: menu.gd _ready now hides RangeButton when Build.ID != "dev". Nothing is deleted — dev / local-tree runs and the harness (ID "dev") keep the entry; a stamped export loses it. The demonstration is the two menu frames below, the second taken with build_windows.sh's exact sed applied temporarily and then reverted.

Item 1 — the crosshair (no switch)

A pixel plus in the HUD's own language: 6 px arms, 2 px thick, white 0.92 with the 1 px dark outline the slot borders and labels use, arms stopped 1 px short of the centre so the aimed block reads through the middle. CrossCtl in ui/inventory.gd; visible in play exactly while the pointer is not the visible cursor (play runs MOUSE_MODE_CAPTURED — Player.start captures it — or HIDDEN for joypad / click-to-toggle), hidden on the death screen and while the panel is open. Measured: 44 near-white px at screen centre in both frames, centre pixel dark (the 1 px gap), 1 px outline legible over grass by day and over space by night.

BEFORE — the assessment's own AC-0384 r24 ground-day frame: no crosshair anywhere (the finding: “no crosshair anywhere in the code”).
AFTER — day (1280×720, seed 44, TIME 0.5): the plus at centre, hotbar and the labelled rows below.
centre region: 44 near-white px; centre pixel (640,360) dark — the aimed block reads through.
AFTER — night (TIME 0.0): the same plus over the darkened terrain — the interface is legible in the night the assessment found too dark for it.

Bug found and fixed during this run: the first crosshair build keyed visibility on MOUSE_MODE_HIDDEN, but play runs MOUSE_MODE_CAPTURED (Player.start) — the crosshair never appeared in the frames (0 white px at centre). The condition is now Input.mouse_mode != MOUSE_MODE_VISIBLE: shown in CAPTURED and HIDDEN alike, hidden whenever the cursor is back (menu, pause, console, inventory drag). The day/night frames above are the post-fix capture.

Item 3 — the inventory recedes the world

Opening the inventory now dims the world behind the panel: a 0.45-alpha black ColorRect as the first child of the HUD layer (the death screen's _dead_bg at 0.72 is the precedent), so the world below the layer recedes while the panel, the craftable list, the rows and the held-cursor item stay bright. Behind inventory_dim (default ON; AWECRAFT_INVDIM=0 = the exact pre-AC-0437 look). Measured on the same scene: world-band mean luminance 51.5 (dimmed) vs 93.6 (undimmed) — exactly ×0.55, the 0.45-alpha contract; sky band 50.0 vs 84.9.

AFTER — default ON: the terrain behind the panel recedes; the panel and its contents hold their brightness.
world band (x30–200, y100–600) mean L 51.5
BEFORE — AWECRAFT_INVDIM=0: the world at full brightness competing with the panel (the reported look).
same band mean L 93.6 — the dim is exactly the 0.45-alpha black (93.6 × 0.55 = 51.5)
