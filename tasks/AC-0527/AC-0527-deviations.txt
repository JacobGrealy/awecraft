
1. **The BOUNDED STEP is implemented as a LEVEL-SET check, not a per-cell step check.** The plan's
   "ratio between adjacent levels" was first implemented per adjacent CELL in a column — and the
   first gate run (halo-r1.log) proved that cannot be the invariant: on the CURRENT tree 85 of 226
   slabs step 0→15 (L ratio 3.81) across two cells. That happens whenever the terrain top lands
   MID-CELL (the top does not coincide with a grid-cell bottom), where the graded middle level is
   simply not in that column — and the pre-fix and post-fix values are byte-identical there, so no
   per-cell threshold can be both green on the current tree and red on the pre-fix binary. The
   durable invariant the fix was actually about lives in the LEVEL SET (the distinct values the
   sky uses: pre-fix {0,15} = 3.81x; post-fix {0,8,15} = 2.50x/1.52x), so the step check runs on
   the run's level set (per recorded array in the NEGCTRL), and the local raw-H spot-check asserts
   the AT cell (terrain top on a cell bottom) is graded STRICTLY between its neighbours — equality
   is the hard step. All plan gates still hold under this reading: green on the current tree,
   RED on the pre-fix binary (named step-ratio breach), monotonicity asserted, threshold stated.

2. **The step check applies only when `at_cols > 0`** (the run has at least one terrain top on a
   cell bottom). A graded product whose tops all land mid-cell legitimately shows only {0,15};
   firing the step check there would be a false red. The census is reported in `b.at_cols`.
   (The NEGCTRL is self-contained — its recorded slab has an AT cell by construction — so the
   negative path always checks the levels.)

3. `rule_bad` is retired → `invar_bad` (+ new `levels` / `at_cols` / `step_fails` fields in `b`);
   `payload_bad` now guards payload shape G³ only; the fresh-emit byte-identity runs on the
   PRODUCT sky (the arm no longer re-derives the sky payload — that re-derivation WAS the stale
   two-level literal). Standing row + generated doc updated; `harness_doc.py --check` clean.

Threshold chosen: **_HALO_STEP_MAX = 3.0** (shader luminance L = 0.20 + 0.80·mix(20/255, 1, a/15),
u_day 1 — the far LOD's own path in lod_avg_seam.gdshader). Justification: 20% headroom above the
worst post-fix level step (L 0.263→0.655 = 2.50x) so the next re-tune stays green, and still 21%
below the pre-fix 3.81x regression (L 0.263→1.0) so the binary rule can never pass again.
