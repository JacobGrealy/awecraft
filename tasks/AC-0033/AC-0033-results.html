Phase 1 — root cause (recap)

Two independent wiring bugs made the menu invisible under Xvfb/llvmpipe (uniform 77,77,77 frame): (1) menu.gd built main_box/pause_box/options_box as dangling references — add_child() was never called, so nothing 2D was in the tree; (2) the menu path never created a Camera3D, so the root viewport ran no 3D pass and collapsed to the default clear color (0.3,0.3,0.3) = (77,77,77). Fix: 13 lines in 2 files (boxes added in _ready; idempotent _setup_menu_camera() in main.gd). Aero grade/sky ruled out by A/B (AWECRAFT_AERO=0 still gray). Detail in AC-0033-phase1.html.

D1 — menu boxes not mutually exclusive (ghosting)

Root cause: box visibility was managed as scattered ad-hoc visible flags in 5 call-sites (show_main, show_pause, open_options, play_clicked, resume/quit). open_options() (menu.gd:95) set options_box.visible = true without hiding the box behind it — so the main box (title, Play, help line, its own Load Texture Pack button) stayed lit under the options panel. Re-verified pre-fix this session on the exact committed tree: AWECRAFT_MENU_SHOT + AWECRAFT_MENU_VIEW=options reproduced the ghost (below, left).

Fix: explicit visibility state machine — _state ∈ main / pause / opt_main / opt_pause / ingame, single _apply_state() sets each box visible exactly iff it matches the state, and hides the whole menu CanvasLayer (visible=false) while ingame (play mode), except show_pause() which re-shows the layer with only pause_box. Every entry point (show_main/show_pause/open_options/close_options/play_clicked/new_world_clicked/hide_pause/resume/quit) now only sets _state; close_options returns to the remembered source (_options_from: main→main box, pause→pause box). _unhandled_input (Esc/E/P closing options/pause) is inert while ingame. Load Texture Pack button kept in ONE place (main menu, per web parity; the options panel's own copy also stays — but exactly one is ever visible, per state).

Deviations / notes

  • P vs Esc pause: frozen web pauses on pointer-lock loss (Esc in desktop browsers). Per the user directive (2026-08-21) the in-game pause key is P on all platforms (the browser owns Esc); Esc still closes the pause menu in the port, and the web's Esc-while-locked exit is not reproduced on web (documented). Pause-state running/suspended set matches the web loop exactly (fluids/sky/streaming/atlas-anim run; player/mobs/drops stop).
  • Sim-distance: slider is chunk-granular (1–8), applies ±(n×16) blocks to the fluid tick region; default 1 chunk (16 blocks) vs the old hardcoded 14 — ±2 blocks, documented approximation of "default ±14".
  • Web texture pack: button present but disabled with tooltip — in-memory pack swap (re-import + live atlas swap from a browser file pick) is not implemented in this build; desktop path (file dialog → Atlas.import_pack → apply) is fully working. Atlas.import_pack_mem(PackedByteArray) already exists as the in-memory entry point for a follow-up.
  • Web fullscreen: checkbox persisted and applied to the embedded window; browsers typically ignore programmatic fullscreen/resize on the Godot canvas without user gesture — cosmetic limitation of the web embedding, state still persists.
  • New env hook AWECRAFT_PAUSE_SHOT=1 (with AWECRAFT_MENU_BOOT=1 AWECRAFT_SNAPSHOT=path) = menu→Play→P→snapshot harness. OPTSYNC print on options open is a permanent diagnostic (env-hook pattern).
  • Pre-existing render-run notices unchanged: ALSA ERR_CANT_OPEN (dummy audio), one atlas ERR_CANT_OPEN (data.gd:64), RID leak warnings at forced quit.
  • Phase-1 before/evidence files (menu-main.png, menu-options.png, playing.png, menu-to-game*) kept untouched.
