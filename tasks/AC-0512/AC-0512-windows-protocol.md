# AC-0512 — Windows protocol (handover)

All measurements in this ticket were taken on the Linux development box under a
**software Vulkan proxy (llvmpipe). Development-only evidence**: valid for
geometry, layout, timing structure and counter behaviour; NOT valid for the
shipped forward_plus look, its colour response, or its frame budget. This file
is the protocol for re-taking the timing-sensitive parts on the Windows target
(build + GPU, per the AC-0484/AC-0485 pattern).

## What must be re-taken on Windows, and what does not

| Item | Re-take on Windows? | Why |
|---|---|---|
| Render set R1-R4 (base / hold / bodyoff / seam) | YES (the 4 renders) | frame rate changes the census "late" frame content and the hold window's frame count; the five-way classification is machine-dependent (how far streaming has reached at the snap) |
| Census JSONs (pose / late / holdend) | YES (regenerated by the same envs) | they are the data-side of the classification |
| genhash 25/25, g0, residency | NO | generation is deterministic and bit-exact per seed across platforms (`-ffp-contract=off`); these gates ran headless on the dev box |
| Signed sat-detail error table | NO (verify) | the SIGNED error is a data property (generator vs chart), not a machine property; the projected-px column IS machine-dependent (it depends on the pose, which is fixed by the protocol, so it should agree) |
| Negative-control counter rise | YES (cheap: R1+R3 pair only) | the RISE direction should be identical; the magnitude scales with how settled the near field is at the snap |

## Procedure (same machine the user plays on; the release build + GPU)

1. Build per `godot/OPS.md` (Windows build + export), launch with the same
   user settings the measurements used: `AWECRAFT_RADIUS=24`,
   `AWECRAFT_FOG_PCT=83` (fog_far 332 / render_edge 400), `AWECRAFT_TIME=0.5`,
   `AWECRAFT_CLOUDS=0`, window `AWECRAFT_SIZE=1280,720`, seed 44 (the default).
   Blur OFF (user ruling — no DoF envs set).
2. R1 (base): `AWECRAFT_CAM=air AWECRAFT_AIR_ALT=300 AWECRAFT_AIR_PITCH=30
   AWECRAFT_AC0512=1 AWECRAFT_AC0512_DIR=<dir>/base AWECRAFT_SNAP_DRAIN=600
   AWECRAFT_SNAPSHOT=<dir>/base.png`. Keep the log (RESULT + AC0512 lines).
3. R2 (hold): R1 + `AWECRAFT_AC0512_HOLD=5000 AWECRAFT_AC0512_HOLD_AT=300
   AWECRAFT_SNAP_STEPS=300,301,600 AWECRAFT_AC0512_DIR=<dir>/hold`. On a fast
   GPU 5 s covers several frames — that is the point of the fixture there; the
   START/END log lines give the exact window and the suppressed count.
4. R3 (bodyoff / negative control): R1 + `AWECRAFT_SAT_BODY=0
   AWECRAFT_AC0512_DIR=<dir>/bodyoff`.
5. R4 (seam): `AWECRAFT_AC0512=1 AWECRAFT_AC0512_LATE=240
   AWECRAFT_AIM=2890,500,0,-1.5708,-0.52 AWECRAFT_AC0512_DIR=<dir>/seam
   AWECRAFT_SNAP_DRAIN=600 AWECRAFT_SNAPSHOT=<dir>/seam.png` (no
   `AWECRAFT_CAM` — the aim-flow teleport).
6. Analyse each frame with `.scratch/AC-0512/gaps.py <case> <png> <log>
   <dir>/<case>/census-late.json <out>.json` (base/hold/bodyoff use their own
   `census-late.json`; hold additionally reads `census-holdend.json` via the
   render log's counters; bodyoff's census is its own).
7. Report: the same tables as `AC-0512-results.html` (per-gap five-way
   counts, signed error per tier × case, exterior-gap counter before/after),
   each labelled with the Windows build id + GPU string.

## Invariants to check on Windows (the measurement is invalid if these fail)

- `RESULT` shows `fog_far: 332.0`, `render_edge: 400.0`, `fov: 99.0` (air) —
  the settings reached the engine.
- `body_phase: 4` (LOADED) in the air RESULTs; `body_off: true` /
  `vis=false` in the bodyoff log's SATDIAG lines.
- `AC0512 hold START` / `AC0512 hold END` lines present in R2 with
  `hold_n > 0` (the fixture actually suppressed publications).
- The census `anchor`/`taxi_max` in R4 shows the recenter landed
  (anchor ≈ [180, 0]).
- genhash 25/25 still passes on the same build (data identity across the
  platform change).

## Interpretation rules (unchanged from the dev-box run)

- A gap pixel whose census column has NO data = cause (1) regardless of how
  settled the frame is — that chunk was never built.
- `discard` (tier 4, data present, nothing drawn) = cause (2) — the designed
  cull, reported as a designed gap, not a defect.
- `delay` (data present, tier ≤ 3, no drawn slab) = cause (3) — the
  held-publication fixture proves the class is observable by construction.
- drawn + |sat − detail| ≥ 0.75 m = cause (4); drawn and agreeing = cause (5)
  (or a coarse-slab false positive, flagged in the evidence column).
