AC-0109 — spec: frustum-culling-chunks (P2, queue 2026-08-28)

Registry note (verbatim): "Per-frame Camera3D frustum cull for chunk/subchunk mesh_instances. In world.gd _process or _recenter, test chunk AABB vs camera frustum; set mesh_instance/fluid/flora visible=false when outside frustum (keep data/mesh resident unlike distance candidate). Keep radial candidate logic; frustum is additional immediate cull. Verify: 360 spin no pop, queue_size stable, GPU verts visible drop when looking down, battery green. Depends: vertical-subchunks if implemented (per-slab AABB better), otherwise column AABB."

Goal

The port currently renders every BUILT chunk (distance-candidate logic only: un-built chunks are culled, built ones always drawn). Standard renderers frustum-cull per-mesh by default; this port never does. Add a per-frame frustum test so built-but-behind-camera chunks stop being drawn — no pop-in, no mesh/data destruction, radial candidate logic unchanged. (User-queued P2 performance task; no external spec references — provenance = in-repo code + user directive.)

Requirements

  1. R1 — Per-frame (world.gd _process or an equivalent hook) test each BUILT chunk's AABB against the active camera frustum. Run-1 to pin the mesh structure first: per-chunk single mesh_instance vs per-subchunk slabs (vertical-subchunks may or may not exist in the current tree — if per-slab instances exist, per-slab AABBs are better; otherwise column AABB). No per-frame allocations that grow with chunk count (reuse scratch objects; 81 chunks @ r4 × ~3 instances = trivial work — the AC-0035 lesson: per-frame main-thread additions erode the frame-budgeted drain, keep this O(n) in cheap ops, no per-chunk array builds).
  2. R2 — Outside frustum: set the chunk's mesh/fluid/flora instances visible=false (all of the chunk's draw instances together — one visibility state per chunk). Keep data + mesh resident — this is NOT the distance-candidate path (no queue entry, no unbuild, no recenter effect). Inside frustum again: visible=true.
  3. R3 — Hysteresis / no-pop: a chunk must not flicker at the frustum edge. Cull with a margin (shrink the frustum or grow the AABB by a margin — Run-1 to pick the mechanism + value), and/or keep the last-visible state until clearly outside. Acceptance: the 360° spin probe shows zero visible→invisible→visible transitions on any chunk within the window (no pop).
  4. R4 — Keep the radial candidate logic exactly as-is (frustum = additional immediate cull on top, not a replacement). The queue/drain behavior must be unaffected: queue_size stable during the spin.
  5. R5 — Scope check: standard per-mesh frustum culling (what any engine does by default). Audit in-repo for any existing visibility culling on the chunk mesh instances (the stars field is set to always-draw — leave it alone). If Run-1 finds the port already culls behind-camera chunks somehow, report it and adjust scope.
