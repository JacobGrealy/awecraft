Registry notes (verbatim, quoted):

1) User Story: The coordinator does ALL the thinking about what to build; subagents only build it or
   measure it. Today one path still breaks that rule: the `design`-labelled path hands the builder
   `tasks/templates/two-phase.md`, whose step 1 is "PLAN - write tasks/AC-NNNN/plan.html". So on the
   hardest tickets the expensive local model is still doing the design work, which is exactly the
   thing that made runs take hours. After this ticket no builder writes a plan, ever: the coordinator
   designs, and when it is missing a fact it sends a MEASUREMENT run (build this instrument, report
   these numbers, change no behaviour) instead of asking a builder to decide.

2) Technical Details:
   USER RULING 2026-10-19: "I want planning done by coordinator, implementation by subagents."
   State before: tasks/templates/implement.md (the medium default) already has the coordinator write
   plan.html, so the default path complies. The gap is two-phase.md - used for `design`-labelled
   tickets and for escalation - which still contains a builder-written PLAN step. Retire that premise.

   THE MODEL AFTER THIS TICKET - two builder deliverables, both coordinator-planned:
     (a) IMPLEMENT: apply plan.html. tasks/templates/implement.md. subagent_medium.
     (b) MEASURE: build the instrument the plan specifies, run it, report the numbers, change no
         behaviour. ALSO tasks/templates/implement.md, as a plan TYPE ("measurement plan"), because
         the deliverable is still "do what the plan says" - only the plan's acceptance differs.
   A `design` ticket therefore becomes TWO runs at most, both cheap: a measurement run (medium) to
   produce the facts, then the coordinator's design pass, then the implementation run (medium). The
   xhigh builder survives ONLY as the escalation step when implementation itself needs judgement
   (second triage hit, per the ratified ladder).

   CHANGES:
   - tasks/templates/two-phase.md: DELETED (git rm). Its premise - plan + implement in one turn - is
     the thing being retired. Git history keeps it; a stale template that tells a builder to plan is a
     trap, not a reference.
   - tasks/templates/implement.md: add the measurement-plan section (deliverable = numbers + the
     instrument; it may NOT change game behaviour; its acceptance is "the numbers are in a log and the
     behaviour is byte-identical when the instrument is off"); generalise the effort line to medium-by-
     default / xhigh-on-escalation.
   - tasks/templates/plan.html: header generalised (one builder run, medium by default) + a short
     "measurement plan" variant of sections 3/4/5.
   - .dsh/skills/awecraft-plan/SKILL.md: the "design" guidance is replaced - the coordinator does the
     design pass itself and, when facts are missing, dispatches a measurement run and READS ITS
     NUMBERS BEFORE DECIDING. Design is not delegated.
   - .dsh/skills/awecraft-delegate/SKILL.md: routing table loses the design->two-phase row; xhigh is
     escalation only; the launch rules gain "a builder never writes a plan".
   - .dsh/skills/awecraft-file-ticket/SKILL.md: the `design` label now means "the coordinator's pass is
     a design pass and will likely need a measurement run first", NOT "routes to xhigh".
   - AGENTS.md role line: state it explicitly - planning is coordinator-only; subagents implement or
     measure.
   - godot/ARCHITECTURE.md:19: the pointers row names tasks/templates/two-phase.md - correct it (keep a
     single pointer to the templates dir).
   - tasks/scripts/spec_template.py: its generated note names two-phase.md as "the prompt template".
     Fix the string; it is a GENERATED spec source, so specs written from now on are correct. Do not
     regenerate historical specs.

   GATES: none - documentation and one generator string, no engine code, no gate value moved, no godot
   run owed. Proof: `python3 tasks/scripts/test_tasks.py` still reports 53 checks green (spec_template.py

   two-phase.md reference while an older spec still does (the historical specs are deliberately left
   alone).
