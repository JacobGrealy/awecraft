AC-0472 — does the home drain actually erase face light keys?

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Measure first, then guard. The hazard was found by diagnosis (AC-0463 L7) and is currently unmeasured in both directions.

1. The hazard, as established

_star_settled_drain scans keys belonging to FACE chunks as well as its own, because it must keep querying the home engine for face keys or it would double-settle (AC-0463 L2). There is no face-key guard at world.gd:6223. Home chunk coordinates run −196..196; face chunk coordinates run 0..392. In the [0,196]² overlap the namespaces collide numerically, so a settled home column can overwrite a face chunk's published last_eff (6239) and erase the face key from the owed/settled bookkeeping (6236-6245). If it fires, that face column never settles and its margin-ring glow stays stuck on pre-settle light.

This became reachable only because AC-0459/AC-0465 gave both lanes one key shape and AC-0469/AC-0471 put both on one 1 m grid with overlapping index ranges.
