2. Where the anchor was decided

The drip pass in gdext/src/gen.cpp gen_flat() (AC-0292): per column it walks the air/water runs [a, b] (a = bottom of the run, b = top). The two speleothem blocks carry swapped names in the comments, which matters for finding the culprit:

  • The block commented "Stalactite — from the ceiling" is actually the floor-anchored stalagmite: ceil_solid tests the cell below the run (a−1, the floor) and places h = 2 + floor(hash2i·5) ∈ 2..6 cells at a..a+h−1, growing UP from the floor (only into air — water cells are skipped, which is what lets a spire keep the water at 126 and still stand at 127+).
  • The block commented "Stalagmite — from the floor" is the ceiling-anchored stalactite: it grows DOWN from b+1 into b−h+1..b. It can never stand above the water surface (it hangs from rock that is above the run) — no guard needed.

In an open-sky ocean column (H < 126) the run is [he+1, top-of-slab]: the AC-0342 water fill at he+1..126 plus open air from 127 up — no ceiling. So the floor-anchored spire, anchored to the seafloor, has its air cells only at ≥ 127 and stands above the intact sea surface whenever it fires (35% hash) — AC-0374's column dump (stone 118–121, dirt 122–124, sand 125, water 126, dripstone 127–130) is exactly this shape. (AC-0374's phrasing "anchors to the SLAB-GENERATION top" refers to the run's top bound b; the placement itself is floor-anchored.)

3. The fix — option 1: do not place above the sea

The ticket offered two options; carving the water around the spire was rejected: it would replace sea-surface water cells with solid (breaking the surface_ok_at_sea/flooded_to_sea classification — the affected columns would become water_below_only), and it is anti-vanilla — vanilla speleothems are ceiling-capped (a stalagmite column never pokes through the air pocket's ceiling) and dripstone is not an open-water feature at all. The chosen rule:

// AC-0375: a run that crosses the water surface (an
// open-sky ocean column, or a submarine cave opening
// into the sea) caps the spire strictly BELOW the
// surface - the vanilla speleothem rule (a column
// never pokes through the ceiling, and the water
// surface is the ceiling of an open run). The run's
// cells at or below the surface are the AC-0342
// water fill, so the cap removes exactly the cells
// that would stand above the intact sea surface;
// spires in cave air entirely below the surface are
// untouched (h naturally stays under the cap).
bool crosses_sea = a <= sea && sea <= b
        && flat[(size_t)(sea << 8) | base] == B_WATER;
...
if (crosses_sea && h > sea - a)
    h = sea - a;   // spire top ≤ sea−1

Consequences, by run shape: (a) open-sky ocean run — the spire's only air cells are ≥ 127, the cap leaves none, no spire (the water at 126 is never touched); (b) submarine cave run with air pockets below the surface — spires stay where they were, fully submerged (h naturally under the cap); (c) land caves / sealed underwater pockets — the run does not contain water at 126, guard inert. The cap is applied after the hash gate, so no hash was touched and no spire moved that was not above the sea.
