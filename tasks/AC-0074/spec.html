Deliverable

  1. build_windows.sh at repo root (next to build_web.sh), executable, mirroring build_web.sh's style:
    • Export release → exports/windows/AweCraft.exe: ~/tools/godot/godot --headless --path godot --export-release "Windows" "exports/windows/AweCraft.exe" (create dir first).
    • Export debug+console → exports/windows/AweCraft_debug_console.exe: same with --export-debug (the _console template is selected when the project/preset uses console output; if the plain preset produces a non-console exe, add a SECOND preset "Windows (debug console)" in export_presets.cfg with binary_format/embed_pck normal + console enabled — check preset options binary_format/architecture=x86_64 and the "Debug" template toggle; the reliable route is a dedicated preset with custom_template/debug pointing at ~/.local/share/godot/export_templates/4.7.1.stable/windows_debug_x86_64_console.exe — do what actually produces a console exe and prove it).
    • After each export: verify the exe exists, print size, check PE magic (first 2 bytes MZ — head -c2) — a corrupt/HTML export fails loud.
    • Print the final artifact summary (paths + sizes + build id: stamp exports/windows/BUILD.txt with git short sha + timestamp so the user knows which feature build they have).
    • No network, no godot game run — export only (ONE godot at a time anyway).
  2. Serve exports/windows/ over plain HTTP on the LAN: start a daemon like serve_web.py does — python3 -m http.server PORT --bind 0.0.0.0 --directory exports/windows via setsid, pidfile .scratch/serve_win_export.pid, log .scratch/awecraft-winexport-http.log. PORT = 8080 (fallback 8081/8082 if busy; port-in-use guard prints the picked port). build_windows.sh should ensure the daemon is running (restart it if the pidfile pid is stale) and print the download URLs. Add a --no-serve flag that skips the daemon.
