Console-variant proof method (we can't run the exe on Linux)

GODOT 4.7 does not produce a single console exe. Per editor_export_platform_pc.cpp (prepare_template), the export always copies the normal debug template (GUI, with the reserved pck section), and when the preset has debug/export_console_wrapper=1 it additionally copies the *_console.exe template next to the export as the wrapper. The wrapper (platform/windows/console_wrapper_windows.cpp) allocates console virtual-terminal mode, strips the .console.exe suffix to find the main exe, CreateProcesses it with inherited console handles (so game logs print in the wrapper's console), and waits on a job object for the whole process tree. The spec's "dedicated preset with custom_template/debug = console template" literal cannot work — the console template has no pck section and breaks embed ("Executable "pck" section not found"); the dedicated preset instead uses debug/export_console_wrapper=1. (The spec text anticipated this: "do what actually produces a console exe and prove it".)

Proof without running, all automated in the script (check_exe + section compare, each export):

  1. PE subsystem: the script parses each PE header on Linux. Wrapper reports subsystem 3 = Windows CUI (console); both main exes report subsystem 2 = GUI. Same check applied to the installed templates first as calibration: windows_release_x86_64.exe=2, windows_debug_x86_64_console.exe=3.
  2. Code-section identity: the exported wrapper's 7 file-backed sections (.text .data .rdata .pdata .xdata .idata .tls, 45,056 bytes) are byte-identical to ~/.local/share/godot/export_templates/4.7.1.stable/windows_debug_x86_64_console.exe. (Naive whole-file sha256 equality is NOT the right check: the editor strips the template's bundled .rsrc icon/version resources 141,912→3,296 bytes and re-compacts the PE, so sizes/headers differ by design.)
  3. Distinctness: debug main exe ≠ release exe (sha256), both carry the pck section (PCK actually embedded), sizes sane.

Deviations

  • "Console" deliverable is Godot's wrapper pair (AweCraft_debug_console.exe + AweCraft_debug_console.console.exe), not one console exe — the only way Godot 4.7 does Windows console builds; proven above. On Windows the user double-clicks the wrapper.
  • Wrapper filename is AweCraft_debug_console.console.exe, NOT AweCraft_debug_console.exe.console.exe: godot's prepare_template builds it from String(path).basename(), which strips the final .exe. Verified this still resolves correctly: the wrapper's runtime suffix-strip (rightmost .console.exe) maps it back to AweCraft_debug_console.exe.
  • Debug-console export uses --export-debug on the dedicated preset (per spec) with export_console_wrapper=1 instead of custom_template/debug pointed at the console template — the literal spec route is impossible (console template lacks the pck section; godot errors "PCK Embedding: Executable "pck" section not found"). Spec anticipated: "do what actually produces a console exe and prove it".
  • Webui (5180) answers HEAD with 501 — G2 "curl both still OK" used GET for it (200). Not a fault.
