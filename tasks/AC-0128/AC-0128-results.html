10. RUN 3 rework (bounce, perf fix per S9 direction (b)) - 2026-08-28

Root cause - confirmed by code read (coordinator's candidate): _s_gdist (the ~140k-op Chebyshev-14 chamfer sweep) ran on every bake - the worker build_accs computes it unconditionally before emit, and the E2 re-light re-bakes always self-light (the light-pending flush dispatches eff = {}, world.gd:303) - so every re-light paid the full sweep on unchanged data, plus the sync build_mesh path. The control A/B (83/3587 at the AC-0129 commit, same machine) isolates it to this tree.

Fix (direction (b), with one disclosed refinement): the per-bake sweep is deleted. The mask now comes from the pull kernel (compute_light_flat_chunk_pull): after the existing eff computation (eff bytes untouched - the mask work runs after eff = max(sky, blk) consumed the seeds), the kernel floods the own block array (own glow sources + strip injection, _flood_flat + _chunk_blk_inject - the same code the eff already runs) and returns mask (16x16xh transient byte array, same layout the old gdist had). _mask_sample/_face_mask read that array; the emit signatures carry it in place of gdist. Refinement (probe-driven, two failures found and fixed en route): (1) the mask flood must NOT seed from the existing blk strips - AC-0129's _side_blk_strip carries the sky floor (v = max(block, sky_n)), so "flood-visited" included sky-carry cells: first probe run showed the sky-lit cave at g = 1.0 (bright at night, ok:false). (2) An eff-derived "block-only" companion (eff > local sky) also failed - laterally-leaked sky in a closed column satisfies that test (cave still g = 1.0, darkside 53). Final form: the mask flood seeds from a new block-only strip companion that reads the neighbor's last_blk_ring - a sparse per-chunk array of the LIT boundary cells only (PackedInt32Array, pack (side<<16)|(yy<<8)|level, built in the pull kernel from the final flooded blk values - own sources + what crossed into them, transitive). A lava chunk's ring is a few hundred bytes; a sky-only chunk's is empty (0 B). last_eff is trimmed to {mn,w,d,arr,blk_src} at both assignment sites (build_mesh, apply_accs) - the mask itself rides the light dict only (bake + bounded 128-entry eff cache, ≤2.5 MB worst case). Disclosure: the ring is new (small, sparse, data-dependent) per-chunk persistent state - a deviation from "no persistent per-chunk state" as spec'd; it replaces a 20 KB transient with a ~0.5 KB persistent for glow chunks, and the r50 memory band must be re-verified by the coordinator's heavy job (not run by RUN 3).
