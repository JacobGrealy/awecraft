1. Goal

Make night actually dark in the Godot port with web parity: the rendered brightness of baked vertex light must follow the web formula 0.12 + 0.88·max(uDay·sky, block) × faceShade (index.html:736-746). A sky-lit cave cell renders 15-class at noon (uDay = 1 → factor 1.0) and lands on the 0.12 floor at midnight (uDay = 0); torch/block light (14/12/15) is UNSCALED — "torches stay bright at night" (index.html:737). Mechanism: shader uniform u_day updated per frame from DayNight.day(t) (web :1349 parity), with a mask-bit hybrid channel repacking vColor (chosen design, §5).

5. THE RESOLUTION

5.1 Chosen design — mask-bit hybrid + unlit shader uniform (web parity)

vColor is repacked to the exact web layout (index.html:736): r = sky_part, a stays 1.0 — i.e.

r = mask ? 0.0 : s        g = mask ? s : 0.0        b = fsh[fi]        (s = clampf(eff/15, MIN_AMB, 1.0), the EXISTING scalar)
xquad (flower) b = 0.9 (web :1148); torch/thin via fsh[fi] (Godot shape, existing)
shader fragment (each new .gdshader):
  vec4 tex = texture(atlas, UV);
  float L = 0.12 + 0.88 * max(u_day * COLOR.r, COLOR.g);
  ALBEDO = tex.rgb * COLOR.b * L;   (torch variant: ALPHA = 0.62 * tex.a)

u_day = DayNight.day(Game.time_of_day), set per frame in _update_sky (main.gd:1454) onto the 4 cached ShaderMaterials (Chunk.set_day_factor, web :3222 parity). The eff SAMPLES are byte-identical to today (_face_light :182-201, 20×20 bake box, AC-0129 strips) — only the COLOR packing, the material model, and the atlas tint location change. Merge key unchanged → mesh/vertices unchanged → MINFO byte-identical (§6.2).

5.2 Mask rule (bake-time, from data + eff — no light-time change)

per chunk build: sources = {cells in own-chunk data with id ∈ {22,23,24}}
  evidence = Chebyshev distance transform (3 separable 2-pass sweeps over 16×16×80, µs-class)
mask(face) = (eff15 > 0) AND (evidence[d] ≤ 14 for ANY of the face's 5 light-sample cells d)
  — distance-14 ball = block light's exact reach (15 − attenuation; battery torch_far_after 9 = 14−5·… consistent with the flood's attenuation table lighting.gd:29-48)

Why not the naive mask = (eff > sky_column_scan): the data-only column scan under-estimates flooded sky at cave MOUTHS (AC-0129 D1 — sky floods in laterally); a mouth cell with sky-derived eff 15 and a lava pool 14 away in-chunk would get mask=1 and render bright at night. The evidence-conjunction keeps mask=1 only when a real source can explain the eff. Own-chunk-only evidence (side-neighbor data is NOT in the worker dispatch — chunk.gd:1233-1249 dispatch carries diagonals only) keeps the dispatch/memory frozen; the cross-boundary gap (a source ≤14 in a side neighbor) is quantified by the probe's darkside_candidates count and, if significant, is Run-2's documented fallback (4×20480 B TRANSIENT per dispatch — still inside the memory fence; NOT the default).

5.3 Exactness argument (eff = max(sky, blk) — the pull kernel's own combination, lighting.gd:327-330)

  • Noon (uDay = 1): L = 0.12 + 0.88·max(sky_part, blk_part) = 0.12 + 0.88·s — mask-independent. Every cell renders exactly the web's noon value for the same eff. Geometry/merge unchanged → MINFO byte-identical, genhash 25/25, battery exact.
  • Night, mask = 1: L = 0.12 + 0.88·blk_part = 0.12 + 0.88·s, uDay-INDEPENDENT → torch day == night EXACT (gate G1). Where eff is block-derived (blk = eff) this is the web value EXACTLY. Where eff is sky-derived but a source exists within 14 (mouth cells, open lava-adjacent sky: eff 15 = sky and the source's own 15), it renders s instead of the web's 0 — over-bright by construction, never under (L_mask1 ≥ L_web always at night). Counted by the probe (mouth_bright_cells), accepted as documented one-sided error.
  • Night, mask = 0: L = 0.12 + 0.88·uDay·s. EXACT when blk = 0 (sky-only cells — surface cells, the probe's cave cell). Under-bright ONLY when blk > 0 but no own-chunk source within 14 (cross-boundary source) — the darkside_candidates count. Natural r4 world: the only natural source is lava (generator.gd:269), so exposure is bounded by lava-pool proximity to chunk boundaries.
  • Tie cells (sky == blk): inexact by ≤0 in the max (0-difference) — exact.

5.4 Rejected options

  • (i) Full sky/block channel split (r=sky, g=blk, true values): requires true post-flood sky AND blk per build. The pull kernel computes them separately then DROPS them (lighting.gd:300-334); the AC-0129 eff cache (world.gd:141-143, cap 128) stores combined-only. Options: second flood pass per light compute (extra boundary cost on the path AC-0131 is recovering), or +2.5 MB skyf per 128-cache entry (r50 141.7 → ~144.2 — inside the 140.6–146.9 band but ~80% of the headroom + cache code changes + the eff==skyf tie still needs blk for the lava-open case). Strictly more cost and memory for the same one-sided caveats as §5.3. REJECTED.
  • (iii) Scale the whole combined eff by a dayFactor curve: dims torches/lava at night — violates the binding "BLOCK channel UNSCALED" parity (index.html:737). The shader cannot recover per-vertex block-ness from a grayscale channel. REJECTED.
  • Keep lit StandardMaterial3D + shader_parameter hooks: the engine PBR lighting (sun×NdotL + ambient) cannot express 0.12+0.88·max(uDay·sky, blk) as a per-vertex multiplier of the lit result; the 0.12 floor and the uDay-scaled max are non-separable from PBR. REJECTED — hence the unlit shader swap (which is also what the web does: MeshBasicMaterial, :740).

5.5 dayFactor mapping

DayNight.day(t) (daynight.gd:31-32: clampf((elevation(t)+0.12)/0.35,0,1), elevation :27-28 sin((t-0.25)*TAU)) is the byte-for-byte port of web :1333/:1337 (same sin form, same 0.12/0.35 constants; DAY_LEN 600 = web :107). AWECRAFT_TIME=0.5 → el = 1 → uDay = 1.0 (noon); AWECRAFT_TIME=0.0 (or 1.0) → el = −1 → uDay = 0.0 (midnight, satisfies the probe's "uDay ≤ 0.1"). The web's nether branch (world.type==='nether'?0.5, :1349) is DROPPED — grep "nether" godot/**/*.gd returns zero hits (no nether world in Godot); noted in results, no dead code added.

5.6 DayNight interaction verdict

Godot's DayNight already mirrors web :1338-1348 exactly (sun 0.1+0.95·day :39-40, ambient 0.25+0.4·day :43-44, sky lerp :47-50, is_night :35-36) — it drives the SCENE (sky, fog, sun, aero dome). The web's terrain is unlit, so those scene values never touch terrain brightness; Godot's terrain is currently LIT → today's night floor is ambient 0.25 (≥3.75-class), the user-visible bug. Switching the 4 terrain materials to the unlit formula COMPLETES parity (terrain brightness = the web formula only) and does NOT double-dim: at noon uDay=1 the formula returns ≥0.88·eff — brighter than the old lit path (engine lighting <1), at night it floors at 0.12 — darker than the old ambient floor. That is the intended, spec-mandated change. DayNight itself is untouched (scope = vertex-light scaling only). Note: aero's ACES tonemap/exposure 0.85 (aero.gd:12-13, default-ON) remaps final display for everything — pre-existing, probe is raster-independent.

5.7 Torch path detail (found this run)

Torch (id 22) is the ONLY cross+thin block (data.gd:170) → dispatch chunk.gd:1243-1245 routes it to rc_o → "ac" acc → "fluid" material (_assemble_slab :1504), currently a lit, 0.62-alpha-blended StandardMaterial3D. Therefore the "fluid"-kind material MUST also take the unlit formula (else torches dim at night → G1 torch-gate fails). Its 0.62 blend + cull behavior are PRESERVED in the new shader (look unchanged except the day/night formula); web-parity alpha (scissor 0.5, DoubleSide) is noted but NOT adopted (out of scope). Godot's torch renders full 6-face quads (web :1163-1185 is a 1/8-thin stick) — pre-existing shape divergence, out of scope, noted.
