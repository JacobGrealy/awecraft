7. Risks / edge cases

  1. Slab-boundary drift (top risk) — if any builder used a slab-LOCAL merge grid, a strip anchored 3 rows below a slab top (merged quads grow H≤4 along v=y for fi 0/1/4/5) would be clipped on one side and re-emitted on the other → different quad counts (e.g. border face −4/+8 verts), missing/extra walls at y=16/32/48/64. Design prevents it: the merge grid stays COLUMN-WIDE (L481–541 unchanged — identical merge decisions); only the emit destination routes per anchor block. Detector: G2 per-chunk MINFO diff (exact per-chunk vert arrays) + iso render. Fallback: revert routing to a single mesh (task degenerates to col-only split — still a valid partial delivery).
  2. 5× collision bodies → broadphase cost — r4 81→~300–405, r50 ~9–13k StaticBody3D+Concave shapes. Watch: G5 walk p95 ≤ 65, collision_max_ms ≤ 10, ms/n ≤ 2.0, r50 RECSLICE/queue behavior. If walk p95 > 65: decouple — keep ONE column-wide body per chunk for collision (slabs own meshes only); the per-slab win then narrows to mesh/frustum but G2/G4 still pass.
  3. Worker handoff shape — build_accs returns 30 acc dicts (5×6) instead of 6; apply_accs/_acc_from_dict consume res["slabs"]. A missed key = runtime SCRIPT ERROR → G0 catches immediately. Drain pacing unchanged (1 dispatch/apply per column, TM cap 2, dedup by chunk key) — perf r4 build_units 722 / drain_frames 418 / first_draw 195 are the regression fence.
  4. Probe adaptation — every per-chunk instance-field reader must move to slab loops or break: _matinfo_counts (main.gd:297–318 — MATINFO 3/3 fence), mesh_info (world.gd:1502–1526 — MINFO shape for G2), collision_body refs (world.gd:948/977/984; main.gd:4043/5249/5260), AWECRAFT_ONLY (1008–1019) + DBGCHUNK (1020–1036). Missing one = a harness crash or a stale-fence false signal, not a game bug — G0 + gate values catch it.
  5. Recenter/drain slices — stay column-scoped: 1 build unit per column (world.gd L807 u = 1), slab work happens inside it; AC-0118 5-phase budget (8 ms/≤2048 units) and RECSLICE semantics unchanged (gate ≤ 12.2+noise). Unload frees all 5 slabs via c.queue_free() (L1145) — slab structs die with the chunk, no leaks; candidate kill must null slab meshes before freeing bodies (existing pattern, looped).
  6. Memory flat/up (honest) — no structural drop in pass 1 (geometry/data/fl/face bytes unchanged; per-slab object overhead up). G4 is a fence (≤ 140.6), not a promised drop. If it passes flat/up, report it and register per-slab culling (per-slab queue entries + hysteresis + _startup_pending/AC-0079 wall semantics — NOT free in this pass) as the follow-up that realizes the R=50 drop.
  7. mesh_built intermediate state — build_mesh/apply_accs assemble all 5 slabs in one main-thread call → mesh_built flips exactly once per column build (no partial visibility to _startup_pending L409–415, _await_core_3x3 main.gd:4273, AC-0079 wall checks, or the boundary settle loop).
  8. MATINFO fence / materials — slab assembly MUST resolve materials through _get_mat (chunk.gd:55–70, AC-0120 static cache, main-thread only; materials never cross threads). An inline _fluid_material()-style call per slab would blow total_allocs past 3 → G2 catches. Fluid anim material (L1366) stays per-id cache as today.
  9. Fluid double-blend ordering — today each chunk's [opaque+cutout+water+lava] mesh is drawn by BOTH mesh_instance and fluid_instance (fluid alpha 0.62 effectively drawn twice — today's look, preserved per slab). Only the cross-slab ordering of translucent quads can differ (disjoint slab AABBs; rare overlap at a slab border). Detector: iso R=1 pixel diff vs post_r1_iso baseline; mitigation: slab instances added in y order 0→4 (natural loop order).
