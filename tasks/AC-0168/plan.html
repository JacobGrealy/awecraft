AC-0168 — retain mesh at r+1 candidate (hide not kill)

Goal

A chunk one render-ring past the radius (r+1, hidden by the fog at fog_far=(R+1)*16*0.95) keeps its mesh (mesh_built stays true) and stays visible (never visible=false, never mesh-nulled), so stepping back re-enters it instantly with no unload/reload flicker or pop. True free stays at r+2 after the existing 2-recenter-event hysteresis.

What the code actually does today (verified)

  • Stream set = circle(R) ∪ diamond(b1_eff+1) ∪ circle-ring (world.gd in_stream_set:981). The ring (one out, fog-hidden) is in the stream set: the WANT pass early-returns on nb==3, so a meshed chunk crossing the circle edge into the ring already keeps its mesh intact.
  • One recenter later the chunk leaves the ring → _enter_candidate (world.gd:2985) kills the expensive parts: mesh_built=false + chunk._enter_candidate_slabs() (mesh/fluid/flora instances mesh-nulled, collision bodies + occluders freed). So the mesh dies exactly one recenter after the circle edge — at r+2 in the task's wording.
  • Free pass (world.gd recenter:3062-3082): two_out = not circle-ring AND taxi > b1_eff+2; cand_since increments per two_out recenter, free at ≥2.
  • Flicker mechanics: player oscillates at the edge → fog-line chunk goes ring (mesh kept) → candidate (mesh killed) → player steps back → re-enters with mesh_built=false → WANT re-queues "build" → worker re-mesh (frames) → hole at the fog line → pop.
  • Fog (core/daynight.gd:11-12): fog_far(R)=(R+1)*16*0.95, applied main.gd:1760-1761 — ring near-face distance is (R+1)*16−8 (R≤8: fog ends past the face) or the fog ends before the face (R≥9, e.g. R=50: 775.2 < 808) → the r+1 band is fully fog-covered. Already correct — not touched.

Fix (hide not kill)

  • world.gd _enter_candidate: stop killing. Keep mesh_built, keep the slabs whole (mesh/fluid/flora instances, collision bodies, occluders). Candidate = node + data + edits + mesh, all retained; still clears pending light/fluid/tex/col work (re-entry re-marks dirty via the normal paths).
  • chunk.gd: _enter_candidate_slabs() becomes unused → removed.
  • Re-entry: chunk back in the stream set with mesh alive → instantly visible, zero re-mesh, zero collision gap; also closes the AC-0134 stale-queued_keys re-entry hole for r+1 chunks (a meshed re-entrant is never WANT-queued). One guard added on the re-entry branch: _stage_check(c, key) re-stages a band-0 collision body if it was still pending (body not yet staged) when the chunk became a candidate — with the old kill the re-mesh path re-staged it; retaining the mesh removes that trigger.
  • Free timing unchanged: still 2 recenter events after leaving the r+1 band; the retained mesh is freed with the node. Memory = at most ~2 recenter-events of edge arc (R=50: tens of coarse chunks; the task accepts the extra ~300–400 cols).
  • Staleness: a retained candidate can only have data touched by band-0 fluid ticks (small R) → that path marks fluid_dirty → the flush loop re-meshes it (mesh_built gate passes) — fresher than today's dead mesh. Edits/light waves can't reach (16+ blocks). Atlas swap re-meshes all (mesh gate passes).
  • No comments in new code (ARCHITECTURE §1); two stale existing comments updated to match the new behavior.

Risks

  • Boundary/perf r4 baselines: at R=4 every r+1/r+2 candidate is band-3 data-only (never meshed) → retention is a no-op there; loads/unloads/flap/built_final/p95 expected unchanged. (Coordinator re-runs heavy anyway.)
  • Memory: large probe jumps (nltest-style 256-block hops) hold the whole old world's meshes for one extra recenter event — same meshes, no double allocation; freed at the unchanged cand_since=2. Bounded by design.
  • LOD interplay: re-entry reband still runs (WANT pass, _reband); a retained mesh now serves as the old-mesh during retain-until-swap (strictly better than a null-mesh candidate). lodswap gate re-checked.
  • Frustum cull vs "visible": cull still runs normally; the probe asserts the tracked ring chunk is not hidden (visible meshes > 0, all slab meshes present) while in frustum — candidacy must not force-hide.
