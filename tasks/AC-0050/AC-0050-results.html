AC-0050 - crafted items must land in the VISIBLE inventory when hotbar is full

Status: DONE, verified. All verify gates passed, zero script errors. Godot port only; web/ source untouched (web rebuilt from godot/).

Root cause (confirmed per AC-0049 research G1)

  • The E-inventory UI drew the 27 storage grid slots backed by inv[27+idx] = inv[27..53] (godot/ui/inventory.gd:748-750), but inv is only 36 long (godot/player/player.gd:16). Clicks on storage rows 2-3 mutated never-initialized tail entries via _inv_set grow (player.gd:912-915), inflating the array past 36.
  • inv_add (player.gd:797-817) scanned index 0..35 from the hotbar, so with the hotbar full, crafted output silently landed in hidden inv[9..26] - slots no UI surface draws. That is the "items vanish" bug.
  • Shift-click (player.gd:966-987) only spanned 9 slots per direction (STORAGE_OFF=27), so storage items shift-clicked into the 9 hidden slots at inv[27..35] instead of the hotbar.

MC-exact target achieved: one backing array of 36 = 9 hotbar + 27 storage, ALL visible; auto-fill order storage(9..35) then hotbar(0..8); no hidden reserve, no array growth past 36.
