2.1 Stage A — per-slab occluders (implemented, node-graph verified)

  • world/chunk.gd: build_accs + build_mesh count non-solid cells per slab (c_ns); a slab with c_ns == 0 is fully solid → _assemble_slab attaches an OccluderInstance3D with a BoxOccluder3D size 15³ at local (8, y0+8, 8) — a 0.5 inset on every side so the occluder box never coincides with a neighbouring slab's mesh faces (close-camera culling artifacts at slab edges). Freed in all three rebuild paths.
  • project.godot: [rendering] section — occlusion_culling/use_occlusion_culling=true (master; camera culling is inert without it) + camera/cull_3d=true + camera/cull_2d=true. Verified against the engine's canonical property list: these resolve to rendering/occlusion_culling/….
  • Headless gate: occluder nodes are only created when DisplayServer != "headless" — headless (dummy VisualServer) would register 0 useful occluders and skew harness counts; the arm reports 0 there by design.
Limitation (recorded, not a failure): the actual draw-call reduction from Stage A is unprovable on this box — no forward_plus GPU (gl_compatibility software GL only, and occlusion culling's ray-casting path is renderer-dependent). Verified instead: (1) node graph correct (25 occluders, right size/ placement), (2) engine settings canonically enabled, (3) zero no-regression across every gate. The user's Windows forward_plus build is the real proof; the occlude arm's box_sample field prints the first occluder's transform for spot-checking there.

2.2 Stage B — 6-solid-neighbour interior pre-pass (implemented, no-op by design)

chunk.gd::_s_is_interior (padded snap grid, boundary voxels never interior) skips face emission for fully-embedded voxels in both build paths. Outcome: zero geometry change — the AC-0106 greedy mesher's per-face neighbour culling already emits nothing for such a voxel, so the pre-pass is a redundant-but-cheap guard (one table lookup vs six) that the greedy mesher's integration can build on. Proven: MESHRECS 81/81 identical + genhash byte-identical + SMOKE exact. This is a legitimate task outcome, recorded as such per the plan.
