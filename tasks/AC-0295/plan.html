AC-0295 — lowering render distance must free what is now out of range

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Reproduce first — this ticket predates the migration and may have been fixed by it — then fix only the eviction, not the standing policy.

1. The likely mechanism, from the code (a hypothesis to test, not a finding)

  • note_render_distance(prev) (world.gd:6901) only starts a loading screen when the value changed: start_loading("Loading render distance %d"). It does not itself evict anything.
  • Eviction is done by the ONE resident sweep — _resident_sweep (world.gd:12244), driven from recenter (12296) — which consults resident_of against the CURRENT window. So a shrunk radius WOULD be honoured the next time a sweep runs.
  • The gap is whether a sweep runs at all. The sweep is travel-gated, and the user's ruling is explicit: "keep everything loaded while you stand still". So a player who opens Settings, lowers render distance while standing at the same spot, and closes it, may trigger NO sweep — leaving everything beyond the new radius resident forever. That is a direct interaction between a policy the user chose and a settings change nobody wired to it.
  • Also worth checking: the ticket's own update says slider changes should be staged while the menu is open and applied on close (recenter + chunk work), so there may be a deliberate deferral to test.

2. Verify first

  • 2.1 Reproduce on the CURRENT tree (1 m cubic grid, unified residency): load at a large radius, let it settle, lower the radius while STANDING STILL, and count how many chunks beyond the new radius remain resident. Then do the same while travelling. The two numbers together are the whole diagnosis.
  • 2.2 If nothing is orphaned in either case — the migration already fixed it — cancel this ticket with those measurements. Do not fix what is not broken.
  • 2.3 If orphans remain only when standing still, the cause is the travel-gated sweep and the fix is small: a render-distance change is an EXPLICIT EVENT and must force a resident sweep immediately, regardless of the travel gate. The standing-still "keep everything loaded" policy must NOT be weakened — the user asked for it, and it is about normal play, not about a settings change that has just redefined what "in range" means.
