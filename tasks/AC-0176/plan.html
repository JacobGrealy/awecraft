AC-0176 — saves live in an AweCraft folder, not Godot/app_userdata

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Small, but it moves where saved data lives, so the risk is orphaning saves rather than breaking code.

1. The change

Two project settings, both currently absent (project.godot has only config/name="AweCraft" at :5):

  • application/config/use_custom_user_dir=true
  • application/config/custom_user_dir_name="AweCraft"

Effect per the ticket: Windows %APPDATA%/AweCraft, macOS ~/Library/Application Support/AweCraft, Linux ~/.local/share/AweCraft — instead of %APPDATA%/Godot/app_userdata/AweCraft.

2. What to verify, in this order

  • 2.1 The path actually moves. Print OS.get_user_data_dir() (or equivalent) before and after in a headless run, and report both strings. Do not infer the path from the docs — the same setting behaves differently across platforms and this box is Linux while the product is Windows.
  • 2.2 Saves still work end to end through the real save/load arms, in the NEW location, from a clean state: save ok with its inventory/block checks, load ok with simband_ms in the usual class.
  • 2.3 Nothing was orphaned silently. If code anywhere hardcodes the old path, or a test asserts on Godot/app_userdata, it must be found by grep and reported. If a migration of existing saves is needed, say so — but for a product that has not shipped, deleting the old folder is likely correct and must be an explicit, stated decision, not an oversight.
  • 2.4 The Windows claim stays a claim. This box cannot verify %APPDATA%. Report the Linux path as measured and state plainly that the Windows path is documented, not verified — unless the Windows build can actually be exercised, in which case say how.

5. Acceptance

Both settings in place, the measured Linux path reported before and after, saves and loads green from a clean user dir, no silently orphaned path, the Windows claim labelled as documented rather than verified, and ARCHITECTURE.md §5 updated.

6. Risks

(1) Changing this quietly relocates every save, so a "successful" load that found an OLD file would be a false pass — hence the clean-user-dir requirement. (2) The sandbox's HOME=/tmp/dsh_home means the measured path is a sandbox path; report it as such rather than presenting it as the user's real Linux path. (3) Do not add a migration unless something real would be lost — state the decision either way.
