5. THE RESOLUTION

5.1 R3 — player light (user-directed deviation; the web has none)

Chosen: per-fragment add in the four unlit chunk shaders via two shared uniforms — u_player_pos (vec3) + u_player_light (float, default 0.0), pushed EVERY frame from main.gd _update_sky :1457-1477 by iterating _ChunkScriptM._mat_cache (chunk.gd:62) — the exact pattern set_day_factor uses (8 set_shader_parameter calls/frame, same class as the existing 4). GDScript has no enforced privacy, so the "private" static cache is reachable from main.gd without touching chunk.gd (read-only fence). The player is treated as a block-light source of level L_p = 5 at the player's feet position, with MC-style −1-per-block Euclidean falloff, using the web's own 0.12+0.88·(level/15) level→brightness mapping (:746 semantics):

// added to EACH of the four shader fragments (after the existing L line, before ALBEDO):
uniform vec3 u_player_pos;                 // default (0,0,0)
uniform float u_player_light = 0.0;        // 0 = feature off (safe default)
float pl = 0.12 + 0.88 * clamp(u_player_light - distance(WORLD_POSITION, u_player_pos), 0.0, 15.0) / 15.0;
L = max(L, pl);                            // max, NOT add
// existing: ALBEDO = t.rgb * COLOR.b * L;  (faceShade b applies to player light too — consistent)

Exact values: L_p = 5 → pl(d) = 0.12 + 0.88·clamp(5 − d, 0, 15)/15; at d=0 → 0.4133; at d=5 → 0.12 floor; beyond → 0.12 (i.e. radius = L_p = 5 blocks). Rationale for L_p = 5 (vs the prompt's alternative): the pitch-black guard demands "≥ the L_p-falloff value around them" — 5 gives ~41% brightness at the player, clearly visible, while staying well below a torch (14 → 0.9413) so real block light is never visually confused with the player halo. (L_p = 14 would make every cave look torch-lit — rejected.) Constant const PLAYER_LIGHT_LEVEL := 5.0 lives in player.gd (the light's owner); _update_sky reads Game.player.PLAYER_LIGHT_LEVEL (0.0 when no player — menu: no halo, safe default). Viewmodel gets it too (hand is at the player → d=0 → floor 0.4133 — a pitch-black cave still shows the hand, §5.2). Defaults are safe: u_player_light = 0 → clamp(0−d,0,15) = 0 → pl = 0.12 → max(L, 0.12) = L (L ≥ 0.12 always) — a fresh material cache entry after a texture swap is inert for ≤1 frame.

Rejected: PointLight3D scene light — unlit shaders (all four, + the unshaded viewmodel) IGNORE scene lights, so it would light nothing the player actually sees at night; also light-count/shadow-budget noise. Baking the player light into chunk light/eff — FENCE (persistent per-chunk state, remesh on every player move). Additive L += pl instead of max — would push daylit pixels above 1.0 (white-out). The lit fluid_anim water/lava surfaces (core/fluid_anim.gdshader, the documented AC-0128 out-of-scope lit gap) do NOT get the player light — they stay scene-lit, never pitch black; recorded, out of scope.

5.2 R2 — viewmodel lighting

Chosen: unshaded player-local materials + per-frame albedo_color modulation in player.gd, driven by ONE exact light read per cell change. The read: World.light_at(eye.x, eye.y, eye.z) (world.gd:1674) at the player's EYE cell (floor(pos.x), floor(pos.y + EYE), floor(pos.z)) — verbatim the web's own F3 read semantics (index.html:3253). Cached: re-read only when the eye cell changes OR a 500 ms TTL expires (amortizes the 3-7 ms compute_light_split to ~4 calls/s while walking; §7 budget). Levels 0..15 → normalized /15, then the web formula with the SAME u_day value AC-0128 pushes (DayNight.day(Game.time_of_day), web :1337/:3222 parity):

// player.gd vm_refresh(force=false)  — shared by _process (game) and the probe (force=true)
var L := 0.12 + 0.88 * maxf(day * sky / 15.0, blk / 15.0)     // web :746 at the player eye cell
L = maxf(L, 0.12 + 0.88 * minf(PLAYER_LIGHT_LEVEL, 15.0) / 15.0)   // R3 add at d=0
for [m, base] in _vm_mats: (m as StandardMaterial3D).albedo_color = base * L

Material application (one pick, no double-dim — AC-0128's atlas-tint move is preserved):

  • held_box: (HeldMeshes.box_material()/cross_material() as StandardMaterial3D).duplicate() ONCE per kind (cached), shading_mode = UNSHADED, set as material_override. UNSHADED is REQUIRED: the current shared material is LIT (roughness 0.95) — without this the viewmodel would be double-dimmed (L × scene ambient).   • held_fist: the existing local UNSHADED material (player.gd:386-389) → albedo_color = Color(0.87,0.73,0.57) × L (base captured at build).

5.3 R1 — stars (Godot implementation of web :718-730 + :1347 + :3248)

Chosen node spec — one MeshInstance3D named "Stars" + one unlit ShaderMaterial (godot/core/star.gdshader, NEW):

  • Mesh: ArrayMesh, one surface, PRIMITIVE_TRIANGLES, indexed: 500 stars × 4 corner verts (800 verts, 3000 indices).   • Positions = the web's EXACT 500 points: a verbatim port of mulberry32(42) (:125) in GDScript (32-bit wrap + _imul = low-32-bit signed product), then per star (two draws each): phi = acos(2·u1 − 1), theta = u2 · TAU, p = (320·sinφ·sinθ, 320·cosφ, 320·sinφ·cosθ) (setFromSphericalCoords :722, Y-up on both engines).   • Shader (godot/core/star.gdshader): shader_type spatial; render_mode unshaded, cull_back, transparent; — vertex: vec4 pv = MODELVIEW * vec4(VERTEX, 1.0); pv.xy += (UV − 0.5) * 0.70; VERTEX = pv; (view-space billboard; outputting view-space is the standard spatial-shader idiom); fragment: ALBEDO = vec3(1.0); ALPHA = u_opacity; (uniform u_opacity float default 1.0). No fog() call — custom spatial shaders get no engine fog unless fog() is called: the web fog:false equivalent (G6 render double-checks, §7.1). Material transparency (render_mode transparent) = web transparent:true, depthWrite:false (depth TEST stays on — same as the web's default depthTest:true).
  • Per-frame (in _update_sky, the same value AC-0128's u_day uses — no new day computation): _star_mat.set_shader_parameter("u_opacity", 1.0 − day) (web :1347) and _star_node.position = player.position + Vector3(0, EYE, 0) — the web MOVES the stars with the camera every frame (:3248, after :3246 sets the camera to the eye position) — so the follow is a FAITHFUL port, not a deviation. Null-guarded when no player (menu).
  • Mapping notes: sizeAttenuation:false ↔ fixed world size at FIXED distance 320 (the sphere follows the camera) → constant screen size; 0.70 world ≈ 1.8 px at 1080p / fov 75° (0.70·2·tan(37.5°)·320/1080 ≈ 1.8; measured ≈2.1 px, cosmetic). frustumCulled:false ↔ a radius-320 sphere centered on the camera ALWAYS intersects the frustum — never culled in practice (Godot has no per-MeshInstance3D frustum-cull disable; not needed). Camera far 4000 (default) > 320 ✓.

Rejected: PointMesh — engine-generated uniform box distribution, cannot carry the 500 custom positions. Custom-shader PRIMITIVE_POINTS — closest to the web, but Godot does not expose gl_PointSize to user shaders (point size engine-controlled / 1-px class) → the web's 1.8 px size is unreachable; also the only renderer with guaranteed point-sprite behavior is Compatibility, and unverified point size is a G6 render risk.
