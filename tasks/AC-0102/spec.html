AC-0102 — tasks/scripts/spec_template.py: auto-fill spec.html from a TASKS.yaml entry (SDLC 2026-08-23 item 3)

Status: open (priority 1) · Source: user SDLC batch · Goal: cut coordinator context before subagent launch — the spec for a task should be generated (metadata, frozen-spec refs, Data.* constants, default verify gates, expected RESULT shapes) from the registry entry + repo facts, leaving only the task-specific sections for the coordinator to fill.

Deliverable: tasks/scripts/spec_template.py (stdlib-only python3, same style/conventions as tasks/scripts/tasks.py — read it first). Usage: python3 tasks/scripts/spec_template.py AC-NNNN [--force] [--out PATH] → writes tasks/AC-NNNN/spec.html.

Behavior (hard requirements)

  1. Inputs: TASKS.yaml entry for the id (notes/title/source/parent/created_at — the same parse tasks.py uses); tasks/HARNESS.md (the AC-0103 mode table); godot/core/data.gd (or wherever Data.* lives — locate it) for the canonical constants.
  2. Generated sections (auto-filled):
    • Header: id/title/status/parent/created + the registry notes verbatim (quoted, not interpreted).
    • Frozen spec refs: index.html = build 20260816-r12, "source of truth, do NOT modify" + the minecraft.wiki canonical-refs line (Tool/Block/Mining/Crafting_table/Item) — fixed boilerplate.
    • Data.* constants: parse data.gd for the key constants (SEA level, HEIGHT, biome thresholds, block/fluid id tables — whichever are top-level constants; render as a table with the current values from the file, file:line refs) so the spec never carries stale numbers.
    • Verify gates (default): G0 zero-script-errors; the AC-0061 tiered protocol summary (SMOKE by subagent / FULL battery by coordinator / dependency table pointer → tasks/AC-0061/AC-0061-results.html); sandbox env block (the HOME=/tmp/dsh_home one-liner) + "one godot at a time".
    • RESULT shapes: pull the relevant rows from tasks/HARNESS.md for the default battery modes (player/interact/light/fluids/buckets) + genhash — embed as a small table (mode | key RESULT fields | typical wall) so the coordinator doesn't grep main.gd.
    • Known-stable values: the current stable gate values (parse from HARNESS.md's known-stable section if possible, else fixed boilerplate listing sea 2730/1406 etc. with "verify fresh" note).
  3. Coordinator-fill sections (clear placeholders, NOT auto-invented): ## Goal (one line from notes, marked "REVIEW"), ## Task-specific requirements, ## Task-specific gates, ## Scope (files expected to change), ## Fences — each with an HTML comment <!-- FILL: ... --> and a 1-line example. The tool must be obviously a scaffold: auto sections labeled "AUTO (from TASKS.yaml/HARNESS.md/data.gd — do not hand-edit)", fill sections labeled "FILL BY COORDINATOR".
  4. Refuse to overwrite: if tasks/AC-NNNN/spec.html exists → error + exit 1 (print what exists); --force overwrites. --out PATH writes elsewhere (for tests). Unknown task id → exit 2. Task with status done → warn but allow (coordinator may regenerate).
  5. No network, no godot, stdlib only. Must not modify TASKS.yaml or any other file.

Verification gates (hard)

G1 No-overwrite: run against an id whose spec.html exists (e.g. AC-0061) → exit 1, file untouched (mtime+hash before/after); --force → overwrites.
G2 Bad inputs: unknown id → exit 2 with a clear message; missing TASKS.yaml → clean error, no traceback.
G3 Content (dogfood): generate a spec for a real open task that has NO spec.html yet (pick the next queue task the coordinator hasn't spec'd — if every candidate already has a spec, use --out /tmp/… or a scratch copy of TASKS.yaml with a fake task) → verify: (a) registry notes appear verbatim, (b) Data.* table values MATCH the actual data.gd constants (spot 5 values), (c) HARNESS.md RESULT rows for the 5 battery modes + genhash are present and match HARNESS.md, (d) all 5 FILL sections present with comments, (e) valid HTML (opens, no unclosed tags — basic well-formedness check).
G4 Reproducibility: run twice → byte-identical output (no timestamps in the file except a "generated" note that is deterministic — e.g. the date is allowed to be the task's created_at, NOT today's clock).
G5 G0: no godot involved — but confirm git status shows only tasks/scripts/spec_template.py + tasks/AC-0102/ artifacts (no code changes, no stray writes).

Fences / deliverables

  • Changes: tasks/scripts/spec_template.py (+ tasks/AC-0102/AC-0102-results.html evidence: test matrix with actual exit codes + the dogfood spec embedded/summarized + spot-check table). No .gd changes. No TASKS.yaml changes. No git. No coordination files. No python kills.
  • Stdlib only (os/sys/argparse/re/html/yaml-if-tasks.py-uses-it-check — if tasks.py uses PyYAML, the template may use it the same way; if tasks.py is hand-rolled YAML, match that approach). Match tasks.py CLI conventions (argparse, exit codes, no fancy deps).
  • Report ≤15 lines: files changed, test matrix (G1–G5 outcomes with exit codes), dogfood target + spot-check results, deviations.
