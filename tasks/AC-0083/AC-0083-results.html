AC-0083 — Broken-block drops show the block's texture

Status: complete · Task: AC-0083 (top priority) · Date: 2026-08-23

Summary

The world drop entity (the small pickup item that spawns when a block is broken) now renders with the same UV-mapped block-face texture as the block it drops — a per-face textured 1×1×1 box (top/side/bottom tiles from Data.block_rect + Data.atlas_tex + Data.block_tint vertex colors) — instead of a flat solid color. It reads as a small version of the broken block. Cross-quad (flower) drops use the held cross-quad mesh.

What changed

FileChange
godot/entities/drop.gd Replaced the solid-color BoxMesh + unshaded StandardMaterial3D with the shared HeldMeshes.box_mesh(id) / HeldMeshes.cross_mesh(id) + their materials, scaled to the 0.3 drop size. Cross-quad blocks (flower, id 18/19, cross=true and not thin) use the cross-quad mesh; all other block drops (incl. thin torch) use the textured box. Box size (0.3), Area3D r1.1, attract <2.5, pickup <1.1, 120 s life, and world.gd spawn_drop are all unchanged.
godot/scenes/main.gd Added a small AWECRAFT_LOGIC=dropshot render hook: mines one dirt block at spawn, spawns its drop, frames it with a dedicated camera, and snapshots. Kept minimal (one branch + one helper).

Non-box drops (documented choice): cross-quad blocks (flowers) fall back to the held cross-quad mesh (HeldMeshes.cross_mesh) so they read as a small plant, matching the held viewmodel. Thin blocks (torch) and all solid cubes use the textured box. The texture is derived from the drop's block id via Data.block(id) + the same Data.block_rect/block_tint/atlas_tex mapping the held block uses, so the drop always matches the broken block's atlas tile.
