Risks / fences specific to this change

  • Single-source rule: the fade target must be u_air itself (already a uniform in this shader, pushed from env.fog_light_color = Aero.fog_display(t) — the same value the dome and the sky use). No new uniform, no new colour constant.
  • Ground (120 m) look: the fade target change also affects low altitude, where haz_b was ≈0.62 (a hazy dome the annulus matched). At the user config (fog full at 332 m) the engine ramp fog_f is already 1 across the annulus there, so the fixed annulus is uniform air out to the edge — the pre-r8 look — and the dome beyond stays hazy via its own model. The 120 m render is a no-regression check, not an acceptance altitude.
  • Render traps (cost hours here): NO AWECRAFT_LOGIC arm (the menu boot owns the snapshot); AWECRAFT_SIZE=1280,720 with a COMMA; SNAP_DRAIN counts FRAMES; check each file exists > 50 kB after the run (Debug.snap prints SNAP FAIL rather than falsely reporting success); the log must carry the Forward+ boot line and zero SCRIPT/SHADER ERROR.
  • Concurrent session: 4 dirty files (main.gd, game.gd, drop.gd, debug.gd) belong to another session — never edit them; every render runs on the same tree before/after, so the A/B is fair.
