What shipped

  • 20 Hz game tick (0.05 s) is the simulation clock — replaces the 5 Hz fluid Timer. Fixed-step accumulator on the real frame delta in world.gd::_process (max 4 catch-up ticks/frame; backlog dropped on stalled frames, no death spiral). Fluid simulation runs inside the tick (same band-0 scope, same fluid_wet sleep optimization, N=3 unchanged — at 20 Hz sleep engages in 0.15 s, i.e. faster than the old 0.6 s).
  • Tick region = band-0 taxicab diamond, 41 columns (|dx|+|dz| ≤ 4) — band 1–3 (the 13–50 render circle) NEVER tick (structural: the pass only iterates chunks with face ≤ 1 and band == 0).
  • Random ticks: exactly 1 per 16×16×16 subchunk per 20 Hz tick over the 41 columns (984 touches/s). Deterministic: the cell is a pure function of (world seed, tick index, column, subchunk) via a splitmix64 chain (one column hash per tick + one mix per subchunk, 12 low bits → lx/ly/lz). Two fresh runs produce byte-identical sequences (window md5 identical across 5 independent process runs).
  • Random-tick consumer = counter/hook (random_tick_total, random_tick_map, opt-in random_tick_seq log, hook point _apply_random_tick). No crops/wheat/redstone blocks built.
  • Region/rate contracts (predicates + constants only): REDSTONE_DUST_DELAY_TICKS = 1; in_mob_spawn_region(dx,dz) = circle 24–44 (squared-distance, unit per caller) ∪ the (n−1) taxi diamond of the Simulate radius (n = band0_r = 4). Feature work (redstone dust block, mob spawner) DEFERRED.
  • New probe arm AWECRAFT_LOGIC=tick (main.gd _tick_test): rate, scope, distribution, determinism, fluid-hz, per-tick ms — one process, headless ≤ 60 s.

Deviations / interpretations

  1. "half columns" — read as: the 41-column taxi diamond ticks ≈ half the columns of the 81-column (9×9 chebyshev) square the note rejects ("41 not 81"). The tick set is exactly 41.
  2. "~1/68 s per wheat" — with the spec's exactly 1 random tick per 16³ per tick at 20 Hz, one wheat cell (1 of 4096 in its subchunk) is picked every 4096 ticks ≈ 205 s. The note's ~68 s corresponds to ~3 ticks/16³/tick (Bedrock's actual randomTickSpeed=1 behavior). Implemented exactly-1 per the brief; the 68 s cadence is a property of a 3× variant, recorded here for when crops land.
  3. Redstone / mob-spawn deferral — the note's "redstone 1-tick dust" and "mob spawn 24-44 circle + n-1 diamond" are shipped as pure predicates + rate constants only (self-checked in the probe, region_ok:true). No redstone block, no mob spawner — feature work is follow-on. The "24-44 circle" unit is unresolved in the note; the predicate is unit-agnostic (squared distance in the caller's units).
  4. hz is gated on the last-half window rate (hz2) — a few >200 ms frames (worker-handoff spikes) drop catch-up ticks via the 4-tick cap and drag the full-window rate (observed hz 17.2 in one mid-build run); the steady-state clock rate is the half-window rate (20.03 here). Both are reported.
  5. Probe boot is disk-cached — user://chunkdir_0 (AC-0155 chunk files, seed 44) serves the 41-set in ~3 ms; a fresh no-files boot adds ~3–6 s (still ≤ 60 s wall). The tick sequence itself is disk-independent (pure function of seed + tick index + the 41-set).
  6. Settle before the window — the hz window runs only after the 41-set is meshed and the stream queue size is stable (90 frames; 40 unbuildable outer-ring entries linger forever, so queue_size==0 is not the criterion). With builds in flight the measured hz collapses (9 Hz) — settle is what makes the 20 Hz measurement meaningful.
