AC-0085 — Held items: swing = rotate, vertical at rest, handle off camera

Status: open (top priority) · Source: user report 2026-08-23 · Project: AweCraft (Godot port) · Spec references: frozen web ../index.html (held/attack representation) + Minecraft first-person (minecraft.wiki Sword / File:ShieldFirstPerson).

User report (verbatim): "held items like sword, axes should swing (rotate), not just move out and in positionally. Also they should be held more or less straight up and down before the swing. the handles should be off camera (lower than the view port). The held cubes should also be lower in the view port."

Requirement

Four changes to the first-person viewmodel (hands + held item):

  1. Swing = rotation, not translation. The current swing moves the held item out-and-in by position (a position lerp). It must instead ROTATE the tool through an arc about a shoulder/hand pivot (a real swing), like Minecraft and the web spec.
  2. Vertical at rest. Before/during the swing start, the tool should be held roughly straight up and down (more vertical), not horizontal/diagonal.
  3. Handle off camera. Lower the whole viewmodel so the tool handle goes off-screen below the bottom of the viewport (off camera), like Minecraft first-person.
  4. Held cubes lower. The held block/cube should also sit lower in the view port (consistent with #3).

Known location / state (keep intact)

  • godot/player/player.gd — viewmodel root/pose + swing driver (AC-0048 swing sweep 0.1→0.2 s; AC-0060 walk sway via sway_root; swing loop LMB-hold). The swing pose math (position lerp → rotation arc) lives here.
  • godot/core/held_mesh.gd — held box/cross/tool voxel meshes (geometry; pose/transform is applied by player.gd).
  • KEEP intact: AC-0067 (viewmodel always on-top / no depth test), AC-0070 (voxel tool models), AC-0073 (tool orientation + scale ×2, TOOL_POSE_ROT), AC-0060 (walk sway).

Scope

  • Change the swing to a rotation arc about a pivot; adjust the resting/swing-start pose to be more vertical; lower the viewmodel so the handle clears below the viewport and held cubes sit lower.
  • If the AWECRAFT_LOGIC=swing harness thresholds were tuned to the old translation animation, re-tune them to the new rotation animation (keep the gate meaningful: it should still assert a real swing cycle occurs and settles).
