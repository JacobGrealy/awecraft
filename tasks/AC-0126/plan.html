7. Risks / edge cases

  • Spawn-chunk sync in an edit set: a break whose 3×3 contains (0,0) incurs one ~65 ms contract-sync frame — the pinned cells are chosen to exclude (0,0) from all three 3×3s (§4). This is a probe property, not a code property; if future probes change, re-check the invariant.
  • Cap-drop defer starvation: pool=2, 9-chunk edit set → defers are the norm (perf_edit_defers > 0 expected, healthy). Re-queue is FIFO-preserving; in-flight dedup clears when threadmesh_poll lands the task. Pathological stall → caught by the 600-frame settle bound (gate, not a guess).
  • Byte-identity scope creep: the minimal-correct edit set is actually the broken chunk only (contained light is a function of own data; neighbors' eff is invariant). The plan DELIBERATELY keeps the 3×3 (set_block/_mark_light_around unchanged) because neighbor MESHES can change (boundary-face culling reads diagonal neighbor data) — dropping them to 1 chunk would go stale and fail the A/B MINFO diff. Do not "optimize" the edit set down.
  • Sync fallbacks inside the window: spawn/diagonal syncs can blow the 40 ms budget guard (65 ms); acceptable — contract path, never fires in the pinned probes (invariant in §4). The guard remains as a safety net for the worker-dispatch case.
  • Coalesce counting: perf_edit_light_passes counts dispatches with empty eff (one contained pass each) — counted identically in PRE and POST (probe-first), so the ≤18 gate tests coalescing (2 batches), not dispatch count. PRE today already coalesces via chunk-key dedup; the gate guards against a POST regression (e.g. per-break queueing).
  • r=6 probe startup: 169 chunks, ~48 rim chunks sync-build (~65 ms each, main thread) → steady-state wait ~25-35 s per process × 3 cases × 2 phases ≈ 5-6 min of godot time; keep the probe's wait generous (no timeout before the break).
  • genhash sensitivity: world/* untouched (only world.gd + main.gd) → 25/25 trivially safe; if Run-2 unexpectedly touches chunk.gd/lighting.gd, genhash + full battery catch any drift before the heavy gates.
  • Fallback if the plan is wrong: if p95 misses (e.g. handoff apply_accs costs more than measured), the lever is EDIT_FLUSH_MAX_PER_FRAME / the budget guard, not the worker contract; if A/B diff appears, bisect via the 3×3 eff_md5 keys (they localize the divergent chunk, and dump_gen.gd-style raw dumps diff it cell-wise).
