AC-0061 — Tiered verify pipeline (user 2026-08-23: "the battery is overkill")

Status: open (priority 1, queue head) · Source: user directive + agent design · Type: process/tooling task — deliverable is a single-process multi-mode battery harness plus the tiered verify protocol (smoke / full / dependency gates / caps). No game-visual changes; no renders needed.

Goal: cut per-task verification cost WITHOUT losing rigor (G0 zero-script-errors + per-mode RESULT + pixels stay). Three tiers: (1) SMOKE per task (subagent), (2) FULL single-process battery once before builds (coordinator), (3) DEPENDENCY gates that pick only the relevant modes per change area, plus hard caps on renders/browser.

Deliverable A — single-process multi-mode battery (godot/scenes/main.gd)

  • New env AWECRAFT_BATTERY = semicolon-separated list of AWECRAFT_LOGIC mode names (e.g. AWECRAFT_BATTERY=player;interact;light;fluids;buckets). Do NOT reuse AWECRAFT_ONLY — that name is already taken by the chunk-visibility filter (main.gd:854).
  • One godot launch, one spawn/recenter: run each listed mode sequentially in the same process, reusing the existing AWECRAFT_LOGIC dispatch code paths (player/interact/light/fluids/buckets/genhash/toolres/toolpose/held/swing/… — whatever exists; don't fork the mode implementations, drive the same entry points).
  • Emit each mode's RESULT {...} line verbatim as today, then a final combined RESULT {"battery":{mode:{...}}, "script_errors":N, "ok":true|false}, then quit.
  • State isolation: between modes the world/player state must be clean enough that each mode's RESULT equals its standalone run. Minimal reset that achieves parity (recenter + await build, respawn player, clear edits/fluid/timing accumulators as needed) — document exactly what the reset does.

Deliverable B — tiered protocol (protocol text; coordinator lands it in AGENTS.md/CONTINUITY.md at commit time)

  1. SMOKE (every task, run by the subagent): G0 = headless --quit with 0 script errors, ALWAYS; + 2–4 relevant AWECRAFT_LOGIC modes per the dependency table (below); + genhash (already 5×5 = 25 chunks, main.gd:796) only if world/* changed; a cheap R=1 render only if the task spec requires a visual; no browser.
  2. FULL (coordinator, once, before builds): AWECRAFT_BATTERY=player;interact;light;fluids;buckets (+ genhash when world/* changed) — single launch; then ./build_web.sh + ./build_windows.sh.
  3. DEPENDENCY gates (which modes per change area — build the table from the AWECRAFT_LOGIC set in main.gd + historical task usage, and document it in results.html):
    • world/* (generator/world/chunk) → genhash + fluids (+ interact if edit paths touched)
    • player/player.gd → player + swing + toolpose (+ held)
    • core/held_mesh.gd → held + toolres + toolpose (+ viewmodel render if pose changed)
    • entities/drop.gd → interact (+ dropshot/crossshot render if visual)
    • inventory/craft → guiclick + interact
    • fluids/* → fluids + buckets + genhash
    • settings/ui → settings + guiclick
  4. Caps: renders ≤ 1–2 small (R=1–2) per task per the task spec; browser retest only after a fresh build (user's call); no re-running the full battery for tasks whose smoke+full already passed (coordinator reviews subagent report + screenshots).

Verification gates (hard)

G0 Headless --quit: ZERO script errors.
G1 No cross-mode contamination: AWECRAFT_BATTERY=player;interact;light;fluids;buckets in ONE launch → 5 RESULT lines; each mode's non-timing RESULT fields identical to a standalone AWECRAFT_LOGIC=<mode> run of the same mode (record both, diff in results.html; fluids sea 2730/1406; genhash 25/25 MD5 identical if included).
G2 Cost: report wall time of the single battery launch vs the sum of 5 standalone launches (honest numbers; the tool must not be slower than the 5 separate runs by more than ~10% — if it is, analyze why and say so).
G3 genhash 25/25 unchanged vs current (this task must not touch terrain output).
G4 Builds (coordinator: web + windows, both exit 0).

Scope / fences

  • Changes: godot/scenes/main.gd (battery runner + reset) ONLY. No world/*, player.gd, chunk.gd, generator, mesh/light/fluid changes. No renders. No UI.
  • No git; no coordination files (AGENTS.md/CONTINUITY.md — coordinator writes the protocol section at commit time); no python kills (8443/5180/8080); godot one at a time.
  • Sandbox env: every godot call in ONE bash command: export HOME=/tmp/dsh_home; mkdir -p $HOME; ~/tools/godot/godot ...
  • Deliverable: tasks/AC-0061/AC-0061-results.html — self-contained: battery mechanics + reset description, G1 parity table (per-mode fields battery vs standalone), G2 cost numbers, the DEPENDENCY table (Deliverable B.3) as the coordinator-ready protocol text, deviations.
