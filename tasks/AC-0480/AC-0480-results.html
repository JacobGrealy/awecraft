4b/4c — the plan's leading mechanism, refuted

The plan: "QUANTIZATION IS PER-SAMPLE AND PER-CHUNK … adjacent chunks quantize the same terrain to different buckets … a visible seam exactly at every chunk edge." The code says otherwise:

  • The merge bucket q = (int)(cr*31)*1024 + (int)(cg*31)*32 + (int)(cb*31) (mesh.cpp:2869) is a pure function of colour — global, not chunk-relative; the same colour lands in the same bucket in every chunk. The emitted quad colour is the unquantized origin-cell average (mesh.cpp:2924-2926) — quantization shapes quad layout, not visible colour.
  • The key's (k+1) term is the slab-local outermost-plane index — it only orders merges within a face; the merge never crosses chunks because meshing is per-slab, but the colour on either side of a chunk edge is each cell's own average — so a chunk edge shows a step only where the terrain's 2 m cells differ, i.e. exactly the 2 m lattice (every 8th line). No extra 16 m structure exists.
  • The per-cell sky is a pure function of the cell's own footprint (far H is byte-identical to the full path — farab gate) — no chunk-edge light jump.
  • Geometry: the home warp _warp_home_cell_point (chunk.gd:1937-1940) is a pure function of world position (C0 at chunk edges; 16·(c+1)==16c+16 exact in float) — no geometric gap at chunk edges.
  • The ONLY chunk-relative term in the far tier is the water-tile UV origin (31 px per G-block from the chunk's own corner, mesh.cpp:2968-2971) — water surfaces only.

Conclusion: a 16 m chunk-boundary seam is structurally impossible in the opaque far tier. The intra-tier lattice is the 2 m averaging-cell grid (world-anchored), 8× denser than chunks. "Between chunks" is perception: the lattice crosses every chunk edge but does not live on it.
