AC-0213 — forward-move-inside-chunk-tanks-to-5fps-queue-budget — results

2026-09-04 · subagent · engine Godot 4.7.1 · seed 44 · C++ hot path (no fallbacks, AC-0208) · godot/world/world.gd + godot/world/lighting.gd + godot/player/player.gd (comment) · logs .scratch/AC-0213-gates/

ALL GATES GREEN. The R16 5 fps tank is gone. Root cause (proven by bisection, not assumed): the ~473 ms stall that AC-0212/AC-0219 had labeled a "pre-existing periodic engine event" is player.vm_refresh → world.light_at — the GDScript multi-chunk light kernel, called every 500 ms and on every eye-cell change. A 17×17×17 box spans at most 4 chunks, but the kernel called chunk.flat_data() (a 98 304-cell GDScript palette decode) once per column — up to 289 re-decodes per call ≈ 473 ms (measured: 473.1 ms). The fist view-model material is always registered (player.gd _build_held), so the refresh never early-returned. Fix: materialize each distinct chunk once (+ a gen-stamped world-level cache — steady state re-materializes nothing): 473.1 ms → 18.9 ms cold, ~13 ms warm; byte-identical light values (25-cell A/B dump, original vs cached kernel, diff clean). On top of that, the task's queue-budget changes landed as specified: the drain paces at 1 unit/frame for 1.5 s after any recenter (small-move budget), a recenter one chunk past the previous center within 1 s skips the full ahead-ring queue rebuild (requeue debounce), and recenter stays positional-only (camera-only look never requeues). R16: moving p95 480 → 21 ms, p50 71 fps, max 29 ms, no static-vs-moving drop; 797/797 built, no pop. G0 clean; SMOKE ok:true ×4; no-regression arms all green.

1. Root cause (bisection evidence)

The stall (~473 ms, ~502 ms period, ~5 % of frames, in BOTH the static and the moving R16 phase, starting exactly at player spawn) was bisected with a temporary diagnostic arm (removed before shipping):

→ the stall is in the player script, not physics/camera/mesh. The script's per-frame light lane is vm_refresh: it calls world.light_at(eye) on the 500 ms timer and whenever the eye cell changes (every cell tapped/walked through). Direct measurement: light_at = 473.1 ms — an exact match. Cost anatomy: 289 × flat_data() (each re-decoding all 24 paletted slabs, 98 304 cells, in GDScript) + the two-flood box kernel. This is the "plus palette reads" half of the task's root-cause note; the queue side (below) was real but small in R16 (R16 never crosses a chunk boundary, so no recenter runs at all in the arm — drain sub-ms, TMWAIT 0).

2. What changed

2a. godot/world/lighting.gd — the 473 ms fix (kernel intact, values identical)

sitechange
compute_light_split (the multi-chunk box kernel) the per-column loop now materializes each distinct chunk once into a local cflat (≤4 entries for a 17-wide box) instead of calling chunk.flat_data() per column (≤289 calls). An optional flat_cache argument ({key: [data_gen, PackedByteArray]}) is consulted first, so a world-owned cache can serve warm materializations across calls.
the full-light sibling kernel (same box pattern) same per-chunk cflat (no flat_cache argument — rare path, unchanged semantics).
semanticsunchanged: same sky scan, same two floods, same eff/max dict. A/B on 25 probe cells (surface + deep, 5×5 around spawn): byte-identical sky/block/eff between original and cached kernel.

2b. godot/world/world.gd — cache owner + the queue-budget changes (queue logic intact)

sitechange
light_at + new _lightflat dict world-owned gen-stamped flat cache: entries are reused while chunk.data_gen is unchanged (set_block → set_local bumps it, so edits always re-materialize), capped at 8 entries (≤786 KB). Steady-state light_at ≈ 13 ms (flood + scan only), no main-thread palette decode.
new SMALL_MOVE_BUDGET_MS = 1500, _sm_move_until small-move budget: recenter() marks a 1.5 s small-move window; inside it the drain budget clamps to 1 unit/frame (the trickle rate) instead of 2 — a tap forward no longer bursts 2 gen/build units per frame on top of the recenter work. Startup (12) and loading (LOAD_DRAIN_UNITS) windows are untouched.
new AHEAD_RING_DEBOUNCE_MS = 1000, _last_recenter_ms/pcx/pcz ahead-ring requeue debounce: a recenter whose center is exactly one chunk from the previous recenter's center and within 1 s skips the full want-walk queue rebuild (_rec_pending stays untouched — an in-flight walk continues, a finished walk stands). The candidate/free hysteresis walk, the 5×5 spawn pre-warm (dedup-safe _enqueue_build), the 5×5 burst bookkeeping, and the (0,0) sync-gen contract all still run — nothing is dropped. The next non-debounced recenter rebuilds the queue from the current center. Walking across boundaries at ≥4.3 m/s (≈3.7 s apart) never debounces; only tap-forward bursts do.
unchangedthe drain itself (windowed pool scan, defer-on-cap, time budget, band buckets, scoring), the recenter slice, the handoff cap (AC-0219: 1 streaming mesh/frame), the edit lane, the startup burst, the loading window.

2c. godot/player/player.gd — camera-only guard (documentation of the existing invariant)

_recenter() fires only on a positional chunk change (pcx/pcz vs the cached chunk); look changes touch nothing — camera-only moves never requeue (no code change; the invariant is now documented at the site).
