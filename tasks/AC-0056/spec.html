AC-0056 — give the game a Frutiger Aero look: (A) fullscreen color-grade + (B) aero skybox

User request (2026-08-20, verbatim)

"can we apply some kind of color grading to make our game have frutiger aero aesthetic?" + "also add a skybox that has the frutiger aero aesthetic". These are the user's two headline asks. They flow into BOTH the desktop godot render AND the web build (web/ is rebuilt from godot/ — the primary surface is the browser on 8443).

What "Frutiger Aero" means here (the target, be specific)

Mid-2000s glossy optimistic "aqua/aviation" look: highly saturated cyan/blue/green, glassy bright highlights, a big soft glowing sun, a clean vertical gradient sky (deep azure → bright cyan → pale near-white horizon), puffy glossy clouds, and a "clean, cool, milky-lit" world with lifted (never pure-black) darks and subtle bloom. Tasteful, not neon. Reference mood: Windows Vista sky, early iOS water, glossy "aqua" UI.

Part A — fullscreen color grade

Apply a post-process grade to the whole 3D frame. Grade ops (all tunable uniforms): saturation/vibrance (up ~15-25%), split-tone (teal shadows → cool cyan-white highlights), an S-curve contrast punch in the midtones, lifted milky blacks, a soft bloom/bloom on brights, and a low-amount aqua screen-wash. Must read as "clean, bright, saturated, cool" without blowing out.

  • Preferred implementation: a full-viewport post-process via a SubViewport — render the game (world + camera + aero sky) into a SubViewport, and show it through a fullscreen unlit quad whose ShaderMaterial samples the subviewport texture and applies the grade. This is the standard Godot 4 pattern for arbitrary color grading and works under gl_compatibility.
  • Fallback (only if the SubViewport route proves flaky under llvmpipe): a WorldEnvironment Environment with glow (bloom) + tonemap for the brights, and accept a lighter grade — but the aero SKYBOX (Part B) must still land fully. Do NOT silently drop the split-tone/saturation grade without telling me.
  • Key grade uniforms (saturation, blue_wash, bloom, lift, contrast) must be editable Constants at the top of the shader so we can dial it from a re-render without re-engineering.

Part B — aero skybox

Replace the current flat Environment.background_color sky with a Frutiger Aero sky.

  • Preferred: a large back-face sky surface (inverted sphere or a big quad set) with a shader: vertical gradient (zenith azure → mid cyan → pale horizon using the values above) + a soft-edged sun disc with a large radial glow (position the sun using the existing sun/day-night direction) + a few soft puffy cloud blobs (2D noise, low alpha, slow drift, subtle cyan rim) + a thin light-cyan horizon haze band. It must enclose the world and not be clipped by the far plane (either very large or parented to the camera, and raise far plane if needed).
  • Alternative (simpler): a Sky resource / ProceduralSkyMaterial with animated top/horizon/sun colors + glow — acceptable if it reads aero; preferred is the custom gradient surface.
  • DayNight integration (required): find how the sky currently updates (search _update_sky in godot/scenes/main.gd and the DayNight autoload) and modulate the aero palette by the same time-of-day: day = full azure/cyan, night = deep indigo/teal, sunset = warm→cyan. The grade should also shift cooler at night.

  • Expose the key grade/sky amounts as constants so a follow-up pass only needs a numeric tweak.

ROUND 2 — user feedback 2026-08-20 (after testing the 19:01 web build) — THIS PASS MUST COVER

User tested the aero web build and said (verbatim): "in the aero styling sand should be more yellow. Maybe what I want is more the sega pallete from like sonic the hedge hog" + "I can't see the skybox because of the fog, I don't think mine craft works that way?"

  1. Skybox invisible (BUG): the sky sphere sits ~1000 m while fog_far ≈ 76 (r=4) → fog fully washes it out. CONFIRMED (coordinator research): in Godot 4 a spatial shader with an empty fog_fragment() still gets environment fog (unshaded included); the reliable per-material switch is render_mode fog_disabled. Add fog_disabled to aero_sky.gdshader render_mode (and to aero_wash.gdshader for safety). In MC the sky is always crisp; fog only fades terrain to the chunk edge — our fog span is correct, the sky must be exempt.
  2. Palette → Sega / Green-Hill-Zone energy (user preference): the current grade drifts too cool/milky — sand reads cyan-tan instead of yellow. Retune toward vibrant Sega primaries: bright azure sky (keep), sun-warmed yellow sand, lush greens, punchy saturated mids. Levers (edit the aero.gd constants, re-render, iterate): reduce the additive aqua WASH (cyan wash directly desaturates yellows — e.g. WASH_AMOUNT 0.07 → ~0.03, or a lighter blue), reduce milky black-lift/contrast softness, add a small warm midtone push (saturation up ~10-20% on the yellow-orange side; the split-tone shadow may stay cool but should not drag the mids blue), keep glow modest. Target: a sand surface in an aero render must read clearly yellow-sand (≈ #E8D090-ish), and the overall frame should feel like a sunny Sega cartoon, not misty Vista.
