AC-0187 fix — breaking a block shows BLACK LINES for a few seconds

User story: as a player, breaking or placing a block must not flash corrupted/dark texels (black lines) on that chunk for a few seconds. The hole/appearance must look correct immediately (the scoped remesh) and stay correct (the wave's full rebuild).

Root cause (one paragraph)

In godot/world/chunk.gd, the scoped (edit) build emits its opaque faces through the plain per-face path (_s_emit_faces), which computes UVs in PLAIN atlas space: make_ctx() sets ctx["atlas_px"]=Data.ATLAS_PX and ctx["brect"][id_face]=Data.block_rect(id, face). But the opaque surface material was always built as _get_mat("opaque", ms.tex) inside _assemble_slab (chunk.gd:1957), where ms.tex is the MERGED atlas texture (_merge_atlas()). So the freshly-edited slab's plain-space UVs were sampled against the merged texture → wrong texels → black lines, until the light "wave" did a full (merged-UV) rebuild. Every other surface kind (cutout rk, flower rq, fluid, cutout-opaque rc_o) already uses a PLAIN-atlas material, so ONLY the opaque ro path was mismatched. The full-build path (build_accs non-scoped, apply_accs) correctly pairs merged UVs with the merged material, so the bug is scoped-path-only.

The fix (exact diff — surgical, chunk.gd only)

Make the scoped build's opaque material use the PLAIN atlas so it matches the plain emit's UVs. apply_edit_accs (used only by the scoped/edit path) now passes a plain-ms (tex=null) to _assemble_slab; _get_mat("opaque", null) → _lit_material(..., null) → _lit_atlas_tex() = the same plain atlas the plain UVs reference.

 godot/world/chunk.gd  (apply_edit_accs, ~line 2360)
 func apply_edit_accs(res: Dictionary, ms: Dictionary) -> void:
+	var pms := {"tex": null, "rects": {}, "h": 0.0}
 	var si0 := int(res.get("si0", 0))
 	var si1 := int(res.get("si1", slab_n() - 1))
 	...
 	for i in range(si1 - si0 + 1):
 		var row: Array = res.slabs[i]
-		_assemble_slab(slabs[si0 + i], _acc_from_dict(row[0]), ..., _acc_from_dict(row[5]), ms, bool(row[6]))
+		_assemble_slab(slabs[si0 + i], _acc_from_dict(row[0]), ..., _acc_from_dict(row[5]), pms, bool(row[6]))

Nothing else changed in chunk.gd. The full-build call sites (build_mesh line 2314, apply_accs line 2354) still pass the merged ms; _get_mat, _merge_atlas, the merged emit, fog, and all generation code are untouched. No comments in new/changed code. main.gd gains two harness-only arms (editmat + editmatshot), never run in game.

editmat probe — RESULT (the primary, deterministic gate)

New AWECRAFT_LOGIC=editmat (R=2): builds a stable chunk, breaks a surface block, and reads the scoped-rebuilt slab's opaque surface immediately after the scoped handoff (before the wave's full rebuild) via the _editprobe handoff hook (kind=="edit" confirms it is the scoped handoff). Asserts the material's sampled texture is the plain lit atlas (ChunkScript._lit_atlas_tex()) and is not the merged texture (ChunkScript._merge_atlas()["tex"]), and that every opaque UV ∈ [0,1].

Deviations / notes for the coordinator

  1. Material-cache ping-pong (expected, harmless). After the fix the scoped handoff calls _get_mat("opaque", null) and the wave's full build calls _get_mat("opaque", merged); each clears the identity-keyed _mat_cache and recreates the opaque ShaderMaterial. A few allocations per edit; sampling is always correct (plain UVs ↔ plain texture on the scoped mesh, merged UVs ↔ merged texture on the full mesh). No visual effect beyond the intended fix.
  2. editfront place 48.7 ms is within the <50 ms gate but a touch above the AC-0187 baseline (37.3 ms) — machine variance under the fix's extra material recreation; the gate (ms < 50.0) holds and drops stay 0.
  3. Render = steady-state proof. The black-line window is only the few frames between the scoped remesh and the wave's full rebuild; a Debug.snap (which awaits frame_post_draw) lands after that window, so the render shot shows the settled (correct) state. It confirms "no black lines at the edited block after the remesh" and that the fix produces no corruption; the scoped-window material identity is the authoritative headless editmat gate (with a pre-fix A/B).
  4. New harness arms editmat / editmatshot are harness-only (env-gated, never run in game), consistent with the other AWECRAFT_LOGIC probes.
