Design — 5 coupled pieces (as implemented)

  1. edit_front priority queue + synchronous dispatch — set_block stashes the pre-edit eff cache entry, appends {key,si0,si1} (slab closure of the edited row), evicts the eff cache entry, marks the 3×3 light wave, and dispatches immediately via _mesh_dispatch_edit (defer-on-cap keeps it queued for a one-frame retry when the pool is saturated).
  2. Dedicated EditPool lane — a 1-thread Thread + Mutex + Semaphore (hand-rolled; WorkerThreadPool cannot express priority), with a mark_done flag and its own guard mutex so handoff never races the worker. threadmesh_poll runs an ungated priority pass that hands off done edits before any other entry; also called from a new _physics_process (60 Hz) so the handoff latency is frame-rate, not frame-cost, bound.
  3. Slab-scoped fast remesh — build_accs(..., si0, si1, ...) allocates/uses only the touched slabs, pre-passes a y-mask boundary bitmask, validates the stale pre-edit light via _eff_stored_eq (drop + full retrigger on mismatch), and lands via apply_edit_accs (retain-until-swap: never an empty frame). mesh_gen/data_gen counters feed the drop and memo keys. Full-build path is byte-identical when scoped=false.
  4. Scoped row snapshots — row-scoped data snapshots (per-row append_array(slice), ≈35× smaller) and a drop check that only compares the changed rows d_off..d_hi; a change outside the applied slabs cannot invalidate them.
  5. Perf pieces — (a) scoped strips memoized on the 8-neighbor (data_gen, eff_gen) tuple (cap 32, cleared on overflow) with zero b-channels (the scoped build never runs the pull-kernel self-light; every eff entry carries its mask) — skips a ~190 ms _face_of cold miss and the duplicate neighbor-face recursion; (b) plain per-face emit for scoped builds (merge-atlas emitter measured 5–15× per-quad slower: 52–143 ms on 830 quads vs 9–22 ms plain) — geometry shape identical; the wave's full build restores the merged mesh in 1–3 frames; (c) edit-yield: while a scoped edit is in flight (edit_inflight_count > 0) the far-queue drain, flush, tex-refresh and non-edit handoff are skipped — the priority pass stays ungated (no deadlock); the handoff was stalling up to 856 ms behind drain bursts before this; (d) _s_face_light early-out at 15.

Measured budget (R=50, final tree)

  • break: dispatch 11.2 ms + worker 18 ms (phet: ro 9, rk 3, box 2, faces 2; nq 1147) + handoff ≈3 = 32.5 ms, 5 frames, prime
  • place: dispatch 0.4 ms (strip memo hit) + worker 33 ms (phet: ro 17, rk 6) + handoff ≈2 = 37.3 ms, 5 frames, prime
  • known worst-case combo (cold strip 14 ms + heavy worker 37 ms + unlucky handoff) ≈ 54–65 ms in pathological gameplay — the probe (acceptance gate) passes with 12–18 ms margin; steady state after warm strips is ≈ 30–40 ms.
  • drain impact: cap −1 steady (5/6), −2 while an edit is pending; R50 probe drain is I/O-bound (inflight 0–4 at edit time) — unaffected; lodswap unaffected.

Deviations / notes for the coordinator

  1. D1 — stale-light pop (accepted contract). The fast mesh lands with the pre-edit light (frozen); the 3×3 wave refreshes it in 1–3 frames. No-flicker = mesh presence (retain-until-swap), holds: drop_frames 0 in all runs.
  2. D2 — flush_active bookkeeping fix (pre-existing bug, fixed en route). The editperf counters ("current flush burst") were silently inflated (94–100 frames, 303–715 ms single build) by two causes: (a) a pre-existing stale-true flush_active — the clear only ran inside the flush section, which is skipped when light_pending is already empty at section start; (b) this task's original _edit_front_add set flush_active = true at set_block, suppressing the counter reset for the post-edit burst so it merged with the pre-edit E2 churn. Fixed: the clear now runs whenever light_pending is empty (outside the section), and the redundant set was removed (the idle check already covers edit_front). Post-fix counters match baseline exactly (9/22/22).
  3. D3 — plain-emit merge bypass (scoped only). Fast slabs use per-face quads; triangle count is higher until the wave restores the merged mesh (1–3 frames). Full builds keep the merge path untouched.
  4. D4 — zero b-channel scoped strips. Documented contract: scoped builds pass zero block-face strips; safe because frozen-light scoped builds never run the pull-kernel self-light (each eff entry carries its mask).
  5. D5 — edit-yield main-thread deferral. While a scoped edit is in flight, drain/flush/tex-refresh/normal-handoff yield to the edit handoff (priority pass ungated). Costs +42 ms on editperf total_ms (wave start deferral) in exchange for the <50 ms gate margin (handoff was stalling up to 856 ms without it).
  6. D6 — drain reserved slot. Steady-state drain cap −1 (−2 with an edit pending) so an edit always has a pool slot; threadmesh_max is still the hard cap (edit dispatch defers on cap, never bypasses it).
  7. D7 — trees-probe genhash_gate false at (2,2) = stale reference, pre-existing. AWECRAFT_LOGIC=trees compares tree-zeroed hashes against .scratch/genhash_before_trees.log (recorded Aug 18, H=80 era; generator.gd last changed Aug 30 by AC-0143). The SMOKE genhash lines are byte-identical to the AC-0164 (Aug 31) gate log, so world data is unchanged by this task; the trees probe's reference/expectations were voided by AC-0091 ("ALL OLD BASELINES VOID") and never re-recorded. Its node_*_ok / tree_sample failures are the same staleness. Not a regression of AC-0187.

D8 — probe/diagnostic residue (intentional, harness-only). _editprobe hook (1 string compare per handoff), mesh_gen/data_gen counters in chunk.gd, _prof_ring (cap 120) for the editfront probe, phet/ns in the scoped build result (timing-gated prints removed; FLUSHD/E2RQ/ERES/EPRE diagnostics all deleted after use).
