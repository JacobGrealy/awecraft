AC-0187 — priority-remesh-on-block-edit: skip the queue to the front

Goal

When a player breaks or places a block, the affected chunk remeshes immediately — it bypasses the ~7710 queued far chunks at R=50 — so the hole/appearance change lands in <50 ms with no drop and no flicker. The far-queue streaming and the AC-0182 LOD transition must not regress. The threadmesh_max in-flight cap stays enforced (no unbounded builds).

Design (5 coupled pieces — final, implemented)

  • 1. Edit-front priority queue (world.gd) — set_block stashes the chunk's last full light dict (from the eff cache, pre-eviction), pushes the chunk onto edit_front (deduped, merged slab ranges), and dispatches synchronously (in the call). A _process drain retries any cap-dropped/deferred entry before the AC-0126 light flush. The 3×3 neighbor re-light wave still runs afterwards on the existing path — geometry lands first, light converges over the next frames.
  • 2. Dedicated EditPool lane (world.gd) — the scoped edit builds run on a private 1-thread pool (Thread + Mutex + Semaphore + guard-Mutex mark_done flag), not the shared 6-worker mesh pool: no contention with the ~7710-chunk far stream, cap still enforced (threadmesh_max checked at dispatch; drops re-queue, never unbounded). A priority pass in threadmesh_poll (called from both _process and _physics_process) hands off completed edits before any other inflight entry.
  • 3. Slab-scoped fast remesh (chunk.gd) — the edit path builds only the dirty slab closure (rows (y−3)/16 … (y+1)/16, ≈ 1-3 of 24 slabs) through a build_accs row-range variant (scoped face loop with a ymask boundary-bitmask pre-pass; scoped acc allocation) and applies only those slabs (apply_edit_accs, mesh_gen bump) — untouched slabs retain their mesh (no flicker). Light: the stashed pre-edit light (stale-but-current) is validated against c.last_eff at dispatch; if the chunk was re-lit since, the fast entry drops (the wave already remeshed it). eff_trust=false so the stale light never re-enters the eff cache.
  • 4. Scoped row snapshots — the worker sees per-row data/fl slices (d_off…d_hi, ≈ 35× smaller than the full column) + 8 scoped neighbor copies; the handoff drop check compares only the scoped rows (a change outside them cannot affect the applied slabs).
  • 5. Performance pieces — (a) scoped strip memoization keyed on the 8 neighbors' data_gen/eff_gen (cap 32), with zero-filled b-channels (the pull-kernel is the only b consumer and frozen-light builds never run it — skips a ~190 ms _face_of cold miss); (b) edit-yield: while edit_inflight_count > 0 the main thread defers far-queue drain, light flush, tex refresh and non-edit handoffs, so the edit handoff lands on a short frame instead of behind a 300 ms drain burst; (c) scoped builds emit per-face quads (plain emit path) — the merge-atlas emitter measured 5-15× slower per quad and its merged runs span cells a fast build can't validate; geometry is identical, the wave's full build restores the merged mesh in 1-3 frames; (d) _s_face_light early-out at 15 (skips redundant max samples on lit faces).
  • Probe hook — chunk.mesh_gen int, incremented on every mesh apply (build_mesh / apply_accs / apply_edit_accs); the probe also reads dispatch/worker/handoff stamps off the entry for the RESULT breakdown.

Risks (final, with measured outcomes)

  • 50 ms budget — met. Measured R50: break 31.8 ms (dispatch 10.6 + worker 18 + handoff ≈3), place 39.5 ms (dispatch 0.4 + worker 37 + handoff ≈2), both with 0 drop frames. The two levers that made it fit: the scoped plain-emit (the merge-atlas emitter measured 5-15× per-quad slower — 52-143 ms on 830 quads vs ~9-22 ms plain) and the edit-yield (handoff was stalling up to 856 ms behind 300 ms+ drain bursts before the yield). Residual variance: worker emit scales with slab light complexity (9-37 ms observed); a cold strip-cache miss adds ~10-14 ms dispatch (warm: 0.4 ms).
  • Stale-light visual pop — accepted & documented: the hole appears with pre-edit light; the 3×3 wave refreshes within ~1-3 frames (AC-0126 contract). Mesh presence never drops (retain-until-swap), so the no-hole/no-flicker contract holds.
  • Scoped plain-emit mesh — the fast slab mesh uses per-face quads (not merged runs); geometry is byte-identical in shape, triangle count is higher until the wave's full build restores the merged mesh (1-3 frames). Also avoids merged runs spanning cells a scoped build cannot validate.
  • Drain cap −1 (−2 while an edit is pending) — slightly reduces far-queue throughput when saturated (5/6 slots); the R50 probe's drain is I/O-bound (inflight 0-1 at edit time) so the probe is unaffected; steady-state r4 demand (9-14 chunks/s) still fits — coordinator re-runs the heavy boundary gates.
  • Zero b-channel scoped strips — the scoped build passes zero block-face strips: the only consumer is the pull-kernel self-light, which frozen-light scoped builds never run (every eff cache entry carries its mask). Also skips a ~190 ms _face_of cold miss on the main thread.
  • flush_active bookkeeping fix — the perf-counter reset was suppressed when a burst drained to empty at section start (stale-true flush_active), which merged an earlier E2-churn burst into the editperf RESULT (94 frames / 303-715 ms counters vs the true post-edit wave of 9 dispatches). The clear now always runs when light_pending is empty; counter semantics unchanged, only the stale state removed.
  • LOD interaction (AC-0182) — an edit on a lod_pending chunk dedupes behind the in-flight LOD task (same-key inflight check) and re-queues; the stale-band BANDBREAK reroute is untouched. lodswap gate covers it.
  • Rapid re-edit — second edit before the first fast task lands: stale scoped data-snapshot drop re-triggers a fresh dispatch; the light wave always terminates the sequence with a fresh self-lit 3×3, so final state is byte-correct.
