AC-0418 — bake-exit use-after-free: workers that hold no reference to the node

Tree b5b1d5c, engine 4.7.1.stable.a13da4feb, headless, seed 5432 (non-canonical → forced bake) for the exit probes, seed 44 (canonical) for the re-bake. All runs: HOME=/tmp/dsh_home, ulimit -v 8388608, one godot at a time. Logs under .scratch/AC-0418/.

1. The defect, in code

The bake's pool tasks were methods of the SatelliteBody node: pool.add_task(_mt_shard_task.bind(_mt_g, s), true) etc. A worker thread executing one of them is inside the node's script instance. Closing the game mid-bake runs the scene-tree teardown (in Main::start finish), which frees the node and its script instance, while the pool's finalize() (in Main::cleanup) joins the workers — i.e. the worker's frame can outlive the instance. Every instance read in the frame (seed, HMAX, SEA, R, pay, …) is then a use-after-free. The shipped mitigation (static var _mt_exit_aborted + _exit_tree()) makes each worker stand down at its next boundary — but the check cadence is the whole problem: shard loops check per record (µs window, the mitigation covers it), face slices run up to 5000 ms without a check (a whole slice of exposure). The mitigation also cannot shrink the epilogue: returning from a GDScript function still runs inside the instance's VM frame.

Manifestations (both measured this ticket): hard — SIGSEGV, rc=139, backtrace on the pool thread in the worker's frame; soft — SCRIPT ERROR: Bad address index in the worker's frame (the VM catches the freed read instead of the kernel), process exits rc=0. The defect leaves a clean log until that line — the exit status (and the Bad-address scan) is the signal.

3. The fix: workers that hold no reference to the node

New plain script godot/world/satellite_bake_worker.gd (class_name SatelliteBakeWorker, statics only). Every worker task is now a static function of that script, and everything it touches travels in st — a plain Dictionary (RefCounted) the node fills in _bake_state() before enqueue and passes as a bound argument. A Callable to a static holds no object; the state is kept alive by the tasks' own bound arguments, so at process exit the node is freed and the state is not. The worker frame then holds only: its own state, the AweGen C++ handle (a C++ singleton, alive for the process — the same precedent threadgen/threadmesh already use), class statics (SphereMath, the exit flag) and engine singletons. Nothing in it is freed with the node.

The arithmetic is copied verbatim (instance reads → st reads; the node's consts travel by value, their single home stays satellite_body.gd); same values, same operation order → same bytes. The node keeps: the main-thread poll/merge/assemble (_bake_main_step_mt, now reading the state), a new thin _bake_main_step_single() collect for the OFF path, and the consume/load paths. Deleted from the instance: the per-face row-machine fields (pay, color_row, _h2/_t2/_bld_row/_out, the chunk cache _ch_cx/_ch_cz/_h16/_t16/_gx16/_gz16, _first_col, _hgrid), the worker channels (_mt_g, _mt_shard_bufs/err/ms, _mt_face_*), bake_abort (→ st["abort"]) and every worker-side function (_mt_shard_task, _mt_face_task, _bake_worker, the _step_face*/_pixel* machines, _gen_one, the offsets, _l2s/_byte, _load_png, _guard_check*, _geom_for_face_local, _mesh_grid, _hgrid_sample, _ship_faces).

The shipped mitigation stays and is exercised on both paths: every task reads SatelliteBody._mt_exit_aborted first (readable without touching anything that gets freed) and stands down at the next boundary. With the workers detached the epilogue no longer touches the node either, so the flag is now a speed/politeness measure, not a safety net — safety is the detachment.

4. After: the same exits, repeatedly

After total: 18/18 clean (before: 8/18 symptomatic — 4 hard crashes + 4 soft). The stage-2 row is the one that matters: the as-shipped tree SIGSEGV’d twice on exactly this state (face 8/12, face 9/12, the worker in _pixel_mt); with the workers detached the same exits complete cleanly — the node is freed at teardown and nothing in a worker frame is freed with it. The mitigation is still exercised: every task reads SatelliteBody._mt_exit_aborted first (the flag is set by _exit_tree on every one of these exits and stood the workers down at the next boundary; the detachment is what makes the epilogue safe). 6. Normal shutdown and shutdown during the hold

Three shutdown shapes, all measured:

  • Shutdown during the load hold / mid-bake (the defect's case): all 36 exit attempts (18 before + 18 after) quit while the bake is in WORK — stage 1: the arm observes the payload stage at its spawn (stage_wait_ms: 0 — the bake is already there) and quits ~5 s later at payload 75–83/98 (the loading-window hold had released at its 42 s budget); stage 2: the arm waits ~80 s for the face stage, then quits 5 s in with faces 8–9/12 in flight (the bake, well past the hold). After: all clean.
  • Normal shutdown (bake completes, world presented, then quit): the satexit arm's complete mode boots seed 5432, waits until phase == LOADED (the consume loop finished, the body is in the tree), then quits. Before: rc=0 (boot bake 107,638 ms). After: rc=0 (boot bake 105,114 ms; max frame hitch 11.9 s vs 16.2 s — the main thread is lighter once the merge reads the state). The teardown ordering (scene tree first, pool finalize after) is the one that used to hit the UAF; with the workers reference-free it is now a plain join.
  • Normal in-game quit (no bake in flight): the canonical seed-44 res:// path (the SMOKE battery + PROBE runs above) and G0 — all rc=0, census 0/0.

7. The AC-0403 link — tested, not assumed

Refuted as the specific cause; confirmed as the failure class. AC-0403's signal-11 ran on the canonical seed 44 → res:// path → no bake in flight (a bake only runs for non-canonical seeds / missing caches), at t≈27 s during steady-state physics, on the main thread (slab read chunk.gd:657 get_local from the player's physics step), with a clean log across 14/14 reruns. This defect needs a bake in flight, strikes on pool threads in the worker's frame, and manifests at process exit (teardown), not steady state. The two crashes are separate causes of the same class: concurrent VM use where a frame holds a node's script instance that another actor can free or race. AC-0403's remaining candidates stand (threadgen/threadmesh node methods running from pool threads the whole time + the PBA shallow-handle edge, AC-0403 §7); this ticket's scope is the bake workers, and the streaming workers keep the same exit-race class at a far lower in-flight fraction (thousands of clean arm exits bound it empirically) — a follow-up ticket.
