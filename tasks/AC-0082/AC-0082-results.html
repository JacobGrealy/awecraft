AC-0082 — Threaded chunk DATA generation (Phase 2, desktop-gated) — Results

Status: DONE (all gates pass) · Date: 2026-08-24

Design

Chunk data generation (WorldGen.generate) is moved off the main thread onto Godot 4 worker threads via WorkerThreadPool (engine singleton). The drain loop in world.gd enqueues gen tasks and polls for completion. Results are handed back as fresh PackedByteArrays; init_fl and _apply_edits_to_chunk run on the main thread after handoff.

Main thread (drain loop, per frame):
  for each gen unit in build queue:
    if chunk.data is empty AND threadgen is on AND not spawn chunk:
      threadgen_enqueue(cx, cz, key, instance_id)   # add_task to WorkerThreadPool
      return 0  # skip mesh, wait for gen to complete
    else:
      c.data = WorldGen.generate(...)               # sync (spawn chunk or threadgen off)
      c.init_fl()
      _apply_edits_to_chunk(c)
  threadgen_poll():
    for each in-flight entry:
      if WorkerThreadPool.is_task_completed(tid):
        c.data = entry.result                       # fresh PackedByteArray from worker
        c.init_fl()
        _apply_edits_to_chunk(c)

Worker thread (WorkerThreadPool worker):
  _threadgen_worker():
    entry = _tg_slots[get_caller_task_id()]
    entry.result = WorldGen.generate_args(cx, cz, seed, HEIGHT, SEA)

Boundary conditions (all satisfied)

  • 1. Pure-static generate: WorldGen.generate_args(cx, cz, seed, hmax, sea) takes all data as explicit arguments. No autoloads, no globals, no shared state. The original generate(cx, cz, seed) is a thin wrapper that passes Data.HEIGHT and Data.SEA. PASS
  • 2. Fresh arrays: Worker allocates its own PackedByteArray via generate_args. Main copies it into chunk.data in threadgen_handoff. No shared buffers. PASS
  • 3. Main-thread init_fl + _apply_edits: Both run in threadgen_handoff (main thread, called from threadgen_poll in the drain). PASS
  • 4. In-flight cap ≤ 6: threadgen_enqueue checks threadgen_inflight.size() >= threadgen_max (default 3, max 6). PASS

Correctness invariants

  • AC-0080 hysteresis safety: threadgen_handoff checks chunks.get(key) and is_instance_valid before writing. If the chunk was freed/recreated, the result is dropped cleanly. PASS
  • Determinism: Genhash parity (G2) proves byte-identical output. PASS
  • Web path: OS.has_feature("web_nothreads") gate at world.gd:86 disables threadgen on web. PASS

G3 Fix — root cause and resolution

Root cause: threadgen_enqueue had no deduplication. Multiple call sites (_chunk_data at the inst=-1 path, _gen_unit at the inst=instance_id path, and recenter→threadgen_poll handoff) could enqueue the same chunk key more than once. Each duplicate created a separate worker task and a separate entry in threadgen_inflight. When the cap (threadgen_max) was reached, threadgen_enqueue silently dropped new requests. The critical failure path: _chunk_data (called from get_block during surface_top/spawn_point) enqueued an async task for a chunk, then immediately called create_chunk which did a synchronous WorldGen.generate for the same chunk. The sync gen set c.data. Later, when the async task completed, threadgen_handoff saw c.data.size() != 0 and returned — harmless. But the duplicate entries consumed cap slots, and in edge cases the interplay between the drain's sequential processing and the async handoff timing caused a chunk's data to never be seen by the mesh phase, leaving _await_spawn_floor (which waits for mesh_built) to time out.

Fix: Added a _tg_inflight_keys dictionary to world.gd that tracks which chunk keys currently have an in-flight task. threadgen_enqueue checks this dict first and returns immediately (incrementing _tg_dedup) if the key is already in-flight. The dict is populated on enqueue and cleared on handoff (in threadgen_poll). This ensures each chunk key has at most one task in the pool at a time, eliminating the cap-slot waste and the handoff race.

Files changed: godot/world/world.gd — added _tg_inflight_keys dict + 6 counters, dedup check in threadgen_enqueue, cleanup in threadgen_poll, outcome tracking in threadgen_handoff, AWECRAFT_TGDEBUG env for debug prints.

Debug instrumentation: AWECRAFT_TGDEBUG=1 enables per-event prints (ENQ, CAPDROP, STALE, DATADROP, GENHAND). Counters (_tg_enq, _tg_dedup, _tg_capdrop, _tg_handoff, _tg_stale, _tg_datadrop) are always tracked (zero cost) and available for future diagnostics.

Deviations / known limits

  • Spawn chunk (cx=0, cz=0) generates synchronously even with threadgen=1: the player needs immediate ground data. _gen_unit checks absi(cx) > 0 and absi(cz) > 0 before enqueuing to thread. Chunks with cx==0 OR cz==0 (but not both) are also synchronous — existing Phase-1 behavior.
  • Godot 4.7.1 WorkerThreadPool API: Task.create/Task.run are not available (parse error). Used Engine.get_singleton("WorkerThreadPool") + add_task/is_task_completed + get_caller_task_id instead. Per-thread args passed via _tg_slots dictionary keyed by task ID.
  • AWECRAFT_TGDEBUG=1 enables per-event debug prints (TGEN ENQ/CAPDROP/STALE/DATADROP + GENHAND). Counters (_tg_enq, _tg_dedup, _tg_capdrop, _tg_handoff, _tg_stale, _tg_datadrop) always tracked (zero cost). Kept for future diagnostics.
