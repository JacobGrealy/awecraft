AC-0082 — Threaded chunk DATA generation (Phase 2, desktop-gated)

Status: open (priority 1) · Source: user order 2026-08-23 "do the multi threaded chunk management task next" · Parent: AC-0034 (chunk streaming) · Plan: AC-0071 Phase 2 (tasks/AC-0071/AC-0071-plan.html) · Prereqs landed: Phase 1 = AC-0075/0076/0080 (budgeted main-thread streaming + hysteresis) — done.

Goal: move chunk data generation (WorldGen.generate — the ~0.03–0.7 s/chunk terrain/cave/ore computation) off the main thread onto a worker pool, so desktop walk/recenter frames no longer pay gen cost. Mesh/face-scan, lighting, and the web export stay exactly as they are (rejected-by-plan — do NOT thread them).

Requirement

  • Generate chunk data (world/generator.gd WorldGen.generate) on Godot 4 worker threads (Task/WorkerThreadPool), triggered from the existing drain loop in world/world.gd where data-gen currently runs on the main thread.
  • Desktop-gated. Threaded path active only when not OS.has_feature("web") AND AWECRAFT_THREADGEN is not "0" (on-by-default desktop; =0 ⇒ byte-exact Phase-1 single-thread behavior). Optional AWECRAFT_THREADGEN_N = worker pool size (default mini(cores-2, 3)).

Boundary conditions (ALL must hold — code-review gate)

  1. Workers touch ONLY WorldGen.generate. It must be pure-static: no nodes, no autoloads/globals, no shared mutable state — in particular no shared PackedByteArray between tasks. If generate currently reads autoload state or module globals, refactor it to receive everything as explicit arguments (seed, chunk coords, and any data needed), keeping its output byte-identical.
  2. Results hand back to main as freshly-allocated arrays (worker allocates its own PackedByteArrays; main copies/moves them into chunk.data in the existing drain data-unit region). No worker keeps a reference into shared buffers.
  3. init_fl + _apply_edits_to_chunk run on the MAIN thread after handoff (fluid init + AC-0062 edit-delta re-apply must never run in a worker).
  4. In-flight generation cap ≤ 6 chunks (queue depth for the worker pool).

Correctness invariants (hard)

  • AC-0080 hysteresis safety: a chunk may be freed/candidated between enqueue and handoff ⇒ on handoff, if the target chunk no longer exists (or is a different object), drop the result cleanly (free the arrays, no use-after-free, no crash). No re-queue needed; the region policy will re-request if still wanted.
  • Determinism: terrain output is a pure function of (seed, coords) — threaded runs must be byte-identical to single-thread (genhash gate below proves it).
  • Web path: thread code must be unreachable on web (the OS.has_feature("web") gate); web behavior stays byte-identical single-thread Phase-1.

Verification gates (hard)

G1 Headless load with ZERO script errors under both AWECRAFT_THREADGEN=0 and =1: ~/tools/godot/godot --headless --path godot --quit (check stderr, not just exit code).
G2 Genhash parity: AWECRAFT_LOGIC=genhash with AWECRAFT_THREADGEN=0 vs =1 → MD5 identical (the 25/25 set + extra seeds 999/424242 — check the harness envs in main.gd). This proves data-gen output is unchanged.
G3 Full logic battery with threadgen ON (desktop): AWECRAFT_LOGIC=player|interact|light|fluids|buckets each exit 0, sane RESULT, 0 script errors; fluids sea stays 2730/1406 sea_stable (AC-0062 edits + fluid init still main-thread).
G4 Perf A/B (desktop, headless perf harness from AC-0075/0076 — AWECRAFT_LOGIC=perf + AWECRAFT_TIMING=1 with the existing caps): at r=4 AND r=50, AWECRAFT_THREADGEN=0 vs =1 → expect gen ms to disappear from walk/recenter frames on the =1 side (recenter/first_draw/walk p95 table before/after in results). Keep r=50 runs capped per the existing harness caps; do not let a run exceed ~15 min each.
G5 Web path: grep-proof that the thread path is unreachable on web (the gate check) + AWECRAFT_THREADGEN=0 behavior = Phase-1 behavior (G2/G3 with =0 must also pass).
G6 Builds (coordinator runs ./build_web.sh + ./build_windows.sh after the subagent; both must exit 0; web export = single-thread behavior).

Scope (files expected to change)

  • godot/world/generator.gd — WorldGen.generate pure-static refactor (arguments in, fresh arrays out) if needed.
  • world/world.gd — drain loop: enqueue data-gen tasks (cap ≤6), main-thread handoff into chunk.data + init_fl/_apply_edits_to_chunk on main; hysteresis-safe drop on stale handoff.
  • scenes/main.gd — AWECRAFT_THREADGEN / AWECRAFT_THREADGEN_N env parse (pass through to world).
  • NO UI changes. NO mesh/lighting changes. NO web-export changes.
