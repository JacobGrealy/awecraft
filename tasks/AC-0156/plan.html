AC-0156 — plan: light-cache-per-section

Goal

Embed the column's light (the eff channel + the block-light mask — the exact channels the renderer consumes) into the per-column AWCC blob so a revisited column loads its light instantly with zero kernel recompute; legacy v1 blobs (no light) still decode and recompute as today; Save.clear wipes light together with blocks. Per-column data-format change only — AC-0175's region-file layout change reads/writes through the same encode_column/decode_column and preserves the light automatically.

What is saved (honest scope note)

The engine's light kernel returns one merged channel the renderer consumes: eff = max(sky, blk) per cell (0–15), plus a 0/1 mask ("visited by the block-light flood") that drives the AC-0134 face-mask bake. Separate sky/blk channels are kernel-internal and are never persisted anywhere today. So the blob carries eff + mask — the same channels the renderer consumes — nibble-packed per 16³ section (4096 nibbles/section/channel = 2048 B/section/channel; ~96 KB uncompressed per column, zlib → tiny). Neighbor-dependency: block light crosses column borders; the saved eff/mask are a consistent snapshot taken with the saved block data (same blob). A neighbor edit after save is reconciled by the existing edit-time recompute (E2 _eff_landed wave re-bakes the affected column fresh and the next save captures the update). A save-time pending re-light mark suppresses the capture (falls back to recompute-on-load) so a pre-settle light is never persisted.

Risks

  • Mask availability at save: the mask is transient (never pinned per-chunk — memory fence r50). Source = the bounded eff cache (cap 128, LRU) at evict time; typical r≤4 streaming sets (≤69 chunks) always hit; a cache miss (or pending re-light) degrades gracefully to "no light saved" → recompute on load (today's behavior, never wrong).
  • Deferred builds must not lose the saved light: saved_light is consumed only at apply points, not at dispatch, so cap-drop deferrals / dedup retries keep feeding it; freed chunks drop it with the node.
  • Edit staleness: re-applied JSON edits that actually change a cell invalidate saved_light (recompute); idempotent re-apply (AC-0155: file is ≥ edits) preserves it.
  • E2 settle wave on revisit: a restored chunk's own settle re-bakes neighbors (byte-identical, no cascade via the per-side frame gate); the target's own counter stays 0 in the isolated revisit. A neighbor edited after its region save is the documented Minecraft-class staleness, healed by the existing edit-time recompute.
  • AC-0175 forward-compat: only the per-column blob changes; region grouping later reuses the same codec → light preserved with zero further work.
