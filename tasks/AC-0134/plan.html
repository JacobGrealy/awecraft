4.4 What the "fully lit at night" visual most plausibly is

On a chunk_lit material at midnight, only g-channel faces (mask=1, block-light visited) stay bright: L = 0.12 + 0.88·s (web :746). The mask is the pull kernel's block-flood visited set (lighting.gd:334-357) seeded from OWN glow sources (ids 22/23/24) + the neighbor's last_blk_ring (block-only, world.gd:997-1003/:1047-1050) — sky can never enter it. So a bright-with-no-source face would be a genuine mask/ring defect — and the probe's bright_no_source check is built to catch exactly that (expected 0; the ring gap at world.gd:1001-1003 only UNDER-marks). The other explanation is the legitimate one: lava is a light source the user may not see. Cave space below y=8 is lava — port generator.gd :269 (verbatim) data[ci] = B_LAVA if yc < 8 else 0 = web :828 data[i]=(y<8)?24:0 — and the lava sea (light 15) floods up shafts and laterally: y=8→14, y=9→13, …, y=21→1. Any cave at y≤21 (or within 14 of a lava pocket) is legitimately night-bright with its source out of sight below — "no light source for either". The nightlot probe records, for every block-lit sealed cell, the nearest glow source distance (Chebyshev, own data + neighbor rings), so the user's world can be classified: bright + source ≤14 = correct MC behavior; bright + no source = real defect → new task.

Root-cause verdict: (a) CONFIRMED — the eff build-order lottery via the sky-carry strip (world.gd:1044-1045) + E2 blk-only gate (world.gd:1101-1102) + recenter re-roll (world.gd:1303-1324): sealed-cave cell eff = 0 or ≤14 by neighborhood landing order; face light alternates 15/0 where the cave meets open sky. (b) EXCLUDED as a per-chunk mechanism (path-independent _get_mat, §4.3) — guarded by per-chunk material enumeration in the probe. The "fully lit" night visual is most plausibly legitimate lava g-channel light (§4.4) — the probe discriminates in the user's world.
