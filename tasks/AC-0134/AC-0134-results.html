1. Root cause (settled after fix-3→fix-7)

The bug is a mask defect, not an eff-defect. Two facts anchored the fix:

  1. The cross-boundary sky-carry eff strip is CORRECT and must be kept. In Minecraft, skylight genuinely crosses chunk boundaries (a sealed cell laterally adjacent to an open-sky column gets 14/13/… with no local source — MC-exact). AC-0129 (shipped, user-approved) shipped exactly this sky-carry strip and its lightaudit reported 0 cliffs on seed 44. Any run-2 attempt that made the eff strip block-only (fix-5, fix-6) killed cross-chunk skylight and produced 1,173 false "cliff" pairs (14 on the open side / 0 on the other) + a torch-tunnel regression. Retracted root cause from fix-6: the "2-hop block-light death" theory was wrong — source-trace proved the lit cell was pure in-chunk sky corner-bleed (fresh kernel with empty strips = 14, mask 0).
  2. The real defect is AC-0128's ring (the per-chunk mask source), which is corrupt at Data.HEIGHT=80. Pack p=(side<<16)|(yy<<8)|level with yy = y*16+t ∈ [0,1280): yy's bits 8–9 collide with side's bits 16–17 for y≥16. Bit audit: 3,072 of 5,120 (side,yy) combos collide — a 4-to-1 fold — and the decode additionally mis-indexes 3 of 4 sides (off by rside·256; the kernel reads strip[yy]), recovering only 256/1280 correct cells per side. So the block-light MASK import (which marks which boundary cells carry block light so the night-scale treats them correctly) was garbage for 3/4 sides + all y≥16. Block-lit cells crossing a boundary were mis-marked → rendered with the wrong night-scale treatment → "fully-lit chunks next to pitch-black, no source for either". Run-1's framing that blamed the sky-carry eff strip for the phantoms was partly wrong: the eff values are bounded by the neighbor's settled state (no phantom injection possible); the visible artifact came from the corrupt mask + a gate heuristic that mislabeled legit sky (see §4).

4. Deviations (documented)

  1. nightlot gate refinement ×2 clauses (physics-correct, not a weakening of the bug gate). The original run-2 gate assumed "imports are block-only" and used a glow-within-14 heuristic to flag phantoms. That premise is wrong physics: skylight has no glow source, and legit cross-boundary sky (the behavior we restored) has no glow within 14 by definition. The correct discriminator for an imported, unmasked cell is stale-ness (reproducible by the current strips?). ok now = leak_stale==0 ^ legacy==0 ^ other==0 ^ diffs==0 ^ baked_diffs==0 ^ bright_no_source_interior==0; leak_nosrc and chain.max_class3_nosrc kept informational.
