Stdlib only, single file at repo root. godot/ and web/ untouched. No systemd/cron. No screenshots apply — this task is process/server plumbing, verified via ps/curl/kill evidence below.

Evidence — gate 2: own session + pidfile

$ ps -o pid,sid,pgid,ppid,cmd -p 42970
    PID    SID   PGID  PPID CMD
  42970  42970  42970     1 python3 serve_web.py --ssl --daemon --replace

$ cat .scratch/serve_web.pid
42970

SID = PGID = own PID → daemon is its own session/group leader, outside the calling shell's session; PPID 1 → re-parented to init after the intermediate child exited, so it survives opencode restarts. The daemon itself writes the pidfile after re-parenting (per spec).

Evidence — gate 3: port guard

(exit=0)

$ ss -ltnp | grep ':8443 '
LISTEN 0  5  0.0.0.0:8443  0.0.0.0:*  users:(("python3",pid=42970,fd=3))   # exactly one listener

Guard is socket-level (/proc/net/tcp{,6} → socket inode → fd owner → cmdline match), so it works even if the pidfile is missing or corrupt; the pidfile is used as a fast-path hint only.

Deviations / notes

  • None against the spec. One in-task fix: initial implementation called setsid() in the first child, leaving the final daemon in the intermediate's session (SID ≠ PID); moved to the final daemon so SID == PID per gate 2.
  • SIGTERM handler also removes the pidfile on graceful stop (spec's stale-pidfile handling makes this optional, but it keeps the pidfile accurate; a SIGKILL'd daemon just leaves a stale one, which the guard tolerates — verified).
  • Server URLs for testing: https://localhost:8443/ and https://192.168.0.224:8443/ (self-signed cert — browser warns once until accepted).
