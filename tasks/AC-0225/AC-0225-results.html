AC-0225 — configurable-chunks-mesh-per-frame-slider-1-to-100

What it does: a new Options slider “Chunk meshes per frame” (HSlider 1–100, label + value readout, between Flight speed and Resolution) sets Settings.chunks_per_frame (default 3 = the shipped AC-0224 cap, clamped 1–100, saved to user://awecraft.cfg). The AC-0224 drain cap (world.gd stream_ho_cap) now reads that setting every process frame in threadmesh_poll, so a mid-session slider change lands next frame. The AWECRAFT_TM_HO harness env still works — it now preloads the same setting at boot (clamped 1–100, no save, so the harness never clobbers the user cfg). Higher slider = more chunk meshes hand off per frame = chunks appear faster while flying; lower = smoother frame times.

Files: godot/autoload/settings.gd (setting + clamp + save), godot/scenes/menu.tscn (ChunkRow: label + HSlider 1–100 + value), godot/ui/menu.gd (node refs, sync, _on_chunk_changed handler, OPTSYNC line), godot/world/world.gd (per-frame cap read; env preloads setting), godot/scenes/main.gd (settings-test chunks block; R16 ho_cap field; _StubWorld no-op note_render_distance — pre-existing SCRIPT-ERROR fix in the test stub), tasks/HARNESS.md (env-knob + r16 field docs). GDScript only — no C++ touched, no rebuild.

Reading: higher slider → chunks appear faster — the r16 all-meshed build collapses 37.2 s → 13.5 s (2.8×) going 1→3, then hits the C++ build-pipeline ceiling (≈13 s at 10/50/100); at cap 1 and 3 the cap is the binding constraint (ho_max == cap), above that the worker feed (~5 ready meshes/frame) is. The low-cap cost is visible in the frames: at cap 1 the drain tail still streams during the static phase (p95 29 fps, max frame 57 ms) vs 143 fps / 20 ms at cap ≥10 — the smoothness side of the knob. fps_p50 is 200 (uncapped --fixed-fps 600 headroom) in all runs; queue depth (136/65) and ahead-while-moving (279/58) are cap-independent — the cap paces when ready meshes land, never how many build. Fly-phase inner fps (the actual flying frames): fly4 p95 59/63/59/63/63 and fly50 p95 40/42/42/42/42 (cap 1/3/10/50/100) — no lost chunks (0/0) and identical recenter counts (9/27) at every cap, matching AC-0224's fly-phase numbers (63/40): the cap changes landing pace, not worst-case flight fps.
