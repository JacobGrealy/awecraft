AC-0067 — Hand / held item must ALWAYS render on top of the environment

User 2026-08-21: "the hand / anything held in hand should always render on top of the enviroment (ie the block you are holding should not be obscured by the enviroment)." This is the classic MC-style viewmodel: the held item is never occluded/clipped by nearby blocks, even when your face is against a wall.

Current state (coordinator-read, player.gd)

The viewmodel is a set of children under hand_root (→ sway_root → camera), all standard depth-tested, so a nearby block can hide/clip them:

  • held_box (:365-370) — MeshInstance3D, holds solid-block box AND cross-item meshes; material via HeldMeshes.box_material() / HeldMeshes.cross_material() (set in _update_held :412-416). Initial material_override is a plain StandardMaterial3D.
  • held_sprite (:371-376) — a Sprite3D (billboard) used for non-tool ITEMS (100+); texture from item atlas or tint (:426-431).
  • held_fist (:377-387) — MeshInstance3D, fmat = unshaded StandardMaterial3D.
  • held_tool (:392-394) — Node3D; each voxel child is a MeshInstance3D with material_override = _voxel_mat(color) (a StandardMaterial3D, :490) — set up in _setup_held_tool (:504-523).

No depth_draw_mode usage exists anywhere yet.

Requirement

  • Make the entire viewmodel (held block, held cross, held fist, held tool voxels, AND held-item Sprite3D) render with depth testing disabled (StandardMaterial3D.depth_draw_mode = DEPTH_DRAW_DISABLED) so it is never obscured by world geometry. This is the fix; do not reposition/resize/light the viewmodel (position/scale are already correct from AC-0060/0066; lighting of the held item = AC-0035, out of scope here).
  • Apply to EVERY viewmodel material path: HeldMeshes.box_material(), HeldMeshes.cross_material(), the initial held_box.material_override, held_fist fmat, and _voxel_mat() (so all tool voxels get it). Best place for the shared ones: set depth-disabled once where those materials are created (HeldMeshes and _voxel_mat), so it's not repeated per-frame.
  • Sprite3D (the tricky one): first VERIFY whether Godot 4.7 Sprite3D exposes a material_override (check docs or a 2-line headless probe). If yes: set its depth_draw_mode = DEPTH_DRAW_DISABLED. If no: convert the held-item sprite to a billboarded quad — a MeshInstance3D with a small quad/plane mesh (or a QuadMesh) whose material_override is a StandardMaterial3D with the item texture (reuse the exact atlas/tint selection logic at :426-431), set to billboard (use the same orientation the Sprite3D had — a camera-facing quad; simplest is a PlaneMesh rotated to face the camera, or keep a Sprite3D but drive depth via whatever API exists). The item MUST still show the correct icon and stay on top. Document whichever path you took.
  • Keep: hand sway (AC-0060) and swing (AC-0048) — everything under hand_root keeps animating. Keep the fist/tool/block item routing in _update_held. No change to the world/chunk rendering.
