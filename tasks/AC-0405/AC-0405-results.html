1. Technique + reference followed

The user's directive: “I think you just need to rethink clouds. look at how voluminous clouds are done and implement them, forget how we currently do it.” The structural reason four rounds of patterned-surface work (AC-0385, AC-0384 r6–r10, AC-0401) failed: a single surface at a single radius has no parallax and no internal depth — the pattern can only sit ON the shell. The rework is structural: the pattern becomes a density field and the surface becomes a volume.

  • Reference read (per the ticket): godotshaders.com “Volumetric Raymarched (animated) Clouds v2” — followed for the structure: slab/sphere intersection to bound the march, count-based steps (fixed step count, step length = chord/count → distance-adaptive), Beer-law transmittance, phase-function scattering. (The Wayback copy is a partial fetch; the slab+count-step+phase skeleton is what was followed, verified against the Guerrilla model below.)
  • Guerrilla HZD ARTR talk (the lighting model): light each sample with a short march TOWARD THE SUN through the same field (self-shadow — a top sample's march exits the cloud → lit, an underside's stays inside → dark), a Henyey–Greenstein phase, and a powder/dark-edge term so camera-facing boundaries don't read as grey mush.

Implementation (all in godot/core/cloud_layer.gdshader, behind u_vol; the entry sits in fragment() — measured: the dummy parser resolves the fragment builtins + discard in fragment() only, and return is forbidden there, so if/else):

  • The fragment raymarches the annulus [R+275, R+400] about (0,−R,0) — the SAME verified shell extent; geometry/radii/centre untouched. View-ray segments from the sphere-quadratic roots: up to 2 (near-side + far-side of the limb). One-hemisphere rule (camera outside → front face; inside → NEAR face) so each pixel is marched exactly once (no double-blend).
  • 24 view steps per segment, count-based (a 1700 m limb chord gets ~70 m steps, a 139 m interior path ~6 m) — distance-adaptive by construction, which is also the grain gate (the r5 near-disc static cannot happen: at distance the march over-integrates the fine octaves instead of aliasing them).
  • Density = 3-octave FBM (the same ahash/anv noise) in planet-frame unit-sphere coords (|q| NOT renormalised → the field genuinely varies through the layer thickness), with the exact AC-0401 window chain (u_deck-parameterised, byte-identical constants) and the same latitude banding — so the 3-D field is the same weather, now volumetric. A radial gate confines the field to the annulus (measured defect #1 without it: the FBM filled all space, the light march never exited the “cloud”, and the whole deck read as one dark storm band).
  • Per-sample lighting: a 6-tap, 1-octave coarse march toward the sun (80 m steps, early exit at optical depth 3) = the self-shadow; a Henyey–Greenstein phase (g=0.65), peak-normalised (the raw peak is ~13× — unnormalised it saturates every lit sample to flat white, defect #2), in-scatter angle dot(sun, −rd) (defect #3: sign); a 1-tap dark-edge term (density drop toward the camera; suppressed when the sun lights the visible face, kept on backlit silhouettes — the HZD powder role).
  • Beer accumulation with T<0.004 early exit; ALPHA = 1−T (soft silhouette — also retires the D2 crisp deck edge); ALBEDO = tint·u_day·clamp(2.5·L + 0.30·Lo, 0, 1.25); the same u_srgb_pre pow(2.2) convention as the unshaded path.

Switch: cloud_volume (Settings + Options row “Clouds: raymarched volume (real depth)”), DEFAULT ON (the rework was ordered; modern_light/cloud_deck precedent), env AWECRAFT_CLOUDVOL=0|1. Pushed through the existing world._ac0401_push() seam (change-gated; the outer max-h shell carries the march, the two inner shells' visible is false while ON — node visibility only, geometry untouched; restored when OFF). OFF = the exact AC-0401 three-shell path: the shader short-circuits on u_vol < 0.5 before any volume work, and the fall-through body was verified byte-identical to the pre-AC-0405 shader (difflib over the whole fragment body + vertex/fog/ahash/anv/fbm).

8. Deliberate non-actions (and honest findings)

  • Heavy gate set not run (farab / ladder / meshprobe / halo / lightstate / r16 / boundary r50 / full battery / shaderforce) — the coordinator's job per the ticket; this change is rendering-only (genhash 25/25 proves it), and the Forward+ shader is exercised by the 5 render runs (the dummy-parser path by G0). shaderforce (force-compiles every shipped shader on Forward+) will double-verify the volume path on the coordinator's run.
  • Shell geometry untouched: radii 4275/4330/4400 about (0,−R,0), centre, node transforms — the volume reuses the verified annulus extent; only node visible toggles (inner shells hidden while ON).
  • Fence files untouched: main.gd / game.gd / drop.gd / debug.gd needed no changes — main.gd already pushes every per-frame uniform the volume reuses (u_sun/u_day/u_cloud_time/u_drift/u_scale3/ u_center/u_phase/u_coverage/u_cloud_tint/u_srgb_pre); only u_vol + the radii ride world.gd.
  • No C++ changes (ticket constraint).
  • No re-baselines owed: OFF is byte-identical to AC-0401 (proven), the boundary A/B shows no streaming movement, genhash 25/25.
  • Interior/underside darkness (documented, not tuned away): a chord that starts inside or below the deck reads dark (the 300 m frame's near layer, the 120 m ceiling) — the in-scatter L is ~0 there (the light march stays inside the gate) and the single- direction out-scatter (gain 0.30) is a faint fill. Real NMS/Minecraft interiors are brighter; the obvious next lever (if the user wants it) is a small per-sample diffuse fill term (∝ local density × step optical depth) — a bounded one-line addition, not shipped here to avoid an un-tunable aesthetic iteration on the proxy renderer.
  • Faint horizontal moiré in the 120/300 m sky (visible on the llvmpipe proxy): step quantisation on near-horizontal rays through the coarse field — cosmetic at this altitude class, named for the record.

9. Durable rules discovered (for closeout harvest)

  • Godot 4.7.1 dummy-parser limits (measured by G0, all on a shader that compiles on Forward+): (1) fragment builtins (CAMERA_POSITION_WORLD) and discard resolve only inside fragment() — a nested entry helper fails with “Unknown identifier”; (2) return is forbidden in fragment() (“Using 'return' in the 'fragment' processor function is incorrect”) — use if/else; (3) no forward declarations — helpers must be defined before use (a later-defined function used early = “No matching function found”). Practical consequence: any future volume/sky shader entry goes inline in fragment() with builtin-free value-returning helpers.
  • Confine the field you light: a volumetric density that fills all of space (self-marches into its own continuation) reads as one dark storm band — the radial gate (confine to the slab/annulus) is what lets a light march EXIT the cloud and produce lit-top/dark-underside contrast.
  • Normalise the HG phase by its peak before linear gains (~13× at g=0.65): unnormalised, every lit sample saturates to white and the core/underside gradient erases.
  • Battery runs must NOT take --quit (the battery self-quits; --quit kills the process after frame 1 — zero RESULT lines, silent rc=0. The HARNESS.md §4 recipe is as written: no --quit.)
