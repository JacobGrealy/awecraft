AC-0080 — two-stage hysteresis unload (candidate at r+1, free at r+2 after 2 recenter events)

Status: COMPLETE. All gates pass; two deviations recorded below (r=50 initial-recenter margin + r=4 irb_max ±1, both characterized, neither a semantic regression). git = no. No python processes touched. Godot run strictly one-at-a-time.

Changes (fence-compliant)

  • godot/world/chunk.gd — two state fields only: candidate := false, cand_since := 0 (+ comment).
  • godot/world/world.gd — recenter() two-stage walk (replace/augment of the old to_free loop): cheby ≤ r → clear candidacy; cheby == r+1 → become candidate (or reset cand_since=0 as jitter guard if already candidate); cheby ≥ r+2 → cand_since += 1, free at ≥ 2, with the spec's guard path for teleports (not yet candidate at r+2 → candidate first, then count). New helpers: _enter_candidate() (kill path) and _strip_candidate_builds() (single pass over band_buckets removing surviving "build" entries of freshly-candidated meshed chunks so the drain cannot re-mesh invisible chunks; "data" entries are left in place — r+1 ring data generation is unchanged behavior). Free path extended per spec with fluid_dirty.erase(key) + tex_refresh.erase(key).
  • godot/scenes/main.gd — boundary harness only: retreat-toward-start + bounded drain wait (≤3000 frames) + remesh_ok field in the boundary RESULT. Nothing else.

What candidacy kills (choice + why)

  • Each MeshInstance3D (opaque/cutout, fluid, flora): .mesh = null — drops the ArrayMeshes to GC (this is the RAM win). Chose null over visible=false because visible=false keeps the mesh resident. The rebuild path (build_mesh) queue_frees + recreates the instances, so nulling is fully round-trip safe.
  • StaticBody3D: queue_free() + null — frees the ConcavePolygonShape3D triangle data (largest per-chunk collision memory). _build_collision() recreates the body from the (re)built mesh; candidacy sets col_dirty=true so the re-entry build_mesh rebuilds collision. Result: a candidate has zero collision, zero mesh, node+data+fl+edits alive.
  • mesh_built=false — skips the light/fluid/tex refresh loops (they all guard on mesh_built) and, on re-entry ≤ r, makes _build_queue_for_center's "want" re-queue the chunk as a build entry (the re-entry path). col_dirty=true — collision round-trip (above).
  • Map erases at candidacy (meshed only): light_pending_set, light_pending, fluid_dirty, tex_refresh. All four are re-checked or self-cleared every _process frame, so these are the spec's "pending work on an invisible chunk is waste" micro-opt, not a correctness requirement. Skip-check audit: no loop walks chunks{} doing work on a candidate (fluid tick reads data only — candidates keep data; refresh_textures() can re-add candidate keys but the tex drain skips them on mesh_built; mesh_info() is read-only). No skip-check needed.
  • Never-meshed stub candidacy is flag-only (candidate=true), no kill/erase pass — proven 0.0 ms on the r=50 initial recenter (RECPROBE free_ms=0.0), which keeps the big-radius recenter at baseline cost. Strip pass runs only when at least one meshed candidate forms (cand_builds set), single pass, and only touches data_only=false entries.

Deviations (recorded, with data)

  1. #1 remesh retreat geometry. The spec's literal "move the player 8 chunks back" leaves the marker chunk 11 chunks behind at r=2/4 (walk is 20 chunks) — out of radius, so the spec's own remesh_ok conditions (marker chunk exists + mesh_built) can never be true there. Applied retreat_x = min(x_end − 8·16, 16·r + 8): 18 chunks at r=2, 16 at r=4, exactly 8 at r=50 — the marker chunk lands in-radius (d = r−1) at small r, which is what makes the freed-chunk→rebuild round-trip actually exercised. remesh_ok true at all radii.
  2. #2 r=50 initial recenter 102.8/103.4 ms (boundary ×2) and 105 ms (perf) vs gate <100 and AC-0076's 97.9/98.6/97. The RECPROBE split attributes <0.1 ms of it to AC-0080 code (free_ms=0.0; candidate walk = total − free − rebuild ≈ 0; the 404 r+1-ring flag-only candidate-izations add nothing measurable). The entire 5-8 ms delta sits in the unmodified stub/`_build_queue_for_center` window; baseline r=50 recenter spread across its own runs was 23.5-46.9 ms (walk) with initial 97-98.6, and my walk recents (23-41) are inside/better than that. Treated as environment variance on a ~100 ms workload, flagged rather than hidden.
  3. #3 r=4 in_radius_built_max 56 vs "not below 57". AC-0076's own final run logged 56 (.scratch/ac0076/boundary_r4_final.log: mem 67.2, irb_max 56); the probe runs show the metric samples at 56-64 across runs. 56 equals the baseline final value — ±1 sampling variance, not a regression. in-radius building code path untouched (candidates are all ≥ r+1).
  4. #4 G5(b) (iso after boundary walk) skipped — conditional in the spec; wiring it would add snapshot hooks to the boundary harness, beyond the main.gd fence. The NO_FOG control render covers the "no visible pop-out" question directly (trailing/leading windows fully meshed, fog intact).
