AC-0471 — per-axis cell counts, so every block is 1 m × 1 m × 1 m

Coordinator contract. High-effort builder applies it with tasks/templates/implement.md. The user's constraint is fixed: blocks are ~1 m cubes. Today faces 4–7 are 1.000 × 1.000 × 0.500 m and faces 8–11 are 0.500 × 1.000 × 1.000 m, because face_cell_scale halves the width of one axis instead of halving that axis's CELL COUNT.

1. The fix in one sentence

The halved axis must span its half-width with HALF the cells (3,141 not 6,283) rather than the same cells at half the size. Then both axes have 1.000 m cells and the blocks are cubes.

2. Measured today (round 45, do not re-derive)

  • Nominal S = face_width / CELLS_PER_FACE = 6283.2 / 6283 = 1.0000 m.
  • face_cell_scale (sphere_math.gd:450-454): faces 4–7 → (s, s*0.5); every other chart face → (s*0.5, s); faces 0–3 → (s, s) (already correct).
  • Each chart face covers HALF a cube face along its halved axis — that is why the halving exists at all, and it stays: only the MECHANISM changes, from half-size cells to half-count cells.
  • Consequence to be removed: the z-face u chart currently satisfies 6,283 cells × 0.500 m = 3,141.6 m = hw, so the geometry is consistent and only the block shape is wrong.

4. Edit shape

  • 4.1 Census first, by class. Reuse the AC-0469 stage-A discipline: list every CELLS_PER_FACE/6283 site as GRID (cell count / index / clamp), PAYLOAD (bytes — untouched), or OTHER. The list is the deliverable that proves the formats did not move.
  • 4.2 One source of truth per language. GDScript: cells_u(face)/cells_v(face) returning 6,283 or 3,141 by the existing halving rule; everything else derives from them. C++: the same two functions. No second copy of the numbers.
  • 4.3 Keep the chart geometry identical. The halved axis still spans hw; what changes is that it does so in 3,141 cells of 1.000 m instead of 6,283 of 0.500 m. A point's world position must be unchanged for the same (u,v) — verify with the existing probes rather than by eye.
  • 4.4 Rebuild both binaries (Linux .so; report the Windows .dll status — the working SCons recipe is in the AC-0469 deviations).

6. Acceptance

Every face reports 1.000 m on both axes, the world runs and stays bounded, the formats are provably untouched, and the rebase is declared rather than hidden.

7. Risks

Index arithmetic that assumed one count for both axes will silently wrap or clamp at the wrong bound — the GRID census and the cubic-cell report are the guards. The prestream window (AC-0470) may partly fix itself as a side effect; if it does, say so and leave AC-0470's remaining work explicit rather than claiming that ticket done.
