AC-0382 — the satellite bake off the main thread, and the terminator that moves

Shared ticket (no TASKS.yaml edits). The two AC-0310 debts plus one recording: (a) the runtime satellite bake leaves the main thread, (b) the body's shading tracks the world's actual sun, (c) the sub-pixel disc cull is recorded as a visual no-op. All runs headless, ulimit -v 8388608, one engine at a time, logs in .scratch/AC-0382-gates/. Values, not prose.

1. (a) The bake is off-thread — what it took, and why no C++ task type was owed

Route: the whole bake pipeline on one WorkerThreadPool slot (the same engine singleton the thread-gen and thread-mesh lanes use, LOW priority so the streaming HIGH tasks are never starved), launched from SatelliteBody._start_bake(). The worker (_bake_worker) runs, in order: generate_far × 196,196 (the same const C++ call the thread-gen pool already runs from worker threads), the piece-1 colour per face (the old row machine _step_face, un-sliced — budget = INF), the 12 PNG writes (the ~tens-of-ms deflate spike now lands on the pool thread), the read-back + the variance guard on the bytes actually written, and the 12 face geometries (pure SphereMath). The main thread then does the thin GPU-side consumption: one face per frame (its ImageTexture from the worker-decoded image, its mesh node from the worker-computed geometry). Single-writer discipline: until bake_done only the worker touches pay/_out/_h2/_t2/guard/_geom/_worker_images; the main thread reads them only after.

Why no C++ task type (the AC-0310 builder's note) was owed — the evidence:

  • AweGen::generate_far (gdext/src/gen.cpp:4300) is a const method wrapping awegen::gen_far (gen.cpp:2767), a free static whose only globals are constant tables (solid_ids[256] et al.) — a pure function of its arguments.
  • The thread-gen lane ALREADY calls the C++ generator from WorkerThreadPool threads: world.gd:5571 threadgen_pool.add_task(_threadgen_worker, true), and the AC-0263 comment (world.gd:3573-3583) documents workers dereferencing WorldGen.gen_cpp() as the production pattern (the lazy-singleton race it closed is pre-warmed on the main thread at world._ready). The bake's worker takes the AweGen reference as an argument, so the pool thread is never even a first caller.
  • Column I/O already runs on the same pool (world.gd:3589), so the worker's FileAccess/Image.save_png calls ride an established lane.

The "needs a C++ task type" note assumed the work had to join the TG pool's task queue; it does not — a plain GDScript pool-thread twin of the old slice suffices, which is why the native lane was not touched (no rebuild, no Windows DLL, godot/bin/libchunkio.so untouched and staged).

Side fixes made visible by the move: the bake counters (_frame_n/_step_*/_frame_*/_gen_ms/…) are now explicitly reset at the start of every bake/load (the pre-AC-0382 code never reset them, so a rebake after a startup load inherited the startup's stats — a latent measurement bug), and force_rebake refuses to start while a bake is running.

3. (b) Sun-tracking — the DayNight convention, re-weighted in the shader (no re-bake, no new channel)

How the existing day/night works (checked first, reused, not re-invented): DayNight (godot/core/daynight.gd) is the convention: sun_direction(t) is the direction the light TRAVELS (main.gd:1205 points the world's DirectionalLight3D at it, so the sun sits at -sun_direction), day(t) is the 0..1 day factor (0 at midnight, 1 at noon), sky_display(t) the sRGB sky. The pre-AC-0382 satellite shader already consumed two of those (u_air = sky_display, u_day = 0.18 + 0.82·day) as a GLOBAL brightness modulation only — the fixed-sun lambert stayed frozen in the pixels.

The choice — the "third way" (neither re-bake per sun position nor a new slope channel): re-weight the baked lambert by a per-fragment RATIO computed in the existing shader.

  • Re-bake per sun position is rejected outright: the sun moves continuously (a 600 s day); the bake is ≈85 s of CPU per seed and would owe a re-bake every frame.
  • A baked slope/normal channel is rejected as disproportionate: it would change the 1024² texture contract (a 24th texture or a repacked channel), force a re-bake + re-ship of the canonical seed-44 assets, move the piece-1 guard and the rebuild_vs_shipped pixel-compare — for shading a term that is minor next to the radial one.
  • The ratio (implemented): the baked lambert is 0.45 + 0.55·clamp(dot(L, n), 0, 1) in the chart's local (u, radial, v) frame. Its dominant term is the dot with the fragment's RADIAL direction — and the radial component of the bake sun is the SAME constant for every fragment (L_RADIAL = 1/√1.2, the LY component). The shader computes sun_l = clamp(dot(u_sun, NORMAL)·√1.2, 0, 1) (u_sun = -DayNight.sun_direction(t), world frame = body-local frame: the body carries translation only) and brightness becomes tex · (u_day − u_day_gain·(1−sun_l)) with u_day_gain = 0.82·day(t). At sun_l = 1 the factor is exactly u_day (the noon appearance is byte-identical to pre-AC-0382); at sun_l = 0 it is the 0.18 night floor; at night (day = 0) it is the flat 0.18 floor — exactly the pre-AC-0382 night. The per-texel slope modulation stays baked (frozen at the piece-1 fixed sun — the minor term; at the limb, where the slope matters least, the ratio is exact for flat ground).

What it cost: one dot product + one multiply per fragment in the existing shader (no new sampler, no new texture, no re-bake — rebuild_vs_shipped stays 0 diff, the 12 canonical PNGs are byte-untouched), two extra shader parameters pushed only while the body is visible (u_day_gain, u_sun). The visual contract is intact by construction: the dissolve (per-fragment opacity = smoothstep(fog_far, render_edge, d)) and the 0.25 texel-to-chunk ratio are geometry/opacity, untouched by shading; the ladder re-runs green in §5.

The sun's path on the body: at noon (t=0.5) to_sun = (0, 0.928, 0.371) — the home faces read sun_l = 1 (clamped), the nadir of the spawn hemisphere is fully lit exactly as before; at dusk (t≈0.25) to_sun = (1, 0, 0) — the +X limb is at full day, the −X limb at the 0.18 floor, the terminator through the face centre; the line then sweeps the body over the 600 s day. Night: uniform 0.18 (unchanged).

4. (c) Recorded, not implemented — the sub-pixel disc cull is a visual no-op

An explicit "sub-pixel disc cull at altitude" would change no pixels: above the fade band, every drawn-disc fragment farther than fog_far from the player is 100% depth-fogged — it renders exactly the air colour (the same value the body's near-edge haze blends to; AC-0310-results §3). Culling it is a fill/vertex-cost optimization only, and presenting it as a visual fix would be wrong. Landed where the next reader will find it (durable, both places): a comment at the threshold derivation in godot/world/satellite_body.gd::_tick_view ("AC-0382 (c) - RECORDED, DO NOT IMPLEMENT …") and this section.
