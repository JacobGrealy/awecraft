1. Goal

Make the fluid simulation local (skip provably-dry chunks + coarsen the sleep signature so walking a dry world costs ~0 main-thread ms instead of ~12 ms per 0.2 s tick) and fix the first-load fast path: the Continue boot path currently waits on a full-radius condition that (a) degenerates to ~40 ms under AC-0118's sliced recenter and (b) does NOT guarantee the saved chunk is built → measured fall-through: a player saved 3 chunks from spawn falls through the world on continue (dist=3 PRE probe, §5/§7). Both changes must keep the full battery byte-identical (G2) and every G5 floor green.

7. Risks / edge cases

(a) Prescreen bit drift (bit cleared while chunk still wet / never set): mitigated by setting the bit in the LOWEST common write paths only — set_fluid (world.gd:1554), set_block fluid-id branch (world.gd:1371), _apply_edits_to_chunk (world.gd:1399) — which are the ONLY writers of fl (the sim's stale-clear fl[i]=0 :1682-1684 and the set_block non-fluid clear :1375 can only make chunks drier; the sim's internal writes all route through set_fluid/set_block). Single clear site (post-scan all-dry check) makes stale bits self-heal in one tick; battery mode-switch resets (_batt_reset_state, main.gd) zero fl under a live bit → one extra dry scan, then cleared — no value impact. A flow can enter a chunk ONLY via a set_fluid/set_block write (into it), and every such write sets the bit + _fluid_write (global wake) — so a frozen flow can only resume from an in-window write or a window shift, both of which force a full scan of bit-marked chunks. The ±14-block window (28-block span, world.gd:26) exceeds the sim's max single-source reach (an l=8 source spreads laterally until n_l hits 0: 7 blocks, 1 block/tick) and every player action (reach ≤ ~6 blocks) is in-window — no reachable flow can be starved. Proof: bit absent ⇒ all fl==0 ⇒ sim inner loop hits continue for every cell (world.gd:1672-1680) ⇒ skip is observationally identical; bit present ⇒ scan body untouched; cl order untouched ⇒ G2 bit-identical. The battery (player-null) iterates ALL chunks :1618-1620 with sig="all" — its 4 full ticks + 1 sleep tick (measured stable 0,0,1,2,3) are reproduced exactly because fixture chunks carry the bit and sleep state is untouched.

(b) Signature false-sleep: the 32-block sig only throttles REDUNDANT rescans of an already-settled window — it never suppresses a write-driven wake (_fluid_write :1629-1631 resets stability regardless of sig). Reach argument above (7-block max spread < 28-block window). Edge: floor-quantization keeps chunks −1/−2 in one cell (a truncation would false-wake on negatives).

(c) Continue 3×3 core cost: 9 chunks × (gen ~31 ms + build, threaded under the AC-0079 v3 drain) — measured 1239-1592 ms (probe core_ms, r4). Gate = "spawn no longer waits a full radius AND the player no longer falls", NOT sub-second spawn. The core reuses the existing drain paths (_gen_unit world.gd:445+, sync fallback for (0,0) :608, _mesh_dispatch :599) — no new build machinery.

(d) Sim cheaper ⇒ frames improve or stay: G5 walk p95 ≤ 65 is a floor (regression check); 805 ms/run of main-thread fluid scans (PRE) leaving → expect equal-or-better.

(e) Any battery value moving = design wrong (not tuning) — bounce to design review before re-running. The bit-identical invariant + untouched cl order + untouched sleep state are the three load-bearing invariants.
