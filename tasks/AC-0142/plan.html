AC-0142 — the mob table in JSON, using AC-0141's proven contract

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. This is the same job as AC-0141, which just landed, so apply that ticket's encoding contract and proof method rather than inventing a new one.

1. Goal

The mobs table moves from autoload/data.gd into godot/data/mobs.json; data.gd keeps the loader and every lookup, so callers are unchanged.

2. What is known (measured — do not re-derive)

  • The table is var mobs := { at autoload/data.gd:112, with pig/chicken/wolf/spider-class entries. Entries carry nested dicts and arrays of dicts, e.g. "drops": [{"id": 101, "n": 2, "ch": 1.0}, …], plus Color.html("f2a29c") bodies/heads and mixed int/float stats ("hp": 10, "speed": 1.5).
  • THE ENCODING CONTRACT IS ALREADY ESTABLISHED AND PROVEN at AC-0141 (in ARCHITECTURE.md §2/§5 and godot/autoload/AGENTS.md): Godot 4.7's JSON parser yields a float for every bare number (probe-proven there), so ints are tagged {"i": n}, colours tagged {"c": [r,g,b,a]} with the source spelling verbatim, a bare number is a float, and top-level id-ish keys are converted back to int in the loader with a deliberate script error on a non-int key.
  • The loader helper _load_table from AC-0141 already exists in data.gd — reuse it rather than writing a second decoder.
  • THE KEY-SHAPE DIFFERENCE, which this plan at first got wrong and the builder correctly refused: the mob table is NAME-keyed ("pig"), and _load_table deliberately script-errors on any non-int top-level key (that is AC-0141's defence for blocks/items). So extend _load_table with an int_keys := true parameter: blocks and items load with int_keys=true and keep the hard non-int-key error and their negative test; mobs load with int_keys=false and pass string keys through verbatim. One loader, one encoder, one dump-diff proof — only the key policy differs, and it is explicit at the call site. Re-keying mobs.json with integers instead is not an option: the empty-diff proof requires the in-memory dict to keep its name keys.
  • Also in the same file and deliberately OUT of scope here (AC-0141 left them): shapeless (:69), shaped (:96), tiles (:125, currently an empty dict). Do not move them in this ticket — say so if you think one should be, and leave it.

7. Risks

The mob table is SMALLER than blocks/items, so the risk is not volume but complacency: the nested drops arrays carry ints (id, n) beside floats (ch), which is exactly the case the tagging exists for. Do not hand-convert those; let the encoder do it and let the dump diff prove it. And do not "improve" any mob value while moving it.
