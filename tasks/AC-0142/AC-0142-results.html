2. Deviations

AC-0142 deviations (plan: tasks/AC-0142/plan.html)

1. Colour sources were hex, not decimal literals. Every block/item colour AC-0141 transcribed was a decimal literal (Color(0.525, 0.376, 0.263)); every MOB colour is Color.html("rrggbb") (data.gd:112-124 pre-AC-0142). "Source spelling verbatim" has no direct JSON form for a hex spelling, so each channel is the shortest round-trip decimal of the EXACT double n/255.0 (Python repr is round-trip — the generator asserts JSON round-trip equality for all 18 channel values), with the 4th slot written 1.0 explicitly (the AC-0141 convention — never defaulted). Godot's Color.html does the same n/255.0 double conversion, and the in-engine before/after var_to_str dump diff (the gate) is EMPTY (2,200 B each, 9 mobs), so the float32 channels are bit-identical.

2. The dump instrument format differs from AC-0141's. AC-0141's dump_ac0141.gd was deleted at its exit (its deviations #6), and its dump files show a compact one-line-per-entry serializer. This ticket's instrument (the plan-named "canonical sorted var_to_str") emits one "M <name>:" line plus a multi-line var_to_str block per mob (sorted top-level keys, sorted inner dict keys, full-precision colours, type-sensitive: int 3 vs float 1.0 vs a 1-channel-off Colour all read differently) + a mobs_count line. The proof is self-contained before/after under ONE instrument — the format need not match AC-0141's bytes, only be canonical and type-sensitive. The raw engine log per run (raw_<mode>.txt) is kept as the SCRIPT-ERROR evidence; the dump files (dump_<mode>.txt) are the diff inputs.

3. Negative test — implemented and logged, after the AC-0141 pattern: - missing mobs.json (file moved aside): the run log carries "SCRIPT ERROR: Cannot call method 'get_as_text' on a null value." + "SCRIPT ERROR: Trying to assign value of type 'Nil' to a variable of type 'Dictionary'." — rc=1, no dump block at all (an empty table never reads as a pass — the instrument also push_errors "the mobs table is EMPTY"). - corrupt mobs.json (file replaced with non-JSON): "SCRIPT ERROR: Unable to iterate on object of type 'Nil'." + the same Nil-assignment error — rc=1, same shape. Both runs went through the same autoload boot as g0, so G0's census (>0 SCRIPT ERROR) fails identically; mobs.json was restored afterwards (the post-restore after-dump + gate runs are on the restored file). Logs: .scratch/AC-0142/raw_neg-missing.txt, raw_neg-corrupt.txt.

The mobs table has no lookup function in data.gd — its consumers (entities/mob.gd: 50/166/178, scenes/harness.gd:5960/5980/23680) read the dict directly, and the dump diff proves that dict is unchanged.
