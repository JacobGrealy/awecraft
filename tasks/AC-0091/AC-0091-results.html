3. The five H=80 traps — root cause & resolution

Trap 1 — AC-0134 face mask + AC-0128 ring mask (side, yy) encodings

AC-0134 face mask: the live carrier. Per-chunk CLOSED own-column masks m[t·H + y] — the index math is dynamic in H (main.gd _la_col_masks and world.gd _compute_face_blk both size by the runtime height), so it scales with no change. Verified: lightaudit cliffs = 0 and the torch tunnel seq==ref EXACT.

AC-0128 ring mask: old encoding (side<<16)|(yy<<8)|level with yy = y·16+t. At H=384 the yy field reaches 383·16+15 = 6143 (13 bits), which collides into the level field — a real bit-overflow. Re-derived to (side<<17)|(yy<<4)|level (level 4 bits, yy 13 bits, side 2 bits = 19 bits, collision-free).

Provenance note: the ring is confirmed WRITE-ONLY (writes only at chunk.gd :20/:1877/:2042, zero readers — the AC-0134 face mask supersedes it per the code comments). It was re-derived anyway per spec to keep the encoding valid for H=384 in case any future reader is added.

Trap 2 — eff strip lengths

Lighting side strips were hard-coded 2560 (= 2·16·80) and corners 320 (= 4·80). At H=384 these under-size the per-chunk eff side strips (need 2·16·384 = 12288) and corner strips (need 4·384 = 1536), truncating cross-chunk light. All sites fixed to 2·16·h / 4·h: lighting.gd _chunk_blk_inject, world.gd (_side_eff_strip, _compute_face_blk ×4, _side_blk_strip ×3, _corner_eff_strip), and chunk.gd _bake_box (×8 checks). Verified by lightaudit (cliffs 0, tunnel EXACT) + nightday (cave 15.0/3.0, torch 14.19996 — EXACT vs AC-0135).

Trap 3 — fluid sim column limits

CLEARED — proven dynamic. The fluid sim (world.gd tick_fluids) is driven by the fluid_wet cell set and iterates chunk data by index with y read from the (y<<8) bits; set_fluid/get_block bound against Data.HEIGHT. No hard-coded column limit exists. Verified: fluids arm sea_stable true, sea_surface 2730/2730 FLAT.

Trap 4 — recenter / build-queue slab math

Slab count was hard-coded 5 (5×16=80) across chunk.gd (per-slab acc counters, build_accs, build_mesh, apply_accs, init_slabs, slab_for_y, mark_edit_slabs) and the world.gd cull math. Replaced with the runtime Chunk.slab_n() = (Data.HEIGHT+15)/16 = 24 everywhere. In-run gate fix: GDScript has no [0] * n array repetition (unlike Python) — the first G0 failed with 10× "Invalid operands Array and int for *"; fixed with a Chunk._zeros(n) static helper. Verified: MINFO chunks_built 81/81 all_meshed, boundary one-shot ok/remesh/marker all true.

Trap 5 — y-in-low-bits packing (<<8)

CLEARED — proven safe. Chunk data index fi = (y<<8)|(lz<<4)|lx. At H=384, fi < 256·384 = 98304, so the y-field (top bits) never collides with the 12-bit (lz,lx) field. PackedByteArray is 32-bit-indexed; no overflow. No change needed.
