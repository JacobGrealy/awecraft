Goal

Update chunk/world height to match Minecraft: Y = −64 … 319 (384 block levels; sea level Y = 62). Currently 16×H×16 with H = 80 (sea y30). The in-repo generator (generator.gd terrain/biome formulas + data.gd constants) is the provenance — the web spec (index.html) is NO LONGER referenced (user 2026-08-29); remap the existing in-repo generation to the new Y range.

Design decisions (binding unless in-run evidence forces a documented change)

  • Internal index stays 0-based: y = 0 is the bottom (bedrock, MC Y=−64), y = H−1 = 383 (MC Y=319). MC coordinate Y = y − 64 is exposed ONLY at coordinate surfaces (harness RESULT output, any UI text). This keeps every data-indexing expression (y<<8 class packing, light arrays, slab splits, ring masks) a constant-scale change, not a signed-coordinate rewrite.
  • H = 384. Bedrock fills y = 0 (and the generator's existing bedrock layering if any, remapped to the bottom). Sea level: y = 126 (MC Y=62). Spawn at the terrain surface of the spawn column (generator-driven, same rules, new scale).
  • Save format: stores the same internal 0-based y — old saves are forward-INCOMPATIBLE (world height changed); on load, a height mismatch must fail soft (treat as new world / clear edits) — never a script error.
  • Terrain remap: the generator's heightfield/noise→y mapping is re-derived so typical surface lands mid-range (grassland around MC Y 62–100, mountains to ~200+, caves from the same 3D noise re-scaled). Keep biome thresholds and block placement identical; only the vertical scale shifts. Document the exact mapping formula in the results.
  • The H=80 traps (MUST verify each): (1) AC-0134's lossless per-side face mask + AC-0128's ring mask encode (side, yy) pairs sized for H=80 — re-derive the encodings for H=384 (or prove they scale) and re-run the nightday + lightaudit arms. (2) lighting sky columns / eff strips span H — check strip lengths. (3) fluid sim column limits. (4) recenter/build-queue slab math. (5) any `<<8`/bit-pack with y in the low bits.
