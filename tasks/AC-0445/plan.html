Goal (user story → contract)

  • Smoothness fix 1 (tower holes): the real band (tier 0) and band A (tier 1) enable a 16 × 16 column whole, prepared off-thread, switched on in one frame — no horizontal slab slices at the streaming edge — with a short display-side fade so it "arrives" instead of popping.
  • Smoothness fix 2 (vertical flight): a pure 16-block Y move must cost nothing: the Y term of the recenter trigger (player.gd:3310) is deleted, the recenter wy parameter loses its only consumer, and both probe caches stop carrying the player-Y slab in their fingerprints (altitude-stable).
  • Scope (P1 only): anchor removal on all tiers + tier 0/1 column-atomic enable + fade. Not in P1: tier 2/3 (far/low) atomicity — the coordinator's fence keeps that lane slab-granular (it is a separate, later, self-contained piece with its own Run-1). No C++ change (build_accs range emit, range slab_light_payload, and box_settled all exist — see Q1).
  • Guarantees that must hold: (a) never show an unlit slab (the settle gate + lver re-check); (b) the AC-0286 halo is never hidden twice / never double-faded on promotion; (c) settled state == today's opaque draw (the fade is transient display-side alpha only); (d) mesh-attach contract: full builds land via apply_accs (merged-atlas canvas UVs), scoped builds via apply_edit_accs — the column build is a FULL build and lands through apply_accs exactly like the band-A mat landing.

The five Run-1 answers (settled against code)

Q1 — SETTLE GATE: wait for all 24, or drop the unsettled at land?
ANSWER: gate the WHOLE column — wait for all 24 sections. Never drop.
Reasoning:
  • The gate's job is "a face never shows on lighting that is not calculated" (world.gd:8740–8747, AC-0283 P2). A face becomes visible at LANDING, and the landing re-checks box_epochs (lver, world.gd:7819–7829) — so dispatch-time settlement + epoch re-check already makes the shown light final. Dropping an unsettled slab at land would show a hole (the ticket names this the hard-rule violation); there is no other option that keeps both the atomic enable and the no-unlit contract.
  • Waiting the full box is bounded: box_settled (gdext/src/starlight.cpp:660) treats unseeded sections as settled zero-boundaries (:652–659) — only genuinely in-flight relaxation delays, and a new real-band column is seeded as a whole column (_star_seed_column → seed_column, all 24 sections) and settles within the engine's settle wave. The standing settlewait finding (0 episodes — "new-column landings settle before the drain first offers a slab") means the column gate adds no new stalls in practice; it is the max of the per-slab gate completions for the same box neighborhood (the per-slab 3×3 boxes already overlapped the same neighbour sections).
  • Precedent, already shipped: the FULL landing / tex-refresh path gates on the full-column box — star.box_settled(cx, cz, -1, 24) + box_epochs(cx, cz, -1, 24) + the full-column payload (world.gd:6317–6327, :8270s). The column build reuses that exact established contract, widened from the one-slab box. No C++ needed: slab_light_payload(cx, cz, si0, si1) is already a range payload (starlight.cpp:789, window [si0·16−2, (si1+1)·16+1]) and build_accs already emits si0..si1 with was_full = si1 < 0 (mesh.cpp:3431, 3600–3627).
Dispatch: box_settled(cx, cz, -1, 24); payload slab_light_payload(cx, cz, 0, mini(top>>4, 23)); lver = box_epochs(cx, cz, -1, 24); landing re-checks the same box (mismatch → datadrop + retrigger, the whole column redoes — one unit, cheap).
Q2 — PER-FRAME BUDGET: in-flight columns, not slabs — what is the enable cost?
ANSWER: in-flight is bounded in COLUMNS by the existing TM pool cap; the enable cost equals the EXISTING full-landing worst case (same op class, measured). Non-footprint bodies stay staged.
Reasoning:
  • In-flight: the threadmesh pool cap (threadmesh_max = 3, startup 9, world.gd:3492; the drain's tm_cap logic world.gd:8748–8758 is unchanged) bounds tasks. A task is now a column → ≤3–9 columns in flight at once, all worker-side (off the main thread). In-flight dedup (_tm_inflight_keys) was already per-COLUMN (world.gd:8624). The drain's wall-clock unit budget (pace ≈3.5 ms/unit, drain_budget_ms cap) bounds dispatches per frame; a column dispatch is one µs-scale worker submission. The unit accounting in _drain_build_queue keeps counting dispatches (one column = one unit) — the comment "one slab" becomes "one column (tier 0/1)".
  • Enable (landing, main thread): apply_accs (chunk.gd:1708) = up to 24 slabs × _assemble_slab (ArrayMesh build + surface materials + MeshInstance attach). Plus collision — see Q3. This is exactly the existing full-landing op class: AC-0340 measured the immediate-path burst for a footprint column (up to 24 slab bodies in one frame, frame_max ≈35 ms, "unbounded by design (that is the fence)"). The column landing is the full landing's shape with the mat/full landing's bookkeeping — no new worst case, a known one. It is measured before/after with a timing-gated TMH_PART-style line on the column landing (apply= / col= / stage= ms, AWECRAFT_TIMING=1) plus the perf/boundary frame stats (see Gates).
Q3 — COLLISION ATOMICITY: bodies with the mesh?
ANSWER: yes inside the footprint, staged outside — by reusing the existing col_immediate/staged split. No new mechanism.
Reasoning: apply_accs → _post_build_collision (chunk.gd:1476): c.col_immediate (set at dispatch, world.gd:8621/:8419, via _col_immediate_for world.gd:10809 = Chebyshev ≤1 of the recenter anchor + (0,0)) → all dirty bodies build immediately in the landing frame (footprint: mesh and bodies together, the player cannot be there without both); otherwise col_dirty stays for the staged lane _col_drain_step (world.gd:10837: ≤2 cols/frame, collide_drain_budget_ms = 8 ms, debt re-queued, never dropped; the perf_col_deferred_in_footprint tripwire must stay 0). The column landing calls _count_collision_build(c) + _stage_check(c, key) exactly like the mat/full landings (world.gd:8086–8109).
Q4 — FAR / LOW LANES: atomic too?
ANSWER: NO — stay slab-granular in P1 (coordinator fence; P2 is a separate gated piece).
Reasoning: _low_dispatch_slab and the far payload representation have their own per-slab state (the per-slab/tier/dgen/fgen low_cache, the flip-back attach, the tier-handoff drop, the ring batching, the floor prune, the all-air terminal mark) — converting it to column units would change its representation and its whole gate contract, and the ticket's own plan defers that to P2 with its own Run-1. The ONLY low-lane change in P1 is the anchor removal: _entry_best_pending's fan walk around the player slab becomes a deterministic bottom-up walk (si 0→top, same skip/prune/check sequence) and its fingerprint loses the player-Y element. Bottom-up also minimizes all-air terminal-mark dispatches on floored far columns (sub-floor slabs are pruned first). Unit, cache, flip-back, and budget semantics unchanged.
Q5 — FADE: per-column material duplication + material_override — what exactly, and how do both guarantees hold?
ANSWER: per-surface fade materials on the four static lit shaders (opaque/cutout/flower/fluid-cross), ramped wall-clock 0→1 over COL_FADE_MS = 350 ms (code constant; harness-only env AWECRAFT_FADE_MS for A/B; 0 = off, no Options toggle), first-enable only, with the halo held visible under the ramp when a low is showing.
Mechanism (refined vs. the ticket's draft):
  • Shaders: uniform float u_fade : hint_range(0.0,1.0) = 1.0; + ALPHA = u_fade (opaque), ALPHA = t.a * u_fade (cutout/flower — the soft ramp replaces the scissor only while ramping), ALPHA = 0.62 * u_fade (fluid cross — its existing alpha × the ramp). Default 1.0 and the shipped (opaque-pass) materials are bit-identical; the transparent pass exists only while a ramp is live.
  • Not material_override — that hook covers all of an instance's surfaces and would force one shader on a flora mesh's two surfaces (cutout + flower). Instead the landing sets the fade material per surface (ArrayMesh.surface_set_material(i, m)), using the slab's sidx/fsidx to find the opaque (surface 0) / fluid-cross / cutout / flower surfaces. Meshes are per-build ArrayMeshes (freed at the next re-build), so the transient surface materials carry no stale state.
  • Landing (first-enable detection): capture before apply_accs whether any high slab instance is visible. Visible (remesh, promotion with stored high) → no fade (immediate swap — the AC-0286 no-double-fade contract: the thing it replaces is never hidden twice). Not visible (first enable, from sky or from a halo) → fade; and if a low (halo) is visible, keep it visible under the ramp (crossfade) and hide it exactly once, at ramp completion — no double-hide, the AC-0286 halo is replaced, not punched through.
  • Completion (in _col_fade_step, wall-clock, smoothstep curve, frame-rate independent): restore the shared kind materials on the surfaces (a mid-ramp remesh's fresh meshes already wear the shared materials — the restore is a no-op on freed meshes), free the per-column fade materials, hide the held low. Ramp budget is O(fading columns × surfaces) per frame — a handful of columns at most.
  • Guarantee 1 (never show unlit): the fade touches display alpha only — the vertex colors (the settled light) are exactly the ones the Q1-gated build baked; dispatch gate + lver re-check untouched. A face only exists (even at partial alpha) after its settled-light build landed.
  • Guarantee 2 (settled == today): after the ramp the surfaces wear the shared opaque-pass materials again (identical to today's attach), the fade materials are freed, and the only lasting state is zero. Promotion/remesh/tex-refresh never fade (first-enable detection above).
Scope decision: the animated water/lava surfaces (core/fluid_anim*.gdshader, Data.fluid_anim_mats shared per-bid materials with their own per-frame uniform push) do NOT fade in P1 — duplicating them per column would join the uniform-push loop + a second lifetime. Their arrival is usually continuous with the far band's own water draw at the same height (not a pop of new content). Recorded as a deliberate P1 limitation.
