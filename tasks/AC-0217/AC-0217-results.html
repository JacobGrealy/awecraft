AC-0217 — debounce-collect-pool-score-only-on-move-or-turn

Gating the per-frame _collect_pool + _entry_score work in godot/world/world.gd to only rescore when position or yaw changes; reuse the last pool/score when idle. GDScript-only (no C++ touched).

1. What the debounce does

The drain's three scored picks (build / forward-lead / data) each re-ran _collect_pool (up to PICK_POOL_CAP = 512 entries) + _entry_score every frame even when the player stands still and the world is idle — ~1000 entries of pure re-work per idle frame. The picks are now served from a one-slot cache per pass (_pick_build_cached / _pick_data_cached):

  • Key = quantized player position (1 cm) + look dir (1e-3) + maxb (drain window) + _spawn_fast + recenter center (last_pcx/pcz) + a queue version counter (_pool_ver) + (data pass only) the in-flight depths (TG tasks + io reads).
  • _pool_touch() bumps the version at every state mutation: all band_buckets sites (_enqueue_build, _remove_entry ×2 paths, _drop_queued, _cap_queue_depth, _convert_data_to_build, _strip_candidate_builds, recenter merge finalization) + the data-landing choke points (threadgen_handoff, _startup_gen_apply, _land_column, _gen_unit sync, _materialize_chunk_data sync).
  • On a key match the last pool/score is served (rescan + rescore skipped). A cached non-empty candidate is re-validated (c == null / data / mesh_built / _build_ready / in-flight) — a stale candidate re-scans instead of being served. A cached EMPTY pick is trusted: a membership or readiness change always bumps the version, so a matching key means a fresh scan would find nothing either.
  • Any real move or look turn changes the key every frame → always a fresh scan → the forward-move pick order is byte-identical to pre-AC-0217 (verified by the AWECRAFT_PICKLOG=1 pick trace, §3).
