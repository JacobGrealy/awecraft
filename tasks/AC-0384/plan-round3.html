AC-0384 — round 3: the user says NOT FIXED (body inside the bedrock, clouds below the lowest terrain)

Goal

Find and fix the single shared property that makes the satellite body AND the cloud layer read as shells far inside the world in the user's loaded game, and prove it with an actual render of the loaded (shipped, Forward+) path measured at the user's own settings (R24/F83) and altitudes — not with arm geometry numbers.

Diagnosis (code-verified; the renders below confirm it)

The radii are right; the pixels are not. Every path the previous round measured (arm = the same main.gd game path) puts the body at R+H, the clouds at R+275/330/400, the terrain at R+H — a single shared centre (0,-R,0) and a single shared R (Game.planet_R=4000) for all three, verified in the code (satellite_body.gd::configure, main.gd::_place_clouds, the world column transforms) and re-measured live by this round's extended geom gate (clouds_centre_ok + body radius range). No planet picker exists; every world is R=4000; the user's own satdiag says R=4000 — the brief's wrong-shared-R hypothesis has no code path, and at R=4000 the 4275-4400 cloud shells can never be below terrain (max 4384).

The defect: godot/core/satellite_body.gdshader render_mode is cull_back, depth_draw_always — it does NOT disable the engine env fog. The body's own per-fragment model is built to TAKE OVER exactly where the world's depth fog is 100%: op ramps existence over the world's fog window [fog_far, render_edge], haz_a hazes the limb, and haz_d mixes toward u_air — which is DayNight.sky_display(t), the IDENTICAL colour of env.fog_light_color. But with the env fog still applied to the body's fragments, everything beyond fog_depth_end (= 332 m at the user's R24/F83) is repainted fog colour, erasing the established disc at every orbital altitude. At the user's 668 m the whole planet (terrain + body) is a uniform fog-colour disc, and the only non-fogged detail is the cloud shell — which already carries fog_disabled (its comment literally names the failure: "a 4300 m shell would be erased by it"). Puffs on a featureless disc read as "lower than the lowest terrain"; the featureless disc reads as a ball further inside than the bedrock. One shared property (the body missing the fog_disabled the clouds have) explains both clauses of the user's report.

Why the previous round proved nothing: the arms measure radii (geometry) — fog is a pixel effect invisible to them; the r2 "acceptance" render was at ground level where the body is hidden/fogged anyway (the seam was never in frame); AC-0396's planet shot sidesteps the bug with AWECRAFT_NO_FOG=1 in its recipe (the recipe author knew the env fog repaints the body — the user's game has no such env).
