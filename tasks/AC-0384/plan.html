AC-0384 r5 — the near-disc moiré static (round-1 gap 3): mipmapped, anisotropic sampling

Goal

Make the satellite disc sample its 1024² face textures with mipmap + anisotropic filtering — sampler and texture both carrying a real mip chain — so the near-disc stipple (rendered grain 4× source in round 1) collapses toward the source's own grain, measured the same way at the same five altitudes and the same user config as the round-1 ladder.

The hypothesis (tested first, it fits exactly) — VERIFIED IN CODE before any edit

  1. Shader side — core/satellite_body.gdshader:78 declares uniform sampler2D tex : filter_linear; — bilinear, no mip sampling, no anisotropy.
  2. Import side — all 12 godot/assets/satellite/satellite_faceNN.png.import carry mipmaps/generate=false (verified on all 12).
  3. The third side the hypothesis did not name (the half-fix trap) — world/satellite_body.gd never binds the imported texture: it decodes tex.get_image() and wraps the base level alone in a fresh ImageTexture.create_from_image(img) (load path L498, bake path L532, cache path via _load_png L480). Even with mipmaps/generate=true in the import, the mip chain dies in that re-wrap. Import-only or shader-only would each be a no-op; all three sides move together in this task.

Godot 4.7.1 (verified against the sampler-hint strings in this exact engine binary) accepts the combined hint filter_linear_mipmap_anisotropic — linear mipmap sampling plus the renderer's max anisotropy. (filter_anisotropy alone is not a 4.7.1 hint name.)

Measurement (round-1 numbers are the baseline; the ratio is the evidence)

Candid finding first: round 1's exact 53.2/12.7 cannot be reproduced from the archived crops — the saved d5-nadir.png / face00-centre.png crops do not match the archived frames (mean abs diff 58.7 / 91.0 per channel against every candidate box), and no 1–4 px neighbour-diff variant on them lands on 53.2/12.7. This round therefore defines a canonical metric and applies it identically to source, pre-fix and post-fix at the same altitudes; round 1's rendered/source ≈ 4.2× stands as the directional baseline this must beat.

  • Grain metric (canonical, documented in the results): mean over R,G,B of the mean absolute per-channel difference between a pixel and its 2-px neighbour, averaged over the 4 compass directions (the same "mean neighbour diff, 2 px" shape as round 1), sRGB 8-bit units, over a fixed 400×400 box.
  • Source reference: the true centre 400×400 of the shipped satellite_face00.png → measured 11.25 (round 1's source figure 12.7 was computed on a crop that no longer matches the shipped file — same order; the ratio is the comparison).
  • Rendered: the same fixed 400×400 nadir-disc box (440,320–840,720 — the dense-stipple region visible in every round-1 D5 frame; the planet camera + world are static between runs, so the box is comparable) on the new ladder at 2600/1600/700 m (where the body is drawn); 300/120 m are controls — the body is discarded by op below the fog wall, so no body grain is measurable there (the SATDIAG op_nadir lines prove the disc is absent, exactly as in round 1).
  • Ladder: identical recipe to round 1 — the loaded Forward+ path (lavapipe + xvfb + --rendering-driver vulkan, boot line must carry - Forward+ -), user config RADIUS=24 / FOG_PCT=83 (fog_far 332 / edge 400), TIME=0.5, seed 44, fog ON, clouds ON, SIZE=1280,720 (COMMA), CAM=planet + SAT_ALT = 2600/1600/700/300/120, SAT_MESH_STEP=64 (the settled 1.7 M-vertex frame never completes on llvmpipe — the round-2 measured timeouts; its silhouette stair-stepping is round-1 gap 6, a separate proxy-attributed item — holding the step fixed keeps the A/B on sampling only), SNAP_DRAIN=1200 FRAMES, no AWECRAFT_LOGIC arm, 1200 s budget per frame, file-existence + SNAP FAIL + Forward+ boot line + 0 error census per run.

Risks / fences

  • Half-fix trap (this ticket's recurring burn): shader-only or import-only would be a no-op — the code re-wrap kills any import-side chain. All three sides land in this one task; the satellite arm's height_decode + the grain ratio are the tripwires (a mipmap-filtering sampler over a chainless texture leaves the grain ≈ unchanged — that is exactly the failure this measurement exists to catch).
  • llvmpipe anisotropy cap: the software driver may cap anisotropy (≤2 likely) — the mip chain does the bulk of the work; anisotropy matters at the limb. If the ratio does not drop on the proxy, that is proxy-attribution and the fix still stands for the user's GPU (same code path).
  • llvmpipe render-thread class: the 64 m mesh step keeps the settled frame cheap (round 1's ladder completed; the timeouts were the 16 m default). 1200 s budget per frame + file-existence check (the SNAP FAIL class — the hook prints failure rather than silently succeeding).
  • Fences: no commits/pushes, no TASKS.yaml edits, no fenced files, main.gd untouched (no new uniforms owed).

Outcome (2026-10-05, r5) — deviations from this plan

  • The tested hypothesis was half right and half wrong. The mipmap chain was genuinely missing on all three sides (shader filter_linear + 12 imports mipmaps/generate=false + the code re-wrap shipping level-0 only) and is fixed as planned — but the measured effect is −7% clouds-OFF (4.03 → 3.75), masked in the clouds-ON frames (20.76 → 20.52). The near-disc static is the cloud shell’s procedural fbm (finest octaves sub-Nyquist, no mip chain possible for computed data): the decisive A/B is the 2600 m clouds-OFF frame (3.75/0.81, below the source’s own grain of 11.25) vs 20.5/23.2 clouds-ON.
  • Second fix (scope addition, same objective): per-band distance LOD in core/cloud_layer.gdshader (each fbm band’s finest octave clamped to ≥ 2.5 px, per-fragment camera distance + new u_cpxrad uniform) — the plan’s fallback (“find what is [the cause] and say what was ruled out”) turned into a small, measured fix. Result: 2600 m grain 23.23 → 2.09 tight (−91%), 20.76 → 4.87 canonical; the 120 m frame byte-identical (all factors 1.0 at/near ground).
  • Fence deviations, both explicit: (a) main.gd touched (the plan said “untouched”): two small hunks pushing u_cpxrad per frame from window size + camera fov, so the clamp is exact at the user’s window size — stated in continuity, the results page and the report. (b) harness.gd (the satellite arm) touched: height_decode now slices the loaded image to level 0 before comparing — restoring its original base-level semantics, which the new mip-chain contract had broken (4.7.1 get_image() returns the full chain: 5,592,404 bytes, not 4,194,304; first arm run read ok:false, “raw size mismatch” — the tripwire worked). Per the scenes rule, this round’s verdict rests on the render read with the arm’s pixel comparison (12/12 faces, 0 diff px), not the arm alone.
  • Measurement deviation: round 1’s 53.2/12.7 is not reproducible from the archived crops (evidence in the results page §20.2); the canonical neighbour-diff metric (.scratch/AC-0384-r5/grain.py) replaced it and was applied identically to source/pre/post. The pre-fix baseline is byte-identical to r4’s captures (determinism proof).
  • Gates as planned: G0 ×3 (0/0), 17 renders (all Forward+/SNAP/RESULT/0 errors), satellite arm ok:true (height_decode 12/12, 0 diff px, geom 0.49 m, res_export_ok), SMOKE ok:true (224 s).
