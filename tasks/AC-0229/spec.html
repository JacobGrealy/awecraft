Task-specific requirements

FILLED — the concrete behavior/data changes this task makes.
  • Dynamic cap (godot/world/world.gd, threadmesh_poll per-frame branch): stream_ho_cap = clampi(roundi(base × speed_factor × radius_factor), 1, 100) where base = the AC-0225 chunks_per_frame slider value (read every process frame, unchanged), refreshed every process frame exactly as before.
  • Speed factor: the player's horizontal speed (m/s), sampled once per process frame from the player's position delta (not player.velocity — that is input-driven and stays 0 while harness fly phases teleport player.position), smoothed with a 0.3 lerp (converges ~200 ms, returns to the still level ~250 ms after stopping). 0.5 while still (< 0.5 m/s), 1.0 at the WALK reference (4.3 m/s, player.gd WALK), saturating at 12.0 (50x flight = 215 m/s). No player (build phase, the perf R50 arm, menu) = still (0.5).
  • Radius factor: render_radius / 16 clamped to [1.0, 2.0] (the ahead-ring width grows ~linearly with R: ~14 new chunks per chunk moved at R16 vs ~32 at R50). R≤16 keeps 1.0 — every r4 harness arm is unchanged; R32+ saturates at 2.0.
  • Reference points (base = 3 default): R16 still → 2, R16 walk → 3 (the AC-0225 behavior, a no-op at the reference point), R16 50x fly → 36, R50 still → 3 (the AC-0224/0227 R50-drain profile, untouched), R50 walk → 6, R50 50x fly → 72. The slider still bounds the cap from above (100 = the max at every speed/radius).
  • Harness reporting (godot/scenes/main.gd): the r16 arm reports ho_dyn (the base/speed/factors/cap decomposition) + per-fly-phase ho_cap_max (the peak effective cap observed while flying); the perf arm reports ho_cap + ho_dyn at drain end.
