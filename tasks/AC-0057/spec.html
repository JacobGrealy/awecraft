Part 1 — restore click / drag / move (REGRESSION)

Items can no longer be clicked and moved between slots (hotbar↔storage↔craft grid, pick/place, swap, shift). The break entered somewhere in commits 9727c3f..8dc16e3 (AC-0048 → AC-0051). Ranked suspects — confirm which by reading, not by guessing:

  1. AC-0051 _setup_icon (MOST LIKELY). godot/ui/inventory.gd _setup_icon was rewritten to draw the item-atlas pixel-art tile. If it now adds a child control (e.g. a TextureRect/Panel) to each slot to show the icon, that child's default mouse_filter = STOP will SWALLOW the slot's gui_input → the parent SlotCtl click/drag handler never fires → "can't click and move items". FIX: any icon child must be mouse_filter = MOUSE_FILTER_IGNORE (or draw the tile inside the slot's own _draw() with no child). Verify by reading the current _setup_icon and what _slots[i]/SlotCtl actually is.
  2. AC-0050 STORAGE_OFF remap (27→9). godot/player/player.gd STORAGE_OFF is now 9 (was 27); storage now backs inv[9..35]. If the drag pick/drop path and the click path disagree on the storage-idx↔inv-idx conversion (one still hard-coded to 27, the other using STORAGE_OFF/9), a picked item lands in a hidden/wrong slot (appears to vanish). Grep inventory.gd + player.gd for 27, STORAGE_OFF, and every storage-idx→inv conversion; make them all agree on STORAGE_OFF+idx = idx+9.
  3. AC-0052 _route_click / _areas / _indices. The craft area was reworked (2×2 vs 3×3, table_grid, craft cells 9..18 repositioned). If the slot _areas/_indices mapping or the craft-area branch in _route_click (inventory.gd ~397-421) now mis-routes a hotbar/storage click to a craft/table path (or shifts an index), a storage/hotbar pick/drop can land elsewhere. Read _route_click, the _areas/_indices build, and the draw-index math (~735-804) end to end.
  4. slot redraw vs input. The per-frame draw loop builds a key ("id|n|sel") and calls _setup_icon/queue_redraw. If AC-0051 made key change every frame (e.g. a texture ref/pointer in the key), the slot Control could be recreated/invalidated mid-drag, aborting the drag. Confirm the key is still just id/count/sel (no texture reference).

Also re-verify the AC-0045 drag mechanics still work end to end: press a slot → carry the held stack → move mouse → release on another slot (the gui.mouse_focus release-drop path in player.gd: _dragging, held, drag_held, release_mine). Both the click-to-pick/click-to-place (swap) AND the press-drag-release flows must work in hotbar, storage, and craft grid.
