AC-0057 — fix inventory click/move regression + pickup hotbar-first

Parts: (1) restore click/drag item movement in inventory + hotbar, (2) inv_add fills hotbar 0..8 before storage 9..35. Web index.html untouched; Godot-only changes.

Root cause

The web spec does all inventory semantics on mousedown only (no mouseup). AC-0045 (commit 4114f31) added mouseup/release-drop routing on the Godot port, and that path had two pre-fix defects:

  • Same-slot release undid the pick. The release branch of _route_click (godot/ui/inventory.gd) unconditionally called _release_drop(p, rel_pos) — including when the release landed back on the same slot. A plain click (pick with empty hand) leaves drag_held = true, so the click's own release dropped the held stack back into the slot it had just emptied — the pick was undone by its own release and the item bounced back. This is the user-visible "can't click and move items": every two-click move failed at step one.
  • Release after a swap was a no-op. _slot_click in godot/player/player.gd ended its LMB swap/merge branch with drag_held = false (line 1196 pre-fix). For a drag whose press swapped (hand already held a different stack) or merged, the release's had_held and drag_held gate was false, so the stack stayed glued to the cursor and never landed at the drop target (before-run: R3_hot3=[0,0], R3_held=[8,3], R4_dst=[0,0], R5_dst=[0,0]).

Note: the plain empty-hand press→drag→release case already worked pre-fix (the before-run's R2 passed — R2_dst=[2,4]), which is why the reported symptom was "clicking doesn't move items" rather than "nothing ever moves."

Spec suspect #1 (AC-0051 _setup_icon leaving a child Label with MOUSE_FILTER_STOP) was ruled out by reading _setup_icon/SlotCtl._draw: icons are drawn inside the slot control's own _draw (atlas region or texture), and the count Label child is MOUSE_FILTER_IGNORE — no STOP-filter child intercepts the click.

The fix

  • godot/ui/inventory.gd — new _hit_slot(gpos) helper (~line 398) resolves which visible slot a global/panel coordinate actually hits. _route_click release branch (lines 413-417) now calls _release_drop(p, gpos) only when _hit_slot(gpos) != si — a release back over the same slot is a no-op (web-faithful: held stays, no undo), a release over a different slot performs the real drop. _release_drop refactored onto the same helper (de-duplicates the hit test, no behavior change).
  • godot/player/player.gd:1196 — drag_held now mirrors held state (drag_held = int(held.get("id", 0)) != 0) instead of hard-set false, so a release following a swap/pick press correctly executes the drop path.
  • godot/player/player.gd:924-930 — _inv_order() (used by inv_add) flipped: scans hotbar 0..8 first, then storage 9..35. User asked for pickups to fill the hotbar before storage — this intentionally overrides the Minecraft main-inventory-first order (AGENTS.md wiki rule defers to explicit user instruction).

Harness: AWECRAFT_LOGIC=guiclick in godot/scenes/main.gd extended with real InputEventMouseButton injection (_mb/_mm helpers, _guiclick_real) covering R1–R8 (real press/release drag+click routing) and P1–P3 (pickup/merge/inv_add landing). Craft harness made placement-independent (planks normalization + direct armor p.inv[3]/p.inv[4] assignment) so the whole battery is deterministic.
