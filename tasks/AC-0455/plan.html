3. Edit shape

Two constraints this plan was corrected by — obey them, they are not negotiable

  • No scripting against a document's markdown. tasks/scripts/AGENTS.md forbids it, so gate_run.py must NOT parse godot/HARNESS.md for recipes, timeouts or envs. harness_data.yaml is not a machine source for them either: its envs and wall fields are PROSE ("~1–2 min"), and scraping prose is the same mistake in a different file. The only clean machine facts there are battery.smoke (a list of 5 mode names) and the mode NAMES (modes keys).
  • Therefore timeouts and extra envs come from the CLI with documented defaults (see (b)), and the mode name is only VALIDATED against harness_data.yaml when it is a known mode — an unknown name is accepted because ticket probes are deliberately rowless (ac0433probe is the precedent). A machine-readable gate_defaults: block in harness_data.yaml is a DEFERRED follow-up, not this ticket.

(a) context_pack.py AC-NNNN [--out PATH] [--max-tokens 12000] [--stdout]

Emits ONE markdown file (default .scratch/AC-NNNN/context.md) a builder reads instead of seven documents. Sections in this order:

## Ticket            TASKS.yaml title, status, priority, labels, created/updated  (via tasks_lib)
## Notes             the ticket's notes verbatim
## Plan              plan.html §1 Goal text + the §2 file table rows (strip tags; anchors kept)
## Anchors           for each file in §2: each anchor the plan names, resolved and shown with
                     +-8 lines of context, headed by "file:line". A `grep -n "X"` anchor is RUN.
## Frozen refs       lines the plan quotes as constants (file:line + the line text), if any
## Harness modes     for each mode named in plan §4: its row from harness_data.yaml
                     (entry / tests / result_fields / notes) - lookups only
## Architecture      ONLY the ARCHITECTURE.md sections whose heading the plan names
                     (heading match -> until the next heading of the same or higher level)
## Last continuity   the final "## RUN" block of tasks/AC-NNNN/continuity.md
## Cap               "TRUNCATED: " lines, one per dropped item

The hard cap is the point of the tool. Estimate tokens as bytes/3.6; over --max-tokens, drop items from the BOTTOM up (Last continuity and Harness modes are never dropped first) and record each drop in the Cap section. Two structural guards:

  • no single excerpt may exceed 200 lines; and
  • refuse — exit 2 with a clear message — if a target file is one of the known monsters (godot/scenes/harness.gd, godot/world/world.gd, godot/ARCHITECTURE.md, godot/HARNESS.md) AND the request would include more than 200 lines of it.

(b) gate_run.py AC-NNNN --arms g0,smoke,probe [--rev N] [--dry-run] [--mem-mb 8192] [--timeout 600] [--timeout arm=sec,...] [--env 'K=V K2=V2'] [--heavy]

  • Arm vocabulary: g0 = a bare --headless load with NO AWECRAFT_LOGIC (its gate is rc==0 AND the census 0/0 — either alone is a false pass, per gate_census.py's docstring). smoke expands to the five names in harness_data.yaml battery.smoke, each as its own arm and log. Anything else is a literal AWECRAFT_LOGIC mode. Unknown names are allowed; if the name IS in modes, note it in the summary (informational only).
  • Per arm, exactly this shape (models .scratch/AC-0287-gates/gates_run.sh, which is the canonical precedent): 
    bash -c 'ulimit -v <mem_mb*1024>; cd <repo>; HOME=/tmp/dsh_home AWECRAFT_LOGIC=<mode> <extra env> \
  timeout <sec> /home/angrygiant/tools/godot/godot --headless <--fixed-fps 600 when --fps> --path godot' \
  > .scratch/AC-NNNN-gates/<arm>-r<N>.log 2>&1
    --rev N defaults to (highest existing rN for that arm)+1. Envs are passed as a list, never a shell string (no eval, no injection).
  • pgrep guard before every arm: while pgrep -f '[g]odot' matches, sleep 20 s and retry, with a bounded wait (--wait-slot 1800) after which the run exits 3 rather than starting a second engine. NEVER kill a process.
  • After each arm: rc; census(log_path) imported from gate_census; and the LAST RESULT {...} JSON line of the log parsed (absent → null, not an error).
  • Outputs in .scratch/AC-NNNN-gates/: summary.json (per-arm: name, mode, rc, script_errors, shader_errors, wall_s, ok = rc==0 and census clean and RESULT ok if that field exists, the parsed RESULT, log path) and summary.txt (ONE line per arm: arm rc=0 script=0 shader=0 ok=true 42s <headline key=value>). With --heavy, touch HEAVY_GATES_DONE on completion and print the marker path; without it, never create the marker.
  • --dry-run prints the exact per-arm command lines and the planned log paths, invokes nothing, writes nothing outside stdout. This is the only mode CI can run.
  • Exit code: 0 iff every arm is ok; 1 otherwise; 3 slot-timeout; 2 bad usage.

(c) results_page.py AC-NNNN [--deviations FILE] [--headline "text"] [--files "a,b"] [--summary PATH]

Renders tasks/AC-NNNN/AC-NNNN-results.html, self-contained (inline CSS, no external refs), house style = numbered <h2> sections as in tasks/AC-0448/AC-0448-results.html:

1. Gates            table: arm | mode | rc | script | shader | ok | wall | headline RESULT values
                    (headline = the plan §4 keys if given, else ok/ok-ish fields; max 6 columns)
2. Deviations       the --deviations file verbatim (paragraphs), or "None." 
3. Files            the --files list, else `git status --porcelain` filtered to godot/ gdext/ tasks/
4. Artifacts        *.png / *.json in tasks/AC-NNNN/ when present, else the section is omitted

It REFUSES to render a lie (this is the H3 integrity rule made mechanical): exit 1 if an arm in the summary has no log file on disk, or if --headline names a value that is not present in that arm's log. Every number on the page has to be greppable from a log.

(d) builder_stats.py [--since YYYY-MM-DD] [--json] [--top N] [--sessions GLOB]

The scoreboard. Reads ~/.dsh/sessions/*/session.jsonl.zstd (decompress with zstd -dc via subprocess; no python zstd dependency assumed). Per session, in this exact schema:

  • the {"type":"session"} record gives createdAt (ms epoch) and delegationDepth — keep depth > 0 (builders) unless --all;
  • wall = (max time over records) − createdAt, both in ms;
  • steps = count of step/start; tokens = sum of assistant/message → data.usage input/output (accept outputTokens/output_tokens spellings too);
  • report duration h, steps, out/in, out-per-step, implied tok/s.

Then fit wall_s = a + b*out_tokens (ordinary least squares, done by hand — no numpy) and print the law line with R². Baseline to reproduce on the current logs: ~15 tok/s, R² ≈ 0.93, median run 2.40 h / 138k tokens / 154 steps. --json emits the same as a dict for the ticket notes; --top N prints the N longest runs.

(e) test_builder_tools.py

unittest, no network, no godot, everything under .scratch/. One negative test per guard — a guard without a failing replica is not a tested guard:

  • context_pack on AC-0433 (fixture): output ≤ cap, contains an anchor excerpt with file:line, and does NOT contain more than 200 lines from any monster file;
  • context_pack token cap: force a tiny --max-tokens, assert items are dropped and the Cap section names them;
  • gate_run --dry-run: prints N commands for N arms, invokes nothing, creates no log;
  • gate_run arm expansion: smoke → 5 arms from battery.smoke;
  • results_page: a stub summary with an arm whose log is MISSING must exit 1 (H3 negative test), and a complete stub must render a page with the four sections;
  • builder_stats: synthetic sessions with known token counts/timestamps give the exact expected wall and tok/s; a synthetic perfectly-linear set gives R² = 1.0.

6. Known risks

  • Import path: gate_run.py does import gate_census. That works when the script is run directly (sys.path[0] is tasks/scripts) and under test_builder_tools.py, but NOT if imported as a package module — add the sys.path.insert(0, str(Path(__file__).parent)) guard so both work.
  • The real g0 arm needs the native extension. godot/bin/libchunkio.so is present in this tree; if a run reports AWECRAFT CANNOT START, record it as a finding — do NOT copy or rebuild the .so (that is the coordinator's build lane).
  • Memory cap: ulimit -v is in KB and gates run inside the dsh-web.service cgroup — an unbounded run OOM-kills the harness itself (godot/OPS.md §2). Default 8 GB, and never remove the cap to make an arm fit.
