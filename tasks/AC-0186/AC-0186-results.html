AC-0186 results — the continue path gets the loading screen

Ticket: Continue (menu → slot) must show the same loading screen as new-world gen — cover + progress % — and keep the cover until the spawn diamond is fully disk-loaded + meshed (no half-loaded void). Reuse the AC-0178 UI; verify on a 1k+ column save. Outcome: DONE. The window now opens on continue, shows an honest per-column progress line while the saved columns stream off disk, closes exactly at the sim taxi diamond, and only then does the player exist (input blocked by construction, no void pop). Evidence below is from the frames and the captured state, not from description.

What pre-existed vs. what remained

  • Pre-existed (reused, not re-built): the AC-0178 loading screen (ui/loading_screen.gd: cover + title + bar + N% — m / 41 cols (disk X · gen Y)); the window machinery in world.gd (start_loading/stop_loading/_loading_tick, the sim-diamond target — taxi ≤ sim, 41 cols at sim 4 — the AC-0313-corrected gate, not the ticket's pre-correction "R~8"); the AC-0414 bake hold + live bake line (path-agnostic: it fires from _loading_tick whenever loading_active and the bake is WORK — so a continue with a cold bake cache gets the honest bake line for free); the disk/gen provenance counters (_try_disk_load bumps disk_reads — on a continue that number IS the saved-columns load); and main._await_sim_band, which waits on the SAME condition as the window's close — the simband wall is the load→activation wall, so the player can never exist over an unbuilt diamond.
  • Genuinely remained: main._continue_slot (a fenced file — another session's uncommitted work) has no start_loading caller. The window was fresh-spawn-only (start_game). On continue, the menu hid on click and the player then watched the raw half-built world for the whole sim-band wait. Only the TRIGGER was missing; every line the screen would show already worked.

Deviations, stated

  • Trigger location: the ticket's notes assume the continue window is armed on the continue path (i.e., in main.gd) — main.gd is fenced, so the trigger lives in world.gd and arms the existing start_loading entry point. Behaviour is the ticket's; only the owner of the call moved.
  • "R~8 spawn radius": the implemented gate is the SIM TAXI DIAMOND (taxi ≤ sim = 41 cols at sim 4) — the AC-0313 clause-4-as-corrected gate the user decided ("let's do sim taxi distance"), which the code and the standing contract both use. The window closes when that diamond is meshed; no new R8 circle was invented.
  • The 1k+ census uses AWECRAFT_SAVEALL=1 (test-only env, the flysave A/B usage) for the bulk of the saved circle + the 6 marker edits; a natural-flow save of a building world persists the same way (the AC-0287 edited clause) and the standing save arm covers that shape. The census is the largest reasonable save shape — the conservative test for the disk load.
  • Bake line on continue not demonstrated on a fresh bake: seed 44 loads the satellite body from the shipped res:// textures (phase LOAD, never WORK), so the AC-0414 hold cannot engage on these runs — and exiting mid-bake on a non-canonical seed is exactly the stochastic use-after-free class the coordinator flagged (clean log, signal-eleven exit). The hold + live line are the same _loading_tick code AC-0414 measured on the fresh-spawn path.
  • 1-frame gap: the window arms on the world's second _process frame after _continue_slot starts — the menu hides on click, the cover follows within one frame (~16 ms at 60 Hz). The player node does not exist until the diamond is built, so there is no input and no world visible in between.
