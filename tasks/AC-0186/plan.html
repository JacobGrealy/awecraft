AC-0186 plan — continue-saved-world loading screen

Goal

When Continue is pressed, the player gets the same loading screen the new-world path gets — full cover + honest progress — until the spawn sim taxi diamond (taxi ≤ sim; 41 cols at sim 4, 41 = the ticket's "spawn radius" as corrected by AC-0313 clause 4, the user's own "let's do sim taxi distance" decision) is fully disk-loaded + meshed. No half-loaded void, no player input before then (the player node does not exist until the diamond is built — input is blocked by construction; the menu hides on click; the cover is a full-rect layer-90).

What already exists (read, not re-derived)

  • AC-0178 loading screen (ui/loading_screen.gd): cover + title + bar + the honest stats line N% — m / 41 cols (disk X · gen Y). Already path-agnostic.
  • The window machinery (world.gd): start_loading / stop_loading / _loading_tick, the sim-diamond target (_loading_target_col), the loading caps, the diamond close. The continue path's await (main._await_sim_band) waits on the same condition — the simband wall is the load→activation wall.
  • AC-0414 (bake before load): the loading window also holds the world release for an in-flight satellite bake (bounded 42 s + loud release) and shows the live bake line (set_note: seed, shard k/98, face k/12). Measured on this box: 169 s bake, 48.4 s release. Path-agnostic — it fires from _loading_tick whenever loading_active and the bake is WORK. So a continue whose bake cache is absent gets the honest bake line for free once the window opens on that path.
  • Save/continue: save.gd slots (SAVE_VERSION 4), ChunkIO region saves (AC-0287 filter: SIM DIAMOND + edited columns; AWECRAFT_SAVEALL=1 test-only bypass), _try_disk_load (disk reads, disk_reads counter), main._continue_slot (edits/pose restore, recenter, sim-band await, spawn, Game.start). The standing save arm proves continue correctness.
THE GAP (what genuinely remains): main._continue_slot (a fenced file — another session has uncommitted work there) has no start_loading caller. The window opens only on the fresh-spawn path (start_game). On continue, the menu hides on click and the player then watches the raw half-built world for the whole sim-band wait. Everything the screen would show (progress, disk counters, bake line, diamond close) already works — only the trigger is missing on the continue path.
