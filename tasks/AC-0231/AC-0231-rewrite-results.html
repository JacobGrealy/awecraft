What changed (the user-refined authoritative spec)

Terminology: Slab = 16×16×16 (24 per column); Column = 16×16×384. The old implementation merged a column's fog into one mesh, drew the low as 4×1×4 (top slab only), and stretched one tile over each quad. The rewrite:

  • Step 1 — Fog wave (data landing, per non-air slab). _low_fog_for() runs at every data-landing site (sync-gen, startup burst, threadgen handoff, _land_column, _materialize_chunk_data): for each slab with c.data[si] != null (the sparse null check, null = air) it ensures ONE instance of the single pre-baked 16³ fog box at the slab-bottom Y (si*16). Instances are separate — a per-chunk MultiMeshInstance3D over the shared pre-baked mesh (1 draw/chunk; freeing a slab = remove it from c.fog_slabs + rewrite the MultiMesh via _fog_sync). Stacked same-color boxes share coincident faces — no z-fight. Tier 0 skips the wave straight to high (the column under the player is never fogged — you never fall through). No gen/flat-pull/greedy involved. Before starting low.
  • Step 2 — Low wave (per non-air slab, 4×4×4, repeating UVs). _low_step() builds ONE candidate per frame on the MAIN thread (never the TG/TM pools): _low_slab_grid() samples the slab's edited data (after gen) at 4×4×4 = 64 coarse cells of 4×4×4 blocks (4 C++ row_bytes calls per slab); _low_emit_slab() walks each face plane from the viewing side and keeps the OUTERMOST solid cell (interior faces culled; slab above/below read through neighbor grids so same-type slab boundaries cull; column edges read air — a face is visible iff its normal-side cell is air, so coincident faces can't both be visible = no z-fight). Air cells are skipped — a sparse tree slab stays small quads with shape, never a 16³ block. 2D greedy merge of same-type neighbors per outermost plane (mesh.cpp emit_ro_merged pattern), u-span ≤ 16 blocks, v-span ≤ 4 blocks (the merged-atlas strip is 4 rows = 128px; the high mesh caps its v span at 4 blocks exactly). UVs are repeating: 31px per block from the tile top-left (the qwrite_merged convention — the texture repeats 4× across each 4-block quad, NOT stretched). The low replaces the fog for that slab at its Y (the slab's fog instance is freed); a slab that samples all-air but still has blocks keeps its fog box. Before starting high.
  • Step 3 — High wave: unchanged. The AC-0233 tiers (tier 0 → ring1 8 → FOV cone → rest; ThreadGen pool 4 / ThreadMesh pool 6; full 16×16×16 greedy per slab) run as before; when the high lands, _lod_free_all() frees the per-slab fog + low and bumps low_upgrades_n.
  • Step 4 — Keep rules. A built high is NEVER downgraded to low (low_downgrade_n stays 0 — no path re-marks a meshed chunk low; high stays until freed per cand_since >= 2 after queue work). Low/fog only ever serve never-built slabs. Old LOD dead code (band-2 coarse paths, uv_scale) remains removed — only "gone" comments reference the names.

Notes — engine-build API quirks found while wiring the fog MultiMesh

  • MultiMesh is not a Mesh in this Godot 4.7.1 build. There is a dedicated MultiMeshInstance3D node whose property is multimesh (no underscore) — MeshInstance3D.multi_mesh does not exist and mi.mesh = multimesh is rejected at parse time. The fog instance is a MultiMeshInstance3D per chunk (1 draw, shared pre-baked box + shared unshaded material whose albedo tracks the sky each frame).
  • No instance-transform readback: MultiMesh.get_instance_transform() does not reflect set_instance_transform() under the headless/dummy renderer (always identity). The R16 fog check is therefore data-side: instance COUNT == fog_slabs.size() + shared-mesh identity + pre-baked 16³ aabb; the per-slab Y placement is deterministic from fog_slabs in _fog_sync.
  • ArrayMesh: no get_arrays_for_surface(), no array_data — this build exposes surface_get_arrays(surface) (used by the R16 UV/quad checks).
  • Normal arrays carry ~1e-5 garbage in the off-axis components — face classification in the probe must use the dominant axis (exact-zero tests misclassify, and a (0,0,1) face with y=1.5e-5 reads as a Y face against the wrong position span).
  • Emitter bugs the R16 probe caught and fixed: (a) the greedy merge keyed on id alone merged cells with DIFFERENT outermost planes — a hollow slab meshed as a full 16³ box (the "giant block" the spec forbids); now the key is id*16 + (k+1), merge per plane (mesh.cpp iterates per plane); (b) the v-span was uncapped — a 16-block v span samples 496px against a 128px (4-row) atlas strip, i.e. outside the strip into another block's texture; now capped at 1 coarse cell = 4 blocks, exactly the high mesh's 4-block v cap (h < 4 in emit_ro_merged).
  • R16 not run: R50 (per task instruction — R16 only); no Windows build (per task instruction).
