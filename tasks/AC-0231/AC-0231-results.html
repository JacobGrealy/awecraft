What changed

Distant chunks now have a two-stage cheap placeholder that renders immediately when column data lands, and that is progressively replaced by the full high mesh as the heavy pipeline catches up — while all of the old band-2 coarse-LOD machinery (AC-0181-era) is deleted.

  • First pass — fog boxes (immediate). At every data-landing site (_land_column = all disk landings, threadgen_handoff = all gen landings, _materialize_chunk_data sync-gen, _gen_unit sync-gen, _startup_gen_apply burst), _low_fog_for() instances a pre-baked 16³ box (baked once in _ready: 24 verts / 36 indices + one shared unshaded StandardMaterial3D whose albedo tracks DayNight.sky_display() every frame = the env fog color) per non-air slab, merged into ONE ArrayMesh per chunk. Skips tier 0/ring-1 (≤ chebyshev 1 from the player — those must be HIGH), face chunks, candidates, and meshed chunks. Cost: one data[si] != null scan per slab (24 checks) + a mesh assembly of ≤ 24 boxes — a few ms, once per column.
  • Textured low (4×8×4 sampling + greedy). _low_grid() samples the (edited) column at 4×8×4 = 128 cells: 8 bands of 48 blocks, each band reads ONE 256-byte center row via the existing C++ slab_row (row_bytes(48*sy+24)), each cell takes the dominant non-air id of its 4×4 footprint. _low_emit() runs a 2D greedy merge per face on the sparse grid, scanning each plane FROM THE VIEWING SIDE INWARD so only the outermost shell face is emitted (interior/cave faces dropped). UVs use the same merged-atlas convention as the high mesh (per-unique-solid-tile strips "id_face", 0.5px inset, 31px per tile) via _low_tile_base() (cached). Vertex color repack matches chunk_lit_opaque.gdshader (g=0 so the block-light term is off, b=face shade) — the low mesh reuses the exact cached "opaque" material, so it gets u_day/u_player_light/dither pushes for free. Plane offsets: ±4 world blocks on x/z (cell = 4 blocks), ±48 on y. Winding verified for all 6 faces (CCW-outward, cross-product checked).
  • Pick order (consumes the AC-0233 stamps). _low_pick() scans band_buckets in rank order (the AC-0233 enqueue/rewrite order) and returns the first candidate: tier 2 (FOV cone) ahead (live _look_dir dot ≤ 0) beats cone-behind beats rest (tier 3) — the spec's "nearest cone with no mesh, ahead before behind, then rest by distance". Tier is read from the e["tier"] stamp (fallback live _tier_of); a LIVE tier guard (_tier_of(dx,dz) < 2 → skip) protects against stale stamps mid-rescore/recenter — tier 0/1 are NEVER low. Candidates: data, no high, no fresh low (stale low = edited after build → rebuild candidate). No-candidate verdicts are cached per (pool_ver, pcx, pcz, want) (zero cost between landings/edits; edits clear the cache in _dirty_add). Scan capped at 2048 visits.
  • Per-frame budget. _low_step() (in _process after _drain_build_queue): exactly ONE pick + ONE textured-low build per frame while the heavy pipeline is active (the rescan after a build is the cost; 1/frame keeps ahead of data landings, which arrive at the TG rate — the far fill is data-limited, not build-limited). R16 evidence: static/moving p50/p95 = 3/5 ms — the exact AC-0233 baseline (an early 2-builds/2-rescans version measured 14/21 ms at 60 fps pacing; the throttle + cache made the steady-state cost invisible).
  • No downgrade; high replaces low. A chunk that gains a HIGH mesh — via the worker handoff (threadmesh_handoff) or any legacy SYNC fallback (_mesh_dispatch_impl data-empty / missing-neighbor / cap-drop, create_chunk mesh_now) — drops its placeholder via drop_low() (+ fog live-counters) and bumps low_upgrades_n. low_downgrade_n exists and must stay 0 — no path ever converts a high back to a low; upgraded far chunks keep band 3 (no reband), the handoff band check stays consistent.
  • Idle catch-up. When the heavy pipeline is idle (drain 0 units + TG pool empty + no loading/spawn/recenter, 10-frame grace), _low_step() dispatches low-holding chunks to HIGH through the normal TM path (nearest cone first, then rest — same _low_pick(true) order), 1/frame, defer-on-cap. The dispatch is gated on _low_upgrade_ready() (all 8 neighbors hold data) — a missing neighbor would force the sync fallback (a 300–1200 ms MAIN-thread build, exactly what AC-0160 eliminated); such a chunk keeps its low = the intended far filler (its neighbor is outside the streaming set, so it never becomes ready). Never competes with TG pool4/TM pool6 while they work — the upgrades only run in idle windows and share the TM workers.
  • Old LOD dead code removed. Band 2 is GONE: band_of() returns only {0,1,3}; deleted from chunk.gd — all LOD state (lod_pending, alt_lod, alt_slabs, alt_stamp, alt_atlas, lod_builds, lod_swaps, …) and all LOD funcs (capture_lod, lod_cache_valid, clear_lod_cache, store_lod_cache, _set_slab_lod, swap_to_cached) + the band-2 coarse ctx in build_mesh; from world.gd — LOD_HYS_* consts, the coarse ctx in _mesh_dispatch/_mesh_dispatch_edit, the LOD swap/capture block in threadmesh_handoff, the taxi/alt_lod/hysteresis block in _rec_want_step, the band-2 coarse ctx copy in the meshprobe arm; from main.gd — the lodband + lodswap mode branches and their 5 probe funcs (_lodband_test, _lodswap_test, _lodswap_snap, _lodswap_walk, _lod_fidelity, 362 lines). The C++ coarse/uv_scale ctx parse in mesh.cpp is untouched (inert, defaults false/1). Final sweep: only AC-0231 comments reference the removed names.
  • R16 arm probe (new "lod" RESULT block). _r16_lod_far() samples the resident chunks OUTSIDE the render circle (face ≤ 1, with data): far_n / far_fog / far_low / far_high / far_visible. Sampled at arm start (after build-wait, before the static phase) and again after the spin probe + a heavy-pipeline idle wait (drain 0 + TG empty) + a 450-frame settle window in which the idle upgrades run.

Notes / known flakes

  • One one-off native crash (AC-0206-class .so flake). R16 run 1 died mid-arm with signal 11 (GDScript top frame in the arm's own catch-up await; C++ backtrace libc-only) — the same family the 00z notes recorded twice during AC-0233's R16 verification ("non-reproducible, all retries clean"). Runs 2–4 (including the final) completed cleanly with 0 SCRIPT ERROR; treated as an environment flake, not a code defect.
  • Edits on low-holding far chunks are covered structurally rather than by an arm-sized probe: an edit bumps data_gen (chunk stamp) → _dirty_add clears the pick cache → the stale-low check (low_stamp != stamp()) makes the chunk a rebuild candidate → _low_build re-samples the edited data through the same _low_grid path. low_rebuilds_n = 0 in R16 because the arm's edit probe edits an in-circle (HIGH) chunk — the in-circle edit lane (dirtyQueue, AC-0233 gate #4) is the exercised path; both lanes share the sampling code. (The in-circle edit gate passes at 6.3 ms.)
  • far0.far_high = 0 in run 4 (vs 100 in run 2): the far0 sample is taken right after the build-wait; at that instant no far chunk has a high mesh yet — the run-2 value was recenter walk jitter. immediate_ok is the gate and it holds in both runs (136/136 visible either way); run 4 is the cleaner evidence (placeholders alone cover 100%).
  • fly50.fps.p95 = 84 ms (00z: ~77 ms) — the supersonic phase streams real work (same as AC-0233: not a gate; the ahead-fill/no-lost-mesh gates pass at exactly the baseline values 279/775).
