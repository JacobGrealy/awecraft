  • Banana trees — shore dirt edge only. A GDScript post-pass (godot/world/generator.gd: apply_banana_trees / apply_banana_resl) runs on every world-build landing (5 sites in world.gd: sync gen, _materialize_chunk_data, threadgen handoff, startup-gen apply, face gen). WorldGen.generate() itself is untouched — the genhash arm hashes it directly, so the AC-0215 baseline holds (verified §5). Per-column gates: base ∈ {B_GRASS, B_DIRT} at y ∈ [127,130] (the dirt↔sand transition band, SEA=126), biome ≠ forest, B_SAND within Chebyshev 3 in the shore band [118,130], water column within Chebyshev 4, roll 0.025 (hash2i(seed+919)) ≪ forest 0.14. Tree shape = the exact C++ tree-pass shape (B_LOG trunk 4–6, seed+66 roll; B_LEAVES canopy).
  • Hanging fruit. 2 B_BANANA (id 28) cells per tree, replacing canopy leaves (the MC-apples pattern — the rad-2 canopy fills every air cell, so the fruit is written before the canopy and the canopy's zero-checks skip it).
  • 10-block fall → RigidBody3D bounce. world.gd _banana_tick: every 0.5 s each registered fruit within 10 blocks of the player has a 6% chance to be plucked (re-verified get_block==28 against a stale registry); the cell is cleared and entities/banana.gd (a real RigidBody3D, PhysicsMaterial.bounce = 0.45 assigned to the body's physics_material_override — in this 4.7.1 build CollisionShape3D has no material (verified by dumping a live instance's property list)) bounces against the chunk StaticBody3D colliders until it comes to rest (sleeping / |v|<0.25).
  • Pickup via interact + eat. Settled bananas use the same drop-magnet channel as entities/drop.gd (magnet <2.5 m → collect <1.1 m → inv_add(126) + Audio.play("pickup")). Item 126 "Banana": food: 4, sfx: "gorilla"; eating (existing health+stamina restore path) now plays the item's sfx field via Audio.play — the AC-0039 sound lane (AC-0039 itself is still OPEN; this is the hook only). Block 28 = non-solid cross, light-passing (pre-wired in lighting.gd), drop: 126; the mesher auto-derives its tables from Data.blocks — zero C++ changes. Art: banana crescent painted into the atlas tile at (32,32) (only that tile's pixels changed, verified by full-frame diff).

  • Pre-existing bug fixed (GDScript, 2 call sites in world.gd recenter()): the pre-warm 5×5 enqueue and the startup-burst element builder filtered their 5×5 with in_stream_set(pcx+pdx, pcz+pdz) / in_stream_set(bwx, bwz) — ABSOLUTE chunk coordinates — although in_stream_set is center-RELATIVE (all five other call sites pass the explicit delta cx-pcx/cz-pcz). At the spawn (pcx=pcz=0) delta==absolute so it always worked there; away from the origin the 5×5 was filtered against the origin's stream set — at the e2e's recenter center (1,6) only 8 of 25 pre-warm cells and 8 of 24 burst cells survived (verified via AWECRAFT_TIMING: GENBURST n=8 targeting the wrong row of chunks), so the new center's 8-neighborhood never got its data, the 3×3 never built, _spawn_fast never cleared, and the recenter's queue-rebuild slice (paused during the spawn window) plus the spawn-fast-disabled data path deadlocked the whole build pipeline. Normal walking (1-chunk recenters, post-spawn-window) masked it because the trickle data path eventually covers the gap. Fixed to pass the delta (in_stream_set(pdx, pdz)) at both sites. Behavior at the origin is bit-identical (delta==absolute), so all origin-recentering gates are unaffected — re-verified post-fix.
