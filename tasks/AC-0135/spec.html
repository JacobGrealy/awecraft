Task-specific requirements

  • Core behavior: at night, a cell with eff 0 (sealed cave, no light source) renders at ≈ 0.75 on the 0–15 scale (0.05 normalized), not 0. User gate verbatim: "midnight with no torch still faintly visible, cave 0.75 not 0".
  • Nightness scaling: the floor scales with nightness — full at midnight (u_day = 0), zero in day (u_day = 1) — so daytime output is EXACTLY unchanged (floor contribution 0.05×(1−u_day) → 0 in day).
  • Render-side only: implement in the 4 chunk_lit_* shaders (opaque/cutout/flower/fluid) via the existing vColor/u_day light path (a per-fragment max() floor, or an equivalent u_night_floor-style uniform pushed alongside u_day from world.gd — builder's choice, simplest correct mechanism). NO changes to the eff array, light build, strips, ring, mesher, or the AC-0129/AC-0134 lighting machinery. MINFO must stay byte-identical (face culling reads the eff array, which is untouched).
  • Max() semantics: the floor is a MINIMUM — cells with eff ≥ 1 are unaffected at night (0.05 < their light), so no existing lit value may change; only eff-0 (and sub-floor) cells rise to 0.75/15.
  • Interactions to verify: player light (AC-0035 per-fragment additive) and stars (u_opacity = 1−day) compose independently of the floor — the floor must not double-brighten; check in the viewlight probe (if its cave cell is measured at night, a +0.05 shift on the eff-0 base is EXPECTED and must be documented, order = floor first, player light additive after).
  • Web reference (Run-1): check whether the frozen web build (index.html) night-lighting path already has an ambient floor of its own. If YES → port its exact value/mechanism verbatim (web is the source of truth). If NO → implement the user's ~5% spec as a user-directed feature (class ii — user note wins over web silence).
