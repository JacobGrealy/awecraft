AC-0066 — Viewmodel: held items must match their world form

User 2026-08-21: "the object like flowers that are rendered in 2d should also be rendered in the same way when you hold them instead of as a block. Also, for blocks that you hold, they should look the same as the big blocks just with the entire block scaled down, currently only part of the texture shows on the block and they look different than the blocks in the world."

Root cause (coordinator-verified)

player.gd:357-427: held_box is a single BoxMesh scaled 0.35 with ONE StandardMaterial3D material_override (built in _held_mat, :441) — one icon-ish texture stretched over all 6 faces, so (a) flowers/cross blocks show as a SOLID cube and (b) normal blocks show only part/a single crop of the texture on every face, not the per-face world tiles. held_sprite (Sprite3D billboard) is only used for non-block items (items 100+), NOT for block/cross ids.

Requirement

  • (a) Cross/billboard blocks (flowers 18/19, any cross:true block, leaves-if-cross): when held, render the same cross shape the world chunks use (two crossed quads), scaled down (≈ same scale as held_box, 0.35), with the real atlas tile + Data.block_tint, same alpha behavior as the world cross/leaf material. Never a solid box.
  • (b) Normal solid blocks held: the held block must look like the world block scaled down — each of the 6 faces must show the ENTIRE per-face tile (top face → block's "top" tile, side faces → "side" tile, bottom → "bottom" tile), exactly like chunk meshing, not a partial crop or one texture on all faces. Implement by building a small 1×1×1 box ArrayMesh whose per-face-group UVs come from Data.block_rect(id, face_name) (the same API chunk.gd uses in _face_rect/:108-131) + Data.atlas_tex, per-face vertex-color tint via Data.block_tint(id, face_name) the same way chunk.gd applies it (:249). Cache the mesh per block id.
  • Scope guard: DO NOT redo the held tool voxel models (pick/axe/shovel/sword) — that's AC-0070's job. Keep the existing tool voxel path (_setup_held_tool) working as-is; only touch the block + cross-item held rendering. Keep the AC-0060 sway + AC-0048 swing driving hand_root (everything must keep swaying/swinging). held_sprite behavior for pure-items (100+) and held_fist (empty hand) stay.
  • Positioning/scale: keep the current held offset/scale so the hand still reads naturally (0.35 scale is fine; tweak slightly only if a full-UV face looks too small — but do NOT move the hand position).
