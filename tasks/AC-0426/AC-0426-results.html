AC-0426 — trees render as black silhouettes in daylight

Verdict. FIXED, behind a switch, default conservative. The trunk of the tree ~54 m ahead of spawn (the AC-0425 f1 "blob") reads as a black silhouette because the top log cells are ring-enclosed by their own crown: the sky pull never reaches their faces, there is no block light, and the display formula L = 0.20 + 0.80·max(u_day·s, g) rests on the flat floor at every time of day — the dark bark/leaf atlas cells × faceShade × floor are sub-8-bit, so the pixels come out exactly (0,0,0). The fix adds a sky-ambient term that tracks the sky's actual day factor at that hour to the four chunk_lit_* shaders: L += u_amb·u_day·step(m_direct, 0.08) (GLSL argument order — 1.0 iff the face is at the light floor, i.e. effectively unlit; the mask's threshold is MIN_AMB = 0.08, the constant chunk.gd:995 clamps the light scalar to — see deviation 2). A tree at noon lifts from the floor to L ≈ 0.61 (measured: 1,320 blob pixels change, bark pixels read e.g. (44,15,0) where they read (0,0,0)); a tree at midnight stays exactly black (u_day = 0 kills the term bit-for-bit — the night check in §7 is measured AND provable); every face with real direct light (pull ≥ 21/255) is untouched at any hour, and the open terrain is pixel-identical (0 px in the ground band, §6). Switch: Settings ambient_sky (default OFF = today's behaviour, proven pixel-identical in §4) + AWECRAFT_AMBSKY=0|1 harness env (boot preload, no save) — the project's standard look-change pattern (settings row, clamp chain, change-gated push in world._ac0401_push, shader default 0.0 short-circuit).

Render caveat: frames are lavapipe Vulkan (the SHIPPED Forward+ path, the mandatory boot line Vulkan … - Forward+ - … llvmpipe (LLVM 20.1.8, 256 bits) present in every render log), 1280×720, R24, the default boot camera — the AC-0425 f1 viewpoint. The BEFORE frame reproduces the published AC-0425 f1 frame pixel-exact in the tree region (0/12,750 px differ at x 690–860, y 0–75; the 1.26 % frame-wide residual is the sky/satellite-body region above the horizon, shot-moment state) — so "before" here IS the published audit evidence.

2. The fix

// the four chunk_lit_*.gdshader (contract comment in chunk_lit_opaque.gdshader):
float m_direct = max(u_day * COLOR.r, COLOR.g);
float L = 0.20 + 0.80 * m_direct;
L += u_amb * u_day * step(m_direct, 0.08);   // AC-0426: 1.0 iff m_direct <= MIN_AMB (at the light floor)
  • Option chosen (ticket menu): option 2 + the time-of-day variant — an effectively unlit face falls back to a sky-ambient that reflects the sky's actual brightness at that hour (u_day is DayNight.day(t): exactly 0.0 at night, 1.0 at noon), rather than the constant floor. Rejected: raising the 0.20 floor (user-directed value; it sits in the lit path too — const+gain = 1.0 — so raising it brightens full sun and flattens the scene, exactly the failure mode the ticket warns about); re-baking / different term combination (touches generation-fed data, owes the mesh re-bake + the bake standing set, for a look change).
  • DEVIATION 1 (caught by measurement): the first implementation of the mask was 1.0 − step(0.0, m_direct) — but m_direct is non-negative by construction, so that mask is always 0.0 and the term was dead. The A/B measurement caught it (the ON frame came out byte-identical to BEFORE); the second-pass mask was step(m_direct, 0.0).
  • DEVIATION 2 (caught by measurement): the strict-zero mask STILL produced a byte-identical ON frame — because the light scalar is clamped to the MIN_AMB = 0.08 floor at mesh time (chunk.gd:995), "zero light" is unreachable: an unlit face stores 20/255, not 0.0 (the 4,461-vertex probe: zero at 0.0, r_min = exactly 20/255). The shipped mask is step(m_direct, 0.08) — 1.0 iff the face is at the floor ("effectively unlit"). 0.08 is the light-layer constant itself, not a new tunable: the floor is deterministic (round(0.08·255) = 20), so 20/255 < 0.08 holds exactly, and every real pull value (≥ 21/255) stays untouched — including the 25/255 faces of the floating structure above the tree the probe column also sampled, which a wider threshold would have lifted.
  • Off state (u_amb = 0.0, the shipped default): 0.0·x = 0.0 and x + 0.0 = x in IEEE 754 → the AC-0128 formula bit-identical regardless of the mask. Proven: the off-state frame is pixel-identical to the pre-fix frame (0/12,750 blob px, §4) — and the re-targeted mask changes nothing there (0.0 multiplied by either mask is 0.0).
  • Night (any switch state): u_day = 0.0 exactly (AWECRAFT_TIME = 0.0 → clamp((sin(−π/2)+0.12)/0.35, 0, 1) = 0.0) → the added term is exactly 0.0 → the night look is bit-identical. A tree at midnight being black stays correct (the ticket's own words). Measured in §7: 0 px differ below the far-field band between the ON and OFF night frames.
  • Magnitude (ON, noon): AMB_SKY_L = 0.35 (world.gd const, measured against the atlas): a floor face lifts L 0.263 → 0.613 (×2.33) — the darkest bark cell lifts from (0,0,0)-rounding to readable dark brown (measured pixels: (44,15,0), (7,56,0) where they were (0,0,0)); a sunlit face (pull ≥ 21/255) is untouched, so the tree reads in-the-shade, not in-the-hole. Zero-light cave walls/hollows brighten by the same measured amount at day — the contrast measurement in §6 is the flattening guardrail the ticket asks for (open terrain: 0 px differ).
  • Switch (the standing look-change pattern): Settings ambient_sky bool (default false — conservative; sanitize_bool clamp; Options row "Shadowed faces: ambient sky light"), AWECRAFT_AMBSKY=0|1 boot env preload WITHOUT save (world.gd, the AWECRAFT_RAMPS/MODERN pattern), change-gated push in world._ac0401_push (value + material-set-size gate, the AC-0420 late-material pattern), shader uniform default 0.0 short-circuit. No bake, no data, no mesh — colour-only display-side.
