AC-0369 — decomposing the ~4.5 ms per-unit DRAIN dispatch cost (and the ~25 ms/frame COLLIDE share) into named terms

Role: bounded MEASUREMENT step (no optimisation, no retuning, no TASKS.yaml edit, no renders). Tree: bcdf045 (HEAD at run start; includes AC-0367's vanilla-carving terrain — NOT byte-identical to AC-0364's e39e550). Seed: 1. Knobs: AWECRAFT_LOGIC=boundary AWECRAFT_RADIUS=24 AWECRAFT_WALK=10 AWECRAFT_TICKTIME=1, ulimit -v 8388608, ONE godot run, capped (~2 min wall), one godot at a time (slot verified free before each run).

Method: the existing wprof ring splits the FRAME (DRAIN/COLLIDE/…), not the per-unit path. This run added temporary usec sub-stage brackets inside the per-unit dispatch path (world.gd: pick bracket + steady-list-rescan bracket + per-lane unit wall + per-term brackets in _build_unit_hslab / _mesh_dispatch_hslab / _low_dispatch_slab / the data pass; chunk.gd: four sub-brackets inside _build_slab_collision) gated to the drain's steady loop by a _sub_in_drain flag (so the star-remesh lane, the promo burst, the recenter re-dispatch and the loading window do not pollute the lane terms). One WPSUB line every 60 frames (28 counters). Brackets removed after the run; G0 re-verified on the pristine tree; git diff --stat empty on both touched files. Nothing outside the brackets was changed, so the run measures the shipped dispatch path (instrument validation in §7).

Verdict (from numbers): a dispatch unit is NOT 4.5 ms. One HIGH-lane unit (one high-slab dispatch) costs 0.23–0.40 ms main-thread (walk-phase 0.395 ms: 58–61% of it the engine's star light payload capture slab_light_payload+box_settled+box_epochs, 19% the 8-neighbour snap_rings C++ calls, 8% full-column slab copies, 9% entry-dict/ctx, 3% eff-lookup + pool handoff). The gen enqueue is 0.02 ms. The "4.5 ms per unit" is per-frame overhead amortised over the 6–8 units the frame's budget dispatches: the pick machinery (pool rescan + steady-list rebuild 5.4 ms/frame avg, up to 10 ms/frame + data-lane pick 2.8 ms/frame) and the staged collision lane (0–29 ms/frame, inside the DRAIN stage itself — _col_drain_step runs inside _drain_build_queue) — plus loop bookkeeping. The COLLIDE share splits per slab (1.87 ms): 42% set_faces (engine), 39% body+shape scene-tree creation (engine), 15% the GDScript vertex gather, 3% surface-array extract — 81% engine-side. The LOW lane dispatched zero far-slab units in the whole run (a regime finding, §6), so its per-unit cost is not measurable here. The ticket's later fix should target the per-frame scan machinery and the staged collision, not the dispatch call itself (§4 names the candidates with numbers).

0 units dispatched in the entire run — every WPSUB window shows lo=0. This is a regime difference from AC-0364 (same drain code, two days earlier: low 85/s vs high 5.8/s, remesh_ok: false): on the current tree remesh_ok: true, the settle gate passed and the TM cap (inflight 8) never bound, so the drain stayed high-saturated. The LOW lane's per-unit cost is therefore not measurable in this run (§6) — the AC-0364-era low numbers (the worker does the grid sample + greedy mesh; the main-thread share was sky + full-column copy + entry dict + pool, all small per the bracket design) stand as the last measurement, and a later run needs a knob (e.g. a longer walk past the high set, or forcing high defers) to re-measure it on this tree.

4. Redundant / hoistable terms (the AC-0356-shaped candidates, with numbers)

  1. The defer-frame steady-list rescan — 3,556 ms total, 5.4 ms/frame avg, up to 10.0 ms/frame — the single largest drain term (44% of all pick time). On every defer frame the 512-cap candidate list is CLEARED, REBUILT (_collect_pool × 512 entries: dict-get + _lod_tier_of + _build_ready (8 neighbour chunk-gets) + _entry_best_pending_cached probe + _grid_score) and RE-SORTED. The list is a snapshot that only needs incremental invalidation: a deferred column is removed from the list, and the rebuild is owed only when the pool itself changes (_pool_ver — the pick cache key already tracks it). Per the AC-0356 model this removes a per-frame main-thread cost wholesale: the 5.4 ms/frame average becomes the small per-change delta.
  2. The data-lane pick scan _pick_data_cached — 1,842 ms total, 2.8 ms/frame (4.8 ms/frame in the late windows), the same shape (a cached full-pool scan for the gen feed). Same incremental treatment.
  3. hi_nbs — the 8-neighbour snap_rings are recomputed per slab (24× per column) even though a neighbour's ring only changes when that neighbour's data does — 0.043–0.076 ms/unit, i.e. ~1–1.8 ms per column of pure recomputation. The AC-0354 nbs_stamps (the 4 axis neighbours' col_gen/data_gen/fl_gen epochs) already exist on the entry as the staleness key — the snapshot is cacheable per column against exactly those stamps. A per-column ring cache keyed on the stamps cuts this 24×.
  4. hi_copy — two FULL-column C++ value copies per slab (0.018–0.030 ms/unit). The comment says the copy is "shared with the handoff stale check" (the check is stamp/colgen-based — c.stamp() is copied separately); the worker's own-slab need is 1 of 24 slabs (the emit path's comment says si-1/si/si+1). Whether a 3-slab copy suffices for the high build + the stale check is a verify-then-cut candidate.
  5. hi_eff — 0.009 ms/unit, and its result is DISCARDED whenever star is on (_mesh_dispatch_hslab replaces eff with the star payload pl — this run was star-on for every unit: light_self_computes: 0). Dead work, but 9 µs — a no-cost cleanup, not a window-mover.
  6. COLLIDE: the per-slab body is the unit, but 81% of it is engine-side (set_faces 42% + tree 39%): the GD-gather 15% (0.28 ms/slab) is the only in-process-cuttable slice; the structural hoist is one body per column (24 bodies → 1: −23 shape builds, −23 node pairs per column) — but AC-0337 deliberately picked per-slab bodies so streaming slabs detach without a full-column rebuild; that is a design trade to make on purpose, with the number above, not a slip.
  7. hi_star (0.13–0.24 ms/unit, 58–61% of the unit) is the largest per-UNIT term but engine-side (C++ AweStarlight). The 3×3×3 settle boxes of adjacent slabs overlap heavily; a column-level capture (one payload per settled column instead of per slab) would be the ~24× analog of item 3 — but it needs C++-side timing before it can be believed (§6, the instrument note).

5. What could move to the worker, and what would have to change

The TG (generation) side has nothing to move: the gen enqueue is already 0.022 ms main-thread — the "99% idle" TG worker capacity is a generation-capacity fact, not a per-unit cost site. The per-unit prep that COULD leave the main thread is TM (mesh-worker) input preparation: hi_nbs (43 µs), hi_copy (18 µs), the entry dict (26 µs), and — the big one — hi_star (134 µs). What would have to change: (a) the TM worker would need a thread-safe, epoch-validated view of the live neighbours — the snapshot happens on the main thread because AC-0354's contract validates nbs_stamps against the LIVE neighbours at handoff; moving it worker-side means a C++ API where the worker takes the ring snapshot AND checks the epochs itself (the TM worker already calls AweMesh on value copies, so this is an API addition, not a threading overhaul); (b) slab_light_payload reads engine state (AweStarlight) — the TM worker does not touch star today, so star-payload offload is engine-threading work (a star API callable from a worker against a settled snapshot, or the column-level capture of §4.7 computed in C++); (c) the pick machinery (§4.1–4.2) cannot move — it schedules against the live queue on the main thread; it must be made cheaper where it is.

6. What could NOT be measured (and the instrument that would be needed)

  1. the LOW lane's per-unit cost — zero far-slab dispatches in the whole run (the drain stayed high-saturated: no TM-cap/settle defer ever let a ring-2/3 entry through the re-pick; §2.2). Instrument that would close it: a later R24 walk long enough to pass the high set (or a run with high-lane defers forced — e.g. AWECRAFT_TM_HO-style cap lowering — if one exists for the slab lane), re-running these same brackets.
  2. three long main-thread stalls outside the frame (t ≈ 13.4–27.7, 27.7–46.2, 46.2–61.1 s — 14.3/18.5/ 14.9 s of window wall each). The WPSUB cadence (60 frames) cannot see between-frame stalls, but the wall-time arithmetic proves them: a gap window's 60 frames carry only ~2–4 s of frame time (e.g. window t=27710: 702 ms of pick + 156 ms of dispatch + 326 ms of collide in 60 frames) against 14.3 s of wall — and the 289-frame storm cap (wfc_total_n) rules out ~60 × 250 ms storm frames filling the gap. No in-process bracket can attribute a stall that happens between frames. Instrument that would be needed: an external 1 Hz sampler on /proc/<pid>/stat + RSS (or perf trace -e sched:sched_switch,page-faults) running alongside the walk; candidate causes to distinguish: machine memory pressure/swap (this box's 16 GB battery, per the standing continuity note), a Godot main-loop sync operation, or an engine GC pause (the AC-0365 lesson: engine GC is not exposed in-process, and its absence here is consistent with that). Consequence for this ticket: the per-window averages understate the worst-frame composition by whatever share the stalls displaced; the per-UNIT numbers (bracketed inside the frames) are unaffected.
  3. inside the engine terms — slab_light_payload/box_settled internals (134 µs/unit) and set_faces/add_child internals (1.53 ms/slab) are C++; a C++-side timer (gdext perf counters / Godot profiler at C++ granularity) would be needed to split them further. The GD-side sub-split (shape vs tree vs gather) is the actionable half and is already delivered.
  4. immediate vs staged COLLIDE per frame — both ride the one WP_COLLIDE stage and one per-slab census; one extra counter (tag the slabs served by _col_drain_step) would split them in a later run.

7. Reconciliation against AC-0364's c ≈ 4.5 ms, and instrument validation

c is not a dispatch cost. AC-0364 computed c = (DRAIN-stage ms of the worst 20 frames) ÷ (units/frame) ≈ 25.7–48 ms ÷ 6–8 ≈ 4.5 ms. This run's brackets show what those DRAIN ms contain per frame (walk-phase average, 180 frames): pick + rescan 6.73 + data-pick 1.56 + HIGH dispatch 2.02 + staged collide 3.65 + star 0.2 + bookkeeping ≈ 14.4 ms, and the worst frames in the same window carry DRAIN 28–35 ms with collide up to 29 ms inside — i.e. c ≈ (14–40 ms per frame) ÷ (6–8 units) = the observed 4.5 ms, of which the actual per-unit dispatch (0.40 ms) is ~10%. The window is bounded by the per-frame scan machinery + the staged collision lane amortised over the budgeted units — cutting "the 4.5 ms per unit" means cutting §4.1–4.2 and the collide per-slab cost, not the dispatch call.

Instrument validation (the AC-0362 seam lesson, applied):

  • Collision sub-brackets tile exactly onto the shipped census (AC-0337's per-slab counter, already in the arm's RESULT): this run's brackets 888 slabs / 1,659.8 ms / 1.87 ms-slab vs the shipped census 894 slabs / 1,685.1 ms / 1.88 ms-slab — the 6-slab / 25 ms delta is exactly the un-emitted tail (no WPSUB window after t=68,429 ms); sub-splits sum to the per-slab total with 0 µs residual.
  • Frame-level reconciliation: the per-frame drain terms (16.4 ms full-run avg, 10.4 ms walk) sit under the DRAIN-stage ms of the corresponding worst frames (17.4–40.9), with the difference accounted by the staged collide + star + bookkeeping (worked example in §3); no term exceeds its stage.
  • Run sanity: arm ok: true, 10/10 crossings, walk_s: 10.95, storm_walk_p99_ms: 90 (gate ≤ 200), max 388, resident_final: 1453, queue_size: 1281, staged_pending_final: 0 — same shape as AC-0364's run (queue flat ~1,255–1,352, in-radius high growing 13→97 during the walk here vs 13→84 there).
  • Deviation (stated, not hidden): the run measured on bcdf045 (post AC-0367 terrain: 66% cave-free columns) is not AC-0364's tree; the lane-mix difference (§2.2) is the visible consequence. The per-unit terms are tree-local measurements of the shipped dispatch path (the brackets changed no behaviour — G0 with brackets: rc 0, zero SCRIPT ERROR; pristine re-verified: rc 0, zero SCRIPT ERROR; git diff --stat empty on godot/world/world.gd + godot/world/chunk.gd).
