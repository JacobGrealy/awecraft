1. Findings from the code (grep-only, functions involved)

1.1 Why the steady list rebuilds every defer frame (world.gd 8162–8270)

steady_list is a per-frame local of _drain_build_queue. On every defer frame the first defer re-runs _collect_pool(true, false, maxb, false) (up to PICK_POOL_CAP=512 entries: dict-get + chunk-get + _lod_tier_of + _build_ready (8 neighbour chunk-gets) + far pending probe) + _grid_score per admitted entry + sort_custom. The pick cache (_pool_ver-keyed) protects the TOP pick only — the steady list never consults it. That is the 5.4 ms/frame.

Consequence: every list change is either a single-entry event or a domain move. A single-entry event costs a binary insert / remove (µs at ≤512–1,300 slots); a domain move costs one full rebuild (the exact pre-change scan). This is the AC-0356 shape: the per-FRAME main-thread cost is removed wholesale and replaced by per-CHANGE deltas.

1.3 Why _pick_data_cached rescans every frame (world.gd 7786–7833)

Its cache key is _pool_key(maxb) + tg_inflight.size() + io_inflight.size(). The TG pool churns (enqueue/land) every frame in the walk regime, so the key misses every frame → full _collect_pool(false) rescan + rescore. The data-lane score is taxi × 10000 ONLY (no-data chunks have no pending → layer 0) — a pure function of the domain. So the data list needs membership events (queue add / data land / removal) and domain rebuilds — the in-flight dedup set is a skip-walk at pick time, not a key element.

1.4 The snap_rings inputs and the AC-0354 contract (world.gd 7293–7312, handoff 6295–6322)

mc.snap_rings(nc.data, nc.fl, dx, dz, nc.gen_keep, nc.far_payload()) is a pure function of the neighbour chunk's state, which is pinned by (col_gen, data_gen, fl_gen) (edits bump data_gen — chunk.gd 648; landings bump data_gen+fl_gen; full regens bump col_gen; gen_keep/far_payload are set at those same landings). The handoff validates the entry's nbs_stamps (the 4 AXIS neighbours' epochs) against the LIVE neighbours — a mismatch drops + re-dispatches with a fresh snapshot. A cache keyed on the all-8 neighbours' epochs (strictly more than the contract's axis set — a stale DIAGONAL ring is impossible, which today's per-slab re-snapshot also guarantees) and carrying the same axis-only nbs_stamps into the entry preserves the contract exactly: ring + stamps are captured atomically, verified against live state at dispatch, re-verified at handoff.

1.5 _eff_for is dead on the star path (world.gd 7532–7547, 7164–7357)

_build_unit_hslab calls _eff_for unconditionally and passes the result to _mesh_dispatch_hslab, which replaces it with star.slab_light_payload whenever star != null (7334) and ignores it entirely on the band-A path (uses _band_a_eff_for). _eff_for itself is a pure cache lookup (its only side effect is the perf_light_cache_hits counter). With star on, the result is discarded on every dispatching path. Star is live in the headless harness (unconditional AweStarlight.new() in world _ready; the harness arms call world.star.* directly) — verified by a one-line probe (star_null=false, probe removed before closeout).

2. The changes (four targets, in measured-value order)

T1 — incremental build-lane steady list (the 5.4 ms/frame) REVERTED

Implemented (below), measured a real win (§5), then REVERTED: it regressed the r16 arm (far_holes 0 → 7–10, both bands; pristine 0/0). See the §4 log for the diagnosis chain and the revert decision.
  • _steady_list (sorted [score, e, c]) + _steady_idx (key→slot) became PERSISTENT members, maintained per the §1.2 event census: binary insert / remove on single-entry events; _steady_ensure(maxb) compares the score domain (last_pcx, last_pcz, _player_slab(), band0_r, medium_start_r, low_start_r, render_radius) and does one full rebuild (the exact pre-change scan) only when the domain moves.
  • the drain's defer-frame walk re-checked each offered slot against live state (the stale-list guard the AC-0335 fix added stays; the chunk is re-fetched from chunks, strictly fresher than the pre-change rebuild's stored node) and skipped steady_skip — selection is the lowest-score valid, non-deferred candidate, same priority order.
  • the TOP pick (_pick_build_cached, non-fb) walked the same list from the front with the same admission re-check — its pre-change _collect_pool rescan on every _pool_ver miss was replaced by a front-walk (usually 0–2 slots). The fb pass (include_fb) kept its own cached rescan (rare: only when the in-radius pool is empty).

T2 — incremental data-lane list (the 1,842 ms) REVERTED

Reverted with T1 (same r16 gate, same root cause class — the incremental lists). The data list itself was never the measured r16 difference, but it shares the _steady_* machinery and the green-gate constraint governs the whole change set.

T3 — per-column snap_rings cache (the 24× recompute) KEPT

_nbs_ring_cache: key → {rings, stamps(axis-only, into the entry), key8(all-8 epochs / missing marker)} inside _mesh_dispatch_hslab's main path. Dispatch verifies the cached all-8 epochs against the LIVE neighbours (8 × chunk-get + 3-int compare ≈ µs); a hit serves the captured rings + stamps atomically, a miss runs the exact pre-change snapshot loop and stores it (cap 256 columns, clear-on-full). The band-A path (one dispatch per column per residency) is left uncached and said so. The AC-0354 handoff validation is untouched and strictly MORE protected (diagonals now epoch-verified too — never weaker).

T4 — drop the discarded _eff_for (the 0.009 ms/unit) KEPT

_build_unit_hslab: var eff = {} if star != null else _eff_for(c, cx, cz); the saved-light restore is gated to star == null (with star on the restored eff would be replaced by the payload anyway). The star-null path is byte-identical to before. Census counters light_saved_restores / perf_light_cache_hits drop on star-on runs (counters, not world state — §7).
