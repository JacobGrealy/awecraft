AC-0327 — is the bedrock read a race, or is the expectation stale?

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Prove which one it is before changing anything — the ticket's own first step, and the two answers lead to completely different fixes.

1. The red, as recorded

basis reports bedrock_ok false with ocean_bedrock_y0 11 (also surface_eff/surface_sky 15, spawn_top_y 136 — the pad-era build, so AC-0314's bisect is honest). The recorded diagnosis is a boot-burst READ RACE dating to AC-0263: the arm reads the bedrock column before the startup burst has finished writing it. Pre-existing, not an AC-0314 regression.

2. Two facts that make this worth re-proving on the CURRENT tree

  • The picker moved at AC-0326 (last round). The basis sea/bedrock picker no longer scans the GDScript mirror — it now scans the generator's own analytic H over ±8 chunks and selects a different cell (cell 5 at [8,73]). So the column being read for bedrock is not the same column the original race was diagnosed on. Any conclusion from the old log must be re-established.
  • ocean_bedrock_y0 11 may simply be CORRECT. AC-0326's own dump shows block id 11 = bedrock at y0 in the C++ column (with stone 3 above it). If the arm expects 0 (or a different id) at y0, then there is no race at all and the expectation is wrong — which is the second outcome the ticket explicitly anticipates ("if it is always 11, the expectation itself is stale and the fix is to correct the arm's expected value with evidence").

3. What to do, in the ticket's own order

  1. 3.1 PROVE THE RACE (or disprove it): run the arm N ≥ 5 times on the current tree and record ocean_bedrock_y0 (and bedrock_ok) for every run. Always 11 → no race, stale expectation. Sometimes 0 / sometimes 11 → race confirmed. Report the full per-run values, not a summary.
  2. 3.2 ESTABLISH WHAT THE CORRECT VALUE IS, from the generator rather than from the arm: what block id does the C++ lane put at y=0 for that column, and what does the arm compare against? Name both numbers and say which one is wrong.
  3. 3.3 FIX THE RIGHT THING: if the expectation is stale, correct it with that evidence. If it is a genuine race, make the arm WAIT for the state it asserts — a settled/count gate, never a sleep — or, if the race is real in the GAME rather than only in the arm, fix the write ordering and say which of those the evidence supports.
