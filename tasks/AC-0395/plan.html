AC-0395 — plan: the noclip toggle (disable the player's collision for geometry inspection)

Goal

The user asked, in their words, for "an option for disabling my characters collision box so I can [fly] through blocks" — a tool to inspect misbehaving geometry without walls in the way. Ship a

Noclip toggle that disables the player's collision with the world while movement stays under the player's control. Hard requirements: the default state is byte-identical to today (the same collision, the same movement), the toggle cannot be left on by accident (default OFF, visible indicator, Options surface), and nothing else in the world changes — mobs, drops, arrows and the mine/place raycast behave as they do in both states.

Design decisions (the two the ticket leaves open)

  1. Noclip implies free flight, it is not just "collision off". With collision off alone, the walk band's 26 m/s² radial gravity would make the player free-fall through terrain — unusable for hovering over a broken chunk. The AC-0145 flight model already exists (no gravity, thrust control: WASD + A up / Shift down + sprint, the fly key F stays the exit). Noclip ON therefore sets the existing flying state and disables the player's CollisionShape3D; OFF restores both. This also satisfies "must not fight the radial gravity" by construction: the flight branch never applies gravity at any altitude. One line is owed beyond the shape toggle: the void kill (flat_h < -12) must not fire while noclip is on — the tool's purpose is being below the surface, and the void rule is a wall-in-the-way of exactly that. (Fall damage / drown / hunger already skip for flying; lava damage stays — documented, not gated.)
  2. Reached two ways: the Options-surface checkbox (persisted, default OFF) + the harness env AWECRAFT_NOCLIP=0|1. No extra key — see below.

How the toggle is reached — and why that matches this project

Every player-facing switch in this project follows the same shape (AC-0205 smooth_ramps, AC-0389 ambient_enabled, AC-0394 viewmodel_occlude, the AC-0401–0405 look toggles): a bool in Settings.DEFAULTS (defaulting to the conservative behaviour), sanitize_bool-clamped, persisted via Settings.set_value, a CheckBox row on the Options surface, and an AWECRAFT_*=0|1 harness env that preloads Settings.values without save() so arms never clobber the user's cfg. The user called the tool "an option", and the ticket's standing convention says a player-facing switch lives on the Options surface and persists — so: checkbox on the Options (Settings) tab + AWECRAFT_NOCLIP for scripted/arm use. A dedicated key is deliberately not added: the one-keystroke path is the very "left on by accident" route the ticket forbids, and the fly key already covers the in-flight exit.

The player owns the switch (like viewmodel_occlude): player.gd preloads the env in _ready (the AC-0394 seam) and syncs the live value in _process, applying on change only — no apply step in settings.gd (the cloud_deck/limb_space pattern). The state that ships is exactly today's: noclip defaults to false, the sync is a no-op, and the shape/flight/void code paths are only reached when the value changes to on.

Visible when on: a one-line label (“NOCLIP — collision off (free flight)”) on the player's existing debug CanvasLayer (the _debug_label home, player.gd _build_debug), visible only while on — the ticket's one-line indicator, in the place the project already draws debug overlays.
