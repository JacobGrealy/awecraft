AC-0117 — plan: greedy-mesh texture mismatch (AC-0106 regression)

1. Goal

Fix the AC-0106 merged-mesh texture regression — the cache-hit path of _merge_atlas() omits the "h" (extended-atlas height) key, so every chunk built after the first divides merged y-UVs by ATLAS_PX (1024) instead of the real texture height (1760) and samples another block's tile — by adding that key to the cached return so all chunks use the correct y-scale. UV-only change; geometry and the AC-0106 vertex win are untouched.

7. Risks / edge cases

  • Exact fix (chunk.gd:47, 1 line, no comments): return {"tex": _ms_tex, "rects": _ms_rects, "h": float(_ms_tex.get_image().get_height())} — the cache-hit branch must mirror the fresh-build branch (chunk.gd:107). ImageTexture.get_image() returns the stored image (no re-decode), called once per build_mesh() — negligible. Alternative (static _ms_h var) rejected as less minimal (touches 3 lines vs 1). The fresh-build and AWECRAFT_MERGE=0 fallback (chunk.gd:831-832) paths are unchanged.
  • Optional hardening (chunk.gd:427, 1 token): the tile-bearing fallback (blocks that have a tile but no strip — unreachable today, §4) divides the y-UV by Data.ATLAS_PX on the 1024×1760 texture — same bug class, latent. Change denominator to Vector2(Data.ATLAS_PX, ms_h). Behavior-identical with the current blocks table; include it (keeps G5 "only chunk.gd" true) or drop it — builder's call, note in results.html.
  • 31/32 phase drift vs the spec's "≤1px pad band" wording: the spec G2 assumes merged UVs equal per-block UVs except ≤1px. That assumption was never true: AC-0106's merged quads sample a slope-31 span over 32px-pitch strip repeats, so a W×H quad shows up to (W−1)/(H−1)px of intra-tile pattern shift vs the per-block render (1×1 quads are exactly identical — both sample [0.5, 31.5] of the same tile). This drift shipped in AC-0106 and is visually benign for the noisy tiles used; fixing it would require re-designing the strips (31px pitch bleeds across tile edges; per-block UVs kill the vertex win). Out of scope for AC-0117 — the user's report is about wrong TILES. G2 therefore gates on "no foreign-tile substitution" (crops + diff-band analysis), not strict pixel identity; report the measured residual % in results.html. If the residual % surprises (≫ pre-fix 1.97%), stop and re-check rather than paper over it.
  • Vertex impact: zero — quads/groups unchanged, UV-only. G4 expects 125552 exactly (AC-0106 r4 seed-44 measurement). Merging is NOT disabled (spec: do not remove the win).
  • Why AC-0106's gate missed it: its A/B used seed 44 (R=1 iso ≈ sky + spawn-chunk land only) — and the spawn chunk (0,0) is the FIRST chunk built, the only one with the fresh-build "h" key → pixel-identical by construction. G2 uses seed 16 + top view to make every chunk visible.
  • genhash/battery risk: none expected (no data/geometry change); genhash still mandatory (world/ touched) and must match AC-0106 byte-for-byte.
  • Fallback if post-fix A/B still shows a foreign tile: strip contents and UV math are both numerically verified correct (continuity.md: 11067-cell simulation + live Godot atlas probe) — the remaining suspect would be texture upload/filtering of the 1024×1760 image (check material texture filter in _opaque_material chunk.gd:656); add a one-shot debug UV dump then, and report before continuing.
