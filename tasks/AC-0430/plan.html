2. Locate what is emitting the wrong tile

Temporary UV-census arm in harness.gd (in and out in the same task — pristine rule; AC-0427 did the same): for every resident chunk near spawn, walk the emitted accs (opaque + cutout + fluids + cross) and for each quad record (position, normal, 4 uv, the atlas tile implied by the uv). Check every face's uv against the tile its (block id, face index) OWNS (Data.atlas_rects / merge-atlas rects): flag any face whose uv falls in a different block's tile — above all the lava rect [0,32]. Run on B (find the offending faces: which block, which face, which quad path, where) and after the fix (must be zero).

Candidate mechanisms to test in code order (none assumed):

  1. A newly-extended side face (AC-0427 seamv) written with the wrong face-type rect — e.g. the merged path (qwrite_merged) still extends TOP only while the per-face path extends sides, so the two paths DISAGREE at the seam; a face whose geometry moved is still sampled by the tile of the face it was merged with / copied from.
  2. A visibility effect: the extension exposes a face (of some block, e.g. a lava pocket or a mis-id'd edge column) that was hidden on the exact seam plane.
  3. A merge-atlas strip rect or a brect lookup returning the lava rect for a non-lava (id, face).

Forbidden: patching the atlas lookup without explaining WHY the tile was chosen wrongly. The census output (which face, which rect, which code path) is the explanation.

3. The fix

Wherever the offending faces are emitted, every newly emitted face must carry its OWN orientation's tile. Expected shape (pending the census): the merged path's seam extension must apply the same edge-column side-face extension the per-face path got in AC-0427 (or vice versa — whichever the census says the game path is) WITH the per-face tile of that face's own orientation — never the copied face's rect, never a default. The seam closure (AC-0427's verified fix) must stay: extending the side face is what closes the under-void, so the fix keeps the extension and corrects the texture — not the other way round.
