AC-0430 — results (terrain faces wearing the lava texture)

2026-10-15 · subagent (UV-audit + mesher fix) · engine 4.7.1.stable · headless llvmpipe proxy renders

Verdict

FOUND + FIXED + GATED. The uncommitted working-tree mesher change (AC-0427) is NOT the cause. The defect is in the committed mesher: the non-uniform (per-corner-light) fallback quad inside emit_ro_merged (gdext/src/mesh.cpp) gets its UV from s_uvc → s_corner_uv, which divides by atlas_px (1024) — the PER-FACE path's space — but the merged build is assembled against the merge canvas (ms.h = 2144 tall). The unscaled v is read 2.094× lower on the canvas: faces walk into neighbouring atlas rows, and column-0 tiles (grass top [0,0]) land on [0,32] — the lava tile. Stepped far terrain (band A, the materialized tier-1 ring) has non-uniform step-edge faces en masse → the fallback fires en masse → "grass replaced with lava". Flat near terrain has uniform corners (all faces merge) → clean. The fix rescales the fallback quad's v by atlas_px / ms.h (one cached value per quad set — the quad then samples its own tile in the canvas's base region, pixel-identical to the strip's source tile). Post-fix r8 census: 0 foreign, 0 lava across 155,143 quads / 113 chunks (pre-fix: 30,586 + 9,316).

Root cause (proven at every level)

The emit map (verified in code): a FULL non-scoped build with a nonempty merge atlas dispatches to emit_ro_merged (canvas space: strip UVs tv = (sr.y + vv) / ms.h; plain-fallback UVs also ÷ ms.h). Every corner of a face is checked for per-corner light uniformity (s_modern_corner (msl, mosh) under the default modern_light). A face with ANY differing corner drops out of the merged strip path into the per-corner fallback (qwrite_vc, one colour per vertex). That fallback's UV came from s_uvc — 1024-space. Data (pre-fix r8): 100% of the 30,586 foreign quads are (i) single-block (corner-v span ×1024 = 31.0 — the qwrite_vc signature; zero multi-block), (ii) 2–4 distinct corner colours (per-corner light gradient), (iii) valid original-1024-space UVs for their OWN face tile (orig_uv_foreign = 100% per chunk) — and the chunks' opaque material is the 2144-tall canvas (mat_h = 2144 on every bad chunk). Worked example: stone bottom face (own tile [128,0], uv v = 16/1024) sampled at canvas y = 16 × 2.094 = 33.5 → row 1 → [128,32] (a foreign block's tile); grass top (column 0) → [0,32] = the lava tile. Band A (far + tier-1 materialized columns — AC-0321's Sept band-A texturing, which fixed the MATERIAL half: the mat landing must wear the canvas material via apply_accs) is exactly the materialized textured ring past the near tier, so its step edges are where the fallback fires; bands B/C far are no-UV average-colour placeholders (cannot wear a tile). MSDEBUG instrumentation (temp, removed at closeout) proved the merge table was FULL (72 rects, h = 2144) at ready and at every mat dispatch — dispatch/assembly table divergence ruled out.

The fix

gdext/src/mesh.cpp — emit_ro_merged, the non-uniform fallback (the ONLY call site of
s_uvc that lands on the canvas material; emit_faces keeps 1024-space UVs for the
1024-atlas per-face builds):

-   const float *uvs = s_uvc(uvc, ctx, r.id, fi, face_idx);
-   qwrite_vc(accs[r.y / 16], cc, n, uvs, FCV[fi], r.lx, r.y, r.lz, ...);
+   const float *uvs16 = s_uvc(uvc, ctx, r.id, fi, face_idx);
+   float uvs_ms[8];
+   if (ms.h > 0.0f && ms.h != ctx.atlas_px) {
+       float kv = ctx.atlas_px / ms.h;              // 1024 / 2144 = 0.4776
+       for (int j = 0; j < 4; j++) {
+           uvs_ms[j * 2] = uvs16[j * 2];            // u: unchanged (both ÷ atlas_px)
+           uvs_ms[j * 2 + 1] = uvs16[j * 2 + 1] * kv;
+       }
+   } else { /* copy unscaled */ }
+   qwrite_vc(accs[r.y / 16], cc, n, uvs_ms, FCV[fi], r.lx, r.y, r.lz, ...);

// the canvas-space formula is EXACTLY the qwrite_merged plain-fallback convention:
// tv = (tl.y + 0.5 + cvv*ppb) / ms.h  ==  (tl.y + 0.5 + cvv*ppb)/1024 * 1024/ms.h

The quad then samples its own original tile in the canvas's base region — identical pixels (the strips are repeat blits of the same original rects), so the base-region and strip-region reads agree exactly. No geometry, light, or hash input is touched — UVs only.
