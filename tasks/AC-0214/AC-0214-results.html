AC-0214 — palette-reads-remaining-gdscript-to-cpp

Move ALL remaining per-block palette reads/writes out of the GDScript hot paths into ChunkIOPalette (C++). Direct palette index ops, cached unpacked views per section. Five new C++ methods on the existing registered class (no .gdextension change): palettize_flat, slab_set, slabs_top, slab_row, slab_copy.

1. What the ops do

  • palettize_flat(arr, nsl) — flat column bytes → 24-slab paletted array (per-slab LUT + one batch bitpack, sorted palette; null if empty, n==1 uniform, n==0 raw when >16 ids).
  • slab_set(slabs, si, pos, val) — one-cell write; mirrors the GDScript _slab_write branch-for-branch (null→slab, uniform split, palette grow + bit-widening repack, raw fallback at n≥16, nz recount, null when nz==0).
  • slabs_top(slabs) — first non-null slab from the top, per-cell direct index ops + per-palette non-zero prefilter (port of Chunk.update_top).
  • slab_row(slabs, y) — 256-cell row (null slab = zero row).
  • slab_copy(slabs) — deep copy (memcpy p/i, nulls kept) for the save worker.

3. Bug found + fixed (godot-cpp COW semantics)

The first slabops A/B run failed 16/17 columns. Empirical probes (.scratch/AC-0214-gates/cow_test.gd, cowcpp_dbg.gd) established that in this godot-cpp build a PackedByteArray is an opaque engine-handle wrapper: raw ptrw() writes on a handle shared with a Dictionary do NOT propagate back to the dict entry (scalar fields and fresh-array assignments do). Fix: slab_set never mutates a shared packed array in place — every branch builds fresh std::vector<uint8_t> payloads, converts with pba_from(), and publishes a fresh Dictionary via slabs[p_si] = nd. Post-fix standalone write battery: 84/84 exact.
