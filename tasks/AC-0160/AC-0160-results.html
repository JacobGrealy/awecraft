1. Resolution per user decision (2026-08-30)

The defect had two classes. The impostor class (black floating rectangles — stale _tm_ctx has_tex/brect = −1, winding 0,2,1 → −Y faces culled, UV flipped) is MOOT by decision: the user chose to remove the impostor/billboard machinery entirely ("let's just get rid of billboards") — no fixes, no variants, no improved impostors. The drain class (spawn 3×3 = 11.7 s vs spec ~1 s, ~7,700 chunks stranded) was fixed.

  • Removed: chunk.gd build_impostor/apply_impostor/_impostor_quad_acc/_lod_material; world.gd band-2 worker/handoff/dispatch branches, _impostor_dispatch, _build_ready band-2 self-only branch. Band 2 now renders as a normal full-fidelity chunk mesh (same builder path as band 0, no tick, no collision). Zero functional references remain (commemorative comments only).
  • Added: the circle-boundary data-only ring (band 3) — 408 chunks at R=50 — so circle-edge band-2 full-mesh chunks have neighbor data to build against (without it the queue would strand ~300 chunks).
  • Fixed (the drain): root causes found by the builder — (a) the shared 6-thread pool let gen saturate the low-priority slots and starve builds; (b) the drain took sync fallbacks (270–1235 ms main-thread builds) on every cap-drop / missing 8-neighbor; (c) the recenter slice raced the spawn window (keying it on _startup_pending() disabled the data pass for the whole walk → empty world ahead). Fixes: TM builds always high priority / TG data low (caps threadgen_max=4, threadmesh_max=6, env-overridable); drain never sync-builds (all-8-neighbor-data gate, else defer); 5×5 spawn data dispatched as one high-priority 3-wide group at recenter and held until fully landed, then the 9 spawn chunks dispatch in one frame (TM cap 9 during startup); recenter slice pauses only for the one-shot _spawn_fast window; burst group task ids tracked so slot arrays stay stable under running workers.
