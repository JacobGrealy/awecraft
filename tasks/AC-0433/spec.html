Registry notes (verbatim, quoted):

1) User Story: The world is one planet and it should behave like one. Today one cube face - the
"home" face, the patch we spawn on - is built by a different set of rules than the rest of the
planet: a different cell size, a different chunk size, a different placement formula, a different
meshing lane, different coordinate conversions, and a different set of things that work on it at all
(mobs, spawns, entities). That is why seams behave differently depending on where you stand, why one
lane had a fix the other never got, and why "fix the seam" keeps turning into "fix the seam on one
face". When this lands, every part of the world is the same kind of thing: walking off the spawn face
changes nothing about how the ground, the seams, the mobs or the coordinates behave. The user waived
the compatibility argument for this (2026-10-15, pre-alpha): re-keying the save format and re-basing
the genhash anchor are both acceptable, so they are NOT reasons to keep the split.


2) Technical Details:

FOUND BY THE INVESTIGATION OF A USER-PHOTOGRAPHED SEAM. The user stood on a chunk line and saw a
crafting table and the neighbouring sand block each rendered stretched over the other along the whole
line. The cause of THAT artifact is the AC-0423 seam-V extension, which deliberately overlaps two
chunks' edge rows by ~650 mm; it is filed separately as its own ticket. Asking "why did only one lane
have that extension?" produced this one.

THE TWO MODELS TODAY (all read from the code, not assumed):

- KEYING AND GRID. Home = cube faces 0/1, chunks keyed by flat (cx,cz), 1 m cells, 16x16 = a 16 m
  chunk (AC-0143, AC-0306 grid lock). Non-home = faces 2-11, keyed "face:ccx:ccz", 1024x1024
  ANISOTROPIC cells per face (~6.14 m per cell in u - ARCHITECTURE.md:1017-1028), 16x16-cell chunks =
  a 49-98 m footprint. Storage routing is by face: world.gd:14741-14744 ("Face 0 (colx,colz) = flat 1m
  world columns (routes to the flat API); faces 1-11 = 1024-cell grid columns").
- PLACEMENT. Home = one rigid facet per chunk column, sphere_math.gd:332-362 (column_transform),
  mirrored for the meshing lane in gdext/src/sphere_math_cpp.h:109. Non-home = a per-chunk
  least-squares affine fit, sphere_math.gd:470-539 (face_chunk_transform), with its justification
  recorded there: a tangent-plane-at-centre construction left far-edge cells 3-4 m off the chart and
  adjacent chunks' shared edges 98-189 m apart on the mirror class, while the fit holds cells within
  ~0.4 m and shared edges within ~0.8 m. So the rule differs because the FOOTPRINT differs (16 m vs
  49-98 m), not because face 0/1 is geometrically special - that is the core finding of this ticket.
- MESHING LANES. Home builds through the C++ worker lane (World._tm_ctx; the ctx key sphere_r is set
  at world.gd:3860, 5607, 6092) and the sync path (chunk.gd:1626). Non-home builds synchronously via
  chunk.build_mesh_face (chunk.gd:1643), which sets NO sphere_r, so the AC-0423 seam extension is
  silently absent there. This is why AC-0423's first two probe rounds measured no extension at all
  (its own continuity journal records it), and why "is the other side armed?" is a question anyone
  has to ask.
- FRAME. The GLOBAL frame is the planet frame shifted by (0,-R,0), so the home patch's flat origin is
  the world origin and flat coords agree with global to mm near spawn (sphere_math.gd:310-314). Spawn,
  the save keys and every arm that reads the flat world sit on this anchor.
- CONSUMERS THAT ARE HOME-ONLY. Mob spawn picks the home-pair spawn region and SKIPS a face spawn
  rather than misplacing it; the mob walk/facing model is still flat (world-xz intent + rotation.y)
  with the tangent-plane port listed as follow-up; banana gravity branches "home: the world->flat
  conversion, face: the anchor's cell frame" (ARCHITECTURE.md:1008-1016).
- THE SPLIT'S OWN SEAM IS UNFILED. ARCHITECTURE.md:1027 records a crossing-row chasm 2.19 m and a
  corner 3.73 m between the net and the chart placement, and calls the split's closure "a separate,
  unfiled concern". This ticket is that closure.
- PRIOR INVENTORY. AC-0425 (audit remaining flat-world assumptions) is the census of this class. Its
  C4 finding measured a face chunk adjacent to the 3141 m patch edge sitting ~3.1 km from its
  flat-frame cull box (fixed in the dev manual-cull lane, genhash-neutral).

HYPOTHESIS TO MEASURE BEFORE ANY OF IT IS RELIED ON (explicitly NOT verified - it is arithmetic from
the code plus first-order geometry): the 2.19 m crossing row and the 3.73 m corner may not be an LSQ
in-plane residual at all. Every chunk in BOTH lanes extrudes its columns along the radial at the
CHUNK CENTRE (home: Basis(x*s, n, z*s) with n at the centre, sphere_math.gd:336-362; face:
"local +Y = the radial at the chunk centre", sphere_math.gd:474-475). Two adjacent chunks therefore
part with height by (centre separation) x h/R:

  - 16 m chunks: 16 x 140 / 4072 = 550 mm, against the 552-558 mm crack AC-0423 measured. Its own
    K1[k] = -To.m[1][0] (mesh.cpp:1043-1052) is already a linear-in-height model of exactly this term.
  - 98 m face chunks: 49 x 140 / 4072 = 1.68 m per side, 3.4 m across - the same order as the 2.19 m
    crossing row and 3.73 m corner. A corner takes both axes' contributions, which is the right shape
    for 3.73 m.

If that holds, the crossing row is this term at a 6x larger footprint rather than a fit artifact, and
one change closes both. The existing seam probe already computes the divergence and the lean, so this
is one arm run - DO IT FIRST, in P1, and report the decomposition before any rule is chosen.

PIECES (worked one at a time; each delegated to a single blocking subagent, gated and committed before
the next starts):

- P1 DECIDE AND DOCUMENT THE ONE MODEL (design piece; documentation only, no gameplay code). One grid
  definition (cell size, chunk footprint, keying), one placement rule, one local<->world conversion
  API, one meshing lane, and the fate of the far/LOD tiers, the save keys and the frame anchor. Ends in
  ARCHITECTURE.md plus this ticket's spec, and it starts by running the measurement above. Candidate
  models, each with its cost stated rather than assumed: (a) 1 m cells and 16 m chunks on every chart -
  uniform and matches block size, with the chunk-slot count per face (~392x392) and the streaming/
  far-tier budget as the open question; (b) one fitted, chart-following placement rule at every scale;
  (c) per-vertex chart placement instead of per-chunk frames, which removes the frame divergence at
  the source instead of covering it with overlap.
- P2 ONE PLACEMENT RULE AND ONE CONVERSION API. Collapse the two math homes (the home pair in
  sphere_math.gd/.h and gen.cpp's SM_FIT_INV face fit) behind one entry point and route every
  local<->world conversion through it. The surface is already sized: 21 placement-transform call sites
  in harness.gd, world.gd, generator.gd and player.gd, plus 45 "T * Vector3(...)" conversions in 3
  files. Candidate (c) concretely: extrude each column along its OWN radial - a shear of d/R per metre
  of height, <= 0.28 m at 140 m height on a 16 m chunk and <= 1.7 m on a 98 m face chunk, under 0.2
  degrees of tilt - which makes two adjacent chunks agree at every height by construction and removes
  the need for any seam extension at all.
- P3 ONE MESHING LANE. Delete the second build lane (the separate ctx/rings path in
  chunk.build_mesh_face) so every chunk is built the same way, and make "does this placement have a
  seam rule?" a property of the PLACEMENT rather than a ctx key that has to be remembered at each of
  the four call sites.
- P4 THE CONSUMERS GO FACE-AGNOSTIC. Spawn, the player's recenter/sim frame, mob spawn (stop skipping),
  mob walk and facing, drops and entities, and the save/keys. The save re-key is explicitly accepted:
  bump the format version and reject an old save cleanly (no migration - old worlds are disposable
  during development), and re-derive the key format from the one model.
- P5 VERIFY ON THE WHOLE PLANET. The acceptance is the epic's Story 1 (docs/planet-epic.html): walk
  the x=0 midline and the +/-3141 m cube edges both ways with on_floor true, no void and no light
  seam, then circumnavigate and return to spawn. The home<->face crossing row and corner are closed
  here, and ARCHITECTURE.md:1027's "unfiled concern" is retired.

GATES. G0 semantics + census + exit status; genhash re-baselined IN THE SAME TASK as any commit that
moves placement, with the old 25/25 anchor recorded before and after rather than silently drifted;
boundary r4 walk/p95; the seam instruments (ac0423probe ext_edge/ext_overlap_mm, seamcensus) on every
piece; a whole-planet crossing arm for P5. Standing gate values that move are re-established in the
same task (godot/world/AGENTS.md), and the farab/ladder bit-exactness contracts are re-checked
wherever the placement change can reach them.

DEFERRED / OUT OF SCOPE. The seam-overlap artifact the user photographed is its own ticket and will
land first if it is cheap. The sky, satellite and cloud work is untouched. No new player-facing
setting is owed by this ticket as written, because it removes a special case rather than changing a
look - but if P1 concludes that the visible result changes, the filing rule applies and the new
behaviour ships behind a switch defaulting to the world the user already knows.
