3. The fold algebra — resolved here, do not re-derive

3.1 Plane table. A cube plane's cells are addressed by two in-plane axes; the normal axis is fixed at ±N:

planenormal axisnormal signa axisb axis
0 (+Y)y+1xz
2 (-Y)y-1xz
4 (+X)x+1yz
6 (-X)x-1yz
8 (+Z)z+1xy
10 (-Z)z-1xy

Plane id from a normal (axis, sign): axis x → base 4, y → base 0, z → base 8; id = base + 2 when the sign is negative.

3.2 One rule covers all 24 cases. When a step pushes an in-plane coordinate out of [-N, N), the cell folds onto the plane whose normal is that same axis:

  • An a-step overflow means the current plane's a axis reached +N (dir 1) or -N (dir 0); the far plane's normal is that axis with that sign.
  • A b-step overflow means the current plane's b axis reached the boundary; the far plane's normal is that axis with that sign.
  • On the far plane the coordinate along the current plane's normal axis takes N-1 when the current normal sign is +1 and -N when it is -1 — the far cell is the last row touching that edge.
  • The far plane's other in-plane coordinate carries the current cell's remaining in-plane coordinate unchanged: after an a-step that is the current b, after a b-step the current a.
  • Assign both values to the far plane's (a, b) by axis match, not by position — this is the crux and it removes the a/b swap risk entirely: for each of the far plane's two slots, look up that slot's axis in the plane table; if it equals the current plane's normal axis, use the boundary value (N-1 or -N); otherwise use the carried coordinate. Three worked placements are given below and they all fall out of that one rule.

Worked checks, hand-verified from the lattice (the probe re-checks them geometrically): plane 0 a=+N → plane 4 with a=N-1, b unchanged. Plane 0 b=+N → plane 8 with a unchanged, b=N-1. Plane 8 a=+N → plane 4 with a = the current b, b=N-1. Plane 4 a=+N → plane 0 with a=N-1, b unchanged. Each must round-trip back to the original cell.

3.3 Shape. Keep cell_neighbour's signature and return shape: {ok:true, face, i, j}, and {ok:false, reason:"invalid"} only for an invalid face/radius/cell/dir. The "cube_edge" reason disappears for valid input — if something still returns it, that is a finding to report, not to paper over. Clamp nothing: a fold result that fails cell_owner's domain is a bug.

3.4 Probe (new p2b3_probe.gd; one RESULT line; exit 1 on any failure). Sample cells on all 12 faces (i,j from {0, 1, 15, N/2, Nu-2, Nu-1} clamped to the face domain, de-duplicated).

  • T1 total adjacency. For every sampled cell and dir 0-3, cell_neighbour returns ok:true — zero sentinels across the whole sample. Report checks and sentinel_count (0).
  • T2 shared corners for every neighbour. The P2b-2 rule, now applied to folds too: the two cells' four-corner vertex_key sets intersect in exactly 2 keys and they are the expected pair for that dir (dir 1 the i+1 edge, dir 0 the i edge, dir 3 the j+1 edge, dir 2 the j edge, chart-local). This is what proves a fold is geometrically right. Report pairs and shared_mismatches (0).
  • T3 fold census. Count the T2 pairs whose result is on a different plane than the source; require folds > 100 (the coordinator measured 216 on this sample). Report folds and fold_shared_mismatches (0).
  • T4 invalid. face -1/12, R 0/negative/INF, i/j -1 and Nu/Nv, dir -1 and 4: ok:false. Report invalid_cases and invalid_failures (0).
  • Negative control. Take one real fold result, shift its carried coordinate by 1, and confirm the shared-corner test then fails (negative_detected true).
