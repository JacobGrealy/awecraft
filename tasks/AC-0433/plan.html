AC-0433 — one world model, no home face

Run 1 (measurement + this plan + first increment). 2026-10-19. The ticket's core finding — the placement rule differs between the lanes because the footprint differs (home 16 m rigid column facets vs non-home 49–98 m per-chunk LSQ fits) — is the design premise. Unification means one footprint rule; placement (and the seam behaviour) follows from it. This page records (1) the measured hypothesis, (2) the target end state and the ordered stages, (3) what run 1 lands and how it is proven.

1. The hypothesis, measured

The ticket asked whether the standing 2.19 m crossing-row split and 3.73 m corner split are the frame-lean term (each lane extrudes local +Y along the radial at its own chunk centre, so adjacent lanes diverge in height by centre-separation × h/R — the AC-0423 V-crack class at 6× the footprint), or in-plane LSQ residuals. The ac0433probe arm (godot/scenes/harness.gd) measures the exact decomposition at every home-edge cell of all eight non-home faces (8,344 sites) plus the home/home and face/face controls:

offset(h) = offset(0) + h · (n_face − n_home)        (exact by construction)
chasm(h)  = |offset(0) + h·(n_face − n_home)|

Verdict — the hypothesis is refuted as literally stated, confirmed in substance. The 2.19 / 3.73 m standing values are h = 0 base-plane splits (grid offset + the folded-net residual), not the lean term — the lean is zero at the height where they were measured. The ticket's arithmetic (49 × 140/4072 ≈ 1.68 m/side, "3.4 m across → 3.73 m at the corner") coincidentally matches the base value's magnitude but attributes it to the wrong mechanism. What is confirmed: the lean term is real, exactly linear in surface height, and equals footprint/R per metre — 16 m/R at home (the AC-0423 V-crack, reproduced), 49–98 m/R on the face lane, where the face/face seams are purely lean (base ≈ 0) and reach 2.1–4.1 m at terrain height.

Consequence for the fix strategy: the seam-V extension (AC-0423) closes exactly the lean part — so it is the right stopgap on the face lane (face/face seams: closes everything below the clamp; home/face seams: closes the lean, leaves the base for the footprint unification). The footprint unification (stages below) is what removes both terms by construction.

2. The live defect, confirmed and counted

The AC-0423 seam-V extension is armed only where the build ctx carries sphere_r: the worker ctx template (the comment at world.gd:3889 says so in writing: "the home worker ctx template; the face-chunk sync path keeps no key") and the sync home path (chunk.gd:1667). The face lane is sync-only (world.gd:15262: "the face chunk is few and the sync lane is its build lane" — all three build_mesh_face call sites are sync), so build_mesh_face (chunk.gd:1684, ctx at 1708–1713) never sets the key and the extension is silently absent there.

  • Exact count: 10 of 12 faces lack the extension (faces 2–11, the non-home faces). Faces 0/1 (home) are armed. The ticket's "11 of 12" is off by one.
  • Live proof (ac0433probe section B, chunk 4:63:1, face-top 188 m, 1,632 top-face vertices read): every edge band of the live face mesh stops exactly at the nominal footprint — home edge [0.0, 0.0], u-seam [16.0, 16.0], v-seams [0.0, 0.0] / [16.0, 16.0]. No vertex crosses local 0 or 16. Compare the home lane, where ac0423probe reads extensions to 16.88 / 0.33 local. The see-through slits are therefore live on all 10 non-home faces, up to 4.1 m wide at the 98 m-direction (u) face/face seams at terrain height.
  • The one-line arm is mathematically wrong (ticket's "unverified hypothesis" pattern, confirmed by code reading): build_seam_ext (mesh.cpp:982) hardcodes sm_column_transform for both own and neighbour frames — on the face lane it would treat face-chunk indices as home column indices (a different region of the sphere) and build garbage K tables. The fix must generalize the transforms, not just arm the key.

3. Target end state and ordered stages

End state: every part of the world is the same kind of thing. One placement rule: terrain is a field of columns, each column a rigid facet extruded along its own radial; the footprint (the facet's width) is the same everywhere. The seam behaviour then becomes a property of placement (two facets sharing an edge agree at every height by construction, up to one footprint of lean) and the per-lane special cases — the face LSQ fit, the home-edge ring resampling, the per-lane clamps — collapse or disappear.

4. What run 1 lands (P0)

  1. Probe — ac0433probe arm in godot/scenes/harness.gd (kept, like ac0423probe: the standing instrument for the unification rounds). Section A: the 8,344-site decomposition + controls (this page's numbers). Section B: the live face-chunk edge bands at the deterministic census site + the home drain state.
  2. Shared header — gdext/src/sphere_math_cpp.h gains SM_FIT_INV, sm_face_mirror_x, sm_face_chunk_transform (moved verbatim from gen.cpp, the AC-0423 pattern for the home math).
  3. Face-lane seam extension — gdext/src/mesh.cpp: build_seam_ext gains the face path. Design:
    • ctx gains face (0 = home lane = pre-feature path, byte-identical), seam_v_max (m, per-lane clamp), face_edge_class (4 × int: 0 = off, 1 = home edge, 2 = real same-face neighbour), face_edge_nb (4 × [nccx, nccz]), face_edge_home (16 × [hcx, hcz, lx, lz] — the per-cell home seam cell, mirroring _face_home_ring's resampling).
    • Own frame: home sm_column_transform (unchanged) / face sm_face_chunk_transform. Neighbour: class 2 → the same-face chunk's transform; class 1 → the per-cell home column transform (sm_column_transform(hcx_i, hcz_i, R)). Class 0 (synthetic-solid / window / sector edges) → act = false (the ring is solid but the terrain across it is owned by another face — extending into it would z-fight).
    • Unified formula (dot-product along the seam-normal axis, exact for the face frames whose local x-axis is not world-x at the home edge): 
      E_world(i, t) = (Tn.o + lxₙ·col(Tn,a) + lzₙ·col(Tn,g) + tₙ·col(Tn,1)
               − To.o − a₀·col(To,a) − i·col(To,g)) · x̂   −   t·col(To,1)·x̂
E_local(i, t) = E_world(i, t) / |col(To,a)|            (cell units; home: /1 = unchanged)
      It reproduces the home-lane formula term-for-term (verified: with x̂ = (1,0,0), L = 1, lxₙ = 0, lzₙ = i, a₀ = 16 it is exactly the shipped K0[1][i]) — the home lane keeps its own code path anyway, so byte-identity is guaranteed, not approximate.
    • The clamp and the 0.05 m margin are world-metre quantities; seam_ext_at converts through the per-edge scale (home scale = 1.0 exactly → home mesh byte-identical).
  4. GDScript arming — godot/world/chunk.gd build_mesh_face sets sphere_r + the face edge metadata; godot/world/world.gd gains _face_edge_meta, sharing its edge classification with _face_rings (one source of truth for home-edge / real-neighbour / synthetic-solid).
  5. Face clamp — 6.0 m (measured worst chasm at h = 168: 5.63 m; the u-seam lean 0.02454·t reaches it at t ≈ 244 m > realistic face terrain; in local cell units that is ≤ 1 cell of extra stretch — the UV cost is milder than the home lane's existing 3.5×).

Proven by: G0 (census + exit status), SMOKE (meshprobe — the C++ lane parity; seamcensus — the standing seam instrument), genhash 25/25 (no data/placement change → must not move), the probe's before/after (section B edge bands), the far-tier + boundary arms (the change touches the draw path at the seam), and the crossface F-audit standing values (placement untouched → must not move; the coordinator's heavy set re-runs it fresh).
