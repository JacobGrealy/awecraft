3. Edit shape

3.1 The rule (corrected after PLAN-INSUFFICIENT at run 1). Two facts decide everything, and the second one was missing from the first version of this contract:

  1. In chart index space the lattice directions are uniform on every face (verified in P2b-1): dir 0 = -i, dir 1 = +i, dir 2 = -j, dir 3 = +j. A neighbour is a lattice step, not a geometric operation.
  2. The sector/sign is DERIVED from the lattice coordinates, never carried. P2b-1's cell_owner(plane, sign, a, b, R) takes sign as authoritative, so a lattice point that crosses the sector boundary comes back with an out-of-domain index (measured: cell_owner(0, +1, -1, -3145) returns i = -1). The owning chart is a pure function of (plane, a, b):
plane classsplitting coordinateeven face (owner)odd face (owner)
0, 2, 8, 10 (non-X)aa in [0, N)a in [-N, 0)
4, 6 (X)bb in [0, N)b in [-N, 0)

So this unit changes cell_owner's signature to cell_owner(plane:int, a:int, b:int, R:float), deriving the owner rather than trusting a caller:

  • Non-X planes: face = plane (a >= 0) or plane + 1 (a < 0); i = a (even) or a + N (odd); j = b + N.
  • X planes (4, 6): face = plane (b >= 0) or plane + 1 (b < 0); i = a + N; j = b (even) or b + N (odd).
  • Invalid plane (not 0,2,4,6,8,10), or a or b outside [-N, N) -> {ok:false}.

Then:

  1. Take cell_lattice(face,i,j,R); if not ok return {ok:false, reason:"invalid"}.
  2. Step per dir on a or b.
  3. If the stepped a or b leaves [-N, N) return {ok:false, reason:"cube_edge"}. Do not implement the 90° fold.
  4. Otherwise return cell_owner(plane, a', b', R) with "ok": true. The sector crossing now falls out of the derivation - no special case.
  5. Any dir outside 0-3 returns {ok:false, reason:"invalid"}.

Also update P2b-1's probe (tasks/AC-0433/p2b_probe.gd): its T1 calls cell_owner with the old four-argument form and must be changed to the derived call; its assertions stay identical (round trip, no collisions, corners match vertex_key, negative control fires). This probe is the only permitted edit outside the two files above.

Signature: static func cell_neighbour(face:int, i:int, j:int, dir:int, R:float) -> Dictionary. cell_lattice keeps returning sign as derived convenience data, which must always agree with the range rule (the probe checks it).

3.2 Keep it small. Roughly 25 lines of code with a short doc comment. No helper tables, no per-edge cases.

3.3 The probe — four tests, one RESULT line, exit 1 on any failure. Sample cells as P2b-1 did: all 12 faces, i and j from {0, 1, 15, N/2, Nu-2, Nu-1} clamped to the face domain, de-duplicated.

  • T1 adjacency + shared corners. For every sampled cell and dir 0-3, ask cell_neighbour. When it returns ok, the two cells' four-corner vertex_key sets must intersect in exactly 2 keys and those must be the expected pair — dir 1: {vertex_key(face,i+1,j), vertex_key(face,i+1,j+1)}; dir 0: {vertex_key(face,i,j), vertex_key(face,i,j+1)}; dir 3: {vertex_key(face,i,j+1), vertex_key(face,i+1,j+1)}; dir 2: {vertex_key(face,i,j), vertex_key(face,i+1,j)}. Also verify that applying the opposite dir (1<->0, 3<->2) to the neighbour returns the original cell. Report adjacency_pairs (must be > 100) and adjacency_mismatches (0).
  • T2 sector seam, 12 named checks. Each pair below is the two charts of ONE cube plane, and each must return ok:true with the stated owner, carrying the along-seam coordinate unchanged. A-split planes: (0, i=0, dir 0) -> face 1 i=N-1 and (1, i=N-1, dir 1) -> face 0 i=0; the same two-way pair for 2/3, 8/9 and 10/11. B-split X planes: (4, j=0, dir 2) -> face 5 j=N-1 and (5, j=N-1, dir 3) -> face 4 j=0; the same two-way pair for 6/7. (An earlier version of this plan named 4/6 and 5/7 - those are opposite cube planes, not a sector pair.)
  • T3 fold sentinel, computed independently. For every sampled cell and dir, compute in the probe from cell_lattice whether the stepped a or b would leave [-N, N). That prediction must equal the API's answer: cube_edge exactly where predicted, ok everywhere else. Report fold_probes and fold_wrong_ok (calls that returned ok where a fold was predicted) — both the misprediction count and fold_wrong_ok must be 0.
  • T4 invalid. face -1/12, R 0/negative/INF, i/j -1 and Nu/Nv, dir -1 and 4: all ok:false with a reason, no SCRIPT ERROR. Report invalid_cases and invalid_failures (0).
  • Negative control. Take one valid T1 pair, shift the neighbour's j by 1 and confirm the shared-corner test then fails on it (negative_detected=true).

Additionally assert, for every sampled cell, that cell_lattice's sign agrees with the range rule of §3.1 (field sign_disagreements, must be 0).

RESULT keys: ok, sign_disagreements, adjacency_pairs, adjacency_mismatches, sector_checks, sector_failures, fold_probes, fold_wrong_ok, invalid_cases, invalid_failures, negative_detected, fails.

5. Acceptance

In-plane neighbours resolve with exact shared corners on all 12 faces, sector crossings land on the paired chart with the along-seam coordinate carried, cube edges report the sentinel exactly where the lattice predicts, and the module still has no caller.

6. Risks

A "helpful" fold implementation is the failure mode: return the sentinel. A direction convention that disagrees with the lattice will show up as a shared-corner mismatch, which is the check.
