5. Outcome — findings about the shipped default (plan §6: reported, not fixed)

Finding 1 — the shipped face aim mixes two coordinate spaces. The DDA origin (player.gd _flat_ray face branch) is the player's offset in the ANCHOR CHUNK's local cell frame — measured ocell [0.93, 139.49, 7.93] (warp on) / [0.94, 139.46, 7.76] (warp off), i.e. in [0,16), for a player whose anchor chunk is (63,63) (diag.anchor_cc), the (u~1, v~1) corner of face 5. But the block callback feeds those local indices to world.get_block_key, whose contract is ABSOLUTE face-grid columns 0..1023 (_ensure_face_chunk floors by 16). The ray walks local cells (0,136,7)-ish while the data it reads is the CHART CORNER CHUNK (0,0) — the opposite corner of the face. The game's own _sim_cell_center (the drop spawn's cell->world map) puts the aimed cell 6274.25 m (on) / 6274.16 m (off) from the eye; the arm's placed-surface model puts it 5841.189 / 5840.47 m from the aim point. A player-facing face edit does not land on the block the player's ray points at — break_ok/place_ok are true (the face-routed pipeline, AC-0309 C5, runs clean and writes face data), but the block edited is 5.8 km from the aim. Aim and data agree only for a player standing in the chart's corner chunk (0,0) region.

Finding 2 — the warp flag cannot be discriminated by this measurement. Warp OFF (5840.47 m) is NOT larger than warp ON (5841.189 m) — 0.719 m smaller, inside the ~7 m run-to-run noise floor (spawn position varies run-to-run; deviation 6). The reason: the frame mismatch (~5.8 km) dwarfs the placement residual (the cm-m scale the flag actually toggles, visible only in the node transform: identity under the warp vs the LSQ chunk_origin [2346.69, -6233.86, -2346.43] with the flag off). The plan's contingency applies: reported as non-discriminating, no tolerance adjusted.

Finding 3 — secondary frame bug in the key API (reported, not fixed; keys are read-only per plan §3). world.key_for_sphere_pos derives (u,v) from the UN-shifted position, while player_anchor shifts by (0, R, 0) into the planet frame before SphereMath.world_to_face. For the same point the two disagree on u: diag.player_key 5:281:1022/1023 vs diag.anchor_cc [63, 63] (absolute cells 1008-1023).
