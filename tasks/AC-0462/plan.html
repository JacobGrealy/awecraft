AC-0462 — prove an edit on a face lands where the player aims

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. The warp is the DEFAULT placement since AC-0460, so the thing to prove is player-facing: when you stand on a chart that is not the spawn face and break or place a block, the block you change is the one you aimed at, and the surface you hit agrees with the cell the game derives. Measure it; change no placement.

1. Goal

One arm that edits a block on a face chart with the warp on and reports, in metres, how far the surface the player hits is from where the game's own cell maths says it is — plus the same numbers with the warp off, for contrast.

2. What is already known (do not re-derive)

The player anchor (world.player_anchor, world.gd:15231), the block keys (key_for_sphere_pos, :15295) and drops all derive cells through SphereMath.world_to_face — the CHART mapping, which is the exact inverse of the pointwise warp. So with the warp on the geometry should AGREE with the cell maths; with it off, the legacy per-chunk LSQ fit is what disagrees. The arm's job is to show that in numbers, from the player's position, on a face.

4. Edit shape — the arm

  • Position the player on a face chart near the home/face boundary, the same way warpcensus does, and let the face lane stream (wait the same bounded frame count it uses). Assert the anchor's face is > 1 — if the player is still on the home pair, the arm must FAIL loudly rather than silently testing the spawn face (that would be a green test of the wrong thing).
  • Find a target with the same aim/verify approach the interact arm uses (a real aim, not a teleport into a wall). If no target is found on the face, report no_target with the anchor and position — that is a finding, not a pass.
  • Measure, before editing: aim_point (the world position the aim resolves to), aim_cell (the cell the game derives for it), and surface_error_m = the distance from the aim point to the nearest surface of aim_cell as the GAME places it (derive that surface from the cell's own bounds — do not invent a second placement).
  • Break the aimed block and assert it became air, then place a block back and assert it landed in the SAME cell. Report break_ok, place_ok, and the cell identity before/after.
  • RESULT keys: ok, face, frames, aim_point, aim_cell, surface_error_m, break_ok, place_ok, warp (0/1), fails.

6. Acceptance

A player-facing edit on a face works and the numbers show the warped geometry agreeing with the game's cell maths better than the legacy placement does. If either half fails, that is a finding about the shipped default and must be reported as such — do not adjust the placement or the tolerances to make it pass.

7. Risks

The arm's target search may land on the home pair despite the boundary position — the face > 1 assertion exists for exactly that. A silent no_target must not read as a pass.
