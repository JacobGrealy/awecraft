AC-0462 (fix) — put the face aim ray in absolute columns

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. The bug is proven (ticket journal, round 18): the face aim ray runs in the anchor chunk's LOCAL cell frame while the block API indexes ABSOLUTE face columns, so every edit on a chart other than the spawn pair has been landing on that chart's corner chunk. One function produces the frame.

1. Goal

Face edits land in the cell the player aims at, on a mirror face and a non-mirror face alike.

3. The mapping (established by the AC-0458 warp inverse; do not re-derive)

_flat_ray's face branch currently returns, for the anchor chunk (ccx, ccz):

o_local = ( o.dot(bx)/sc.x , o.dot(bn) , o.dot(bz)/sc.y )
d_local = ( ad.dot(bx)/sc.x , ad.dot(bn) , ad.dot(bz)/sc.y )      reach = REACH / |d_local|

o_local.x is the along-u cell offset inside the anchor chunk, o_local.y is height in metres, o_local.z the along-v offset. Convert to ABSOLUTE columns before returning, and flip the direction component when the mirror reverses the axis:

mirror = SphereMath.face_mirror_x(face)
abs_x  = ccx*16 + (16.0 - o_local.x  if mirror else o_local.x)
abs_z  = ccz*16 + o_local.z
d_x    = -d_local.x if mirror else d_local.x
d_z    = d_local.z

Return {"o": Vector3(abs_x, o_local.y, abs_z), "d": Vector3(d_x, d_local.y, d_z).normalized(), "reach": reach} — reach unchanged (it is already in cell units). Rationale for the mirror form: the face data layout runs its local +X against u (face_local_x = 15 − k on the mirror class), so local x = 0 is the chunk's absolute column ccx*16 + 16; the AC-0458 native warp uses the same inverse (u1024 = ccx*16 + 16 − lx). Do not "fix" this by changing get_block_key — it already applies face_local_x for absolute→slot, and the ray must hand it true absolute columns.

Why the height is untouched: the face frame's y is unscaled metres above the anchor plane, which is exactly what get_block_key's y means. Do not scale or shift it.

6. Acceptance

An edit on a mirror face and on a non-mirror face lands in the aimed cell, in both warp states, with the reported error down from kilometres to under a third of a cell.

7. Risks

(1) The mirror flip is the piece most likely to be wrong — that is what the two-chart arm exists for; if only the non-mirror chart passes, the mirror form is inverted and that is the finding. (2) Other call sites may still mix frames (_sim_get_block/_sim_set_block consume DDA coords, so they inherit this fix; visible_cell_key at 3232-3239 computes its own from world and may still be local — if the arm shows an inconsistency, report it rather than silently fixing a second place).
