Deviation / notes log

  1. top is derived by a post-gen scan, not a generator formula. update_top() scans the data (top-down, ≤256 tests per empty row, early-out) at every data-finalization point; set_local raises it monotonically between rescans (stale-high = extra work only, never wrong; stale-low impossible). The generator is untouched — genhash is identical by construction, verified empirically.
  2. Before-baseline run discipline. First R50 before attempt (new arm + pre-edit code) exited 124 with no RESULT: the arm's RESULT section referenced the new world.perf_build_worker_ms_list property (absent in pre-edit world.gd) and the arm had no progress output, so a slow headless tick masked it. Fixed (null-safe read + PERFPROG line) and re-run against pre-edit world/chunk/lighting/io staged from the git index (post-edit copies backed up; md5s in .scratch/AC-0197-gates/md5_state.txt). The scoped redefinition (top-clamped full build keeps the full/merge-atlas path) was found by review of the same pass and fixed before the after run.
  3. In-memory stays dense. chunk.data/fl keep full 98304 B; every existing consumer (get_block, fluid sim, face probes, strips) is unchanged. Sparseness = codec v3 + skipped scan/flood/mesh work. This is the lowest-risk shape of the win.
  4. Back-compat: v2 saves decode (accept {1,2,3}); writes are v3. An old reader meeting a v3 blob rejects and recomputes (fail-closed, per AC-0156 contract). AC-0175 region storage reuses encode_column/decode_column, so it rides v3 automatically.
  5. _compute_face_blk intentionally NOT truncated. Block light relays transitively across chunk boundaries from taller neighbors at any y (a torch at y≈300 on a mountain lights a sealed cave at y≈180 on a neighbor whose own top is 190) — own-top truncation would corrupt cross-boundary block light. Same cost before/after (fair comparison).
  6. Storage delta is modest by construction — v2 zlib already crushes zero slabs (before avg 4338 B, not the 8 KB in the notes). Expected win: codec section ~20% smaller uncompressed (measured 22.4% on the reference column in the format self-test), compressed delta smaller; the headline is CPU (scan 98k→~51k cells, eff flood 98k→~51k, bake-box 153600 B → ~65k B per build).
  7. D3 — pre-existing cross-thread slot race fixed (required to run the R50 gate at all). The first R50 before attempt segfaulted (signal 11) at ~22 min in the threadmesh worker's _tm_slots.get spin (a worker thread reading a Dictionary the main thread concurrently set/erases — AC-0152/AC-0178 spin pattern; Dictionaries have no internal locking). Fix: a Mutex around every _tm_slots/_tg_slots access, applied identically to the before and after code (behavior-neutral; spin semantics unchanged). Evidence: r50_before_crash1.log (propagate_notification ERROR + signal 11 backtrace, frame 80400). Re-run with the fix passed the old crash point cleanly.
  8. Arm bug in the 2nd before attempt (mine, fixed). var wml: Array = world.get(...) assigns Nil into a typed Array var, a GDScript runtime error on the pre-edit world.gd (property absent) - the coroutine died before Debug.result and idled to the timeout (exit 124). Note the meshing had COMPLETED by then (all true at ~frame 98500, PERFPROG built=7831/7845). Fixed: untyped var wml. Log: r50_before_partial2.log.
  9. 3rd before attempt killed by machine load (external). Machine loadavg rose to ~4.2 on 6 cores (external job), halving the headless tick rate 64 to 32 fps; the run would have missed its 3200 s timeout by ~2 min. Killed cleanly (no orphan), relaunched with a 4800 s timeout, completed EXIT=0. The after run shares the same load window, so the before/after comparison is load-fair; absolute ms are not comparable to AC-0178's idle-machine numbers.
  10. Two syntax slips caught by the gate run itself (fixed, gates re-run). (a) The v3 rewrite dropped return {"arr": out, "off": o} from legacy _decode_array, a parse error cascading to the save.gd autoload (2 SCRIPT ERRORs on G0; the genhash arm does not touch ChunkIO so its 25 lines were still valid, but G0 was re-run clean after the fix). (b) An orphaned over-indented line in v3_selftest.gd. Both fixed; all gates green on re-run (see table).
