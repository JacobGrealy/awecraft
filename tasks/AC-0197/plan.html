AC-0197 — sparse-air-slabs-skip-empty-top

Goal: the sky above terrain (top of each column) is all air. Stop scanning / storing / meshing / light-flooding it. #1 invariant (lossless): the sparse representation must round-trip to EXACTLY the same blocks, and genhash (25 lines) stays byte-identical. Generation code is untouched — only the representation and the per-chunk work are made sparse.

Design

  1. Per-column top — chunk.gd: var top := -1 = max y with any non-air DATA byte (water/lava count; the fl overlay always rides a fluid data id, so a data-only scan is complete).
    • set_local() (the only per-cell writer, used by set_block AND set_fluid) monotonically raises top. Stale-high is safe (only extra work); stale-low is impossible.
    • Full rescans at every data-finalization point: init_fl() (covers ALL 5 gen paths: sync gen, startup apply, threadgen handoff, materialize, face chunk), both disk-load sites (_try_disk_load, _io_read_handoff), and _apply_edits_to_chunk (an edit may clear the top).
    • update_top() = top-down scan with per-row early-out (~256 tests per empty row).
  2. Mesh build — build_accs reads ctx.get("top", -1) (default -1 = legacy, so the AC-0187 scoped edit path is untouched):
    • full builds: si1 = mini(slab_n()-1, top/16) — slabs above top are empty by definition;
    • plus y_hi = mini(y_hi, top+1) when si1 == top/16 — the rows above the topmost block are air by definition; the +1 snap/bake margin still covers face/interior sampling (bake fills to y_hi+1 ≤ top+2 ✓).
  3. Bake box — _bake_box allocates only rows y_lo..y_hi with bmn.y = y_lo (was a full w*w*h = 153600 B). Every emitter samples via (y - lmn.y) (_s_effl/_effl) — no emitter changes. The full-height call (0, -1) stays byte-identical (y_lo = 0).
  4. Light kernel — compute_light_flat_chunk_pull(..., top := -1): hact = top+1.
    • column scan runs only y < hact; eff rows above top are filled 15 directly — provably identical to the old kernel (nothing above top → open sky → eff 15 exactly; flood only raises, 15 is the max).
    • eff flood + eff blk-inject + re-flood truncated to hact (an imported raise above top is impossible: cand ≤ 14 < 15).
    • own-glow flood truncated to hblk = min(h, top+15) (glow sources ≤ top, attenuation ≥ 1/step → cannot reach above top+14).
    • imported light (neighbor strip) stays FULL height — a tall neighbor's torch can carry block light above our top; the mask there stays byte-identical to the old kernel. Cost delta is one 24k-cell inject loop — negligible.
    • _flood_flat(..., hact := -1): seed scan + upward-step bound + pattern buffer sized to the active rows; default = full height (every other caller unchanged).
  5. Codec v3 — chunk_io.gd VERSION := 3; decode accepts {1, 2, 3} (v2 = AC-0156 dense+light, decodable, never written again).
    • v3 section format: u8 n_present + n_present × u16 slab index (ascending) + self-delimiting payloads (n, bits, order, bitpack — unchanged per slab). Absent slab → zero-filled (out array pre-zeroed).
    • slabs > top/16 omitted without scanning; slabs ≤ top/16 get an early-exit 4096-byte zero scan (mid-column carved-out slabs also skip).
    • encode_column(..., top := -1) derives the top internally (_column_top) — the io write worker needs no world.gd change.
    • decoder fail-closed: count, index range/duplication, palette/bit consistency, truncated payload → reject.
    • Light section format unchanged.
  6. Dispatch — world._mesh_dispatch carries ctx_w["top"] = int(c.top) alongside the strips. apply_accs becomes range-aware (res.slabs[si - si0]) for partial full builds; apply_edit_accs was already partial-aware — untouched.

Deliberate non-changes

  • _compute_face_blk (world.gd:2466) is NOT top-truncated — block light relays transitively across chunk boundaries from taller neighbors at any y (a torch at y≈300 on a mountain lights a sealed cave at y≈180 on a neighbor whose own top is 190). Truncating it by own-top would corrupt cross-boundary block light. Same cost before/after → fair comparison.
  • In-memory representation stays dense (all consumers unchanged). Sparseness is in the codec (v3) and in the work skipped (scan/build/flood). This is the lowest-risk shape of the win.
  • Genhash path: untouched by construction (no generator.gd edits).

Risk register

  • partial res.slabs index error in apply_accs (clamped full builds produce si0..si1 only) — fixed by the range-aware loop; the pre-fix code would crash on any column with top < 383.
  • v2 saves — decode accepts ver 2 (dense path) so existing saves keep working; writes are v3.
  • eff above top — provably 15 (open sky, no attenuation path exists there); filled directly, flood never touches it.
  • mask above top+14 — the own-glow flood cannot reach there; the imported-light path is left full-height, so the mask is byte-identical to the pre-change kernel in ALL cells (including the unobservable ones).
  • stale-high top after mining — only extra work until the next rescan; correctness intact. Settle happens on any gen/load/edit finalization; disk round-trip rescans.
  • storage delta may be modest — zlib already crushes zero slabs in v2 (before avg 4338 B, not the 8 KB in the notes). The headline win is CPU; report measured bytes honestly.
