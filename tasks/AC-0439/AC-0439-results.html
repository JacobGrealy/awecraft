AC-0439 — the sky must be consistent with where the player actually is

Verdict. The user's rule is now what the code does: the sky is consistent with where the player actually is. The AC-0429 floor weight ws — which keyed below-horizon space on the sky blend (smoothstep(0, 0.3, w), 1 from ~630 m, deep INSIDE the A = 1200 m atmosphere, producing the user's "blue above, black below" frame — is now the player's inside/outside position: Aero.sky_outside(alt) = smoothstep(A, A + 0.25A, alt), pushed per frame as u_space_out (world.gd, the same seam as u_space_sky). Inside the atmosphere the below-horizon sky is the same air as the sky above (only the planet's surface ends it); outside, space with the planet as the only boundary. Both acceptance halves hold in the same build: the user's 941 m frame re-taken is one consistent sky (below-horizon rows 248.4–248.8, max single-row step 1.43, was 37.81; zero black sky pixels), and the 2141 m outside frame still shows space below the horizon (rows 0.00, spread 0.00, 1624 stars) with the planet's limb the only boundary (the only step, 21.12). The transition happens at the A shell (1200 m radial), faded over the limb's own 0.25A tail [1200, 1500] m. Ships behind the existing no_sky_floor switch (default ON; OFF stays the pre-AC-0429 path — the A/B frame at 941 m reads the same continuous-air sky, within display quantization). All light gates green: G0 rc 0 + 0/0, SMOKE ok, genhash 25/25 ×2 byte-identical to the current-tree reference, meshprobe ok, shaderforce 12/12 (sky shader 27/27 with the new uniform declared + pushed). Heavy gates are the coordinator's.

2. Where the sky was actually doing this, and where the decision is made now

In sky_on() (godot/core/aero_sky_gradient.gdshader), the floor's space weight ws drove all three of AC-0429's changes (the below-horizon fill belowc = mix(u_air, space, ws), the gradient's horizon anchor anchor = mix(horizon_color, space, ws), the horizon haze band hz *= (1-ws)) and was derived ws = smoothstep(0, 0.3, w) from the sky's A-window blend — 1 from ~630 m radial, deep inside the atmosphere (A = 1200 m). The inside/outside decision was made in the shader from the sky blend, and it fired 570 m too early.

Now: the decision is the player's radial position about the A shell, computed in GDScript and pushed per frame — Aero.sky_outside(alt_rad) = smoothstep(A, A + 0.25A, alt_rad) → u_space_out (world.gd _ac0401_push block (3), the same live radial / seam / gate as u_space_sky). The shader reads ws = u_space_out and everything else is untouched.

3. What changed (4 files, one switch)

  • godot/core/aero.gd — sky_outside(alt_rad) (the one home: A; the 0.25A tail reuses the limb's atmo_limb_falloff fraction); the ATMOSPHERE_HEIGHT consumer list gains the new consumer.
  • godot/core/aero_sky_gradient.gdshader — uniform u_space_out (default 0.0 = conservative: the floor stays air, no black floor can appear on a material that never sees the push); ws = u_space_out in sky_on() only. Untouched: sky_off(), thin = mix(mix(w*w,w,u), w*u, u_horizon) (the uniform sky transition rate stays uniform), the limb term, sun, stars, u_no_floor = 0 contract (ws unused ⇒ bit-for-bit pre-AC-0429).
  • godot/world/world.gd — _ac0439_space_out state var + the per-frame value-gated u_space_out push (render-only: no mesh, no bake, no data).
  • godot/ARCHITECTURE.md — the sky-pass note + the no_sky_floor description synced in the same task (invariant 2).

Ships behind the existing no_sky_floor switch (default ON, the user asked for it): this ticket re-keys what the switch's ON path means to the rule the user has been stating — a correction to the shipped look, not a new look option, so no second switch. OFF remains the pre-AC-0429 path bit-for-bit (the A/B reference).

4. The inside/outside transition: altitude and why

A = 1200 m radial (Aero.atmosphere_height(), env AWECRAFT_ATMO override). Below A: INSIDE — the below-horizon sky is the same air as the sky above (the AC-0428 continuous-air shape: fill u_air, anchor horizon_eff, haze band alive); the surface ends it. At/above A: OUTSIDE — the above-horizon sky is already fully space (w = 1 from A), so the floor is space with the planet's limb as the only boundary (the AC-0429 shape). The fade window [A, A+0.25A] = [1200, 1500] m reuses the limb's own 0.25A tail — the floor's last air is the grazing column the limb term already paints, and the fade runs with the player's CLIMB, not across the frame, so no single altitude shows a line. Why A and not the old w ≥ 0.3 (≈630 m): A is the sky's own space boundary — the one home for "how far up is space" that u_space_sky, the star field, the sun glow and the body already key on — and the rule is that the decision keys on WHERE THE PLAYER IS relative to that shell.
