AC-0084 — Flowers / 2D objects render as sprites, not cubes

Status: open (top priority) · Source: user report 2026-08-23 · Project: AweCraft (Godot port) · Spec reference: frozen web ../index.html — source of truth for block types + appearance.

User report (verbatim): "flowers and other 2d objects should appear as rotating sprites, not cubes."

Requirement

In the Godot build, flower/plant/cross-type blocks (poppy, tall grass, and any other planar/non-rectangular block) currently render as full cubes. They must render as sprites — cross/billboard geometry with the block texture, not solid cubes. Per the user they should "appear as rotating sprites": FIRST check the frozen web spec's block table to see exactly which block ids are cross/plant type AND how the web draws them (static crossed quads vs camera-facing billboard vs actual spin), then match the web (frozen spec = source of truth). A camera-facing billboard reads as "rotating" to the viewer; for a chunk-merged mesh the performant equivalent is crossed-quads (XQ) geometry.

Known location / state

  • godot/world/chunk.gd build_mesh — where the per-block world geometry is emitted. Find the pass that emits a full cube for cross-type blocks and route those ids to cross-quad geometry instead.
  • Existing XQ cross-quad machinery: AC-0066 already built chunk cross-quad (XQ) geometry (ALPHA_SCISSOR + CULL_DISABLED) and a held cross mesh in godot/core/held_mesh.gd. AC-0073 notes a flower is "real icon pixels on a cross-quad" in some context — reuse/adapt the XQ geometry for the world.
  • godot/autoload/data.gd (Data.blocks) — where to mark the cross/plant block ids. Derive the id list from the frozen web spec's block table, not by guess.
  • godot/core/atlas.gd / assets — block texture lookup (Data.block_rect / atlas_tex).

Scope

  • (a) Mark the cross/plant block ids as cross-type in the block data (from the web spec).
  • (b) In the chunk mesh, emit cross-quad billboard geometry (two crossed quads carrying the block texture) for those ids instead of a full cube.
  • (c) Keep alpha/scissor/cull correct (reuse the XQ material settings).
  • HARD GATE: this is a MESH/APPEARANCE change only. DO NOT change terrain or fluid DATA — the sea-stability + genhash gates must stay byte-identical.

Verification gates (hard)

G1 Headless load → zero script errors.
G2 Full logic battery 0 script errors, no data regression: AWECRAFT_LOGIC=player|interact|light|fluids|buckets each exits 0; fluids/sea results must match the known-stable numbers (sea surface/backed counts unchanged).
G3 Genhash parity: AWECRAFT_LOGIC=genhash (or the terrain hash gate) byte-identical to before — proves terrain data untouched.
G4 Render proof: an xvfb-run screenshot (R=1–2, AWECRAFT_NO_FOG=1 if needed for a clear frame) showing flowers/plants as sprites (crossed quads), NOT cubes. Save PNG into tasks/AC-0084/.
G5 Web rebuild (coordinator runs ./build_web.sh + ./build_windows.sh after the subagent).

Deliverables

  • Block-type marking + chunk cross-quad emission for cross/plant ids.
  • Render screenshot(s) in tasks/AC-0084/ + self-contained tasks/AC-0084/AC-0084-results.html (which ids became cross, before/after, gates, embedded screenshot).
