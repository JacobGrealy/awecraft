AC-0388 — recenter crossing burst over gate: close the cold set

Tree: 1e92dca (AC-0388 filed) · 2026-10-02 · headless 4.7.1, ulimit -v 8388608, one godot at a time, seed 44.
Gate (RED on the user's R24 box): crossing_burst_p50 <= 10 ms read 4.6 / 9.6 / 14.2 ms across three trees, crossing frame p95 79 ms. The ticket names the cause: the COLD fraction of the recenter sweep — columns that never rode the far band have no resident payload to reuse, so the sweep pays a synchronous generate_far (~3.3 ms) per one on the main thread.

Verdict: implemented option (a) — SHRINK THE COLD SET. The far payload (a pure f(seed, cx, cz)) is now produced at the full landing — the C++ full path already computes all three components in-scope (heff/bcode/topblk), so the 1024-byte projection rides the full landing's resl as resl[2] and is stamped dormant (the column stays full; the bytes are inert). The column's FIRST demote then REUSES the resident bytes (the AC-0387b lookup) instead of paying a synchronous generate_far. Measured with the gate's own instrument across 3 runs: the cold set is CLOSED (gen_far 0/0/0, was 41–42) and the burst tail is ~3x smaller (max 46.9–47.2 → 12.5–15.8, p95 20.2–20.3 → 8.5–13.7). The gate crossing_burst_p50 <= 10 is MET on this box: 4.0–4.4 (§5 states the honest bound and why this box could not reproduce the user's 14.2).

2. The fix (option a)

2.1 Why it is bit-exact (the hard constraint: the far lane's OUTPUT must not change)

The dormant payload is the full path's own projection, not a recompute:

componentfull path valuefar lane valueidentity
H (256 × u16 LE)heff (carved top)topfarab-verified: h_mismatch 0 (the negative-tested gate — it fails on the un-carved build)
top block (256)flat[heff] (final block at the carved top)topidfarab-verified: slab_mismatch 0/0 both grids (1080/1080)
biome bcode (256)bcodebcodebit-identical BY CONSTRUCTION: col_heights_pass derives bcode from two direct fbm2 calls (seed+21/seed+33) — a pure f(x, z, seed), independent of the field table. The full/skip/far paths all call the same pass, so the bcode cannot differ.

The projection reuses values gen_flat already computed (a ~microsecond 256-iteration copy) — it is NOT a recompute and adds NO worker task. The full landing's slabs/flow are untouched, so genhash is byte-identical and farab (which compares the far lane to the full path) is unchanged and stays green.

2.2 The code

  • C++ gen.cpp (the touched lane — native rebuild + re-stage done): gen_flat gains a p_far out-param; at the tail, when p_far != nullptr && !skip (full path only — the skip/far values are NOT the far lane's carved top), it projects heff/bcode/topblk into the 1024-byte gen_far layout. generate_resl passes it for skip==0 and rides the result as resl[2] = {h, bm, top} (the same shape as the far landing's payload). generate_flat (the genhash path) passes nullptr — untouched.
  • GDScript world.gd (no C++ needed for the stamp): threadgen_handoff now branches on the skip flag the worker ran (e["args"][5]): a far landing (==2) keeps the _gen_far_stamp path (it sets the far FLAG); a full landing carrying resl[2] calls the new _stamp_dormant_far, which retires the far flag + derived caches (clear_far_keep_payload) and stores the bytes — c.far stays false, so the bytes are inert (every reader is flag-gated on c.far; the pooled-node reset still clears them). The next _demote_to_far then takes the resident-payload REUSE branch.
Coverage: _gen_skip_flag returns only 0 or 2 (streaming never enqueues skip=1), so every streaming full landing is skip=0 (gets the dormant payload) and every far landing is skip=2. Disk-loaded full columns (not in the gate runs) and the one-frame save race are the documented residual; the fallback synchronous generate_far remains for them.
Promotion contract (ARCHITECTURE.md §6) read before touching the landing: a far→full promotion still re-seeds the whole column (the was_far branch is unchanged); the dormant stamp runs AFTER the re-seed and stores the full path's own bytes (bit-identical to the far lane's), ready for the next demote. No all-air seam is introduced.

5. Plain statement — is the gate met, and what is the honest bound?

Met on this box. crossing_burst_p50 reads 4.0–4.4 ms across 3 post-fix runs (gate ≤ 10 — 57–60% margin). The cold set — the ticket's identified cause, the deliberate price of AC-0387's synchronous generate_far on the main thread — is closed (gen_far 0, 100% reuse), and the burst tail is ~3x smaller.

Honest bound — why this box could not reproduce the user's 14.2: this box's baseline p50 was already green (4.6–4.9), so the user's RED (14.2 at R24) is box-state (a slower box with a larger resident set), not reproducible here. On a fast r4 box the median crossing carries ~0 cold demotes, so the p50 is the band-bounded recenter scan (O(ring) — scanned ~3900–4500 over the run), and the fix moves the p50 only ~0.5 ms while killing the tail. On the user's R24 box the resident set is ~1453 columns and the median crossing carries more cold demotes, so the cold set contributes more to the p50 there — removing it (this fix) is what drops the p50 back under the gate. The remaining p50 floor is the scan itself (a separate cost from the cold set, band-bounded since AC-0350); if a later R24 run shows the p50 still riding above 10 with gen_far 0, the scan — not the cold set — is the next place to look. The cold-set component, which this ticket owns, is eliminated.
