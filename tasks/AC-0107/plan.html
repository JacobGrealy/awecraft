Main thread CONSUMES in threadmesh_poll(): stale checks (D4) → c.apply_accs(res, ms_full) (ArrayMesh/StaticBody/materials/collision + last_eff = res.light). No GDScript object is ever mutated by both threads: copies in, fresh objects out.
D3 — merge-atlas thread safety (decision 3). Mechanism: the main thread pre-builds the extended atlas ONCE, before the first dispatch: the first _mesh_dispatch (and refresh_textures(), which already invalidates the cache at world.gd:211-214) calls ChunkScript._merge_atlas() on the main thread, populating the existing static cache _ms_key/_ms_tex/_ms_rects (chunk.gd:40-42, keyed by Data.atlas_tex identity — AC-0117's "h" fix at line 47 stays). Workers NEVER touch the texture or the cache: they receive a duplicated rects dict + h (UV math needs only those — _qwrite_merged uses sr + ms_h only). The Texture2D is consumed ONLY on the main thread (_opaque_material(ms_full.tex) in apply_accs). The merged-vs-plain decision is made ONCE on the main thread (use_merged = ms_full.tex != null and AWECRAFT_MERGE != "0" — mirrors chunk.gd:830-831) and is passed down consistently (worker ms vs apply texture), so worker UVs and the applied material can never disagree. No per-worker atlas rebuild, no cross-thread Texture2D reads, no writes to the cache while tasks fly (cache is written only when atlas_tex identity changes, which happens in refresh_textures on the main thread, and in-flight tasks then stale-drop via data/fl or re-dispatch).
D4 — dispatch shape (decision 4). Pool: the SAME WorkerThreadPool engine singleton AC-0082 uses (Engine.get_singleton("WorkerThreadPool") returns one shared object; AC-0082 never calls set_thread_count). Separate bookkeeping: threadmesh_inflight: Array, _tm_slots = {}, _tm_inflight_keys = {} + counters (_tm_enq/_tm_dedup/_tm_capdrop/_tm_stale/_tm_datadrop/_tm_handoff, AWECRAFT_TMDEBUG=1 prints them). _mesh_dispatch(c, cx, cz, eff) → bool (main thread, replaces the 4 production build_mesh call sites world.gd:187/203/228/399; harness site main.gd:1327 and create_chunk @607 stay sync):
1. if not threadmesh, or (cx == 0 and cz == 0) (spawn chunk ALWAYS sync — first-frame guarantee, same as AC-0082's spawn-data rule), or c.data.is_empty() (own data still generating — skip, returns false) → c.build_mesh(get_block, eff) (legacy sync path) and return true.
2. if any of the 8 neighbors has no data → sync fallback build (this is exactly today's on-demand-gen behavior; the drain's _build_ready 4-orthogonal gate is UNCHANGED, so no drain-filter change).
3. dedup: key "%d,%d" in _tm_inflight_keys → drop, _tm_dedup++, return true (the in-flight task covers this chunk — AC-0082's duplicate-enqueue-hang defense).
4. cap: threadmesh_inflight.size() >= threadmesh_max (≤6, default 3 = maxi(1, mini(OS.get_processor_count()-2, 3)), env AWECRAFT_THREADMESH_N, clamp ≤6) → sync fallback build (_tm_capdrop++; forward progress guaranteed this frame).
5. enqueue: build slot entry (D2 copies) → tid = pool.add_task(_threadmesh_worker) → _tm_slots[tid] = entry, _tm_inflight_keys[key] = tid, append tid; return true.
threadmesh_poll() (called from _process @130 next to threadgen_poll, and once from recenter next to line 804): for each in-flight tid, if pool.is_task_completed(tid): remove from inflight/slots, erase dedup key; c = chunks.get(key); if c == null or instance gone → _tm_stale++ (stale-target drop); elif c.data != entry.data or c.fl != entry.fl (player edit / fluid tick / battery reset landed mid-build) → _tm_datadrop++ + re-enqueue via the existing band queue (_enqueue_build(cx, cz); dedup key already cleared); else c.apply_accs(res, ms_full) + perf_build_ms += assembly ms + perf_build_worker_ms += worker ms + _tm_handoff++. Dirty-chunk remesh (player edit): set_block marks light_dirty → the existing flush path (world.gd:187) now routes through _mesh_dispatch with the bulk eff; fluid edits → fluid path @203; texture swap → tex path @228 + _tm_ctx rebuild. Edits during flight are neutralized by the data/fl stale check (rebuild re-enqueued). Gate/kill switch (mirrors world.gd:95-109): AWECRAFT_THREADMESH — default ON on desktop (tm != "0"), OFF if AWECRAFT_FORCE_WEB=1 or OS.has_feature("web_nothreads") (web build = sync path, byte-identical, code stays reachable); prints THREADMESH on threadmesh=true pool=N / THREADMESH off (…). _exit_tree sets threadmesh = false (mirrors @127).
