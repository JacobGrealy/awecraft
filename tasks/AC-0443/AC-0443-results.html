AC-0443 — the unexplained dark patch at the horizon

Frame under question: tasks/AC-0384/ac0384-r24-ground-west-day.png (R24, FOG_PCT 83, seed 44, T=0.5 frozen, ground level at spawn facing west; clean archive of commit 56c9095, drain 3000 frames). The whole-experience assessment flagged exactly one unattributed region: a small flat dark patch at the right horizon, ≈(30,27,23)/255, behind a sheep. This page attributes it with evidence, rules in the defect, fixes it, and re-takes the frame.

Verdict. The patch is a legitimate object — real terrain: the west-facing cliff flank of the north-west ridge at ≈120–135 m, drawn by the far LOD band (BAND B, 8×8×8 average, lod_avg.gdshader). It is not a hole, not an animal, not a tree, not a cloud, not a satellite-body leak, not a pending-slab gap. But its darkness is NOT correct at midday: the band's side faces carry the 0.2 "cave floor" light because the heightmap-sky rule marks every face at/below the terrain top as a=0, so a sky-exposed surface cliff renders at the cave floor (≈30/255) while the identical face one tier-seam closer (BAND A, chunk_lit with the AC-0426 ambient lift) reads ≈(135,116,103) — a 3.5× brightness step across the seam. That is the AC-0432 "unlit terrain = shaded, not black" collapse, fixed for the chunk tiers and never extended past the tier seam. Defect, on a real object. Fixed by extending the same measured lift (AMB_SKY_L = 0.35, Settings ambient_sky) to the band: patch box (29,29,27) → (50,40,31), frame-wide change 0.9% of pixels, all on band a=0 faces.

4. Why it is dark (the colour model, verified to a few units)

lod_avg.gdshader (pre-fix):  lit = mix(0.2, 1.0, COLOR.a)   // a=0 side face -> 0.2 "cave floor"
ALBEDO = COLOR.rgb * day.rgb(0.7529) * jit(±6%) * lit        // material is SHADED
engine: sun lambert(west face, noon, u_sun=(0,0.928,0.371)) = 0; ambient = 0.65 * sky ≈ 0.58
fog at 130 m (begin 100, end 332, eased) ≈ 4% toward (161,224,246)

(51,51,51)/255 * 0.7529 * 0.2 * 0.58 -> sRGB ≈ (40,35,30)      (observed 32,33,32)
(38,31,9)/255  * 0.7529 * 0.2 * 0.58 -> sRGB ≈ (30,26,15) + fog ≈ (31,28,19)  (observed 30,27,23)
parity: same face on the BAND A side of the seam (chunk_lit unshaded,
L = 0.20 + 0.8*m_direct + 0.35*u_day*step(...) = 0.55) -> ≈ (135,116,103)  // 3.5x brighter

The heightmap-sky rule ("1.0 above the terrain top, 0.0 at/below") cannot tell a sky-exposed surface cliff from a cave: both are "at/below the terrain top" of their own column, so both get the 0.2 floor. The near tier has a real per-face sky pull (plus the AC-0426 lift) and reads bright; the far band does not. Result: the horizon cliff wall renders as a flat near-black mass at midday — exactly the flagged patch, exactly 30/255.

6. The fix and the re-take

Change (2 files, colour-only — no mesh, no bake, no data):

godot/core/lod_avg.gdshader
+ uniform float u_amb : hint_range(0.0, 1.0) = 0.0;   // AC-0426 parity lift; 0.0 = bit-identical
  float lit = mix(0.2, 1.0, COLOR.a);
+ lit += u_amb * day.r * (1.0 - COLOR.a);             // a=0 faces only; day-gated (night ~= 1/255)
  ALBEDO = COLOR.rgb * day.rgb * jit * lit;

godot/world/world.gd (the AC-0426 push seam, block (1b) of _ac0401_push)
+ var _ac0443_lod_amb := -1.0
+ if _lod_avg_material != null and _ac0443_lod_amb != amb_v:
+     _lod_avg_material.set_shader_parameter("u_amb", amb_v)   // same AMB_SKY_L / ambient_sky switch
+     _ac0443_lod_amb = amb_v

Same measured constant (AMB_SKY_L = 0.35) as the chunk tiers, same Settings ambient_sky switch (OFF = u_amb 0.0 = bit-identical on the shader side), day-gated (at night day≈0.07 → the lift is ≈1/255: the horizon stays black at midnight), and it touches only a=0 faces (top faces and the OFF path are bit-identical).

8. Deliberately not done

  • No C++ emit-side "sky-exposure" flag for band side faces. The true fix would let the emit mark surface-exposed side faces a=1 (as the real band does) instead of lifting the 0.2 floor — that changes the far emit's contract, the farab battery, and the h-only representation; the parity lift achieves the acceptance ("the darkness is correct" → "no longer collapsed") with a colour-only, switchable, gateable 2-line change. The floor-vs-exposure distinction is the honest follow-up ticket.
  • No full-parity brightness (3.5× seam step remains, 2.7× post-fix). The band is a shaded pipeline (engine ambient × lit) and the near tier unshaded (L is the whole); true numeric parity would need an unmeasured 1.42 lift on a tier that is deliberately low-fidelity (±6% jitter, 8×8 average). The measured AC-0426 constant (0.35) is the project's own standard for "shaded, not black" — applied, not reinvented.
  • No commit/push — coordinator's closeout (delegation contract: deliver results page + report).
  • Not chased: the muted teal sky band (66,117,118-class) that the current tree shows above the ridge where the r24 commit showed bright sky — present with clouds fully off (r2), so it is the sky shader's own below-horizon output, a separate pre-existing tree difference outside this ticket's patch region.
