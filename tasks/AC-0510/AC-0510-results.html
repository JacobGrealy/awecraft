2. Deviations

AC-0510 deviations from plan.html

1. world.gd NOT edited (plan §5 row says "Edit per 3a" at "the fog uniform push and DayNight.fog_far call site"). The push there (world.gd:5461-5477, _ac0401_push block (1)) is the AC-0401 u_fog_far OWNERSHIP WALL, not an atmospheric term: the satellite body's per-fragment op ramp (satellite_body.gdshader op = smoothstep(u_fog_far, u_render_edge, d)) and every near-tier discard (lod_avg / chunk_lit_* / fluid_anim_*) ride on it. It carries no colour. The plan's own fence protects the consumer ("do not touch: the planet body"), and the wall is exactly where the satellite LOD takes over — the behaviour the user asked for ("chunks should appear out of the satellite lod"). Gating it off with fog would delete the handover. The atmospheric push path is ONLY main.gd (the env init + _update_fog), and both are now gated. Stated here, not invented: the plan's §2 location note ("the fog uniform push in world.gd") is stale — world.gd pushes the wall, main.gd pushes the fog.

2. §3c's premise is stale: core/lod_avg.gdshader carries NO haz_b. The far tier's hand-rolled haze (the AC-0384 r8 bridge, thinned by AC-0400, bridge removed by AC-0404, the duplicate deleted by AC-0415) is gone from that file — its header documents the deletion and the single-source consequence. The far tier now RIDES THE SAME ENGINE ENV FOG as the near tier, so fog OFF removes both tiers identically: no residual far-tier asymmetry survives this ticket. AC-0399's repair lives in the satellite BODY's haz_d rim (satellite_body.gdshader) — fenced ("do not touch: the planet body") and not a near-tier term. No shader edit made; nothing to remove. Reported per the gate, not silently.

3. 3a decision (the plan leaves it to me): the setting STAYS as an opt-in, default false — not removed outright. Why: menu.gd (the "Enable fog" checkbox, menu.gd:335-342, its sync at :1255, the fog_start_pct slider enable state at :1302-1303, the toggle handler at :1617-1620) is outside the plan's §5 file list; removing the key would strand those rows and the settings load-path parse branch (settings.gd:685) — the removal is a separate ticket. SAVED-CFG BEHAVIOUR (stated per the gate): - fog: a saved user://awecraft.cfg with fog_enabled=true is HONOURED — load_settings pulls the key (it stays in the table) and the per-frame _update_fog enables the engine fog. An explicit user choice is not silently dropped. A fresh/default cfg gets OFF. - wash: it was NEVER a Settings key — a saved cfg CANNOT request it. The only gate was the dev env AWECRAFT_AERO_WASH (A/B for AC-0241-era work); it now has no effect (wash_on() is false unconditionally).

4. _update_fog keeps pushing the depth WINDOW (env.fog_depth_begin/end) even with fog off. The engine applies no fog while env.fog_enabled is false, so this changes nothing visually; it keeps (a) the u_fog_far wall home (main.gd:1515 feeds the lod_avg material from env.fog_depth_end) "one number, one home" and (b) the rowless fogsettings probe's contract (the slider's live wiring) intact.

  • What they WERE hiding: (a) the per-chunk lattice + LOD slab steps at the frontier (wall-jump 2×, 300–400 m contrast ×2.3) — a crisp tier boundary is now the read; (b) part of the aerial perspective at low altitude (the contrast falloff above). At the user's documented 941 m altitude BOTH terms contributed exactly zero (ground ≥800 m, outside the 332 m fog window; wash faded to amount 0.006, sub-8-bit) — the 941 m frames are BYTE-IDENTICAL before/after (md5 match). The "blue" at 941 m was never the fog/wash: it is the satellite body's own haz model (haz_a limb + haz_d rim, AC-0390) + the sky's air fill — both fenced ("do not touch: the planet body / sky gradient") and unchanged. If the emergence still reads misty to the user, that is the body's haz model — a separate (AC-0390-class) decision.
  • The wash's measured size: isolated on the fog-ineligible body class, before−after = top (0.03, 0.35, 0.73), mid (0.64, 0.71, 1.05), bottom (1.95, 2.42, 3.71) /255 — a 1–4 unit blue lift (WASH_AMOUNT 0.03, blend_add, fading with sky_space). Real, now gone, but NOT the mist the user saw with fog off.
  • Aerial readability (gate d): at 941 m altitude still reads as altitude (byte-identical — the planet's curvature, disc and sky gradient carry it; the fog was never providing it there). At 300 m the distance cue is now texture-driven to the wall and the body's haze gradient beyond (near (71,119,49) vs body (214,248,248) — a strong depth step); the fog's partial fade is gone, honestly reported above.
