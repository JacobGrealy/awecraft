THE DIRECTION RULE (stated BEFORE the change, per plan §3.2)
------------------------------------------------------------
Each face covers HALF the edge. The along-edge cell index of a flat
position f on the face's half is:
  face  4 (+x edge, z>0 half):  cell =  z / stride      (scales from 0)
  face  5 (+x edge, z<0 half):  cell = (z+hw) / stride  (from -hw)
  face  6 (-x edge, z>0 half):  cell =  z / stride      (from 0)
  face  7 (-x edge, z<0 half):  cell = (z+hw) / stride  (from -hw)
  face  8 (+z edge, x>0 half):  cell =  x / stride      (from 0)
  face  9 (+z edge, x<0 half):  cell = (x+hw) / stride  (from -hw)
  face 10 (-z edge, x>0 half):  cell =  x / stride      (from 0)
  face 11 (-z edge, x<0 half):  cell = (x+hw) / stride  (from -hw)
stride = the along-edge cell (the halved axis, 1.00019 m — AC-0471's
per-axis scale, (W/2)/3141). raw_idx = (face == 4 or 6 or 8 or 10).

Three independent code-side sources agree on this rule:
1. _face_stream's own comment (world.gd:15212-15215): "x faces 4/6
   (z>=0): face v = z/hw; x faces 5/7 (z<0): face v = (z+hw)/hw;
   z faces 8/10 (x>=0): face u = x/hw (raw); z faces 9/11 (x<0):
   face u = (x+hw)/hw".
2. world_to_face (sphere_math.gd:175-190): faces 4/6/8/10 take the
   RAW cube coordinate (Cx/Cz); faces 5/7/9/11 take Cx+1/Cz+1 — the
   chart runs from the -hw end only on the mirror members.
3. AC-0471's measurement (its deviations D6): with the true stride,
   9/11's window is CORRECT under the +hw form; 8/10 clamp to the
   far corner — "the 8/10 direction fix stays AC-0470's work".

DEVIATIONS
----------
D1. Plan §3.2 inaccuracy — "z faces 8-11 from -hw" misquotes the code
    comment the plan itself cites: the comment says z faces 8/10 scale
    FROM 0 (raw) and only 9/11 run from -hw. Sources 1-3 above agree
    the code-side rule is 8/10 = raw, so the correct per-face rule
    (above) is what was applied — not a guessed rule. Consequence:
    faces 8/10 change behaviour; 9/11 are untouched by the edit and
    must stay green.

D2. Plan §3.3 status — the per-axis structure was already single-
    sourced by AC-0471 and is left as-is: stride = face_cell_scale
    (per-axis helper), along_max = cells_u/cells_v - 1, rows cap =
    chunks_u/chunks_v, rows = _chunks_across(win, edge-axis scale)
    (the ONE metres->chunks helper, world.gd:15116). The along-edge
    lo/hi -> cell step divides by the SAME helper stride that
    _chunks_across consumes for rows, so no second conversion path
    exists to desynchronise — the residual desynchronisation was the
    direction flag alone. The edit is therefore exactly what AC-0471
    D6 left owed: "that one flag (+ the stale comment)".

D3. Diagnostic convention — "a known flat position" per face: the
    centre of the face's half-edge (the patch centre of that face's
    span), 8 m inside the edge (the warpcensus boundary stand's
    inset; edge_dist = 8 < win = 64, so the face streams). Constants:
    R = 4000, W = 6283.185307 m, hw = 3141.592654 m, win = 64 m
    (sim_dist 4), stride = 1.000189 m, cells full/half = 6283/3141,
    chunks full/half = 393/197. pchunk = the player's own along-edge
    chunk (the centring reference — a correct window centres on it).
