AC-0470 — every chart face prestreams a sane window

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. The lap proved the world is never missing; this proves it is not arriving late. It is the prerequisite for generalising the home lane (AC-0469), because a unified lane has to do what this lane does correctly.

1. The defect, as measured

At 1 m cells the face lane's prestream window is degenerate on the z faces: faces 8/10 collapse to a far-corner clamp around chunk 195-196 of 393, and faces 9/11 were over-streaming the whole chart. AC-0471's per-axis cell counts fixed 9/11 as a side effect and left 8/10 degenerate — the remaining work is the direction/clamp arithmetic for the -Y/+Y pair members. Nothing shows as a hole only because the player's per-frame column query builds synchronously (get_block_key → _ensure_face_chunk, the is_inf-sentinel sync mesh build), i.e. the cost arrives as a hitch instead of a gap.

3. Edit shape

  • 3.1 Diagnose before editing. For each of faces 4-11, compute and record what the current arithmetic derives for cc0, cc1 and the rows count, given a player standing at a known flat position. The expected along-edge span for a player at the patch centre is roughly ±win in chunk terms — so a span that collapses to one chunk, or covers the entire 393-chunk face, is wrong. Put that table in the deviations; it is the evidence the fix worked.
  • 3.2 Fix the direction rule. The sector rule in the code comment is explicit: x faces 4/6 scale from 0, x faces 5/7 from -hw, z faces 8-11 from -hw. Faces 8/10 clamping to the middle suggests the pair-half split (each face covers HALF the edge) is not being applied on that pair. State what the correct rule is per face before changing it.
  • 3.3 Use the per-axis helpers from AC-0471 (cells_u/cells_v, and the chunk counts) rather than re-deriving a stride inline — the metres→chunks conversion must go through the ONE helper (AC-0469 stage B's _chunks_across) so this cannot desynchronise again.
  • 3.4 Do not simply widen the window. A face that prestreams all 393 chunks is as wrong as one that prestreams one — the point is a bounded window matching win, per face, in the face's own direction.
