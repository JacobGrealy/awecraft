AC-0509 — classify every home-face branch; remove the behavioural ones

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. A survey-and-classify ticket first. The deliverable is a table with no branch left unclassified, then removal of the ones that are behavioural leaks — not a blanket deletion.

1. Why this exists (the user's question)

The user, after AC-0479/AC-0482: "why do we still have a home face??? There should be no home face?" Their standing requirement, verbatim: "there are going to be multiple planets, there is no home… You fly in at whatever part of the planet you want. The experience has to be the same around the entire planet."

The distinction that decides every case:

  • LEGITIMATE — canonical chart anchoring. The flat↔sphere math and the bake need some anchor, and SphereMath.flat_to_world must assume one. Code that pre-maps into the canonical chart and then behaves identically on all twelve faces is not a home face; it is a coordinate convention.
  • NOT LEGITIMATE — a behavioural branch. Different code takes a different path depending on whether you are on faces 0/1. That is a home face, it violates the requirement, and AC-0482 proved it can be wrong by 3.3–7.2 KILOMETRES while the home face reads perfect.

  • 29 mentions of "home" in godot/player/player.gd.
  • Only three such branches exist across the whole godot/ tree, so this is a bounded job rather than a sweep.

3. What to do

  1. 3.1 SURVEY AND CLASSIFY — the primary deliverable. For each of the three face == 0 or face == 1 branches and each of the 29 player.gd "home" uses, state: what it does, which side of §1 it falls on, and if behavioural, what the two paths do differently and whether a player can observe the difference. No branch left unclassified. Names like home_point/home_cell that merely name the canonical chart's anchor are legitimate — say so rather than renaming them for tidiness.
  2. 3.2 REMOVE THE BEHAVIOURAL ONES so one path serves all twelve faces. Where a face-dependent path is genuinely required, say WHY with evidence from the geometry — not from history ("this is how it was built").
  3. 3.3 THE GATE THAT WOULD HAVE CAUGHT AC-0482. AC-0482's measurement is already a working instrument: box corner tangential error and box-up angle, per face. Build a standing check that measures it on a home face and at least one non-home face and fails if they differ in kind (AC-0482 measured ~10.9 mm / ~13.8–14.2 mm — i.e. the same class). Reuse that method; do not invent a new one. Wire it as an arm or extend an existing one, and register it in godot/harness_data.yaml if it becomes a standing row.

6. Acceptance

Every home-face branch and "home" use classified; the behavioural ones removed with per-face measurements proving no face shifted; the legitimate ones left alone and named as legitimate; and a per-face gate that is proven able to fail.

7. Risks

(1) Blanket deletion — removing canonical-chart anchoring would break the flat↔sphere math on all faces, which is far worse than the leak. (2) Renaming "home" identifiers and calling it progress: the vocabulary is not the defect. (3) A gate that cannot be shown to fail. (4) Removing a branch that turns out to be required, discovered by a green g0 and a wrong world — so the per-face measurement must accompany each removal, not just the aggregate gates.
