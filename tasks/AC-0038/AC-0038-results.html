Pool design (fixed before implementation)

One ParticlePool node (extends Node3D, godot/entities/particle_pool.gd), added by
_create_game_nodes(), exposed as Game.particles.

Structure:
  - ONE InstancedMesh3D, instance_count = CAP = 200 (the whole visible pool),
    one PlaneMesh(1x1) + one UnshadedMaterial3D (vertex-color albedo, no cull).
  - Pre-allocated packed slot arrays of length 200: pos, vel, up(radial), age,
    life, size, c0 (census emit pos). Round-robin head _rr.
  - Emission = ring write: _rr advances; if the target slot is LIVE it is
    EVICTED (drop-oldest — the ring guarantees the overwritten slot is the
    oldest live one). A burst can therefore never grow the pool.
  - Per-frame step: for each live slot  vel -= up*(9.8*dt); pos += vel*dt;
    one set_instance_transform(i, pos, shared_billboard_basis, scale) with
    scale shrinking over life. Inactive slots hold a zero-scale matrix.
    Camera-facing billboard (one basis/frame from get_camera_3d(); radial-up
    fallback basis when headless has no camera).
  - Allocations: 4 after the pool node itself, all in _ready (mesh, material,
    instance mesh, RNG). An internal counter proves zero after ready.

Event discrimination in the shared pool: a kind id per slot (4 kinds) +
per-instance colour (set_instance_color) + per-kind cfg table
{count, life, speed, size, dir bias, up boost}:
  break   12, life 0.5–0.8 s, 1.5–3.5 m/s, size .10–.20, block colour ±jitter
  hit      8, life 0.25–0.40 s, 4–7 m/s,     size .05–.09, warm, away-from-from
  arrow   10, life 0.30–0.50 s, 1–3 m/s,     size .06–.10, grey, back off -vel
  pickup  8, life 0.45–0.65 s, 0.4–0.9 m/s,  size .12–.24, soft, radial-up biased
Worst-case simultaneous = 38 of 200.

Over-cap policy: DROP THE OLDEST (round-robin overwrite). Reasoning: the point
of the pool is that a burst cannot grow it, and the player is looking at the
NEWEST event — evicting the oldest live keeps the freshest burst intact and
degrades gracefully under machine-gun mining (300 requested → 200 live, the
100 oldest are cut, no allocation, no queue).

No new sun/light convention: quads are unshaded (short bright effects, zero
lighting cost). If lit debris is ever wanted the hook is DayNight.sun_direction
(the standing convention) — nothing else is introduced.

Kill switch: AWECRAFT_PARTICLES=0 → main.gd does not create the pool; all
call sites null-check Game.particles.

Deviations

  1. MultiMesh, not InstancedMesh3D. The design above said InstancedMesh3D; this engine build (4.7.1.stable.official.a13da4feb at ~/tools/godot/godot) does not contain the InstancedMesh3D class (verified: 0 symbol hits in the binary, parse error on use, while MeshInstance3D/MultiMesh/PlaneMesh all resolve). The pool is built on MultiMesh + MultiMeshInstance3D — the engine's native instancing primitive (the class the chunks' C++ lane uses). Same contract: one mesh object, 200 transforms, per-instance colour override, zero per-frame allocation. One draw call either way.
  2. UnshadedMaterial3D absent from this build too — the quad material is StandardMaterial3D with shading_mode = SHADING_MODE_UNSHADED (same no-lighting behaviour).
  3. Material is unshaded on purpose — no new light/sun convention; the standing one (DayNight.sun_direction, godot/core/daynight.gd:73) remains the only hook if lit debris is ever wanted.

MultiMesh misconfig found by the census (deviation 1, completed)

Three engine-build quirks surfaced and were fixed before the green run (each one
aborted _ready silently-to-a-script-error and the census caught it):
  1. this build's MultiMesh has NO `material` property  -> the material rides the mesh (pm.material, the arrow.gd BoxMesh pattern)
  2. `set_instance_color_override_enabled` does not exist -> the property is `use_colors`
  3. `use_colors` must be set BEFORE `instance_count` in this build ("Instance count must be 0 to toggle...")
Until fixed, the census read live bookkeeping correctly but every set_instance_color threw an engine
ERROR (618/run) — the pool must not ship that way; the clean run 5 has only the two documented shader-noise lines.
