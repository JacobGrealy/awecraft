ALL GATES GREEN. The AC-0109 per-frame _frustum_cull_pass (extra CPU on top of the engine's automatic per-MeshInstance3D frustum culling) is gated behind AWECRAFT_FRUSTUM, OFF by default: the new default lane is the render server's built-in cull (zero script cost; _process does one bool check and the pass never runs). The manual pass is kept intact (32 m off-screen margin, slab-granular) behind AWECRAFT_FRUSTUM=manual for A/B + fallback. R16 (16-radius build + moving inside a chunk): the moving phase GAINS 198 fps in the A/B (effective fps at p50: 2 → 200; 501 ms/frame → 5 ms/frame — the manual pass re-evaluated all 933 resident r16 chunks on every camera-change frame, ~0.5 s each at r16) — the no-5fps-drop gate PASS with a large margin. Probe counters updated (new perf_cull_passes/perf_cull_flips, read by both probe arms: engine lane reports 0/0 = no manual cull work; manual R16 run 901/12821). No pop: the spin probe's on-screen-flicker gate stays 0 in both lanes (+ new per-instance counters, meaningful at H=384). G0 clean; SMOKE ok:true ×4 == AC-0211 baseline; no regression (chunkiocpp byte-identical, genhash 25/25 == AC-0188, light == standing baseline, meshprobe/stripsprobe/pullprobe 100% exact).

Margin (task item 2): the engine cull has no margin (exact AABB-vs-frustum, Godot 4.7.1 exposes no per-instance culling margin — verified at AC-0109). A slab instance entering the frustum appears exactly at the view edge — that is normal rendering, not a pop-in: nothing appears/disappears inside the view. The 32 m off-screen margin lives on the manual lane only. Keeping the margin in the engine lane would require exactly the per-frame pass this task removes — so the engine lane relies on the view-edge transition, and the spin probe's flicker gate (transitions/inst_transitions == 0) is the no-pop proof.
