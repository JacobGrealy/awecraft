Coordinator contract. Medium builder applies it with tasks/templates/implement.md. This is the reason the world does not fill, so the order is: instrument, name the reason, fix that reason, prove it with the same measurement.

1. The measurement that defines this ticket (do not re-derive)

  • Build rate: 14.2 chunks/s for 10 s, then 0.0 chunks/s for 194 s. 145 completions against 16,484 dispatch attempts.
  • 145 is exactly the taxi-8 ball (medium_start_r 8).
  • The data set converges fully (1401/1401 by ~30 s) — generation is not the problem; the build/land half stops.
  • The required set is 1401 at spawn / 2503 at a seam; what lands is STABLE (92–93 home / 74 face, leak false, keys_same) — starved, not leaking.
  • Lead hypothesis, explicitly a CODE READING not a measurement: the star pending-queue depth / settled-light gate holds dispatched units so they never complete.

5. Acceptance

The reason table exists and names the culprit, the fix targets it, the rate stays non-zero past the inner ball with a time-to-90%, terrain and light are unchanged, and voxelcost runs clean.

6. Risks

The likeliest wrong turn is "raise the cap" — if units are never revisited, raising a cap changes nothing and looks like effort. Another is disabling the settled-light wait to win rate: that trades a stall for wrong light, which is worse and would pass the rate gate while failing lightstate. If the instrumentation shows the gate is not the cause, say so plainly and follow the counts instead of the hypothesis — including mine.
