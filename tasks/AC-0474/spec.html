## 1) User Story
Fly up or walk out from where you started and the world around you stays half-built forever: the ground near you appears, and everything past it never does. It is not slow - it stops. Waiting longer does not help, and the frame rate is not the problem. This is the reason takeoff still does not look like leaving a real place.

## 2) Technical Details
MEASURED (AC-0473 M1, round 68, all on the current 1 m grid at render radius 24): the build rate is **14.2 chunks/s for the first 10 seconds, then 0.0 chunks/s for the next 194 seconds** - **145 completions against 16,484 dispatch attempts**. 145 is EXACTLY the taxi-8 ball (`medium_start_r 8`). The DATA set converges fully (1401/1401 by ~30 s), so generation finishes and the BUILD/LAND half stops. The required set is 1401 chunks standing at spawn and 2503 at a chart seam; the subset that lands is STABLE (92-93 home / 74 face, leak false, keys_same), so residency is not leaking - it is starved.
THE LEAD HYPOTHESIS (a code reading, NOT yet a measurement): the STAR PENDING-QUEUE DEPTH / settled-light gate holds dispatched units so they never complete. Verify before fixing.
TASKS:
1. INSTRUMENT the pipeline gap: count, per frame, units dispatched / units landed / units dropped, and the REASON for every drop (gate name). The settled-light gate and the star pending depth are the first suspects; the drain's own caps (`ho_cap`, the per-frame budget) are others.
2. FIX the gate that is blocking, once the reason counts name it. The fix must not disable the light-settling guarantee - if a unit waits for settled light, the bug is that the light never settles for those chunks, not that waiting is wrong.
3. PROVE it with the same measurement: the rate must stay non-zero past the inner ball, and time-to-90%-of-required-set must be reported. Then re-measure whether R24 fits in a plausible desktop budget - only then does AC-0473's lever table become a real question for the user.
