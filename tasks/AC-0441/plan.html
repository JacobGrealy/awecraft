AC-0441 — cloud-deck banding and moire at oblique distance — plan

Goal

Remove the banding/moire the AC-0384 §29 assessment found in the raymarched cloud deck at oblique distance — the upper-left concentric stripes in the 120 m frame and the striped horizon cloud band in the 300 m frame — by establishing the cause by measurement (A/B: steps raised vs jitter vs both, per the ticket's method) and shipping the cheapest fix that removes the pattern rather than softening it. The layer's volume, brightness spread and the AC-0436 silver lining must survive, and the frame's render cost must be measured before and after and not increased (the cloud layer already consumes ~1191 s of the 1200 s budget in the heaviest test, so a fix that doubles per-pixel cloud work is likely unrenderable).

Code state of the defect (why the A/B is shaped this way)

The volume path (cloud_layer.gdshader, vmarchseg, default ON via cloud_volume) marches each annulus segment with a fixed 24 count-based steps: dl = (t1-t0)/u_vol_steps, samples at t = t0 + (i+0.5)*dl, no jitter. The step is length/count, so a grazing chord (shallow angle, kilometres long) gets steps of several hundred metres. Two facets, one visible defect:

  • C1/C3 — coarseness / non-adaptive density: the same 24 samples regardless of how much of the layer the ray traverses; at shallow angles the step is too coarse for the field's fine octaves (deck at 1/3 frequency: base ~768 m, finest octave ~186 m; a 2000 m chord samples at ~83 m — under Nyquist for the fine octaves).
  • C2 — coherent alignment: the sample positions are a deterministic function of (t0, dl), both of which vary smoothly across the screen with the ray's impact parameter. Adjacent pixels therefore march the same phased grid against the world-fixed density field → the aliasing is coherent across pixels → parallel stripes (banding) instead of noise (moire where two grids interfere). Nothing breaks the alignment today.

The A/B separates them: u_vol_steps 24→48 removes the pattern only if coarseness is the driver; per-pixel jitter removes it only if coherent alignment is the driver; if both work, the cost decides (jitter ≈ free; 48 steps ≈ doubles the per-pixel march cost — measured, not assumed). If neither removes it, the contingency arm (both) runs and the finding is recorded.

The fix (pending the A/B verdict — expected: jitter)

Per-pixel raymarch-grid jitter in the volume branch: two per-pixel randoms in [0,1) hashed from the shell's world position (v_wp — stable between frames, unique per pixel, parallax-correct), one per annulus segment, shifting each segment's sample grid: t = t0 + (i + 0.5 + j)*dl (a shifted last sample past t1 is dropped — the tail is the Beer-attenuated end of the chord, and the density gate is radial, so out-of-annulus samples are ~0 anyway). The coherent phase offset becomes an independent per-pixel random → the structured artifact becomes uncorrelated noise the eye tolerates. Cost: two 3-hash ahashes per cloudy pixel (≈20 ALU ops) against ~500–1000 ops of the 24-step march — negligible, but the wall time is measured before/after anyway.

  • Light-march taps (5 × 80 m toward the sun/moon) are NOT jittered: their grid is anchored to the sample's world position, not a screen-coherent grid — no coherent aliasing to break, and the moon re-aim (Ldir), the HG phase and the forward-scatter glow (the silver lining) stay exactly as AC-0436 shipped them.
  • Shipped behind the switch cloud_jitter (Settings, DEFAULT ON — the banded look is the reported defect: the AC-0435/AC-0436/AC-0437 re-ruling shape), env AWECRAFT_CLOUDJIT=0|1 (boot, no save), pushed u_jit 0/1 change-gated in world.gd _ac0401_push. OFF = the current appearance bit-for-bit (shader default u_jit 0.0; x+0.0=x, the shift never fires, the break never trips — IEEE construction, the AC-0401/AC-0428 convention).
  • AWECRAFT_VOLSTEPS=n stays as a boot-only cost-knob INSTRUMENT (the AWECRAFT_SPEC pattern — env only, no Settings row) so the 48-step arm's measured cost stays reproducible for the coordinator's budget work (1191/1200 s).

Adjudication by measurement, not by eye alone: a pure-PIL stripe metric (.scratch/AC-0441/stripe.py) on line profiles across the artifact regions — detrended oscillation std (energy) + normalized autocorrelation peak over lags 3–40 (REGULARITY). The pattern is REMOVED when the regularity collapses (periodic → aperiodic); a drop in energy alone is “softened”, not “removed” — the trap this project hit twice. Render cost = per-run wall time (game-clock t at the SNAP line vs wall, same recipe) — must not increase for the winning arm.

Preservation checks (what the fix must NOT touch)

  • Volume: the march, the annulus, the vertical profile, the silhouette gate — untouched code paths; the jitter moves sample positions only, never densities or lighting terms. Evidence: the acceptance frames vs the assessment frames (same weather, same structure).
  • Brightness spread: the AC-0406/AC-0407 lighting model (MS octaves, ambient fill, forward-scatter glow) is untouched — the day-frame cloud-pixel luma distribution (mean, p10/p90, >200 fraction) measured before/after.
  • Silver lining: Ldir re-aim, HG phase, glow — untouched; the night-120 frame shows the moonlit cloud edges.
  • Global cover variation (cloud_gate): untouched (the gate is in vgate, not the march).
