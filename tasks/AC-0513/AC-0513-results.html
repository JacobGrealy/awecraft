Depth: the self-defined acceptance case

Case: camera at the world origin looking along −Z, near 0.1 / far 1000 / fov 75; the resolve publishes the view depth of the detail plane face at z = −40.000 (the depth-band centre ray); the main-pass screen-depth reader reconstructs z = near / raw; error = |z − 40.000| in mm.

Why ≤1 mm was not met: on this API/driver a transparent fullscreen pass publishes its geometric depth, not the DEPTH value its fragment assigns (measured above). Publishing the terrain's depth therefore needs the resolve to be drawn at the terrain depth per ray (depth-preserving geometry / a depth prepass), which is the integration slice's job. At 1 mm the 16-bit quantum (24.4 mm at 40 m) is the binding constraint; at 24-bit (0.0954 mm) it is not.

Measured 4.7.1 API facts the shared plan depends on

  • CompositorEffect callback types: PRE_OPAQUE 0, POST_OPAQUE 1, POST_SKY 2, PRE_TRANSPARENT 3, POST_TRANSPARENT 4; no set_use_post_chain. Source cameras fire 2; the main camera fires 4. Callback cost (llvmpipe): main 0.186 ms, sat 0.029 ms, det 0.018 ms per frame at 640×360.
  • RDShaderSource is set_stage_source(stage, source) + set_language, and ShaderLanguage = {GLSL, HLSL}: the GDGLSL markers (#[compute], #[sampler2D(a,b)]) are rejected by shader_compile_spirv_from_source ("invalid directive" at the marker line) — raw GLSL compiles.
  • Compute lists are handle-based: compute_list_begin() returns an id, …_bind_compute_pipeline(id, pipeline) and …_dispatch(id,x,y,z) take it, compute_list_end() takes none (4.6-style calls are engine errors).
  • UniformType has SAMPLER_WITH_TEXTURE/IMAGE; RDUniform exposes only uniform_type/binding/add_id/clear_ids (no sampler_from, no compliant-resource fields).
  • RDTextureView has no view_name; RenderSceneBuffersRD.get_texture_format is keyed by the render_buffers namespace only (querying an absent name is an engine error).
  • A SubViewport in 4.7.1 has no texture-format property: its get_texture() is sRGB 8-bit, colour only (no depth accessor). Source depth must ride in a colour channel (fixture: blue; alpha is unusable — a transparent target premultiplies).
  • A SubViewport must be assigned its shared World3D after add_child; assigning it in _ready leaves the view with its own world, and every source sample then reads 0 (measured on the first full run: world_eq false, sources black; after the fix world_eq true and the sources render).

What this slice does NOT settle

  • Behaviour on a real GPU (the dev box is llvmpipe software Vulkan): timing of CompositorEffect callbacks, depth-buffer format/quantum, and the reverse-Z behaviour of hardware drivers are unproven.
  • The 0.5 ± 0.002 midpoint as a passing number: the channel to measure it exists and is precise; the fixture's band wiring must be repaired (the satellite half of the blend band reads 0), which is a fixture bug, not an API answer.
  • Round 2 statements above are superseded by ROUND 3: the midpoint is now a passing number, the depth case is measured through geometry-published depth, and the foliage labels are confirmed.
  • A passing ≤1 mm depth gate: needs depth publishing at the terrain's own depth (see gate 3).
  • Same-frame source dependency: the measured lag must be closed (scheduling / compositor ordering), and the same question on hardware is open.
  • MSAA/TAA/AA interaction (all disabled and stated), the per-face chart atlas, residency bookkeeping, and the full retirement schedule (D8).
  • Engine leak report at fixture exit (llvmpipe, after teardown): 56 Framebuffer + 67 Texture + Compute/Shader/Sampler RIDs and 5 ObjectDB instances reported leaked by the engine at process exit — the fixture's retire() frees its own RIDs; the leaked set is the viewport/compositor set that only the engine owns at exit. RD allocation counters are unavailable here, so leak counts are dev-only and not comparable to a hardware run.

What round 3 leaves unproven on real hardware

  • Timing: every millisecond figure here is software Vulkan (the epoch phase ran ~0.47 s/frame because the census does per-frame CPU readbacks). Compositor callback timing, source render cost and the lag mechanism need a GPU.
  • Depth-buffer format and quantum: the +1.16 m offset of geometry-published depth (gate 3) is an llvmpipe reading; the buffer format, its bit depth and the reverse-Z transfer function are unmeasured on hardware (get_driver_allocation_count returns 0, texture counters return −1).
  • Leak counts: RD counters unavailable here; only the engine's own exit leak report is comparable.
  • Gate 1: with a GPU the source SubViewports may render in the same frame; the census says they do not on llvmpipe.
  • The 8-bit endpoint windows (gate 2 endpoints, gate 3 wide-span sub-case) — the readback lags one frame, so endpoint values are read across a transition; the midpoint gate itself is unaffected.
