AC-0467 stage A — the home pair onto the canonical sphere placement (flag-gated)

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. The face lane already ships this (AC-0458 flag → AC-0460 default, occluder parity 335/335, 0.423 ms/chunk native). This extends the SAME placement to the home pair, behind a flag, default OFF, so the shipped game is untouched until it is proven. Stage B flips it and deletes the seam-extension apparatus.

1. Goal

With the flag ON, a home chunk's vertices land on the canonical sphere placement — each corner evaluated at its own (x,z) — instead of a rigid per-column transform. Consequence: two adjacent columns evaluate the SAME shared edge point, so the seam crack is zero by construction rather than covered by an extension.

2. The mapping (this is the whole maths)

world = (R + ly) * normalize(SphereMath.home_point(fx, fz, R)) - Vector3(0, R, 0)
fx = cx*16 + lx        fz = cz*16 + lz          (flat metres; home cells are 1 m)

home_point already exists (sphere_math.gd:324) and is documented as valid past the patch edge. This is the same shape as the face warp: the only difference is home_point(fx,fz,R) instead of uv_to_world(face,u,v,R).

6. Acceptance

Flag OFF provably untouched; flag ON makes adjacent home columns agree on shared corners (measured, in mm) with the seam band collapsing and no standing value moving. The default is NOT flipped in this stage.

7. Risks

(1) The home lane is the shipped game — any flag-off drift is a failure, which is why ac0423probe's exact nine overlaps are gated. (2) _view_basis drives camera up and the walking frame; getting it wrong makes the player feel tilted, so verify the player and planetwalk arms, not just geometry. (3) The home grid is 1 m cells over the same chart, so the sagitta inside one 16 m column is 16²/(8·4000) ≈ 8 mm — expect small displacements, and if you see centimetres, the mapping is wrong.
