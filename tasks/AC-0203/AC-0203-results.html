Deviation / notes log

  1. Runtime representation IS the wire format. The 24-slab array with null | {n,b,p,i,nz} entries is the exact runtime twin of the v4 on-disk section — palettize_flat is the single encoder shared by both, and decode_column reuses the same presence-table parsing. One lossless representation, two transports. _slab_flat materializes per-slab views on demand (null→empty, uniform→fill, packed→unpack, raw→duplicate).
  2. Hot paths materialize once per build. build_accs builds dviews/ fviews (24×4096) + neighbor views once and shares dviews with the light kernel via the new optional param — no per-cell slab dispatch; a null slab skips its whole 4096-cell loop. Steady-state per-tick work (fluids) iterates only wet slabs' non-zero cells with a per-tick slab-view cache.
  3. Stamps replace value-equality. Every == on data/fl (98 KB deep compares) became a 2-int [data_gen, fl_gen] compare: handoff stale check, eff-cache, face_blk cache, LOD alt-cache, lightcache probe. All mutation paths (gen landing, edits, fluid writes, clear) bump the right gen counter.
  4. Two latent pre-AC-0203 bugs surfaced and fixed. (a) _slabs_flat with mid-column null slabs produced a short/shifted flat array (null contributed 0 bytes) — _queue_chunk_save would have encoded a corrupt blob (sub = data.size()/S3 wrong). Caught by the selftest (terrain/top-edge columns failed while leading-null columns passed); fixed: null slab appends 4096 zeros. (b) The build_accs scoped ymask pre-pass read the GW=18 ring cells (lx/lz = 16) with a row-wrapped offset into the flat column — a wrong (next-row same-column) boundary value, OOB on the 4096-byte view. Fixed: ring + out-of-window rows read the TRUE boundary from snap; only the 16×16 interior reads the slab view. Affects only the interior fast-path of scoped edit rebuilds (strictly more correct).
  5. colbytes gain is small by design. zlib already crushed zero slabs in v3, so on-disk storage barely moves (4258→4235 B/col). The target was RAM: 192 KB/col flat → ~10–20 KB/col paletted in steady state (R50 mem delta verifies; see pending row).
  6. No godot runs mid-edit (a crashed mid-edit run at the start of this turn cascaded a single parse error into "Nonexistent function 'new'" everywhere). All gates ran only after the tree was complete and balance-checked; each parse fix verified by targeted --check-only --script + G0 before the gate sequence.
  7. Pre-existing cross-thread race found and bounded (not fixed at root). R50 run #1 showed 9× SCRIPT ERROR: Invalid access to property or key 'tid' in threadmesh_poll. A 4× 20k-frame instrumented diagnosis (mirror-array + mark cross-reference) proved the in-flight mesh entry — written on the pool thread (entry["t_run"], entry["result"]) and read on the main thread every frame — is torn: the SAME object read as a full 18-key dict and as an empty dict microseconds apart (a phantom-object hypothesis was ruled out). The worker write shape is byte-identical to HEAD (AC-0082 handoff pattern, git diff-verified) — the race is pre-existing; this run surfaced it (deeper per-entry reads + ~20% higher box load). Worst case is bounded: a torn handoff read degrades to null result = datadrop + retrigger (safe re-queue); run #1 completed 7845/7845 all_meshed. Bounded fix shipped: both poll loops skip an entry for the frame when has("key")/has("tid") fail (documented inline). A root fix (locked completion queue / flag) is a future task — the pattern is shared by every AC-0082-style handoff.
