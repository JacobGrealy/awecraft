AC-0203 — paletted-sections-per-slab — PLAN

Goal

Represent each 16×16×16 slab in memory as a local palette (MC 1.18 style) instead of a flat u8 array, so an R50 world's column data drops from ~192 KB/col (data+fl, ~1.5 GB at R50) to ~10–20 KB/col (~200 MB), keeping the world byte-identical.

#1 invariant (read twice): the paletted form is lossless — it expands to exactly the same block/fl ids. Therefore genhash (25 lines) must be byte-identical to .scratch/AC-0197-gates/genhash_A.txt; the codec round-trip must be byte-exact (v1/v2/v3 still decode); and the build_accs worker time must not regress (measure build_worker p95 before 240 ms vs after; the hot mesh loop reads paletted slabs via precomputed per-slab flat views — no per-cell Dictionary lookups in the hot loop).

Slab representation (in-memory, per chunk)

chunk.data / chunk.fl : Array (24 entries, kept under the same field names)
  null                                    = all-air slab (AC-0197 sparseness kept)
  {n:1, b:0, p:[v], i:[], nz:k}          = uniform slab (no packed idx; 16³ cells = v)
  {n:2..16, b:1..4, p:[≤16 u8], i:packed, nz:k}  = paletted slab (b = bits/cell,
                                              i = b·4096 bits, MSB-first,
                                              cell → palette index)
  {n:0, b:8, p:[], i:4096 raw u8, nz:k}  = raw fallback slab (>16 unique ids;
                                              cell value stored directly)
nz = count of non-zero cells (drives update_top, null-ification, sparse fluid tick)
empty array (size 0) = column not yet generated (existing sentinel, unchanged)

Cell read (static, worker-safe): _slab_cell(s, pos) = p[(w >> (16-sh-b)) & mask] from the two-byte window at pos·b bits — ~5 ops, no allocation. Hot bulk paths (build_accs, light kernel, _build_snap_data) materialize each slab ONCE into a local 4096-byte flat view (_slab_flat: uniform = C-level fill, mixed = byte→cells unpack for b∈{1,2,3,4}, raw = copy) and run the existing flat loops on the view.

Risks

  1. Hot-loop cost of paletted reads — mitigation: per-slab materialization (uniform slabs are C-level fills; only 2–4 mixed slabs/column pay the GDScript unpack, once per build pass, shared between the light kernel and the cell loop). Measured via build_worker p95; fallback = byte-level unpack micro-opts.
  2. Stamp vs value-equality semantics (eff/face/LOD/dispatch caches) — every in-place mutation path (set_local, set_fl_at, _apply_edits_to_chunk, data_landed, clear_data) bumps a counter; verified by grep that no other writer exists. The SMOKE light/fluids gates exercise edit+relight churn.
  3. Slab invariant violations (non-null all-zero slab, >16 ids, bits mismatch) — palettize + set_local are the only constructors; the self-test round-trips adversarial columns (all patterns, 16+ unique ids, top-edge slabs).
  4. Worker-thread safety — worker payloads are slab deep-copies (shared dict hazard eliminated); static helpers only, no instance state; ChunkIO stays Data/Game-free.
  5. R50 run time (~50 min/arm ×2) — background jobs, load recorded at start of each arm; a loaded box inflates p95 (re-run clean before declaring a regression).
