7. Risks / edge cases

  • genhash parity — merging must be geometry-only: terrain data (WorldGen, block arrays) is untouched, so 25/25 GENHASH must stay byte-identical. Any change to data generation is an immediate stop.
  • Per-corner Acc / light interpolation — a merged quad spanning cells with different light levels or tints must keep per-corner attributes (corner-interpolated), not average them; otherwise lighting/tint banding appears (caught by the light mode + iso render).
  • xtab/ktab + stab cull exemption — cross-quad (ids 18/19), fluid, and stab-cull paths must stay byte-identical behavior; do not let the merge path swallow them (task notes: "Keep stab cull, keep xtab/ktab exempt").
  • Grouping key completeness — merge only runs sharing id + face index + face light + tint; a missing key dimension produces wrong-color merged quads (caught by iso render + tint mode).
  • Per-tier trade — full greedy vs per-y-row strip merge: start with per-y-row strip merge (simpler, ~60% of the win) and only escalate if the vertex target (~60–80% cut) is missed; measure via mesh_info.
  • Fallback — if verts don't drop ≥60% after strip merge, report the measured drop and propose the greedy variant in the results page; do not ship a sub-target result silently.
