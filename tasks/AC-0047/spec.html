AC-0047 — tasks webui accessible on the LAN, surviving restarts

Request (user, 2026-08-19)

"I need the todo webapp to be accessible on LAN not just localhost."

Requirements

  • tasks/webui.py binds 0.0.0.0 by default (keep --port N; default port 5180). No auth (user's own LAN, explicit request).
  • Daemon mode (same proven pattern as serve_web.py --daemon from AC-0030 — study and reuse it): --daemon double-fork + os.setsid(), own session; --replace kills only the identified webui pid/port holder; port guard prints already running (pid X, port Y) and exits 0.
  • Pidfile .scratch/tasks_webui.pid; log .scratch/tasks-webui.log (append + start marker).
  • Existing behavior unchanged: loopback sandbox tests must still pass; edits still go through tasks_lib + re-render; static tasks/ dir serving intact.

Canonical command (after this task)

python3 tasks/webui.py --daemon

Verify (hard gates)

  1. Smoke test still green: python3 tasks/scripts/test_tasks.py (sandbox; live YAML untouched) — zero warnings.
  2. python3 tasks/webui.py --daemon --replace → prints pid; curl -s http://127.0.0.1:5180/ → 200 and contains the Queue section + a task card.
  3. LAN proof: curl -s http://192.168.0.224:5180/ → 200 (the machine's LAN IP; if that IP is stale, detect the actual non-loopback IP from ip -4 addr, use it, and say so).
  4. ps -o pid,sid,pgid -p <pid> → SID = own PID; pidfile matches; second non-daemon start → "already running" exit 0.
  5. FINAL STATE: leave the daemon running; report both http://localhost:5180/ and http://192.168.0.224:5180/ (or detected LAN IP).

Deliverables

  • Updated tasks/webui.py; running daemon on 5180 (LAN-reachable).
