1. What is generated

All audio is generated PCM in code — no .wav/.ogg files are added or loaded. autoload/audio.gd (the pre-existing AC-0039 lane, previously a no-op stub) now owns the layer:

  • Format: mono, 22050 Hz, 16-bit PCM, packed into AudioStreamWAV (the ambient additionally sets LOOP_FORWARD, loop_end = 44100 frames).
  • When: generated once at the autoload's _ready by nine pure, deterministic static func synth routines (fixed RNG seeds per voice — every call is byte-identical, which is what makes the arm's buffer assertions reproducible). Measured startup cost: 32.9 ms total for all 9 buffers (incl. the 2 s ambient; re-measured inside the arm), then zero synthesis per event — play() only touches cached data and the fixed player pool.
  • Loudness safety: a shape-preserving 0.9-peak limiter runs at the end of synth(), so "no clipping" is a property of the generated buffer, not an artifact of the 16-bit clamp.

How a given sound is distinguished from another — the nine voices differ in duration, tone-vs-noise content, frequency contour, envelope and (for the ambient) loop structure:

3. Voice cap, pool policy, allocation proof

Copying the AC-0038 pooled-particle discipline: a fixed 16-voice AudioStreamPlayer pool, allocated once in _ready, round-robin cursor. Cap policy (preempt-oldest): when the cursor lands on a still-playing voice, the new sound steals that slot (stop + play) — the newest event always wins, concurrency can never exceed 16, and no event is ever dropped. The ambient is routed to its own dedicated bed player (outside the pool) — a looping stream must never occupy a one-shot voice or it would hold the slot forever (this bug actually bit the first arm run: two voices stuck "playing" the 2 s loop; the routing fix is in).

4. Buffer assertions + the negative test

The arm (AWECRAFT_LOGIC=sound, --audio-driver Dummy, ~2 s wall) inspects the generated buffer, not the device:

  • Per voice (9/9 pass): exact duration in samples; RMS ≥ 0.01 (non-silent); 0 < peak ≤ 1.0 (no clipping, not all-ones); no NaN; not a DC rail (zcr ≈ 0 with rms > 0.5 → fail). Measured values in the §1 table.
  • Determinism: re-synthesizing all 9 voices byte-equals the cached buffers (deterministic: true) — the cache cannot drift from the generator.
  • Distinctness: all 36 pairs separated (min 0.070 > 0.05).
  • Names: 15/15 resolve; the ambient stream's LOOP_FORWARD flag is asserted.

The negative test (shown failing, as the AC-0310 bake guard was): the same checker is fed degenerate inputs and must reject them — if it passed, the arm fails:

5. Trigger cost (main thread, per event)

Measured around Audio.play() over 1000 triggers (the audio mix runs on its own thread — this is the per-event main-thread work only): avg 5.4 µs, max 18 µs per trigger; startup synthesis 32.9 ms (once). Against the standing picture (AC-0387's carve work made the far lane ~35× more expensive; the R24 crossing burst reads 9.6 ms against a 10 ms gate), a 5.4 µs per-event addition is ~1/1800 of that budget — sound adds no measurable main-thread cost to the streaming lanes.
