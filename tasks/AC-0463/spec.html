AC-0463 INVENTORY (coordinator recon, round 27). This ticket is the largest change in the tree and it is deliberately NOT being rushed. What follows is the measured surface so the work can be sliced rather than attempted whole.

WHY IT IS BIG: godot/world/world.gd is 15,507 lines with 373 functions. The two lanes are not two functions that can be merged; they are two co-existing arrangements of the same responsibilities:
- HOME lane: `_process` (world.gd:5854) drives banded streaming + drain; `recenter` (11733) rebuilds the resident set when the player moves; `_make_chunk_node` (11409) and `_column_checkout` (1384) create nodes; `chunks` (234) is the single dict, keyed `0:cx:cz` since AC-0459.
- FACE lane: `_face_stream` (14996) is a budgeted pass (`FACE_STREAM_BUDGET_MS := 12.0`, 14995) that lazily builds per-face chunks via `_ensure_face_chunk` (15335); per-face light engines live in `_star_faces` (14570).
- THEY ALREADY AGREE on the things that used to differ: one placement (AC-0460 warp, default on), one key shape (AC-0459), world-space collision and light, and exact cell conversion (AC-0462). That is why the merge is now an ARCHITECTURE change rather than a correctness change — nothing is broken by the split today, which is exactly why it must not be attempted in a hurry.

WHAT "REMOVE THE SPLIT" WOULD ACTUALLY REQUIRE (each is its own slice, and each needs its own gates):
1. ONE RESIDENCY MODEL: the home lane owns banded residency and a drain queue; the face lane owns a lazy budgeted pass. Unifying means deciding which policy wins per chunk class and proving no chunk is starved — measurable with the boundary r4 arm plus a new face-residency census.
2. ONE NODE CREATION PATH: `_make_chunk_node` vs `_ensure_face_chunk` must become one function with one identity assignment; the collidable/mesh/occluder contracts all hang off it (AC-0460 shipped occluder parity on the face path, so this path must keep it).
3. ONE LIGHT OWNERSHIP: `_star_faces` per-face engines vs the home light path — the riskiest slice, because AC-0358's feed invariant and the lightstate arm encode the current behaviour.
4. ONE SAVE/RESIDENCY KEY SPACE: already unified by AC-0459/AC-0465, so this slice is mostly deletion.
5. THE PROOF: "walk the planet end to end" — a crossface traversal across all 12 charts with seam and residency censuses at every boundary. No such arm exists today; `crossface` walks the home pair only.

RECOMMENDED SHAPE: do not open with a merge. Open with (5)'s instrument, because it is the thing that can prove or refute every later slice, and because a merge with no end-to-end traversal arm would be unfalsifiable. Then slice (4) deletion, then (1), then (2), then (3) last.
WHY I AM NOT STARTING THE CODE THIS ROUND: the honest reason is that a partial lane merge is worse than none — two half-merged policies produce exactly the quiet starvation this project keeps having to hunt, and the instrument that would catch it (a planet-traversal census) does not exist yet. Building that first is the same order that worked for the keys (AC-0465 before AC-0459) and for the placement (measure, then flip).
