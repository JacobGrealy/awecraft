AC-0463 stage L4 — one edit entry, with the face coordinates carried explicitly

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Step 3 of L1's five-step order. Behaviour-preserving: the same columns are re-lit, in the same way, as today.

1. Goal

Every block edit that changes light enters the light system through one place, and the face path carries explicit face-cell coordinates rather than relying on the home world-coordinate route — removing, structurally, the hazard L1 named as this migration's most likely silent failure.

2. The hazard being removed (L1, verbatim in substance)

The face re-bake is a compare-and-erase one-shot (world.gd:14967-14976) and on_edit has no face-cell coordinates (12999 is a home world-coordinate path). A naive unification therefore un-settles the WRONG column and the trigger never fires — stale face light after an edit, silent, and only weakly caught (crossface C4 eff>=1, harness.gd:35059). Stage L1 said a face-side FEED arm is owed before the FEED unification (step 4); this step removes the coordinate hazard so that step 4 has something sound to build on.

4. Edit shape

  • 4.1 One entry. A single function takes the edit and dispatches: home keeps its two-phase on_edit in home world coords; faces keep their whole-column reseed. Neither rule changes — what changes is that the entry knows which lane it is in and the face route receives face-cell coordinates explicitly.
  • 4.2 Coordinates, not inference. The face route must take (face, cx, cz) — or the face chunk key it already has — rather than deriving them from a world position. If a caller does not have them, that is a finding: report it rather than reconstructing them by a projection that might be wrong.
  • 4.3 Same columns re-lit. For a given edit, the set of columns un-settled and the trigger set must be exactly today's. State how you verified that (a counted comparison over a scripted edit sequence is ideal).
  • 4.4 Do not fix the compare-and-erase one-shot. It is the current behaviour; making it a loop is a behaviour change belonging to step 4.
