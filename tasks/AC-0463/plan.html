AC-0463 stage L2 — one accessor for which engine owns a face (zero behaviour change)

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Pure refactor. Step 1 of the five-step light-ownership order designed at L1, and the step L1 specified as changing nothing.

1. Goal

Asking "which light engine owns this face?" has one answer site, used by every existing caller, and the light is bit-identical before and after.

2. What L1 established (do not re-derive)

  • Home: one star engine (world.gd:265, 3945) — seed at landing (6346), two-phase on_edit in home world coords (12999), dt-scaled step with a settled drain publishing last_eff, E2 frame-diff re-arm and the paced remesh lane (6177-6318); bakes from the star payload with pl["star"]=true and the box-gate lver (9419-9427).
  • Face: per-face engines in _star_faces (14915, 14921-14927) — seed at _face_land (15875), whole-column reseed per edit (15985), fixed-budget step with a compare-and-erase drain (14935-14976).
  • The constraint any later stage must respect: the AC-0358 FEED invariant — applied bake == settled payload == fresh same-input reference — and the payload's w_lo/w_hi strip window (2-row overhang, starlight.cpp:797-803) being exactly what the bake consumes.

4. Edit shape

  • 4.1 One accessor. A function taking a face (and whatever else a caller genuinely has) returning the engine that owns it today — star for faces 0/1, the per-face instance for 2-11. It must not create engines, change lazily, or alter ownership; it answers, it does not decide.
  • 4.2 Same answers, proved. For every converted site, the accessor must return exactly the engine the old inline expression returned. State how you verified it — an assertion, a temporary cross-check over the conversion, or an exhaustive expression diff — in the deviations. A refactor that is merely "not obviously wrong" is not accepted here.
  • 4.3 No behaviour moves. Same cadence, same reseed rules, same window, same bake. If converting a site would change WHEN an engine is created or seeded, leave that site and list it — creating an engine lazily is a behaviour change, not a refactor.

6. Acceptance

One accessor answers engine ownership for every caller, every answer identical, and every light field bit-identical.

7. Risks

The dangerous site is any place that obtains an engine as a side effect of creating one (the per-face instances are created lazily). Converting such a site to a pure accessor would stop the creation happening — so those stay as they are and are listed. If that leaves the accessor covering very few sites, say so and report the count; a one-caller accessor is not worth the indirection.
