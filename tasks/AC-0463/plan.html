AC-0463 slice 2b — one travel gate and one window, shared by both lanes

Coordinator contract. Medium builder applies it with tasks/templates/implement.md. Behaviour-preserving extraction. The user has decided the policy (round 35): eviction is travel-gated, a stationary player sheds nothing, no cap, and there must be no special-cased home. This slice makes the two lanes express that with ONE mechanism instead of two.

1. Goal

A single travel-gate predicate and a single window computation, used by both lanes, with no face-number special-casing — the mechanism the later "delete the home branch" slice needs to exist.

2. What is actually true today (measured by the coordinator, round 36 — do not re-derive)

  • Home eviction is already movement-driven: it happens inside recenter (world.gd:11841), in the to_free loop around 12238, deferring over-cap frees through _deferred_free (AC-0257) and releasing through _free_chunk_key (11612) / _col_checkin.
  • Face eviction is gated on moved > 16.0 against _face_evict_last (14679, used at 15151-15153), with the window win = sim_dist * 16 and evict_r = win + FACE_STREAM_EVICT_MARGIN.
  • So both lanes ALREADY satisfy the user's chosen behaviour (nothing sheds while stood still). The separation is in the MECHANISM, which is what this slice removes.

4. Edit shape

  • 4.1 One travel gate. Extract the "has the player moved enough to justify an eviction sweep" test into one predicate (taking the current flat position and a threshold), and call it from BOTH lanes. Keep the existing 16 m value as the threshold and keep the face lane's existing state variable semantics — the home lane may need its own "last sweep position" to preserve behaviour exactly; that is allowed (two callers, one rule).
  • 4.2 One window. Extract the resident-window computation (the sim_dist→metres window and the evict radius including its margin) into one helper used by both, preserving each lane's current effective numbers. If the two lanes' windows are genuinely different quantities (e.g. face cells vs 1 m home cells), the helper takes the cell size as a parameter and says so in a comment — a parameter for a UNIT is not the face-number special-casing this ticket is deleting.
  • 4.3 No face-number branch added. The predicate and the window must not take a face number at all. If you find yourself needing one, STOP and report — that is the separation surviving under a new name.

7. Risks

The danger is subtle behaviour drift in recenter: its frees are deferred and identity-guarded (AC-0257 — a pooled column keeps its instance_id, so col_gen is the discriminator). Do not touch that machinery; only the decision of WHEN the sweep runs moves. If preserving behaviour requires two separate state variables, that is acceptable and expected — what must be shared is the rule, not the bookkeeping.
