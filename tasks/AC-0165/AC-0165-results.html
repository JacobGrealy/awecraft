  2. godot-cpp ref: 4.5 (round 1) → master @ 05057de7 with api_version=4.7 (round 2). Round 1 picked branch 4.5 (the remote's newest stable branch; no 4.6/4.7 branch or tag exists) on the README's "earlier-minor works in later-minor" claim — that claim failed empirically: the 4.5-built .so crashed with signal 11 on load in Godot 4.7.1. Round 2 rebuilt against master (the only 4.7-targeting ref: supported_api_versions = ["4.3".."4.7"], bundles extension_api-4-7.json) with api_version=4.7 → the .so loads clean (G0). The C++ series (AC-0188/0189/0190) should keep building against this 4.7 ref; if a real 4.7-stable branch/tag appears on the remote later, re-pin to it.
  3. SCons "Argument list too long" trap (documented in the SConstruct header): godot-cpp MUST be built from its own directory. Pulling its SConstruct into the gdext build makes the ar step run with ~132 KB of absolute object paths inside ONE sh -c argument → exceeds the kernel's 128 KB single-argument limit (E2BIG, reported as sh: Argument list too long). Building from the gdext directory instead links the prebuilt .a directly (a normal downstream-project setup).
  4. New .gdextensions need one --import run before the headless runtime auto-loads them (editor filesystem scan registers the file in the .godot cache). Done on this machine; on any fresh clone (or the Windows machine) run godot --headless --path godot --import once. GDExtensionManager.load_extension(path) is the fallback.
  5. Godot 4.7.1 GDScript gotchas hit (for the C++ series): GDExtension classes are NOT resolvable as bare identifiers in GDScript parse (use ClassDB.instantiate("Name") / ClassDB.class_exists); PackedByteArray.get_hexstring() does not exist (manual hex); := type inference fails on and-chains containing Variant comparisons (annotate : bool).
  6. Scope notes vs the notes text: "save 5KB/col" and "boundary p95 drop" are AC-0203 codec-format properties / later integration gains — this turn delivers the pipeline + codec + the decode-speed evidence (slab path 28.6×, flat 8.1×). Wiring the worker save/load paths (world.gd _try_disk_load / _queue_chunk_save) onto the C++ class is the follow-on (AC-0188/0189/0190 series); the codec API is ready for it (decode_slabs returns the exact {n,b,p,i,nz} slab form c.slabs_landed() consumes). R50 NOT run (per coordinator: the performance win is the decode probe, not an R50 build).
  7. Fail-closed strictness (intentional superset): the GDScript _decode_array_v4 has a latent index-out-of-range on a blob truncated right after a slab's n byte (it checks o+1 before n but reads bits unchecked — unreachable in production because MD5 verification precedes decode). The C++ decoder checks both bytes and fails cleanly; on every valid (MD5-passing) blob the behavior is byte-identical to GDScript, which is what the probe asserts.
