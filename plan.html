AweCraft → Minecraft Parity Plan

Goal: make AweCraft as close to Minecraft as possible, closing the 8 identified gaps. All work stays in the single index.html (no new dependencies). Each workstream ships with a build bump (BUILD marker), node --check, and a live browser verification.

Ordering is by dependency + impact: lighting and terrain depth first (they enable the rest), then the survival loop, combat, the Nether, and finally the "feel" systems (particles, sound).

Per-dimension save. Flint & steel item + recipe. Build and light an obsidian portal, walk through to the Nether, and return.
7Particlestodo Pooled particle system (~200, THREE.Points with per-particle color/velocity/gravity/life). Block-break debris (block's average color), hit sparks, arrow-hit burst, small pickup puff. Breaking blocks emits flying debris; hits and arrows produce sparks.

All procedural (no assets). Every core action (walk, mine, place, hit, eat, shoot) has audible feedback.

Known deviations (documented, not bugs)

  • No ambient occlusion, no redstone, no rain, no baby-mob visuals beyond current, no ghast, no enchanting.
  • Portal scale is 1:1 (vanilla uses 8:1 overworld→Nether).
  • Single-file, single-threaded generation; light is recomputed per-chunk on edits (may hitch briefly on large builds).
  • Audio is synthesized, not vanilla samples.

Verification protocol (per workstream)

  1. Bump BUILD marker (e.g. 20260815-r8 …).
  2. node --check on the extracted module — must pass.
  3. Live browser check (Playwright): 0 console errors, __loopErr null, feature exercised via __debug, screenshot captured.
  4. Update this plan's status column.
