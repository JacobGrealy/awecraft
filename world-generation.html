01

The pipeline, end to end

Everything happens in one function — genChunk(cx,cz) (index.html:784–871) — per 16×16 chunk. The chunk is a flat Uint8Array(16·16·80) indexed (y<<8)|(lz<<4)|lx, and generation is a strict sequence of passes: each pass only reads what earlier passes wrote, so the world is fully deterministic from the seed alone.

Why it matters Every field below is a pure function of (x, y, z, seed). No randomness enters after the seed: the same seed always produces bit-identical terrain, in the web build and in the Godot port.
02

Noise primitives & seeding

The generator is built on two 32-bit integer hashes, a quintic smoothstep, and their trilinear interpolation — value noise, not Perlin. fbm (fractional Brownian motion) stacks octaves: each octave doubles the frequency, halves the amplitude, and is re-seeded with +101 per octave so layers don't self-correlate. Output is amplitude-normalized, so every fbm field sits in [0, 1). 

126function hash2i(x,z,s){let h=(s^Math.imul(x,374761393)^Math.imul(z,668265263))|0;
  h=Math.imul(h^h>>>13,1274126177); h^=h>>>16; return(h>>>0)/4294967296}
// ^ line 126 verbatim (one line in the spec, wrapped here). hash3i (line 127) is identical with a y-lane constant 2246822519
128const fade=t=>t*t*t*(t*(t*6-15)+10);   // the C² quintic smoothstep
135function fbm2(x,z,s,oct=4){let a=0,amp=1,f=1,tot=0;
  for(let i=0;i<oct;i++){a+=vnoise2(x*f,z*f,s+i*101)*amp;tot+=amp;amp*=.5;f*=2}return a/tot}
// ^ line 135 verbatim (fbm3, line 136, is the same shape in 3D with vnoise3, oct=3)
// vnoise2 (lines 130–131): trilinear lerp of the four hash2i corners of the unit cell, fade() on x and z
// mulberry32 (line 125) is a PRNG used only for UI particles (line 720) — never for terrain.

Seeding. A world is one int32. The title screen hashes a string with seed = (Math.imul(seed,31) + charCode) | 0 per character (index.html:2997–3001); with no input it rolls (Math.random()·2147483647)|0. Every field below re-enters the seed with a distinct offset (+7, +13, +21, +33, +55, +66, +77, +88, +99, +301, +302, +333, +777, +778), so each field is an independent stream of the same world. The string "awecraft" hashes to -1520868207 — the seed used for every figure in this atlas.

Elevation — three stacked fields

terrainHeight(x,z) (lines 760–767) sums three fields at different wavelengths — a classic continent / hill / mountain decomposition:

c — continental

Slow baseline relief: broad rises and basins.

noisefbm2(x/220, z/220, seed, 3)
wavelength~220 blocks, 3 octaves
weight×14 → ±7 blocks about the mean
feedsy = 22 + c·14 + …

h — hills

The dominant texture: gentle rolling country.

noisefbm2(x/70+333, z/70+333, seed+7, 4)
wavelength~70 blocks, 4 octaves (finest terrain layer)
weight×20 → ±10 blocks
feeds+ h·20

r — ridge mask

Sparse mountain bonus; most of the map gets zero.

noisefbm2(x/300+500, z/300+500, seed+13, 3)
gatefires only when r > 0.62
weight+ (r−0.62)·150 → up to +57 blocks
feedsy >> 56, clamped at 74
760function terrainHeight(x,z){
761  const c=fbm2(x/220,z/220,world.seed,3);
762  const h=fbm2(x/70+333,z/70+333,world.seed+7,4);
763  const r=fbm2(x/300+500,z/300+500,world.seed+13,3);
764  let y=22+c*14+h*20;
765  if(r>0.62)y+=(r-0.62)*150;
766  return Math.max(3,Math.min(74,Math.floor(y)));
767}

The plain (mountain-free) band is 22 … 56; ridges push it to the 74 clamp. The result is floored to an integer and clamped to [3, 74] — always at least three blocks above bedrock-level water, never above the build ceiling of H = 80. Coordinate offsets (+333, +500) shift each field onto a different region of the hash lattice so the layers read as independent.

04

Biomes — temperature × moisture

biomeAt(x,z) (lines 768–775) samples two independent fields at a common 260-block scale — temperature t and moisture m — remaps each to [−1,1) with ·2−1, and walks a threshold ladder in order: 

768function biomeAt(x,z){
769  const t=fbm2(x/260+900,z/260+900,world.seed+21,3)*2-1;
770  const m=fbm2(x/260+1700,z/260+1700,world.seed+33,3)*2-1;
771  if(t<-0.25)return 'snow';
772  if(t>0.35&&m<0.1)return 'desert';
773  if(m>0.25)return 'forest';
774  return 'plains';
775}
  • Snow wins outright: any cold column (t < −0.25) is snow, whatever the moisture.
  • Desert needs heat and dryness: t > 0.35 and m < 0.1. A hot but wet column falls through to the next rule.
  • Forest is everything warm-ish that is wet enough: m > 0.25.
  • Plains is the fallback — the temperate, not-wet, not-hot, not-cold residue.

The biome then picks the column's surface block (lines 800–804):

05

Sea level & water

Water is not a noise field — it's a flat plane at CFG.SEA = 30 (line 103). After a column is filled, anything below the plane is flooded: if (h < 30) for (y = h+1 … 30) block = Water(5) (line 817). So an ocean floor at h=29 gets exactly one water block; a basin at h=12 gets 18. Water is recorded as a fluid source level (8) in the chunk's parallel fl array (line 869) for the flow simulation.

  • Beaches: any non-desert column with h ≤ 31 (one block above the sea) wears Sand on top instead of its biome block — a 2-block-wide shore band around every water body.
  • No trees in water or on beaches: treeAt returns false for h ≤ SEA+1, so the shoreline is always treeless by construction.
  • Ocean vs. sea: because terrain's plain band is 22–56 and sea is 30, roughly the lower third of the continental field becomes ocean — which is why continental scale (220) matters more than hills (70) for where continents sit.
06

Ores & obsidian in stone

During the column fill, every stone block (y < h−3) is offered to four checks, in order, first hit wins (lines 806–814). Three are depth-gated 3D-fbm thresholds (ore veins), one is a per-block hash speckle: 

807  const n1=fbm3(x/7,y/7,z/7,world.seed+77,2);
808  const n2=fbm3(x/9+900,y/9,z/9+900,world.seed+88,2);
809  const n3=fbm3(x/6+1700,y/6,z/6+1700,world.seed+99,2);
810  if(y<16&&n1>0.78)b=16;              // Diamond Ore — deepest
811  else if(y<42&&n2>0.8)b=15;             // Iron Ore — mid
812  else if(y<60&&n3>0.82)b=14;             // Coal Ore — shallow
813  else if(y<10&&hash3i(x,y,z,world.seed+333)<0.02)b=25; // Obsidian — bottom 10

The classic Minecraft depth ladder is preserved: diamonds only below y=16, iron only below 42, coal only below 60, obsidian only in the bottom ten. Because the checks cascade, a deep block that would qualify as iron first gets tested for diamond. Measured by running the spec's own noise on 120,000 sampled blocks per band, the effective vein densities are:

Caves — two intersecting worms

After columns, water and ores are in place, a whole-chunk pass carves caves (lines 819–830). Each block from y=5 up to the surface is tested against two independent single-octave 3D value-noise fields with different axis scales — the y/10 vs x/16 stretch makes the patterns elongate vertically into worm-like tunnels: 

826  const n1=vnoise3(x/16,y/10,z/16,world.seed+301);
827  const n2=vnoise3(x/11+500,y/9+900,z/11+600,world.seed+302);
828  if(n1>0.58&&n2>0.56)data[i]=(y<8)?24:0;   // lava if deep, else air
  • Intersection, not union: carving needs both fields above threshold. Where two worm-tubes cross, air appears — thin winding passages instead of open caverns.
  • Deep lava: carved blocks below y=8 become Lava (24); everything else becomes air (0). Air and water are skipped, and bedrock (y=0) can never be carved.
  • Measured openness: 14.16% of sampled blocks in y=5…70 carve with this seed (120,000 samples), i.e. caves are a minority of the underground but pervasive enough that most deep explorers meet them quickly.

Trees & flowers

Tree placement is the purest noise decision in the game: one hash per column, compared against a biome density (lines 776–783). No clustering, no minimum spacing, no species variety — it is a Bernoulli trial per column, re-derivable anywhere from the seed, which is what lets chunks place trees from their 2-column halo without sharing state. 

776function treeAt(x,z){
777  const h=terrainHeight(x,z);
778  if(h<=CFG.SEA+1)return false;               // no trees in water / on beaches
779  const b=biomeAt(x,z);
780  const d=b==='forest'?0.14:b==='plains'?0.02:b==='snow'?0.02:0;
781  if(d===0)return false;
782  return hash2i(x,z,world.seed+55)<d;
783}

The oak, block by block

Once a column qualifies, its shape is fixed by a second hash: th = 4 + floor(hash2i(tx,tz, seed+66) · 3) — trunk height 4, 5 or 6, each exactly one third of trees. The trunk is Oak Log (6) from h+1 to h+th. The canopy (lines 849–857) is four stacked squares, trimmed at the corners: 

849  for(let dy=1;dy<=th;dy++)put(tx,h+dy,tz,6);            // trunk: h+1 … h+th
850  for(let ly=th-1;ly<=th+2;ly++){
851    const rad=ly>=th+1?1:2;                          // fat lower, slim crown
852    for(let dx=-rad;dx<=rad;dx++)for(let dz=-rad;dz<=rad;dz++){
853      if(rad===2&&Math.abs(dx)===2&&Math.abs(dz)===2)continue;  // cut corners
854      if(ly===th+2&&Math.abs(dx)===1&&Math.abs(dz)===1)continue;  // crown → cross
855      put(tx+dx,h+ly,tz+dz,7);                         // Leaves
856    }}
857  }

For a trunk of th=5: levels h+4 and h+5 are 5×5 rings (12 leaves each, corners removed), h+6 is a full 3×3 (9), and the crown at h+7 keeps only the cross (5) — the classic AweCraft oak silhouette. Two guards keep the pass safe: put() writes only into air inside this chunk (x,z ∈ 0…15, 1 ≤ y < 80), and a ±2-column halo scan means canopies started in a neighbor chunk still land their overhanging leaves here (lines 832–848).

Flowers The last pass (lines 859–868): on any column with h > 30 and h < 78 (H−2) whose top block is Grass, hash2i(x,z,seed+777) < 0.02 plants a flower one block above the surface — a Rose (18) if hash2i(x,z,seed+778) < 0.5, else a Dandelion (19). 2% of grass tops, split 50/50 by species. Sand, snowy grass and ocean floors never flower.

10

The Godot port

godot/world/generator.gd + godot/core/noise.gd re-implement the same generator for the Godot 4.7.1 build. The noise math is bit-identical: GDScript's 64-bit multiplies masked with & 0xFFFFFFFF produce the same low 32 bits as the web spec's Math.imul, and hash2i/hash3i/fade/vnoise2/vnoise3/fbm2/fbm3 use the same constants. Every parameter in the registry table above matches (scales 220/70/300/260, offsets 333/500/900/1700, seed keys, thresholds 0.62/0.78/0.8/0.82/0.58/0.56/0.02, densities 0.14/0.02, SEA = 30, HEIGHT = 80, clamp 3…74).

Two deliberate differences:

  • Spawn plateau (generator.gd:36–42, 125–133) — the port flattens terrain within radius 6 of (8, 8) to h = 34 and smoothstep-blends it back in between radius 6 and 10, so new players always spawn on level ground. The web spec has no such patch and can spawn on a slope.
  • Early-out in tree_at (generator.gd:57–72) — the port rejects columns whose seed+55 hash is ≥ 0.14 before computing height and biome (an optimization). Since every biome density is ≤ 0.14, the accepted set is exactly the web spec's: same trees, same places.

The port also evaluates the five fbm2 fields in batched per-chunk passes (same values, fewer re-computations) and returns only the block array — the fluid array is initialized elsewhere.
