One planet model — coordinator decision

Status: proposed, not implemented. AC-0433 P1. Production still uses its home/face split. The bounded numerical probe passed and was independently rerun by the coordinator; production implementation remains pending. At the sampled equal-height boundaries the maximum shared gap was zero; interior inverse round-trip error was 0.000481 m, and a deliberate one-cell perturbation produced a 0.792551 m gap. Evidence: tasks/AC-0433/p1_probe.gd and the P1 results page. This validates the sampled embedding algebra, not production mesh/collision/streaming performance. This document chooses the design; the builder does not choose it. P2a status (2026-10-19): the pure forward/inverse canonical API (grid_shape, vertex_key, vertex_to_world, cell_to_world, world_to_cell, address_key) has landed dormant in godot/core/planet_grid.gd — zero production callers, no runtime, key, save or native change. Neighbours, key storage and live migration remain pending. No redesign.

1. Grid: one rule, no home exception

Retain the existing twelve half-face charts and prewarped cube-sphere directions, but replace both current address grids with one radius-derived rule. Let H=πR/4. Set N=16·ceil(H/16). A short chart axis has N cells; a long chart axis has 2N cells. Faces 4–7 use (Nu,Nv)=(2N,N); all other faces use (N,2N), as determined by the coordinate spans in SphereMath.uv_to_world. Each chunk has 16×16 horizontal cells and the existing vertical cell count/one-metre height step. Thus all chart edges land on chunk boundaries, including the half-face joins. No partial outer chunks or special spawn grid.

At R=4000 the formula predicts N=3152, long axis=6304, and 197×394 chunk slots per half-chart, 931416 planet-wide. These are address-space capacity, not allocated/resident nodes; streaming remains a bounded local window. The midline nominal arc step is H/N, slightly below one metre. A cube-sphere is not isometric: actual edge lengths vary across the chart. This is a uniform definition and comparable block scale, not a promise of exact one-metre Euclidean squares at every point. The probe must report min/max edge lengths and the midline step. Preserving the old exact-midline rule would require partial boundary cells; consistent chunk topology is preferred here, and the small nominal-scale change requires explicit documentation.

2. Placement: shared vertices, not independent tilted towers

For chart grid coordinates (i,j) and radial height h, define u=i/Nu, v=j/Nv, n=normalize(SphereMath.uv_to_world(face,u,v,R)), and global P=(R+h)n−(0,R,0). Chunk nodes may have a nearby origin for float precision, but geometry is the difference of these common world points, not an independently fitted tangent frame. Mesh, collision, edit ray tests and entity placement consume the same embedding.

The seam proof is elementary: if two incident charts represent the same boundary coordinate, their n is the same; consequently P_A(h)−P_B(h)=0 at every equal h. Independent cell-centre radials do not have this property; they retain h(n_A−n_B). That is why neither shrinking the LSQ fit nor assigning a rigid frame per cell is the chosen fix. The old overlap extensions/grout are transitional machinery, not the final seam rule.

Local voxel meshing remains flat and face-culling remains a local-data decision. Before placement, split exposed quads on the shared one-cell vertex lattice, with one deterministic triangle diagonal. Then warp vertices. Large greedy quads cannot remain single flat quads under nonlinear placement: otherwise neighbouring vertices create T-junctions and curvature disappears across merged faces. A flat 16×16 top therefore has 256 quads/512 triangles before vertex sharing, versus one quad/two triangles in the ideal greedy case. This is a cost to measure in implementation, not a free optimization. Normals derive from displaced triangles (with an explicit material convention for voxel hard edges); collision uses those identical triangles. Winding follows the chart handedness/mirror convention exactly once, never through a negative-scale node.

3. Ownership and conversion API

Canonical address: (planet, face, i, j, k), with chunk coordinates floor(i/16),floor(j/16) and local slots modulo 16. Proposed persisted chunk key is versioned planet:face:cx:cz, including faces 0/1. No flat-key alternate routing. Existing world_to_face tie order chooses ownership; interior domains are half-open. At physical cube edges or corners, vertices are shared positions while cells belong to their chart interiors. Canonicalize shared vertex identity by integer cube-lattice coordinates over a full face of 2N steps; axis/sign chart permutations must produce the same integer triple. Evaluate a canonical vertex from that identity once, avoiding two subtly different floating computations. Cell neighbours cross edges through the same integer cube orientation, not the current approximate 1024-grid 2:1 lookup.

Public API: grid_shape(R), cell_to_world(address, fractional_local), world_to_cell(global_pos,R), neighbour(address, axis, sign), vertex_key(face,i,j,R). Inverse: add (0,R,0), radial h=length−R, call world_to_face, multiply by Nu/Nv and floor for cell ownership; fractional coordinates are retained for movement. Border tolerances need deterministic snapping before half-open selection. Probe interior round-trips first; later collision/edge tests own floating boundary robustness. The origin offset stays purely a global convention; it does not grant face 0 special physics or storage semantics.

4. LOD, workers and consumers

One worker dispatch/landing contract consumes a canonical chart chunk and neighbourhood. Keep column-atomic visibility and collision requirements from AC-0445. No second synchronous face mesher in the final state. Height/average LOD payloads may remain reduced data representations, but their geometry must call the same embedding and boundary ownership. Coarse/fine joins require conforming boundary tessellation (shared fine edge vertices or a validated transition mesh); a skirt that hides a hole is not final acceptance. Body/sky/cloud systems are outside this refactor.

Generation samples the spherical field using canonical addresses. Player recenter/simulation use chart cells and tangent/radial movement everywhere, including spawn. Mob spawn must not skip non-home charts; walk/facing, drops and entities use the canonical tangent frame. Saved player poses retain global position plus canonical address as needed. Save version changes in the same commit that changes keys; old saves are rejected cleanly, never half-loaded. No migration, per the user's pre-alpha ruling. Record the old genhash anchor before any generation change and intentionally establish the new one with the changed convention.

Status of the implementation, 2026-10-19. P2a (grid rule, shared-vertex embedding, forward/inverse) landed dormant and verified, and P2b has since added the cell identity and in-plane adjacency: every chart cell is one unit square of the cube lattice, addressed as (plane, a, b), with the owning chart DERIVED from those coordinates rather than carried — so the sector seam needs no special case. A step that leaves the plane now folds onto the adjacent cube plane, so cell adjacency is total; because a fold is a genuine 90° rotation the return direction rotates with it, which a navigating consumer must respect. Nothing in the shipped runtime uses any of it; key storage, streaming, collision and the player/mob consumers are still on the legacy split. Evidence: godot/core/planet_grid.gd and the p2a/p2b/p2b2 probes under tasks/AC-0433/.

Measured blast radius, 2026-10-19 (AC-0433 M1). Switching placement is not a free swap, so it was measured before any player-visible change: at the same chart coordinates the canonical pointwise placement sits a mean of 0.95 m from the shipped one on the interior of the non-home charts (max 1.86 m, 144 sites), 0.98 m at the home/face seam (max 2.00 m, 48 sites), 0.05 m on the home pair (max 0.12 m), and 0.16 m at ground level at the documented corner site. Every maximum occurs at h = 140 m, not at the surface — the difference is the radial-shear term of the legacy rigid tilted frames, which vanishes at h = 0. What the migration buys is the other side of that ledger: the legacy-vs-legacy across-seam gap of 2.19 m crossing / 3.73 m corner becomes exactly zero at equal height, because two incident charts then evaluate one shared vertex. So the trade is real and favourable at the surface, and its cost is concentrated at altitude, where the current model leans. Evidence: tasks/AC-0433/m1_probe.gd and .scratch/AC-0433-gates/m1-probe.log.

5. Ordered implementation

  1. P2a: pure canonical API alongside old runtime. Add grid_shape, vertex_key and pointwise forward/inverse plus neighbour orientation with no callers switched. Gate integer shared identities, all chart edges/corners, non-boundary round-trips, perturbation negative test and old runtime regression. Bounded subset landed 2026-10-19: the pure forward/inverse API, dormant in godot/core/planet_grid.gd with no callers switched (evidence: tasks/AC-0433/AC-0433-results.html, P2a). The neighbour orientation remains the next medium implementation unit.
  2. P2b: canonical data/address adapter. Define chunk/height semantics and generator neighbourhoods on the new grid; save version/reject and genhash evidence land with activation, not silently earlier. Keep legacy runtime until the canonical lane is complete.
  3. P2c: native tessellating emitter and collision. Same vertex lattice/triangles; compare with API and instrument worker/enable cost. Do not activate globally if timing or atomicity fails.
  4. P3: single streaming lane. Route all charts, spawn included, through canonical worker dispatch, LOD transition edges and common light/ring rules. Remove home-key routing and special face sync mesher only after parity tests. Re-establish deliberate changed standing values with reasons.
  5. P4: player, mobs, entities and persistence activation. Switch world/local consumers together behind the save-version boundary. No world state where new geometry uses old ownership. Delete transitional adapters and extension machinery once unused.
  6. P5: full-planet acceptance. Both directions across sectors/cube edges/corners, floor contact, no voids or light seam, streamed takeoff/descent, return to spawn and save/reload. Numerical equal-height seams are necessary, not sufficient proof of playable topology.

6. Rejected shortcuts and limitations

Retaining the 1024 face grid and merely fitting every chunk uniformly preserves two physical block scales and fails the user's story. Extending edges further preserves stretched textures and hides geometric disagreement. Per-cell rigid radial facets merely reduce, not eliminate, frame divergence. A globally dense planet is unnecessary: the address-space increase must not become an allocation increase. Reduced detail far away is valid, different world rules on the spawn face are not.

The pending P1 probe validates algebra against shipped mapping and regression controls. It cannot establish frame time, collision stability, T-junction-free production emission or save correctness before those implementations exist. Those remain explicit later gates.
